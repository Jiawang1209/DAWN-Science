## 目标

用户希望 DAWN 支持截图中的选项式提问：模型缺少信息时给出明确问题、选项及说明，用户可选择或自行输入，多题逐题回答，提交后模型继续任务。

4. `packages/client/ui-user-questions/src/client/draft-store.ts`：草稿和题号按会话所属 store、请求 key 保存；组件重挂载不丢回答，不串到另一会话。
5. `packages/client/ui-user-questions/src/client/index.ts`：问答卡通过 composer chain 接入输入区，卡片生命周期与是否显示分开；隐藏面板不是回答，工具行可重新打开。
6. `packages/interaction/tool-ask-user/src/timed.ts`、`packages/interaction/user-questions/src/projection.ts`：可选 timed 模式有默认前台等待、pending 结果、open/continued 状态；超时不是跳过或批准，迟到答案作为带来源的新用户消息进入后续轮次。不能只加一个定时器就获得这种行为。

## 方案比较

1. **建议：原生 API 工具 + DAWN 协议卡片，先阻塞等待。** 模型真实收到用户答案，和既有会话、取消、方案期集成；范围明确，可验证完整主链路。
2. 解析模型自然语言中的问题生成卡片：无法可靠确定题目边界、选项身份和等待时机，不采用。
3. 同时引入 timed、迟到回复及各 ACP 桥接：覆盖面更广，但必须先解决队列准入、恢复、适配器能力与重入；作为后续阶段。

## 第一版行为

API 主对话、侧边对话以及 API 远端工作区的根会话可用。问答本身由本地运行时处理，不需要服务器安装新服务。方案期也可提问，需明确列入方案期准入规则；不会因此放开写入或执行工具。子 agent 第一版不注册此工具。

模型工具名为 ask_user_question。questions 每批 1–3 题；每题 id 唯一、非空，question 非空；可有 header、options 和 multi_select；选项每题最多 8 个，标签非空且唯一；无选项时显示自由输入。参数与答案均由后端校验。

待回答卡展开时接管输入区，隐藏普通聊天输入框及工具栏；收起后恢复普通输入框和原草稿，供补充消息或调整方向。顶部显示短标题和问题；选项文字与说明分层；支持单选、多选、自定义输入、上一题、下一题、题号、跳过、收起。第一版选择后不自动跳题，以明确的下一题按钮前进；最后按钮为提交答案。推荐项有提示但不预选、不自动提交。

每题必须已回答或明确跳过，最终一次提交整批。单选自由输入替代选择，多选自由输入可补充选择。返回答案包含每题 id、selected 标签数组及可选 custom。后端验证题号完整且不重复、标签来自原选项、单选不含多个选择、单选自定义不与选择并存；跳过为 selected=[] 且无 custom。无答案不等于允许操作。

收起只改变展示，卡片摘要和重新展开入口常驻。关闭/取消请求采用明确的“取消本次提问”操作，返回取消结果；停止、调整方向、关闭会话则由现有回合中止路径取消等待。全局快捷键不得截获输入框中的 Enter；卡片键盘交互仅在用户聚焦后生效，遵守组词与修饰键规则。

侧栏显示“等你回答”，区别于“待批准”；切换会话可恢复卡片和未提交草稿。主区与侧边对话同一请求同时显示时共享草稿，后端只接受一次提交。提交进行时禁用重复操作；失败保留草稿并允许重试。请求状态由后端权威快照决定。

## 生命周期、历史与恢复

建议新增专门 question 协议条目，requestId 对应 toolCallId，包含题目、状态和已提交答案。状态为 pending、answered、cancelled、interrupted；取消和中断区分用户取消提问与回合被停止。问答条目不能被过程收纳隐藏；普通工具调用可显示简短过程，避免重复完整题目。

答案必须先可靠记入会话的问答记录，再解除工具等待；工具结果也写入 pi 原有日志。写盘失败不宣称提交成功，保持等待和草稿。重复提交同一答案可返回原成功回执，提交不同答案或错会话答案拒绝；回答与取消竞争只允许一次结算。

参考方案簿的会话目录持久化方式建立独立问答记录，不保存 Promise；恢复历史时与当前分支真实工具记录对齐，防止回退/分叉后旧请求复活。进程重启后不能恢复原执行栈：遗留 pending 标为 interrupted，显示“提问已中断，请继续对话重新确认”，保留原题和可恢复草稿但禁止向旧请求提交。完整跨重启续答作为后续 timed/恢复设计，不伪造已续上原工具。

## ACP 与后续阶段

第一版 API 使用新卡片；ACP 保持适配器原有问答方式。后续分别核验安装的 Claude ACP、Codex ACP 是否暴露问答请求、扩展方法或可注册 MCP 工具入口，再决定桥接。绝不通过解析输出文本冒充适配器结构化事件，也不把新工具加入未经核验的 ACP 能力列表。

第二阶段才考虑非阻塞：区分 open/continued、保留迟到答案、与待发队列准入共同实现一次接收、重启恢复和同请求重复回执；前台超时只释放等待，不产生跳过或授权。

## 紧凑样式修订（用户已确认）

问答卡收回输入区的辅助视觉层级：标题使用正文尺寸，卡片内边距 10–12px，选项说明使用小号次要文字，选项保留整行点击。自由输入默认一行；题号与上一题、跳过、下一题同置底栏，取消使用轻量文字按钮。卡片限制为窗口高度的三分之一及 300px；长内容可滚动。浅色、暗色、窄窗均检查几何与可操作性，不改变等待、提交和草稿语义。

## 输入区接管修订（用户已确认）

参考 DSH conversation.composer seat：待回答卡展开时接管输入区，普通聊天输入卡（包括工具栏）隐藏，避免同时显示两个输入面板。普通输入卡保持挂载，保留文字、附件及控件状态；收起问题即恢复聊天卡，便于调整方向，重新展开再接管。回答、取消或中断后自动恢复。停止入口移到问答卡内，仍允许直接中断当前回合。收起状态继续使用按会话/请求共享的草稿簿，主区和侧边统一实现。
