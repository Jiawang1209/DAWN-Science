# 首启向导与解释器检测：装上就能聊；解释器帮你找路径

> 「开箱即用」第二轮（第一轮是 `2026-08-27-打包-design.md`：装得上）。
> 作者 2026-08-27 定的口径（三次收窄后的最终版）：**核心是配 API、调 pi；R / Python 只是锦上添花——做一个检测，找出本机解释器的路径让人选。** 不打包解释器、不替人装任何东西、不按环境定制装法。

## 0. 定下的

| 问 | 定 |
|---|---|
| 门槛 | **只有模型 key**。用户自己申请，向导第一屏就填，填完立刻可聊 |
| 解释器 | 可选。检测本机 Python / R 的路径 + 版本 + 内核包（ipykernel / IRkernel）在不在，列出来，选中即填进设置；缺包沿用现有 `KERNEL_PACKAGE.how` 那一句 |
| 不做 | 不打包 Python / R；不执行安装命令；不按 Homebrew / conda / PEP 668 分口径；不新开设置分类 |
| 向导何时出现 | 没有任何凭证时，主区整屏；可「先跳过」。凭证有了就不再出现（解释器缺不缺都不弹） |
| 复用 | 设置「内核」屏加一颗「检测本机解释器」，列表与向导同一个组件 |

## 2. 协议：`probeInterpreters`（只读）

```ts
probeInterpreters: {
  request: z.object({}).strict(),
  response: z.object({
    python: z.array(候选), r: z.array(候选),
  }).strict(),
  mutating: false,
}
候选 = z.object({
  path: z.string().min(1),                       // 绝对路径
  source: z.enum(["settings", "PATH", "kernelspec", "common"]),
  version: z.string().optional(),               // 起不来就没有
  kernelPackage: z.enum(["present", "missing", "unknown"]),
  problem: z.string().optional(),               // 起不来时它自己说的末尾几行；超时写「8 秒没应答」
}).strict()
```

- **候选从哪来**（去重、按 `settings` > `kernelspec` > `PATH` > `common` 排）：
  - Python：设置里现有的；kernelspec 的 `argv[0]`（language 为 python 的）；PATH 上的 `python3` / `python`（用 `which -a` / Windows `where`）；常见目录：`/opt/homebrew/bin/python3`、`/usr/local/bin/python3`、`/usr/bin/python3`、`~/.pyenv/versions/*/bin/python`、`~/{miniconda3,anaconda3,miniforge3}/bin/python`、`~/{miniconda3,anaconda3,miniforge3}/envs/*/bin/python`、Windows `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`、`%USERPROFILE%\{miniconda3,anaconda3}\python.exe`。
  - R：设置里现有的；kernelspec（language 为 R）；PATH 上的 `Rscript`；常见目录：`/opt/homebrew/bin/Rscript`、`/usr/local/bin/Rscript`、`/Library/Frameworks/R.framework/Resources/bin/Rscript`、Windows `C:\Program Files\R\R-*\bin\Rscript.exe`。
    （设置里填的是 R 可执行文件；探测用同目录的 `Rscript` 跑，列出来的仍是 `R` 的路径，与设置口径一致。）
- **每个候选起一次**（并发 4、单个 8 s 超时）：
  - Python：`<path> -c "import sys;print(sys.version.split()[0]);import ipykernel"`——第一行是版本，退出码非 0 且 stderr 含 `No module named 'ipykernel'` → `missing`；其它非 0 → `unknown` + `problem`。
  - R：`<Rscript> -e 'cat(paste(R.version$major,R.version$minor,sep="."));quit(status=if(requireNamespace("IRkernel",quietly=TRUE))0 else 3)'`——退出码 3 → `missing`。
- 结果不存；每次点「检测」重探。放 `src/kernel/probe.ts`，枚举与解析是纯函数（可注入 `exists` / `spawn`），可测。

## 3. 界面

### 3.1 向导（主区整屏，`.setup-wizard`，只在没有任何凭证时出现）

```
欢迎使用 DAWN Science                                   [先跳过]
模型 key（必需）
  服务商 [DeepSeek ▾]  API key [____________]  [保存]      ← 走现有 setCredential；保存成功那行变 ✓
解释器（可选，笔记本用；不配也能聊）                    [重新检测]
  Python  ( ) /opt/homebrew/bin/python3   3.14.7   ipykernel ✗
          (•) ~/.pyenv/versions/3.11/bin/python  3.11.9  ipykernel ✓
          [ 手动填… ]
  R       ( ) /opt/homebrew/bin/R   4.3.2   IRkernel ✓
          [ 手动填… ]
  缺 ipykernel / IRkernel 的：<KERNEL_PACKAGE.how 那句>
                                                    [ 开始使用 → ]   ← key 保存了才亮
```

- 选中一个候选 = `setInterpreter`；「手动填…」展开一个路径框（与设置里同一个 `InterpreterField`）。
- 一个候选都没找到：「这台电脑上没找到 Python / R；装了之后点重新检测，或手动填」。
- 探测在跑时那块写「正在检测…」，不拦 key 那一段。
- `先跳过` 记 `localStorage["dawn.global.setupSkipped"]`；跳过后底部红字仍在，**点红字回到向导**。

### 3.2 设置 → 内核

两个路径框上方加一颗「检测本机解释器」，点了在下面展开同一个候选列表（同一个组件 `InterpreterPicker`），选中即填进框。原 kernelspec 参考清单保留。

### 3.3 什么时候出现

界面拿到凭证清单为空 且 `setupSkipped` 未记 → 主区渲染向导而不是空态。**e2e / dev:mock 走 `DAWN_SKIP_CREDENTIAL_GATE`，夹具要预置 `setupSkipped=true`**，否则所有用例的第一屏都变（2026-08-12 那种「十几条同时红」）。

## 4. 失败必须出声

| 情况 | 说什么 |
|---|---|
| 候选起不来 / 超时 | 行内 `?`，旁边一行它自己说的末尾几行 |
| 一个都没找到 | §3.1 那句 + 手动填 |
| 探测本身抛错 | 解释器那段顶上红字「检测失败：…」+ 重试；不拦 key |
| key 保存失败 | 沿用设置里现有的错误显示 |

## 5. 验证

- 单元：候选枚举（假 `exists` / 假 PATH）、Python / R 输出解析（present / missing / unknown / 超时）、去重与排序。
- e2e：夹具在隔离 PATH 里放两个假 `python3` 脚本（一个 `import ipykernel` 成功、一个失败）→ 向导列出两条、状态对；选第二条 → `getInterpreters` 里 python 变了；没凭证时首屏是向导，填了 key「开始使用」亮、进入对话；跳过 → 底部红字在、点它回向导。
- `test:packaged` 加一项：`probeInterpreters` 不炸。
- `dev:mock` 人肉看一次向导形态。

## 6. 不做的

- 不打包解释器；不执行任何安装；不按环境分装法口径；不检测 git / Node（git 缺失已有各处出声）。
- ACP 适配器不要求 Node、Win/Linux 真机验证、签名——各自另一轮。
