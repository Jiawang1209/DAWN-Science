## A 档：小改动，立刻有感

- [x] **A1 用户气泡即时上屏**。直接发送（不在忙、不进待发条）时，渲染进程在转录槽里本地插一条回显，样子和真的一样（没有操作行）。真 `user` 条到了（或快照到了）就在同一次落地里撤掉回显；发送失败也撤掉，原话退回输入框（这一步已有）。不能出现两条一样的气泡。
- [x] **A2 失败钉在轮上 + 截断给下一步**。`failed` notice 画成：红点 + 「这一轮没做成」+ 人话原因 + 原始错误（等宽，可折叠）。pi 的回复因输出上限停下（`stopReason: "length"`）时，推一条 notice：「回复到了输出上限，被截断了——说『继续』可以接着写」。协议 8.8 给 notice 加可选 `rawError`。
- [x] **A3 审批卡键盘化**。焦点在审批卡里时：回车 = 允许一次（allow 类的主按钮），Esc = 这一轮先不做；组字中、长按重复、带修饰键的都不算。卡上用字写出「回车 允许 · Esc 先不做」。**09-30 改：不自动抢焦点**——人正要打字时卡片弹出、焦点被拿走、一个回车就批准了没看清的操作，等于绕过「问一句」这道安全闸（dsh 敢抢是因为它的审批占掉整个输入区，没有歧义）。只有焦点已经在卡上（点了卡，或按明确的键进去）时回车 / Esc 才生效。已做：卡片可经 Tab 或点击卡面显式聚焦；回车优先选 `allow_once`，缺席时选首个 allow 选项；Esc 取消本轮；提示常驻可见；未自动聚焦；组词、重复键与修饰键均不触发。
- [x] **A4 侧栏「等你点头」**。会话行状态优先级：等你点头 > 跑着 > 未读 > 空闲。等你点头时，圆点换成 warning 色，行尾时间那一格换成「待批准」。已做：事件快照与主区/坞重同步共同维护待批准会话集合；侧栏以 warning 圆点和「待批准」覆盖跑着/未读状态，回答后清除。

## B 档：治长回复越写越卡

- [x] **B5 增量传输**（协议 8.9）。新增更新类型 `append`：`{ id, field: "text" | "thinking", delta }`，只在「同一条 agent 发言、只是这个字段往后接」时用；其他情况照旧推整条。中枢按 16ms 合批，任何别的更新、新订阅快照之前先冲掉挂着的增量，保证顺序和 revision 连续。渲染进程主区、侧边对话、子转录按 id 追加；目标缺失则重同步。审查远程助理、终端、微信/飞书/桌面通知、任务完成监听：这些消费者只处理完整 item 或不同更新类型，安全忽略 append，最终 item 仍按原协议到达。真实 Electron e2e：单轮 IPC JSON 载荷 6,980 字节、键入延迟 p95 17.6 ms（预算分别 1,000,000 字节、150 ms）。
- [x] **B6 输入卡文字编辑层搬出重渲染**。把引用高亮层与 textarea 包进独立 memo 边界，只按会话、草稿、历史输入、菜单状态和忙闲等窄状态比较；回复正文变化不使输入层重跑。性能脚本要求每个长回复至多 7 次必要状态重跑，并用临时去掉 memo 的反例确认判据会红。输入卡中的上下文仪表仍按自己的 token 用量实时更新。
- [x] **B7 代码块高亮减负**。流式中的代码块先不高亮，写完再高亮；转录里屏幕外的代码块进视口才高亮（全局共享一个 IntersectionObserver）。复制按钮始终在。已做：Streamdown/Shiki 已打包的 346 个语言 ID/别名共用一个自定义渲染器；未完成回复、未闭合围栏或尚未进入视口时显示原代码与复制/下载控件，进入视口且回复完成后再挂高亮组件。共享 IntersectionObserver 按块一次观察，进入视口后即解绑；无 IO 的环境回退为立即可见。为保留可见后才高亮，Streamdown 使用稳定的 streaming parser 模式，回复完成状态单独传给代码渲染器。

## C 档：界面

- [x] **C8 过程两层收纳**。工具组完成态按文件读写 / 命令给动作摘要；运行态显示「正在运行 · pytest」并至少停 150 ms；失败仍只在组汇总里标红。已完成 agent 轮在过程行前显示「已完成 · 用时 · N 步」，可逐轮收起思考与工具，独立的答复文字、内核图片、`GENERATED` 图片产物、案例卡与方案卡都留在收纳外；若答复文字与思考共用一个 item，只隐藏思考块。设置 → 外观提供「简洁 / 标准」，默认标准，简洁模式默认收起。图像路径核验：内核富输出以独立 `kernelOutput` 行显示；工具产物图片经最终回复下方的 `GENERATED` 缩略图显示；案例卡与方案卡也各自挂在答复/独立条目上。当前普通工具 `result` 本身按 ANSI 文本渲染，没有内嵌 DOM 图片可迁移；现存可渲染图片均通过独立结果路径保留。`design-contract` 扫描限制收纳白名单，界面测试验证答复与图卡可见。
- [ ] **C9 思考按段落推进**。思考中那一行显示最近一段已写完的段落的首行，右端渐隐，文字上有扫光（减弱动效时关掉）；秒数照旧。想完是「想了 Ns · 首行」。
- [ ] **C10 节奏与细节**。条间距分档：同一轮里的过程行之间紧，答复与过程之间中等，换一轮说话大；代码块标题栏 sticky（长代码滚动时复制按钮还在）；~~diff 的 ± 统计平时灰色、悬停才上颜色~~ **09-30 改：± 统计始终带颜色，用更淡的红绿**——颜色本身是信息（加多还是删多），只在悬停时给等于违反「看不见等于不存在」。
- [x] **C11 性能预算进 e2e**。一条 e2e：假模型流一段长回复，期间往输入框打字，量键入到画出来的延迟，以及这一轮 IPC 传了多少字节；阈值写成常量，另配一条零余量的反例单测，证明判据真会拒。固定预算：输入事件到双 `requestAnimationFrame` 的 p95 ≤150 ms；单轮 session event 的 UTF-8 JSON 载荷 ≤1,000,000 字节（不含 Electron framing）。真实 e2e 基线：p95 17.9 ms、37,354 字节、23 个输入样本。
