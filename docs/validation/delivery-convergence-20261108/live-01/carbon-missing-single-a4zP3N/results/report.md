## 3. 处理步骤

1. 以 stdlib `csv` 读入，表头与字段数校验；空行跳过（本例无）。
2. 校验目标列存在；仅在该列识别缺失标记 `{"", NA, N/A, na, nan, NaN, NULL, null}`。
3. 目标列缺失 → 丢弃该值（保留该行的其它列，不做任何填补）；非 NA 但不可解析为有限数 → **立即报错退出**，不猜测。
4. 用 `math.fsum` 求和后除以有效个数（避免朴素累加的舍入漂移）。
5. 写出 `results/result.json` 平铺对象 `{n, unit, mean}`，并向 stdout 打印核查摘要。

未删除任何行、未修改任何单元格；`rain_mm` 全程只读。

## 5. 局限与证据缺口

1. **单位只有单一来源**：mg/g 取自列名 `carbon_mg_g`，目录内没有数据字典、仪器导出或 README 佐证；
   未做任何换算（如 mg/g → g/kg 一律未施加）。若上游单位声明另有出处，需用同一份 CSV 重算而非改动单位字符串。
2. **抽样与实验设计不可知**：`input.csv` 不含设计字段，`rain_mm` 严格单调递增（300→817）更像是按梯度排布的样带/序列，
   而 `carbon_mg_g` 未显示随 `rain_mm` 的单调趋势。是否为随机抽样、分层或配对设计，无法从文件判定；
   若存在与 `rain_mm` 相关的系统偏差，简单全样本均值是有偏估计量。按冻结契约不做加权、不做分层、不按 `rain_mm` 子集。
3. **缺失机制未验证**：7 条 `NA` 恰好每 7 行出现一次（plot-1,8,15,22,29,36,43），呈规则间距，
   与「完全随机缺失」的直觉不符，更像采样/登记环节的固定间隔处置。若为 MNAR，41 例均值不能无条件外推到 48 个样点总体。
   按批准规则仅删除，不做插补。
4. **精度可疑（0.1 刻度）**：全部有效值落在 0.1 步长上，说明上游已做过一次舍入；本报告给出全精度均值，
   但其有效数字不应超过输入精度（1 位小数）所支持的范围。
5. **无不确定性区间**：契约只要求点估计均值，未要求 CI/SD；如需推断结论，应另行批准并说明所用方差估计与缺失假设。
6. **未做的事**：未做敏感性分析（如多种缺失处理的对照），因为契约明确禁止插补；也未按 `rain_mm` 做任何筛选或分组。

以上属于证据缺口与解释边界，不构成本次计算的阻塞：所要求的算术均值在给定数据与缺失规则下定义明确、可复现、已用三种实现交叉核对。
