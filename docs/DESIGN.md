# DAWN 视觉与交互契约

加组件、加浮层、改样式之前先读这份。一句话概括：**一个关注点一个 primitive，令牌优先于字面量，扁平优先于套盒。**

本文件拥有**视觉与交互**契约。架构、状态、传输、测试的规矩在
`superpowers/plans/2026-08-08-phase1b-prime-desktop.md`。

## 这份文档的两类内容，维护方式不同

学自 Hermes `apps/desktop/DESIGN.md`：

- **原则**（扁平、意图、反馈、动效、可取消）是**耐久的**。组件来来去去，它们不变。
- **具名契约**（令牌名、`Button` 的 variant、primitive 名字）是设计系统**当下的 API**，
  **与代码一同维护**：改了 primitive、令牌或 variant，就在**同一次改动里**更新本文件的对应条目。

> **本文件里一个过时的名字就是 bug，和一个过时的类型一样。**

规则与代码打架时，去修错的那一个，**不要在调用点分叉出一个一次性写法**。

## 强制方式：能判定的规则都有测试

`tests/ui/design-contract.test.ts` 扫描源码，违反即失败。当前强制这些：

| 规则 | 违反后果 |
|---|---|
| 组件里出现裸色值（`#rgb` / `rgba()`） | ❌ |
| `styles.css` 里出现裸色值（**`tokens.css` 是唯一允许写死颜色的地方**） | ❌ |
| 令牌名不以 `--dawn-` / `--theme-` / `--mix-` / `--z-` 开头 | ❌ |
| 调用点用 `className` 重新指定 primitive 的内距 / 高度 / 圆角 / 描边 | ❌ |
| 功能组件里出现裸 `<button>`（豁免：`primitives.tsx`、`ErrorBoundary.tsx`） | ❌ |
| 按钮带原生 `title=` | ❌ |
| 出现字面文案「加载中」/「Loading…」 | ❌ |
| 使用 `window.prompt` / `alert` / `confirm` | ❌ |
| `styles.css` 里出现 `z-index` 字面量 | ❌ |
| **`var()` 带回退值**（`var(--dawn-topbar-h, 46px)`） | ❌ |
| `border-radius` 不走 `--dawn-radius-*`（`0` 除外） | ❌ |
| `font-family` 不走 `--dawn-font-*` | ❌ |
| `styles.css` 里出现 `--radius-scalar`（在调用点二次缩放） | ❌ |
| 引用了未定义的几何令牌 | ❌ |
| `.sr-only` 用 `display:none` / `visibility:hidden` 实现 | ❌ |
| 用户发言丢掉文字身份标签（只剩气泡） | ❌ |

**为什么要有强制**，两处独立写下了同一条：

> Rho `AGENTS.md`：*"Prefer automated enforcement over remembered convention. When a
> governance rule can be checked deterministically, add it to repository validation or CI
> **in the same workstream**."*

本项目已经证明过一次：「不要用 `window.prompt`」是我自己写下的规则，然后我自己违反了它，
直到作者打开发现白屏。**靠记性维护的规范会腐烂，而且腐烂时没有声音。**

新增一条可判定的规则时，**在同一次改动里**给它加扫描。

## 原则

1. **扁平，不套盒。** 没有卡中卡，面板内不用边框分区。用留白与**单条**发丝线分组，不要嵌套的圆角盒子。
2. **浮层无框。** 浮起来的面靠 `--dawn-shadow-float` + `--dawn-stroke-float`，不是粗边框。要改层级感就**改令牌**，不要在调用点加一次性 shadow。
3. **一个关注点一个 primitive。** 一个 `Button`、一个 `Loader`、一个 `ErrorState`、一个 `LogView`。迁移到它们上面，不要分叉。
4. **令牌，不要字面量。** 颜色一律 `var(--dawn-*)`。
5. **样式住在 primitive 里。** variant 与 size 拥有内距、圆角、颜色。调用点传 `variant`/`size`，不传重新指定这些的 `className`。
6. **意图先于自动化。** 可以提供动作与预览，但**不要**因为某个工具恰好产出了什么就自动开面板、移动焦点、跳转路由。
7. **反馈立即。** 直接操作先画，持久化随后对账，**失败要可见地回滚**。

## 信息架构

**三类界面，规则不同。混淆它们是经典 bug。**

| 类 | 语义 | DAWN 的成员 |
|---|---|---|
| **页面** 持久目的地 | 留在 shell chrome 里 | **对话**（首页）· Runs · 项目 |
| **路由浮层** 短任务 | 浮层卡片，**关闭后回到上一个路由** | 设置 · 模型/凭证选择 · onboarding |
| **工作面（pane）** 工作上下文 | 附着当前任务，**临时隐藏时状态存活** | 变更 · 终端 · 来源与成本 |

- **对话是首页。** transcript 与输入框是主角；工具、预览、文件、终端是它的补充。
- **不要把一个独立的产品名词藏进不相关的页面里。**
- **本机从全局新建直接输入。** 首条消息才创建任务；未选目录的普通会话使用自身临时空间，选择本机目录后归入项目。远端从服务器下新建，沿用服务器返回的家目录；输入框显示真实远端路径，目录切换沿用自然语言机制。两种入口不继承对方目录、草稿或 `@` 文件来源，不增加工作位置向导。
- **导航必须保住上下文。** 后台会话结束、工具结果到达、项目刷新可以更新徽标与缓存，**不得**替换前台 transcript 或抢焦点。
- **可见性不是生命周期。** 昂贵的有状态面（终端、活工具）隐藏时保持挂载。

体系是**派生**的，不是一张色表：

```
--theme-*（种子 + 混合比例）  →  --dawn-*（语义令牌）  →  组件
```

**核心想法：描边、填充、hover 态由「前景色」兑透明得到，是纯中性的。**

> **2026-08-09 的一次反转。** 上一版是「主色以极低浓度混进底色」，理由是
> 「灰描边配蓝主调会显脏，因为色相不同源」。**那只对低饱和主色成立**——
> 换成纯中性灰阶 + 一个高饱和强调色少量点缀之后，带主色的描边会让整个界面泛出一层绿味。
>
> 改成前景派生还白捡一个好处：**一套百分比同时管亮色与暗色**。亮色下前景近黑，
> 8% 兑在白底上是一根浅灰线；暗色下前景近白，同样的 8% 在深底上是一根微白线。
> 上一版为此把暗色的浓度手工上调过（24/16/10 → 34/24/16），现在不需要了。

底层是一条**手工刻度的 13 档纯中性灰**（`--theme-gray-0…1000`）。它暗端排了八档、
亮端只有五档——暗色界面需要很多层「几乎分不出来」的面做层次，亮色界面靠白底加一根线就够了。

| 令牌 | 用途 |
|---|---|
| `--theme-gray-0…1000` | 灰阶种子。**只有 `--theme-*` 与 `--mix-*` 可以被暗色覆盖** |
| `--dawn-text-1…4` | 文字层级，由强到弱（前景兑透明 100/72/55/40%） |
| `--dawn-stroke-1…4` | 发丝线，由强到弱。**`3` 是面板内的默认分隔线** |
| `--dawn-hairline` | 发丝线**宽度**（0.5px）。只用于有阴影兜底的浮层外缘 |
| `--dawn-fill-1…5` | 柔和填充，由强到弱。`4` 是次级按钮的底 |
| `--dawn-surface-app / -sidebar / -panel / -elevated / -input` | 各种面的底色 |
| `--dawn-row-hover / -row-active` | 行的交互态 |
| `--dawn-control-rest / -hover / -active` | 控件三态（5 / 8 / 12%，规范 §6 的**相对量**）。**按下态是 2026-08-09 才有的**——在那之前点下去没有任何即时反馈 |
| `--dawn-accent` | 品牌色本身：描边、图标、链接、选中态 |
| `--dawn-accent-solid` | **实心底专用。** 品牌绿配白字只有 3.2:1，压暗后才达 AA |
| `--dawn-accent-soft` | 强调色兑透明，用于选中行、徽标 |
| `--dawn-on-accent` | 强调色底上的文字 |
| `--dawn-danger / -success / -warning` | 语义色。**名字说用途，不说颜色**（见下） |
| `--dawn-radius-*` | 圆角，见下面「几何令牌」一节 |
| `--dawn-shadow-float` + `--dawn-stroke-float` | **成对**用于所有浮层。这一对是**唯一**把那圈描边放在真 border 上的，其余三档放在阴影的 `inset` 里 |
| `--dawn-shadow-sm` | 贴地的轻微抬起。行、chip、小控件 |
| `--dawn-shadow-md` | **内容面**：代码块、工具卡、消息气泡。**用了它就不许再有 `border:`** |
| `--dawn-shadow-md-bordered` | 给**自己已经有一条描边**的面用的 md（那 16 张主题色描边的卡片）。亮色下与 `md` 相同；暗色下**去掉 `inset 0 0 0 1px`**，因为那圈由元素自己的 border 画。**配 `border:` 是设计，不是 bug**——名字就是用来说这件事的 |
| `--dawn-shadow-lg` | 更大的内容面：输入卡、坞里的面板 |
| `--dawn-blur-overlay` + `--dawn-surface-overlay` | **浮层的玻璃，成对用**：20px/180% 的模糊 + 84% 的半透明底。**只准用在浮层上**。两件缺一不可——2026-09-10 那版只加了模糊、底还是实的，**模糊压在实心板后面，屏幕上什么也看不见**。容器（侧栏、终端坞）不用：背后是平的底色，透了也没东西可看，而 `backdrop-filter` 会把里面 `position: fixed` 的后代钉到容器身上 |
| `--dawn-fs-display` + `-display-tracking` | 欢迎标题 22px，字距收 -.021em |
| `--dawn-fs-display-conversation` | 会话标题 16px；主区 500 字重、24px 行高、正常字距 |
| `--dawn-fs-title / -sub / -meta` | 18 / 14 / 12 |
| `--dawn-fs-badge` | 11px，徽章与胶囊。**旧角色，2026-09-10 才有名字** |
| `--dawn-fs-label` + `-label-tracking` | 10px 分组小标，大写 + .12em，**不加粗**。**跨度的下端**。加粗会把 10px 中文的字腔填死——小、灰、宽三个信号已经够把它和正文分开 |
| `--dawn-ease` | **全仓唯一一条缓动曲线** `cubic-bezier(.22, 1, .36, 1)`。两条曲线的界面会显得不是一个人做的 |
| `--dawn-dur-fast / -base / -slow` | 120 / 180 / 260ms。fast 给控件三态（仍配 `ease`），后两个才配 `--dawn-ease` |
| `--mix-diff` | diff 里加行／删行那层底色的浓度。**量自 Codex**：亮 15% / 暗 23%。**唯一按主题分两档的混合比例**——它兑的是语义色而不是前景，而语义色本身两个主题就是两种颜色 |

**语义色为什么不叫颜色名**：`--dawn-warning` 在亮色下是橙的（`#e25507`），
暗色下才是黄的（`#ffd240`）——纯黄配白底只有 1.7:1，根本读不出来。
叫 `--dawn-yellow` 就没有地方安放这个事实。

**暗色的「高度」靠一圈亮描边 + 深投影，不能只靠投影。** 黑上加黑是看不见的。

> **2026-09-10 补的两件事。**
>
> ① **方向性顶边高光。** md / lg 在暗色下除了一整圈 `inset 0 0 0 1px`，
> 还多一道 `inset 0 1px 0`。一整圈一样亮读起来是「有边框」，
> **只有上边亮才是「有厚度」**——真实的顶部光源只照亮上边缘。
>
> ② **四档必须单调，不然梯子是反的。** 第一版把 `lg` 写成 `0 14px 32px -8px / 9%`，
> 比 `float` 的远层（`0 12px 28px -8px / 10%`）**还散**：浮层开在输入卡上面时，
> 上面那层的阴影反而更大，它就不像浮在上面。现在两个维度都单调：
>
> ```
> blur   2  →  16  →  24  →  28        sm / md / lg / float
> alpha  6% →  6%  →  8%  →  10%
> ```
>
> 暗色那边「高一档」由两件事一起说：投影更小更淡，**而那圈内描边更亮**
> （7.5% → 9%，float 那圈由 `--dawn-stroke-float` 承担、14%）。
> **亮描边才是暗色里表达高度的主力**，投影只负责落地。

**用了 `--dawn-shadow-md` / `-lg` 的规则不许再有 `border:`。**
那两档的一圈描边在阴影的 `inset` 里，元素上再来一条就是两圈，差 1px 的双线，
深色底上看得很清楚。由 `design-contract.test.ts` 扫描强制（扫的是**声明块**不是行）。

**要 border 和深度同时存在，走 `--dawn-shadow-md-bordered`。** 那 16 张卡片
（技能、服务器、用量、权限、日程表单……）的描边是主题色，2026-08-23 作者要的
*「白色背景 + 绿色的线」*；2026-09-10 作者又要它们浮起来。那一档去掉了 inset 那圈，
**由绿边勾形状、阴影给厚度**，各干各的。

> 那条扫描的正则是 `--dawn-shadow-(md|lg)(?!-)`。**`(?!-)` 不是可以省的**：
> `\b` 会在 `--dawn-shadow-md-bordered` 的 `md` 与 `-` 之间匹配，新令牌会被自己的规则误伤。

**暗色只覆盖种子，不覆盖 `--dawn-*`。** 逐个改派生令牌会立刻退化成两套各自维护的颜色表。
例外只有语义色与阴影——它们无法从种子算出来。这条由
`tests/ui/design-contract.test.ts` 扫描强制。

### 明暗切换：三态，且「跟随系统」在 JS 里解析

`system` / `light` / `dark`，存在 `dawn.global.theme`（**作用域写在 key 里**：主题是应用级的，
不属于某个窗口或项目）。

`tokens.css` 里**没有** `@media (prefers-color-scheme)`：媒体查询版与强制类版没法共用一个
声明块，两份暗色种子一定会漂移。所以「跟随系统」由 `src/ui/state/theme.ts` 解析成
`.dawn-dark` / `.dawn-light`，CSS 只留一个入口。`main.tsx` 在 `createRoot` **之前**应用它，
因此不会先画一帧亮色再跳暗。

### z-index 是梯子，不是数字

```
--z-dock(20)
--z-modal-backdrop(120) → --z-modal(130) → --z-modal-popover(140)
--z-toast(200)
启动链：--z-connecting(1200) → --z-onboarding(1300) → --z-setup(1400) → --z-crash(1500)
```

跨组件的层级竞争一律从这里取一档。组件**内部**的堆叠仍可用 `z-index: 1` 这种。
**崩溃永远在最上面**——界面坏掉时用户必须看得见它坏了。

### 几何令牌（`src/ui/tokens.css`）

> **2026-08-09 之前这一层不存在。** 尺寸散在 `styles.css` 各处，值是凭手感定的。
> 更糟的是有五个几何变量以 `var(--dawn-topbar-h, 46px)` 的形式被引用，
> **而它们从来没有被定义过**——真正在渲染的一直是那个回退值；
> 与此同时 `src/ui/layout-constants.ts` 里躺着同一个 `46px`，没有任何地方 import 它。
> **一个值三个家，两个是死的，而界面看起来完全正常。**
> 那个文件已删除，回退值已清空，唯一的家是 `tokens.css`。

数字取自作者提供的 Codex 桌面版实测规范（`learn_UI/CODEX_DESIGN_SPEC.md` §3/§4/§6）。
**只取几何，不取颜色**——理由见下面「为什么不抄它的配色」。

| 令牌 | 值 | 说明 |
|---|---|---|
| `--dawn-unit` | `0.25rem` | 间距的基本单位。规范里每个间距都是它的整数倍，**那是一把尺子，不是一堆数** |
| `--dawn-space-1…6` | 4 / 8 / 12 / 16 / 24 px | 行内距 · 行水平内距 · 面板内距 · 工具栏内距 · 大留白 |
| `--dawn-topbar-h` / `--dawn-statusbar-h` | `46px` / `24px` | grid 骨架 |
| `--dawn-sidebar-w` | `clamp(240px, 275px, min(520px, 100vw - 320px))` | **永远给内容留 320px**。上一版写死 240，窄窗口下照样占满 |
| `--dawn-row-h` | `30px` | 列表行高。**由它定死，不由内容行高撑出来**——否则一个小字就能让这一行变高 |
| `--dawn-thread-max-w` | `768px` | 对话与输入区的宽度上限。挂在 `.turn` 上而非滚动容器上，否则滚动条会被拽离窗口右缘 |
| `--dawn-page-inset-x` | `clamp(1.25rem, 4vw, 4rem)` | 页边距。比例化但两端夹死 |
| `--dawn-page-max-w` | `75rem` | 面板区宽度上限（网格，不受 768 限制） |
| `--dawn-ui-size` / `--dawn-chat-size` / `--dawn-code-size` | 13 / 14 / 12 px | **外壳与对话是两件事**：规范的 14px 是聊天字号，不是界面字号 |
| `--dawn-font-sans` / `--dawn-font-mono` | — | 字体族。写两遍就会有两套等宽字回退链 |
| `--dawn-weight-medium / -semibold` | 500 / 600 | 字重 |
| `--dawn-radius-xs…lg` | 5 / 7.5 / 10 / 15 px | 由 `--radius-scalar` 统一缩放 |
| `--dawn-radius-composer` | `1.375rem` | 输入框。**不随标量缩放**——它是量出来的成品值 |
| `--dawn-radius-full` | `9999px` | 胶囊。**不参与缩放**：它要的是「半圆」，不是某个半径 |
| `--dawn-corner-shape` | `superellipse(1.5)` | 角的形状，比正圆更饱满。Chrome 139+；不支持的路径直接忽略，安全退化 |

**`--radius-scalar` 从 1 改成 1.25**（规范 §3.6）。基准值没动——
整套界面「软」了一档，只改了一个数。

**侧栏折叠断点 768px 只能是字面量**：媒体查询读不了自定义属性。
它与 `--dawn-thread-max-w: 768px` **数值相同纯属巧合，含义无关**，别合并。

**行的内缩挂在 `.row` 自己身上**（`margin: 0 4px`），不挂在列表的 padding 上——
第一版挂在列表上，于是「新建会话」和底部「项目概览」不在列表里，仍然满宽，
**同一种东西两种对齐**。

#### 为什么不抄它的配色

那份规范 §2.1 的表面色是**从一台跑着 Dracula 主题的机器上量的**：
它自己把 `--color-accent-blue` 注成「Dracula pink」，而那个「蓝」与它的「紫」
是同一个值 `#ff79c6`——**一套主题把两个语义角色压到了同一个数上**，
这不是设计出来的调色板。

更根本的原因写在它的架构分析里：Codex 完整继承 VS Code 的主题变量体系
（`--vscode-editor-*` 30 个、`--vscode-terminal-*` 27 个…），
**它自己没有配色身份**。所以「照抄 Codex 的颜色」在概念上就不成立，
抄到的是量它的那个人当时开着的主题。几何则与主题完全无关，可以直接拿。

它的类名同理不可拿：真实产物里是 `_ComposerFooter_1i340_2` 这样的
CSS Modules 哈希，**每次构建都会变**；规范 §5 里那套好看的 BEM 是原型作者自己起的。

### 对话的三块可见形态（2026-08-09）

> 在这之前，**你说的话和模型说的话长得一模一样**，只有上面一个小灰字；
> 输入区是一个光秃秃的 textarea 加一排散落的控件；空态是一行小字加一个按钮。
> 几何层建好之后补的就是这三块——**几何是地基，这三块才是看得见的那一层**。

**① 发言的身份区分。** 用户是一颗有底色的气泡（靠右，最宽 82%），
agent 是**通栏正文**。不给 agent 也套气泡：它的回复常常很长，
长文套气泡会把行长压到读不下去。

**身份不能只靠底色。** 「谁说的」必须同时留在文字里，
用户那一侧的标签用 `.sr-only` 藏起来——**不是 `display:none`**，
那样读屏也读不到，等于把标签删了、只是删得不明显。两条都有扫描。

**② 输入区是一张卡**（`.composer-box`），不是表单控件加散落的按钮。
规范 §3.5 量到的形态：一个抬起的面，22px 圆角，**模型选择器长在它内部**。
聚焦环挂在**卡**上（`:focus-within`），写法与 `.control` 完全一致
（2px 强调色，offset -1）——画在 textarea 上的话，
卡的边缘与环会成为两条相距 8px 的平行线。
卡里的 textarea 用 `.composer-field`：**刻意不叫 `.composer-input`**，
因为「带 `input` 字样的选择器不许重定义 `.control` 的盒子」那条扫描是按
`\binput\b` 匹配的，`-input` 会被它命中。

**③ 空态有欢迎区**：56×56 的 RP 标志（直接复用顶栏同一份 `packaging/icon.svg`，保持原尺寸和位置）、
标题、四张开场建议卡片（`minmax(10rem, 1fr)` 自适应）。

> **建议卡片点下去必须真的发生事情。** 空态没有输入框，
> 所以「把文字填进 composer」这条常见做法在这里不存在——
> 它必须真的建会话、真的把那句话发出去（`startSession(agentId, firstMessage)`）。
> 一张点了什么都不发生的卡片**在截图里完全正常**，那种坏法最难被发现，
> 所以它有一条 e2e（`e2e/openers.spec.ts`）盯着整条链路。

建议的内容也有一条纪律：**每一条都必须是这个工作台真能做的事**。
照抄通用聊天应用那种「写一首诗」，第一次点下去就会暴露它不是给那个用的。

### 页面迭代：导航与结果工作面（2026-10-11）

- 左侧顺序：全局本机新建 → 项目 → 服务器 → 会话 → 最近；定时、按现有条件显示的已归档、设置和更新留在底部。折叠和宽度仍使用原存储 key。
- 服务器目录以连接记录为来源，任务按 `connectionId` 合并；没有会话的服务器也显示，已移除连接的历史组仍保留。只保留一个连接/会话入口。状态有文字和圆点，失败显示未连接，侧栏不铺技术错误；管理菜单保留连接、断开、编辑，常驻“添加服务器”。
- 新增连接采用“保存并连接”，保存后立即记住 ID；连接失败重试复用记录，取消仍保留已保存连接。连接操作不创建任务、不切走当前输入。编辑仅保存，未改凭证时省略 `secret`。远端新建沿用 `createTask({agentId, connectionId})` 和能力过滤，连接失败不回退为本机任务。
- 助手显示每轮厂家身份，输入框显示精确模型及实际支持的推理强度。白色输入上层保留模型/思考/发送；同卡浅灰底栏左组保留文件/目录/终端/优化输入/生成方案，右组 `.composer-status` 承载会话设置、上下文和权限，结构化问答接管时整卡一并隐藏。窄窗口工具可换行，不增加独立“标准”下拉。
- 草稿中的Markdown采用原文语法着色：复用输入镜像，标题/强调/行内代码与围栏标记可辨，带语言的围栏脚本复用Shiki双主题配色和JavaScript正则引擎。保留标记、缩进、CRLF、空行、@引用灰底；不转换为富文本、不推断未标语言的代码。两处输入与坞内会话共用，90ms合并输入更新。textarea继续拥有文字、光标、选区、撤销与组词；仅当前文本高亮就绪时隐藏原生字形，组词期间隐藏镜像并恢复原生显示。迟到结果丢弃，失败显示提示且原文可编辑，CSP不放宽。
- 右侧坞按头部实际可用宽度自适应展示标签，优先顺序为文件/产物/笔记本/审阅/概览/网页/子 agent/团队/对话；当前面板优先保留，展示顺序固定。测量包含语言、字号、选中粗体和计数角标，预留内距、间隙与关闭按钮；溢出时保留更多按钮，菜单仅列收起的标签，全部放下时隐藏更多。隐藏标签不可聚焦且不进入可访问树。菜单支持方向键、Esc 和触发按钮焦点返回；打开菜单后调宽导致聚焦项进入标签栏时，焦点回收至剩余菜单首项；全部展开时回到当前标签。内部九种 tenant ID、坞宽度范围/持久化、正文布局及自动开栏规则不变。
- 本轮结果默认显示实际数量和查看入口，可展开原文件 chips。`ArtifactsPanel` 预览态采用大预览加紧凑真实列表，紧凑列表独立滚动；完整清单态由 dock-body 滚动，不能被预览态的 `height:100%; overflow:hidden` 裁切。缺失、未知和迟到读取保护、PDF blob 回收、外部打开与远端下载语义保持。
- 文件坞普通浏览/搜索采用“紧凑项目栏”：文件夹图标与项目名称在左，主题色“初始化科研目录”按钮在右，窄面板允许按钮自然换行；下方显示上级目录摘要与常驻“完整路径”入口。完整路径默认收起，点击可展开/收起，展开后换行且可选择复制，不依赖悬停；根路径变化时收起，目录跳转不替换项目位置。本地项目树的空路径根显示真实文件夹名，不能只用`/`让用户猜位置。路径展示复用实际文件目标的映射，本地请求仍用相对路径、远端沿用原路径。初始化反馈留在项目栏，文件树只承载目录项。无真实路径时不编造位置，仍保留已有初始化入口；展开阅读沿用既有隐藏工具栏行为。

### 子 Agent 面板：紧凑过程与固定续问区（2026-10-18）

- 调用中的子 Agent 状态列表固定单列，一行一个子 Agent；短条目也不并排。状态按钮靠左、按内容取宽，长活动摘要省略；失败原因继续直接显示，点击仍打开对应详情。
- 顶部一行放返回、真实角色名称与状态，同批切换另占一行。角色标题来自当前项目名册；名册快照必须与当前 projectId 一致，取数未完成或失败时回退原标识符。侧边会话不套用主项目标题。
- 子转录独立使用左对齐紧凑消息，取消逐条重复头像/名称，保留身份的读屏说明、Markdown、思考、图片和复制。首任务文字与任务说明重复时收进可展开任务区；含图片/思考的首条仍完整显示。
- 每个用户轮里最后一次工具后的非空已完成消息按答复突出；只依据转录边界，不根据自然语言删改内容。进展和任务仍能复制。工具的可读摘要来自实际参数/结果，不透明资源 ID 不占摘要；展开保留原工具名、入参、输出、失败和截断提示。
- 过程和默认折叠的原始交回文本统一滚动，标题及续问区固定。原始交回内容不改写、不用前端答复投影替代。输入区保留发送/禁用/草稿失败行为与“不回到主对话”的现有提示。亮暗与280px窄坞沿用设计令牌和现有按钮。

### 面板区：数值是主角，事实只说一次

> 有数据之后才看得出来，面板区**不只是素，有三处是真的坏的**。
> 空项目的截图上它们全都看不见——这是「照着空态做设计」的代价。

**① 上下文那三档曾经渲染成 `系统提示词7.5 KB59%`**，还会在 `7.5` 和 `KB`
之间断行：三个 span 直接并排，中间没有任何间距或结构。
现在是「标签一行、数值一行」，外加一条**三档占比的堆叠条**——
条的宽度是数据（行内 `style`，因为百分比来自实际字节数，不是设计决定），
颜色仍只从令牌来。三段是同一色相的三档，**不是三种灰**：
第一版用 `--dawn-fill-1/2`，后两段彼此和轨道都分不出来，等于只画了第一段。

**② 归属告知曾经出现两次。** 「产出」与「变更」各渲染一份，
于是同一句四十字的橙色警告在概览上并排出现两次——那是整屏最响的东西，
说的却是同一件事。现在由 `AttributionCaveat` 在概览顶上说一次。

> **但不能简单删掉其中一个。** 两个面板的数据来源不同（一个来自 git 基线，
> 一个来自逐次工具调用），只留一个的话，另一个有而这一个没有时
> **警告会整个消失**——那是静默吞掉告知，规格 7.5 明令禁止。
> 所以判定由 `mayIncludeUserEdits(facts, runs)` **合并两个来源**。

**③ 「历史」里的发起方**曾经是 `人`——一个孤零零的汉字挨着绿色的 `agent`，
看着像乱码，而且强调色文字在这一屏里读起来像可点。现在是「你 / agent / 系统」
三个小标签，**「你」与 transcript 里用户发言的标签是同一个词**：
同一个概念在两处叫两个名字，读的人得先想一下它们是不是一回事。

**层次**：`.amount` 18px、`text-1`、等宽数字（一列数字要对得齐）；
标签退到 11px 的 `text-3`。此前所有东西都是 13px 的灰字，
一屏六个面板读起来像六段说明文，看不出哪个是结论。

### Primitive（`src/ui/primitives.tsx`）

**`Button`** —— 唯一的按钮。传 `variant` + `size`，**不要**传 `padding`/`height`/`radius` 类的 `className`。

- **variant**：`primary`（主动作，一屏通常只有一个）· `secondary`（默认非主动作，柔和填充）· `outline`（透明 + 1px 描边）· `ghost`（无框，hover 出底）· `text`（行内文字，无盒子）· `destructive`
- **size**：`default` · `sm` · `xs` · `inline`（零盒子，用于嵌在句子/标题里——**取代 `padding:0` 的写法**）· `icon` · `card`（一整张可点的卡）· `card-compact`（紧凑开场建议，最小 64px）· `pill`

**`Row`** —— 列表里的一行（会话、agent、入口）。它存在的理由是**消歧义**：行的几何与按钮的几何是两套，同时挂 `.btn-default` 和 `.row` 会让两个内距打架，而"谁赢"取决于样式表里谁写在后面——**位置依赖是最坏的一种耦合**。行用 `size="inline"` 清零按钮盒子，几何全部由 `.row` 拥有。

**`Loader`** —— `label` 是**必填**的。理由不是文案品味：一个只会说「加载中」的界面，说不出「在等什么」，也说不出「等多久算不正常」。`label` 逼调用点回答第一个问题。

**`EmptyState`** —— `title` + 可选 `description` + 可选 `action`。**必须给出下一步**。一片空白不告诉用户该做什么，而「不知道下一步点哪里」正是本项目被打回三次的那个问题。

**`ErrorState`** —— 三件必须有：**发生了什么**、**为什么**（有就给）、**下一步能做什么**。只有第一件的错误提示等于告诉用户「坏了，自己想办法」。

**`LogView`** —— 每一处要展示裸文本的地方都用它。它统一了等宽字体、发丝线边框，以及**超长内容自己横向滚动**——最后一条尤其要紧，否则一条长堆栈会把整个页面撑出横向滚动条。

**`Field`** —— 标签 + 控件 + 说明/错误，并统一处理 `htmlFor` / `aria-describedby`。漏掉就是一个无障碍缺陷，而这类缺陷不会有人在界面上看出来。文本控件组合 `.control` 这个共享形状。

**`.control` —— 每一个 `<textarea>` / `<input>` / `<select>` 都必须挂它，不许抄它的属性。**

> **2026-08-09 由一张截图撞出来的缺陷。** composer 的 textarea 与侧栏的 select
> 都没有这个类；它们的样式来自各自的选择器，而那些选择器是 `.control`
> **七条属性的逐字复制**。抄到了长相，**漏掉了行为**——
> `:focus-visible` 的聚焦环只挂在类上。
>
> 后果：全应用最主要的输入框用的是 **Chromium 默认聚焦环，取操作系统强调色**，
> 与主题无关。在琥珀色系统上它看着像警告态。
>
> 三个控件里两个中招，所以这不是一次疏忽，是缺一条规则。现在有两条扫描守着：
> 控件必须带 `control` 类；样式表里不许有别的选择器重新定义 `.control` 的盒子。

### 一个动作一个家（`src/ui/commands.ts` 的 `Actions`）

Hermes：

> ***"One action, one home."*** *A command may have keyboard, palette, and visible
> affordances, but they **invoke the same action and state**.
> **Do not fork behavior per entry point.**"*

**这句话此前只写在文档里。** 做命令面板之前，`App.tsx` 里 `() => setView("settings")`
写了**四遍**，中止与打开项目还各自带着实现——面板再加一个入口就是第五份。

现在动作只有一处定义：

```
Actions（App 里 useMemo 一次）
   ├── 按钮 / 侧栏 / 空态   ← 拿到的是同一个函数
   └── buildCommands()      ← run 只许转发
```

两条扫描守着（`tests/ui/design-contract.test.ts`）：

1. **`commands.ts` 里不许出现实现**——`client.` / `await` / `.then(` / `setView(` 一律拦下
2. **导航状态只在 `App.tsx` 里改**，叶子组件走 prop 回调

e2e 里还有一条从行为上验的：同一个动作走两遍——一遍从面板，一遍从按钮——
**断言两条路落在同一个 DOM 状态**。

### 命令面板（⌘K）

分组：会话 / 模型 / 项目 / 视图 / 设置。标题与**关键词**一起参与匹配——
人记得的往往不是我们起的那个名字（想换主题的人会搜「主题」，也可能搜「暗色」或 `theme`）。

**不可用的命令留在列表里，并写明原因。** Rho 的规矩：**缺失不等于不支持**。
一条命令搜不到时，人无法区分「没有这个功能」和「它现在用不了」。
而且原因要说清是哪一种——「还没有会话」和「当前没有正在进行的回合」是两件事，
笼统写「不可用」等于没说。这与协议层 `ProvenanceLink` 必须给 `incompleteReason` 同源。

不可用的条目**方向键会跳过**：停在一条按不动的命令上很别扭。

### agent 选择器长在 composer 右下角

对标 Hermes `app/chat/composer/model-pill.tsx`，它自己的注释就是这次搬家的理由：

> *"Composer model selector — **the relocated status-bar pill**."*
> *"Display follows **THIS** surface's SessionView — never the primary-only globals

后半句是**作用域纪律**：显示的是「这个会话」的 agent，不是某个全局当前值。

**「选 agent」只有一个家**——就在你要说话的那个输入框旁边。侧栏的「新建会话」按下

让人以为是就地切换、实际悄悄开了个新会话，属于静默偏离（规格 7.5）。

## 加载与失败：五种状态，各有出路

`empty` / `loading` / `reconnecting` / `degraded-stale` / `exhausted-recovery`
**各自都该有自己诚实的文案和自己的出路。**

- 重试**有界**，且以真实的恢复动作收尾——**不是无限 spinner，不是热循环**。
- 「缺少证据」与「确认相同」是两回事，界面上不得混为一谈（详见事实层的设计纪律）。
- 失败**不许静默**：一次工具调用失败却渲染成空白，是本项目真实发生过的缺陷。

## 动效

- 控件上的功能性过渡约 100ms。超出淡入淡出的一律尊重 `prefers-reduced-motion`。
- **动效跟随状态，永不延迟状态。** 选中、拖拽目标、取消、按下反馈在当前帧就画出来。
- 热交互上不要用 `transition-all` 动布局几何。**如果动效在掩盖延迟，去掉动效，不要调动效。**

---

## 键盘与取消

- **键盘归属跟随焦点。** 获得焦点的面赢得它的按键；shell 的快捷键不得抢走终端或编辑器的绑定。
- **一次取消手势只做一件事**：要么取消当前交互，要么关闭最上面那个可关闭的面——不能两件都做，也不能穿透到下面的控件。
- 取消在界面上是**同步**的，即使清理是异步的：浮层、光标、待定手势状态一次性清掉。
- 刻意不可关闭的流程（安装 / 引导 / 破坏性确认）必须把这一点表达清楚。
