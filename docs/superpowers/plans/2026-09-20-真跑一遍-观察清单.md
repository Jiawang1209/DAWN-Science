## 怎么记

跑的时候你不用停下来写东西。**你只要在想切走的那一刻说一句**
（「这儿我想去 RStudio 看一眼」「这个我得自己开个终端」「这张图我想手改一下」），
我把当时的上下文补全后记在下面。不评判、不当场修、不打断你手上的活。

每条四行，缺哪行就写「没量到」——**不许替你补动机**：

| 字段 | 写什么 |
|---|---|
| **那一刻** | 你正在做什么（哪一步、对着哪个数据、agent 在干嘛） |
| **想切去干嘛** | 你想去 RStudio / Jupyter / 终端 / Finder 做的那个具体动作 |
| **界面当时给了什么** | 屏幕上实际有的东西（有但没找到、有但不好用、真没有，三者要分清） |
| **缺的是什么** | 一句话。**这一行允许留空**——当场说不清比编一个理由好 |

最后一行的三分法是要害：**「有但没找到」是可见性的账，「有但不好用」是形状的账，
「真没有」才是新功能**。08-10 两次「没有这个功能」而代码都是好的，就是没分清这三者。

## 跑之前定的两件

1. **用哪一份**：装好的 **v0.0.8 正式包**（不是 `npm run app`）。
   理由是本项目那条老账——*夹具替默认配置补过东西，真实首启 0 条覆盖，打包版三个 bug 全在那条路上*。
   你日常怎么用，这次就怎么用。跑出来的 bug 如果要改，再回开发构建里复现。
2. **跑什么**：一件**你本来就要交的真活**（一篇文章里的一张图，从 `data/raw` 到能进稿子）。
   **不要为这次演练造数据**——造出来的活不会让你想切走，那正是这份清单的唯一信号源。
