# 终端工作区：Agent / Normal

> 历史方案，已被用户确认的 [真正 CLI 入口](2026-10-23-dawn-cli-design.md) 取代；不再以此描述当前界面。

用户否决上下重复聊天的预览，并批准整页终端布局；随后明确两个模式为 Agent（自由对话、按需调用工具）和 Normal（原生终端）。继续在 `codex/terminal-assistance` 实现；不合并、不推送、不替换已安装软件。

## 工作区与唯一入口

本地内置对话打开终端后，终端工作区占据整个主内容区。顶部只有一条工具栏：终端标签、新建、工作目录（启动目录，完整路径悬停查看）、Agent / Normal、必要的控制状态、返回对话。左侧项目导航和应用顶栏保持原位。

Agent 默认选中。直接复用原有完整 ConversationView：一份历史、一份工具呈现、一套权限/问答卡、一个原有品质的输入框，以及原有模型、权限、文件引用等能力。删除旧的小型终端聊天组件，不再复制消息。普通问题直接回答；读写文件等工作按需使用原有工具；需要在当前终端执行时，观察并使用所选终端工具。终端执行不偷换成另一个 shell；显式选择 Notebook 内核仍遵循原有入口。

Normal 原位展示 xterm，隐藏整份对话和聊天输入框，原生处理 cd、ls、Tab、方向键历史、Ctrl-C 和解释器。切换先停止当前 Agent 回合并撤销终端写控制，再显示可输入终端；失败时保留原模式并就地报错。切回 Agent 不自动发话或执行，不重建进程；对话和草稿不丢失，终端 cwd、变量、前台程序连续。

退出工作区恢复同一段普通 DAWN 对话，不复制历史，不终止终端；关闭某个终端仍结束并删除该进程。缺少本地内置对话的旧入口保留原 Normal 终端能力，不伪装成可用 Agent。

## 复用与边界

App 将唯一主 ConversationView 作为内容交给 TerminalDock，模式切换仅隐藏/显示它，保留组件实例与草稿。Dock 负责工具栏及真实终端的可见性，不实现第二套聊天。Agent 提交仍经 writeToSession 的原话、引用、轮次、权限和标题流程，并绑定选定终端。当前版本终端输入不支持边执行边排队或图片；这两种情况在输入处明确拒绝且保留草稿，避免悄悄退回另一执行入口。模型、权限、普通对话、文件引用及工具展示复用原有组件。

## 验收

实际 Electron：Agent 只有一个聊天输入和一份回复；Normal 没有可见聊天输入；两种模式反复切换不重启进程、不丢草稿；真实 shell 的 cd、环境变量与 PID 连续；真实 Python/R 的已有变量连续。自由对话无需终端工具；终端操作真实执行；权限卡仅一份，等待权限时仍能停止并切 Normal。900×700 与 1280×840、明暗主题检查工具栏、输出、输入和滚动，记录真实截图。旧终端生命周期、项目隔离、显式 Notebook 路由及普通 DAWN 对话回归。
