# Bot Team 连续对话

用户已批准：继续 `codex/bot-team`，Bot 在同一团队对话中追问、补充和交接，坞连续展示，用户能插话；保留专业 Bot 私聊、任务和产物能力，不合并。

## 行为

- 坞的团队对话是一条按持久记录顺序显示的时间线：稳定头像、姓名、专业角色、时间、对象（如有）、完整消息；不再把交流藏进请求卡片。
- 同团队成员可在处理请求时继续向原发起者或第三个成员提问。实际回应自动回到正确的等待轮次；只有原任务最终交付才结算任务。
- 用户可以发给整个团队或指定成员；输入在忙碌时持久排队，在下一安全轮次处理，并可被后续讨论读取。用户发言与 Bot 回复进入同一时间线。
- 团队共享的是明确发表的消息，私人历史和内部推理不自动共享。运行工具细节仍可点击成员查看。
- 同项目 scope、身份、attempt、串行会话、权限、输出锁、停止/取消/重启边界继续有效。请求数量及消息长度有界，达到上限明确报错。

## 发言视觉（用户追加要求）

每位发言者使用独立的圆角对话气泡和固定头像；Bot 左侧、用户右侧。名字与专业角色可读，时间弱化，对象放在气泡内。头像根据持久 Bot ID 固定，助手清单及单独聊天标题共用；主对话沿用 RP。支持亮暗主题和 280px 坞，长路径换行，滚动区与输入区分离。不将群聊拆成多列小窗口，以免窄坞无法阅读。

## 数据和调度

扩展现有 exchange 记录关联父请求和原始任务负责人；嵌套等待保留上下文，释放执行轮，不用阻塞 Promise 等待队友。统一的持久房间消息记录承载请求、最终回应、任务交付与用户发言。既有 exchange 历史可投影到时间线，不需要破坏性迁移。

每次 Bot 轮次获得有界的公开讨论上下文；截断明确提示。用户输入按稳定 request ID 幂等落盘，范围变化后的迟到回执不得更新当前坞。

## 验收

数据分析：统计核查缺失编码；数据反问统计处理意图或请另一成员核对；真正收到回答后清洗；统计拟合后交接绘图；绘图反问图形要求；统计回应后实际绘图。中途用户插入样本量标注要求，最终 SVG 与说明反映该要求，原始数据不变。全程在同一对话可见，最终产物核验仍通过。固定推理只验证机制，不冒充真实模型评测。
