# 分析交付整理

把探索过程中已确认的分析整理为可检查、可运行的脚本、说明及最终结果。以实际文件、代码和执行记录为依据，不靠聊天中的“已完成”判断可复现。

## 什么时候用

用户说“整理这次分析”“生成最终分析脚本和说明”“打包交给合作者”“把这些结果整理成交付”。用户已经指定文件、方法或格式时沿用其选择，不再重复询问。

## 什么时候不要用

只是探索数据、修改一张图、解释统计概念，或用户仍在选择方法；不要自动结束分析并生成交付。单纯改进正在编写的分析代码时，现有 `reproducible-analysis` 更合适。

## 1. 确定范围，保留已有结果

- 核对当前会话的目标、成功代码、输入位置及候选结果；只读必要的脚本和日志。仅在用户允许执行代码时，用已配置的解释器检查表格结构、行数和摘要，不把整份数据读入上下文；“只整理、不运行”时从已有代码、元数据和记录静态核对，不为清点而执行代码。
- 用户已确认的最终结果直接采用。多个同类图表无法判断时，列出实际路径与差异请用户选择；不要仅按文件名含 final、修改时间或 v2 判断。等待时可以继续整理无争议部分，候选文件标为待确认。
- 复用用户指定的目录；否则遵循工作区约定，在 `outputs/delivery/<本次名称>/` 新建交付目录。遇到同名已有目录另取名称，不覆盖。脚本、说明和结果可以放在这个自包含目录中，明确它的运行根目录。
- 不修改原始输入、原图或用户手改文件。只复制选定的小型结果；大文件和远端输入默认记录引用及获取前提，不自动复制整套数据、下载或上传。交付中不含凭证。

## 2. 整理脚本与说明

根据成功的实际步骤生成 `.R` / `.py`；需要两门语言时分别整理，并说明顺序。不要直接拼接全部 cell：去掉失败尝试和重复探索，补齐显式的数据读入、前处理和变量定义。

- 参数、过滤规则、列名、分组、单位、模型设置和随机种子按实际记录整理；缺失就标明，不能事后猜一个值再声称与原分析一致。
- 不依赖当前内核的 `df`、已拟合模型或手动变量。若输入与前处理已经丢失，明确只能交付部分分析；获准保存当前对象快照时，注明它是衍生输入及来源缺口，不能冒充原始数据。
- 路径相对明确的运行根目录，或通过输入/输出参数指定；不把作者机器的绝对路径写成合作者必须拥有的路径。远端路径与访问条件单独说明。
- 给脚本提供独立的输入/输出目录参数；检查写入目标在本次交付或验证目录内。验证前排查写死的输出路径、原地改数据、网络写入和依赖安装；不靠改工作目录就假定输出已隔离。
- 依赖版本以实际环境查询为准；不知道的列为未记录，不编造版本或生成不可信的锁定文件。注释解释方法选择和处理规则，不添加执行记录没有支持的结论。

README 至少说明：目的与采用的结果、运行根目录和命令、输入文件及获取条件、依赖、过滤与参数、输出清单，以及验证状态和未解决事项。按任务需要附环境记录和验证日志，不为形式填空文件。

## 3. 从独立状态验证，保护当前内核

先遵守用户执行范围。“只整理、不运行”时仅静态检查，并明确未经运行验证；生成方案阶段也不执行。

用户要求整理并验证、或已授权运行时：

1. **不重启、不清空用户正在使用的内核。** `run_code` 默认复用当前内核；在该内核里 `exec`、`source` 或逐段重跑不能证明摆脱了旧变量。
2. 优先使用工具明确提供的独立内核。没有这种入口时，可通过 `run_code` 在同一机器上启动短生命周期的独立解释器进程：Python 使用当前内核查询的 `sys.executable`；R 使用当前 R 安装下的 `Rscript --vanilla`。使用参数数组及正确路径传参，不猜解释器，不悄悄改用另一套环境，也不把启动独立进程描述成新内核。通过共享内核启动子进程的包装代码使用局部作用域（R `local({...})`、Python 局部函数），避免覆盖或遗留用户全局变量。
3. 子进程只执行刚整理的脚本，工作目录明确，输出指向新建的验证目录；保存退出码、必要日志和实际环境版本。设合理超时；超时后确认并停止本次启动的进程，不终止用户的内核或其他任务。没有可靠的超时与子进程清理能力时不启动重跑。工具限制、解释器未配置或独立执行不可用时说明限制，不绕过限制。
4. 小型完整任务从输入开始顺序执行。昂贵任务先说明成本，遵循已有运行授权；只有抽样或缩小规模时，把验证范围与正式分析区分开。
5. 检查退出码之外的结果：文件实际存在且可读，表格结构、样本量与关键统计量符合已有结果；数值比较明确采用的容差。图表检查数据和渲染，不能仅凭文件大小或不同 PDF 的字节哈希判定一致。没有预期值就报告检查范围，不宣称一致。
6. 重跑失败时先定位，必要时修正脚本再验证；最多三次修复尝试。仍失败就保留可用交付、日志和明确的阻塞原因，不把失败结果替换进最终结果。

缺少原始数据、前处理或依赖时仍可整理已知部分；README 和最终答复都标注缺口。成功从对象快照运行只证明快照之后的流程，不能称为从原始输入完整复现。

## 4. 交回文件与真实状态

提供脚本、README 和最终结果的可访问路径；区分原分析结果、验证新生成的结果和未确认候选。远端结果注明位置，不声称已下载到本机。

报告实际状态：**独立完整重跑通过 / 部分或缩小范围验证 / 运行验证失败 / 未运行验证**，并写明关键比较结果或原因。运行通过也不等于科学结论已获独立核验。保留原文件；不要在交付后自动清理探索结果、提交 Git、发布或上传。
