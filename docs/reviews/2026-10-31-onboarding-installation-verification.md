# 安装世代与四步引导验收

## 用户规则与实现

手动新装、保留用户数据的重装、同版本覆盖安装：首次打开从四步第 1 步开始。引导尚未完成时重启也回到第 1 步。完成或主动跳过之后，普通重启及应用内升级保留完成状态。系统钥匙串授权独立，不作为是否显示引导的判据。

主进程在窗口创建前建立独立安装世代；Mac 读取 .app、执行文件和清单的文件身份，不写签名包；Windows NSIS 手动安装生成新 GUID，`--updated` 沿用原 GUID。预加载同步提供非敏感世代，完成/跳过键按安装隔离；成功换包后、重启前接续同一世代。失败换包不会产生可被后续手动安装误用的待升级标记。

不删除旧完成键，不修改凭证、数据库、模型、解释器和会话；数据库里的远端内核 `install.id` 保持原用途。首次引入安装世代时不会继承未绑定安装的旧完成标记；本世代内的后续受控升级保留状态。开发预览没有安装世代，继续使用原状态。

## 自动化与实际包

- 新回归在原代码上失败：旧完成标记绕过新安装欢迎页；Windows 更新没有传递更新标记。修复后对应回归通过。
- 类型检查和完整构建通过；563 个测试文件全部通过，5849 项通过、10 项既有跳过。命令：`npm test -- --maxWorkers=4`，172.04 秒。
- 首启、旧标记入口、四步向导、密钥、URL、双语、更新：25 项 Electron 回归全部通过，1.1 分钟，无失败或重试。
- 实际 Mac arm64 包通过窗口/SQLite、自带技能及子 Agent、假模型真实子进程链路、PTY、解释器探测、内核目录 6 项冒烟；模型请求发到本机假服务。
- 实际 Mac 包签名校验 `codesign --verify --deep --strict` 通过；被测包与当前构建主进程 SHA256 一致。
- Windows x64 NSIS 安装器编译成功。首轮卸载器编译捕获到未使用安装变量警告，已把安装宏限定在安装器编译域，保留警告视为错误规则。

Mac 生命周期脚本 `scripts/test-packaged-onboarding.mjs` 使用临时 .app 副本和独立用户数据，真实启动 App、操作向导、保留假凭证和未发送消息的会话、实际调用生产换包逻辑。不会改动 `/Applications`、现有预览或真实钥匙串；`--use-mock-keychain` 只在测试进程启用。

7 项生命周期检查全部通过：旧完成键不绕过新安装介绍；引导中途重启回第 1 步；跳过后重启保持状态；同路径同版本替换安装重新介绍；四步完整操作并沿用已有密钥；生产换包后保持已完成状态；原目录直接覆盖也重新介绍。每次替换后同时检查凭证存在、原会话存在、配置内容相同及用户存储标记仍在。更新演练使用同一个构建，隔离证明换包造成文件身份变化时接续原世代，不宣称完成一次线上跨版本发布升级。

## 失败记录与范围

首次全量存在另一项目的并行测试进程，出现远端 PTY 清理等待、Chrome 退出 hook 超时以及 R 签名启动失败；保留该轮日志。后续无并行项目测试，限制 4 个 worker 完整复跑，上述文件及全部其他文件通过。并行运行多个项目的内核压测不在本轮通过声明内，未为此放宽超时或跳过断言。

最初生命周期夹具引用了目录已不存在的 `deepseek-chat`，生产端如实拒绝创建会话；已按实际目录改为 `deepseek-flash` 后完成演练。保留失败截图及启动日志供追溯。

Windows 仅完成安装器构建和逻辑测试，没有 Windows 真机运行证明；Linux AppImage 未做实际安装包验证。文件实例识别针对实际替换/复制安装，不能把原文件实例的原地恢复或备份还原普遍识别为新的安装事件。跨入首次支持安装世代版本前，没有可靠安装来源标记的旧完成状态不迁移。
