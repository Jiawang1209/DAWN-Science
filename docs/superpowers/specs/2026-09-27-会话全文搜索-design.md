## 1. 要解决什么

作者要找「上个月哪次跑过 Cox 回归」。现在侧栏那颗放大镜**只搜名字与路径**——`views.tsx` 里写明了：

```ts
   * **它搜的是名字与路径，不是对话内容**。后者要后端出一个全文检索，
   * 现在没有——而一个看起来什么都能搜、其实只搜标题的框，
   * 比一个说清楚自己搜什么的更坏（不变式 5）。占位符把范围写出来。
```

标题取自第一句话，而一段科研会话前三句往往是「读一下这个数据」，Cox 是第二十轮才出现的。要搜的是**内容**：你说过的话、agent 的回复、工具调用（尤其是在内核里跑过的代码与它的输出）。

搜到还不够，**要能点过去**：点一条结果，打开那段对话、滚到那一处、把词标出来。而转录只渲染最近 40 块（`transcript-budget.ts` 的 `默认转录预算`），第二十轮往往就在预算之外——跳过去必须先把它放出来。

## 3. 搜什么、不搜什么

| 会话 | 搜不搜 | 为什么 |
|---|---|---|
| native（内置对话），本地 | 搜 | pi 替它记了完整消息：`<sessionDir>/pi/sessions/*.jsonl` |
| native，**远端**（服务器上干活的） | 搜 | 运行时在本机跑，只有工具经 `RemoteExecutor` 伸到服务器；记录目录同样在本机（`src/session/manager.ts` 的 `create()` 里 `sessionDir = join(workspace, ".dawn", "sessions", id)`；`createRemoteSession` 与不带工作目录的远端 `createTask` 挂在临时项目下，`workspace` 是本机的临时根）。**以库里的 `session_dir` 为准**，不另算 |
| 坞里的侧边对话、定时任务开的会话 | 搜 | 它们也是 native 会话，有自己的记录 |
| 归档了的 | 搜（§0 第 2 条） | 藏不是删 |
| 删掉的 | 不搜 | 库里没有这条记录了（目录也进了废纸篓） |
| 外部 CLI / ACP / 终端 / 内核会话 | 不搜，**数出来说一句** | 记录不在我们手里：claude / codex 有它们自己的，终端是字节流，内核会话不落盘 |
| 子 agent 的对话（`<sessionDir>/subagents/*`） | 不搜 | 它们不在主转录里，点过去没处可跳；子 agent 的结论在主对话里那次工具调用的输出里，那一处是搜得到的 |
| 被压缩掉的更早内容 | 不搜 | 与点开之后看到的保持一致：续接时 pi 按 `buildSessionContext()` 还原（压缩摘要取代了原文），转录里也看不到它们。**搜得到的就跳得到** |
| 系统注入的（换模型那句、`display: false` 的 custom message） | 不搜 | 与续接同一条取舍：它们不是人说的话（`role: "custom"`，`history()` 本来就跳过） |
| 模型还没回过一句的那段 | 搜不到 | pi 要等第一条 assistant 消息才把记录落盘（`_persist` 里的 `hasAssistant`）；这时库里有会话、目录里没文件 |
| 思考（thinking） | 不搜 | 续接时也不还原——点过去看不到 |

笔记本里你自己敲的那格：它在你下一句话之前作为前缀拼进了那条用户消息（spec `2026-08-26-笔记本-design.md` §4），所以**搜得到**，片段落在「你：」那一处。

## 4. 分层（依赖决策，规格 §4）

- **① 坐在哪**：pi-coding-agent 的三个导出符号——`parseSessionEntries(content)`（逐行 JSON，坏行跳过）、
  `SessionManager.inMemory(cwd, undefined, entries)`、`.buildSessionContext()`。
  读出来的消息交给**与续接同一个函数**还原成条目（`还原历史`，从 `NativeRuntime.history` 里原样抽出来），
  再交给**与续接同一个函数**变成转录条目（`还原成条目`，从 `backend.ts` 里抽出来）。
- **② 放弃了什么**：
  - `SessionManager.open` / `continueRecent`：它们在迁移旧版本记录、或遇到空文件时会**重写那个文件**（`_loadEntries` → `_rewriteFile`），
    而那个文件此刻可能正被一段活着的会话追加。`inMemory` 的 `persist` 是 false，`_rewriteFile` 第一句就返回——**搜索绝不写盘**。
  - `SessionManager.list` 的 `allMessagesText`：它只拼用户与 agent 的文字，**不含工具调用与输出**，也没有逐条的位置——搜不到代码，也跳不过去。
  - SQLite FTS5：见 §5。
  - 不起运行时（不 `resume`）：搜 500 段不能把 500 个 agent 拉起来，远端的还要连服务器。
- **③ 不变式挂在哪**：
  - **「只读」**挂在 `src/runtime/pi-record.ts`：那个文件里不许出现 `SessionManager.open(` / `continueRecent(` / `SessionManager.create(` / 任何 `write*` 调用——设计契约扫描。
  - **「后端说的第几处 = 界面数的第几处」**挂在 `src/protocol/search-match.ts`：命中规则、条目的可搜文本、定位函数只此一份，后端找、界面跳都调它（界面只许经 `src/protocol` 取东西，`tests/protocol/ui-boundary.test.ts`）。
  - **「搜得到的就跳得到」**挂在「同一个 `还原历史` + 同一个 `还原成条目`」：条目 id 由它们给（文字 `r{下标}`，工具用调用 id），与续接恢复出来的转录是同一套 id。

## 5. 中文与匹配规则

- **子串就是命中，不分词。** 词按空白切开（最多 8 个），每个词在同一条里都出现才算（§0 第 3 条），大小写不敏感。
- **为什么不用 SQLite FTS5**——写 spec 时在本机 `better-sqlite3`（自带 SQLite 3.53.4）上量的：

  ```
  文本「帮我做Cox回归分析」            MATCH "回归"   MATCH "Cox回归"   MATCH 整句
  tokenize='unicode61'（缺省）         0              0                 1
  tokenize='trigram'                   0              1                 1
  ```

  unicode61 把一串连着的汉字当**一个词**，「回归」搜不到「做Cox回归分析」；trigram 要**至少三个字**，而最常搜的正是两个字的中文词（回归、生存、差异、热图）。
  要中文分词就得带 ICU 或结巴的原生扩展，为一个子串匹配就能做对的事多一个原生依赖不值。
  而且**不建表**：索引是同一份对话的第二份拷贝，多一张表就多一处会与事实脱节的地方（`views.tsx` 侧栏分组那段注释的同一条理由）——
  删会话、搬目录（`rehome`）、续接追加，每一处都得记得去改索引。
- 最短两个字：一个字（「的」「R」）几乎段段命中，列出来没有信息；框里写「至少两个字」。
- 片段：空白压成一个空格，从最早出现任一词的地方往前留 40 字，共 ≤ 120 字；`toLowerCase` 改了长度的极少数字符（如土耳其语的 İ）出现时不画高亮（免得标歪），命中照算。

## 6. 性能预算

**写 spec 时量的**（作者这台机器上 `~/DAWN` 下全部 pi 记录，`node` 直接跑 `parseSessionEntries` + `inMemory` + `buildSessionContext`）：

```
130 个记录文件，共 21 MB（中位 10 KB，最大 4.9 MB）
冷读（读盘 + 解析 + 还原）：172 ms
抽出的文字：3,455 条，3.8 M 字符
热搜（小写后 includes「回归」）：0.35 ms / 次
```

按 500 段线性外推：冷读 ≈ 0.7 s、文字 ≈ 15 M 字符。所以**不建索引，扫**，外加一层按文件认的缓存：

- **缓存**：后端进程里按会话 id 存「那个文件的 `path` + `mtimeMs` + `size`」与还原好的条目（连同每条的小写全文）。每次搜先 `stat` 一遍（500 次 stat ≈ 几毫秒），
  变了的才重读。缓存上限 **40 M 字符**（约 80 MB）；超了按最久没用的先扔，扔掉的下次重读——慢一点，结果不变。
- **预算**（500 段、上面那种体量）：
  - 第一次搜（冷）：≤ 1.5 s；
  - 之后每次（热，只有刚聊过的那一两段要重读）：≤ 100 ms；
  - 单次上限 **5 s**：到点就停，交回已经搜过的，`truncated: "time"`，界面说「看了 M 段中的 K 段」。
- **不卡主界面**：逐个文件 `await readFile`，一个文件内同步解析；单次最长的同步段 = 最大那个文件的解析（实测 4.9 MB 的那个 ≈ 30–40 ms）。
  **单个文件超过 32 MB 跳过**并计数（`tooLarge`，界面说出来）——实测最大 4.9 MB，32 MB 是「一段对话里贴了几百张图」那种。
- **结果上限**：30 段（请求可给 `limit`，≤ 100），每段最多带 3 处；超了如实说还有几段。
- 界面：打字停 250 ms 才发；飞行中的旧请求回来时**丢掉**（组件里自己的序号，不用全局 `guard()`——那个一领就把转录的请求也作废了）。

## 7. 跳到那一处：为什么对得上

1. 旧对话（这次运行里还没打开过）：点开时 `subscribeSession` → `resume` → `events.restore(sessionId, 历史.map(还原成条目))`。
   搜索那一侧用的是同一个 `还原历史` + 同一个 `还原成条目`，所以结果里的 `itemId` 就是转录里那一条的 id。
2. 这次运行里已经活着的对话：转录是从实时事件长出来的，id 与恢复出来的不同。结果另带 `nth`——**这段对话里第几处命中**（按转录顺序、从 0 数），
   界面在自己手上的转录里用同一个 `命中` 规则数到第 `nth` 处。先按 id 找，找不到再按 `nth`。
3. 都找不到 → §2.3 那句话。
4. 预算：`确保可见(id)`（刻度尺已经在用的那一个，`块们.findIndex(...)` 认得工具组）把预算放大到含住它；两帧之后再滚（与刻度尺 `跳` 同一个做法）。
5. 工具行：工具行的外壳加 `data-item-id`（文字行已经有 `data-turn-id`）；命中的工具行自己展开、所在的工具组展开。
6. 高亮：块级 `data-search-hit="true"` 2.4 秒（淡出，不位移，不受「带位移的动画必须能关」那条管）；词级用 CSS Custom Highlight API（`CSS.highlights`，Electron 43 的 Chromium 支持），
   **不改 React 管的 DOM**；jsdom 里没有它，函数先问一句有没有。
7. 坞里的那段对话（侧边对话）不接跳转——跳转只给主区。点的若是坞里正挂着的那段，照样在主区打开它。

## 8. 协议

- 新操作 `searchSessionContent`（只读，`mutating: false`）：
  - 请求 `{ query: string（去空白后 ≥ 2 字，≤ 200 字）, limit?: 1–100 }`；
  - 响应 `{ sessions: 卡[], matchedSessions, total, scanned, notSearchable, unreadable, tooLarge, truncated?: "sessions" | "time", elapsedMs }`；
    卡 = `{ sessionId, projectId?, title?, place?: { kind: "project" | "server", name }, archived, lastAt, hits: 处[], moreHits }`
    （`place` 给结构不给句子：「项目 x / 服务器 x」是界面文案，归 i18n；`lastAt` 是命中里最新的时刻，记录里没有时刻时退回文件修改时间）；
    处 = `{ itemId, nth, where: "user" | "agent" | "toolInput" | "toolResult", toolName?, snippet, marks: [起, 止)[], at? }`。
- **升一个 minor**（只加操作）：执行时读 `WORKBENCH_PROTOCOL_VERSION` 当时的值 `X.Y`，改成 `X.(Y+1)`（写 spec 时是 8.0 → 8.1；别的计划若已先占了 8.1，就顺延）。
- **mock（准入规则 1）**：这个操作跑在真后端上，`dev:mock` 与 e2e 用的是同一个后端；要补的是**能被搜到的确定内容**——假模型加「跑个 Cox」分支：
  最后一句用户话带「跑个 Cox」→ 先说「我跑一个 Cox 回归。」再调 bash `echo "coxph(Surv(time, status) ~ age, data = lung)"`。
  这样「搜工具参数 / 输出、点过去展开那一行」在 `dev:mock` 里人点得到，e2e 也不靠真模型。

## 9. 测试

- 单元：
  - `还原历史`：抽出来之后与原先 `history()` 逐条相同；带 `at`。
  - `search-match`：拆词、命中（与的关系、大小写、中文子串、跨段不算）、片段（截断与 `…`、marks 位置）、定位（先 id 后 nth）。
  - `pi-record`：只读（读完文件字节不变，含「旧版本需要迁移」的记录）、挑最新文件、没文件是 undefined。
  - 后端 `searchSessionContent`：本地 / 远端 / 归档 / 非 native 计数 / 坏文件计数 / 30 段截断 / 缓存（第二次不重读，改了文件才重读）/ 超时截断。
  - 界面：结果卡（片段、`<mark>`、已归档、还有 N 处、截断那几句）、两颗切换常驻。
- 设计契约：`pi-record.ts` 里没有会写盘的 pi 入口。
- e2e（`e2e/session-search.spec.ts`）：
  1. 说一句带暗号的话 → 按内容搜到它与 agent 的回复，片段里有 `<mark>`；
  2. 「跑个 Cox」→ 搜 `coxph` → 点「命令里」那一处 → 那一行工具展开、在视野里、带高亮；
  3. 预算之外：说 21 句，第一句带暗号 → 搜 → 点 → 第一句出现在 DOM 且在视野里；
  4. 关掉再打开（`dawn.重开()`）→ 仍搜得到、点得过去；
  5. 两颗切换 `opacity === "1"`；按名字时的行为不变（原有侧栏搜索用例照过）。
- 视觉基线：搜索框不在任何一张基线里；红了先看 diff。

## 10. 不做

- 按时间筛（「只看上个月」）：结果按时间排、每张卡带日期，先看够不够。
- 正则、引号精确短语、排除词。
- 搜外部 CLI（claude / codex 自己的记录）与 ACP 会话的内容。
- 离线只读地看一段续不上的对话（服务器连不上时点结果只会打开一段空对话并说明原因）——那是另一件事。
- 语义搜索（「找我做过生存分析的那次」而词不一样）。
- 让 agent 自己能搜历史对话（一个工具）——先给人用，看真机效果再说。
