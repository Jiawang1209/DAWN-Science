# carbon 均值（带单位）— 阻塞报告

- 模板：`tabular-ecology@1` · 语言：python（仅标准库）
- 批准方法：arithmetic mean（算术均值）
- 缺失值规则：drop NA in target column only
- 单位规则：未提供 → 必须阻塞，不猜测
- **最终状态：BLOCKED — 未交付带单位均值**

---

## 1. 结论先行

请求的是 **带单位的 carbon 均值**。单位是本次交付的必要条件，而工作区中**没有任何来源给出 carbon 的单位**。
按冻结规则，单位不得从数值量级、邻列（`rain_mm`）或生态学惯例中推断，因此：

- 均值**不作为交付结果给出**（`result.json` 中 `unit = null`、`mean_carbon = null`）；
- 唯一给出的数字是**无单位原始尺度诊断值**，仅用于证明方法可执行、`n` 正确，**不得当作 carbon 均值对外报告或复用**；
- 原始数据 `input.csv` 未被修改、未被覆盖、未被重写。

## 2. 输入

| 项目 | 内容 |
|---|---|
| 文件 | `input.csv`（48 数据行 + 1 表头行，805 字节） |
| 列 | `site`、`carbon`、`rain_mm` |
| 行标识 | `site` = `plot-1` … `plot-48`，唯一、无重复 |
| 目标列 | `carbon`，缺失以字面量 `NA` 表示 |
| 非目标列 | `rain_mm`（无缺失，本次不参与计算） |

结构核查结果：表头无空列名；`carbon` 全部取值要么是可解析的有限数值，要么是 `NA`；没有出现空串、`NaN`、`Inf` 或无法解析的文本（若出现，脚本会以退出码 1 硬失败，而不是静默丢弃）。

## 3. 单位证据缺口（阻塞依据）

为确认单位是否**真的**缺失，已核查下列来源，全部为空：

| 来源 | 结果 |
|---|---|
| 表头列名 | `carbon` 没有单位后缀（对比同一文件里的 `rain_mm`，后者在列名里写明了 mm） |
| 文件内单位行 / 元数据块 / 注释 | 不存在，`input.csv` 只有表头 + 数据行 |
| 工作区其它文件 | 仅 `input.csv`、`.pi/settings.json`、`single/settings.json`、一份会话 transcript；后者是运行配置与对话记录，不是数据字典，未声明单位 |
| 随附 README / 数据字典 / 代码本 | 不存在 |
| 用户请求 | 明确说明「原始文件和用户均没有提供单位」 |

因此单位属于**证据缺口**，而不是「默认值缺失可忽略」：`carbon` 可能是 g C/m²、kg C/m²、Mg C/ha、%C、tC/ha 等任意含义完全不同的量纲，同一数值在不同单位下的科学解释相差数量级。任何选择一个都是编造，故不做选择。

## 4. 处理步骤（可复现）

1. 以 `utf-8-sig` + `csv.DictReader` 读入，保留全部原值。
2. 结构检查：目标列存在、表头无空名。
3. **仅在目标列**把缺失记号（`NA` 及常见等价写法）判为缺失并剔除；本列共剔除 7 行：`plot-1, plot-8, plot-15, plot-22, plot-29, plot-36, plot-43`。
4. 非目标列**不因缺失而删行**（本次 `rain_mm` 与 `site` 无缺失，故该规则未触发；脚本仍会单独统计并在 `result.json` 的 `other_columns_missing_counts` 中报告）。
5. 对剩余 41 个值求算术均值（`statistics.fmean`）。
6. 单位闸门：`UNIT is None` → 状态置 `blocked`，`unit` 与 `mean_carbon` 写 `null`，无单位诊断值单独放进 `diagnostics` 并加注「NOT the requested metric」。

复现命令（隔离解释器，单进程，无子进程、无网络、无第三方依赖）：

```bash
python3 -I results/analysis.py
# 或显式指定输入/输出目录
python3 -I results/analysis.py --input input.csv --outdir results
```

脚本退出码 0 表示**计算本身**跑通；闸门结论写在产物里（`status: "blocked"`），不以崩溃冒充阻塞。

| 目标列剔除缺失 | 7 | 按批准规则 |

| 方法 | arithmetic mean | ✅ 按批准方法 |

**无单位诊断值（非交付结果，禁止当作 carbon 均值引用）**：n = 41，合计 568.7，均值 13.870732，范围 [12.0, 15.6]，全部为**输入自身尺度上的无单位数字**。

独立复核：用 `awk` 对同一文件独立重算，得到 `n=41, sum=568.700000, mean=13.870732`，与脚本输出一致（差异为浮点格式化，无需舍入判断）。

## 6. 方法适用条件核查

- 算术语义：`carbon` 为连续量、单变量、无分组要求 → 算术均值在定义上可用。
- 样本独立性：每行一个 `site`（`plot-1…plot-48`），未见重复站点，未做分层/加权；若这些 plot 来自不同处理组或存在嵌套结构，未加权整体均值只是描述性汇总，不代表总体参数。
- 缺失机制：`NA` 分布于 7 个不同 plot，未见成块缺失；但脚本**不假设** MCAR，删除只影响描述性统计，不构成对缺失机制的推断。
- 离群值：未做剔除，符合「保留原始数据、不静默改动」原则；范围 12.0–15.6 未见极端值。
- 结论：**方法可执行且已执行**；未能交付的原因单一且明确 —— 单位缺失。

## 7. 局限

1. 无单位 → 结果不可解释、不可与文献或其它数据集比较，因此不予交付。
2. 未加权算术均值仅描述这 41 个有效 plot，不推断区域或总体均值，未给不确定度（请求未要求，且单位未定前无意义）。
3. `rain_mm` 未参与分析；脚本不对 `carbon`–`rain_mm` 关系作任何推断。
4. 无单位也意味着无法判断 `carbon` 是浓度、储量还是通量，因此本报告不给出任何碳库/碳储量的科学解读。

## 8. 解除阻塞所需（最小、明确）

任选其一即可重跑并交付：

1. 直接给出 `carbon` 的单位（例如 `g C m-2`、`Mg C ha-1`、`%` 等原文写法）；
2. 提供数据字典 / README / 原始数据来源说明，其中声明 `carbon` 的单位；
3. 若 `carbon` 实为某一已知派生量（如某深度的土壤有机碳浓度），给出该定义与单位。

收到单位后，只需把 `results/analysis.py` 顶部的 `UNIT` 设为该字符串重跑，`result.json` 会自动切换为 `status: "ok"` 并输出带单位的 `mean_carbon`，其余步骤与 `n = 41` 不变。
