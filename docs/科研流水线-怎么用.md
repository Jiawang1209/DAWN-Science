# 科研流水线：核查、分析、审阅与恢复

本能力在既有 Team 上提供固定的核查 → 分析 → 独立只读审阅 → 有限修正/交付流程。适合方法、输入、输出已确认的小任务；不会替你选择科学方法，也不把模型自评当作科学认证。普通子任务和原 Team/Bot 协作入口继续可用。

## 在主会话中启动

先建立或确认分析路线，明确目标步骤、数据背景、方法和产物文件。告诉主会话使用科研流水线，并从现有子 agent 或已启用 Bot 中选择核查者、分析者和审阅者；分析与审阅必须是不同执行者，核查可以复用审阅者。主会话须处于允许执行的阶段。

例如：

> 按刚才确认的路线核查 in.csv，使用已经确定的方法分析，交付 results/metrics.csv。核查和审阅只读，分析者与审阅者分开，最多修正一次。出现缺资料或未知失败时停止，不自动重跑。

主会话调用 `start_science_pipeline`，参数包括当前路线的 `routeId/revision/stepId`，明确的 `inputs/outputs`，三阶段 `executors`（每项使用 `agent` 或 `botId` 二选一）、任务说明 `instructions`、`requireExecution` 和 `maxRevisions`。分析默认要求实际执行，纯文档写入可显式设 `requireExecution: false`；修正次数为 0–2，默认 1。只支持本地严格契约。

三阶段任务契约、权限档、允许工具、文件范围和模型选择在创建时冻结。阶段推进、产物占用、任务 attempt 与结算继续由原 Team/编排器负责，没有第二套调度循环。通用 Team 改任务、加减成员、转派、统一成员消息及工作台 Bot 追问/派单都不能修改流水线团队；终态也不接收永远不会执行的额外消息。需要额外工作时提交 blockers，由主会话另行处理，结束旧团队后再建立新任务。

## 阶段结果与验收

所有阶段都必须调用 `submit_task_result`。坏参数或引用无效的工具证据会返回可修正错误，当前轮可以修正后再提交；已接受的结果（包括合法 blocked）封存后，本轮不能再写文件、执行或委派。

- 核查：`data-summary`，包括行数、列信息和 issues。必须真实 read 声明输入并引用本轮 callId；发现问题则受阻，不执行分析。
- 分析：`model-metrics`，包括已确认的方法、有限数值指标、样本数和 caveats。要求执行时须引用实际执行证据，产物须符合原契约验收。
- 审阅：`review`，包括 pass/revise/blocked、具体意见及 reviewedPaths。只读，须逐个真实 read 声明产物并引用 callId。revise 才会在次数上限内创建下一次分析/审阅；blocked、未知失败和次数耗尽均停止。

只读科学核查/审阅也在原共享产物锁中预约声明输入，直到宿主验收结束，避免已接入的任务写者在其间覆盖。限定写者仍按声明输出预约，允许任意 shell 的任务仍保守独占工作目录。人工编辑、主会话未接锁的写入、其他进程和跨机器执行不在此进程内协调保证中。

## 看状态和轻量观测

团队面板显示阶段、修正次数、受阻/中断原因、路线冲突及可见的阶段耗时、提交次数、格式退回和 token。

`science_pipeline_status` 返回完整阶段回执和聚合观测：任务数、修正轮数、经过时间、提交/格式错误次数、验收失败数、可见 token、缺失 token 的任务数及 partial 字段。耗时由宿主测量，token 仅来自本轮新增的实际服务端回执；缺失保持未知，不补零，不估算费用，也不上传遥测。中止杀进程前未拿到最终回执的尝试可以没有 observation。

`accepted` 表示满足当前软件契约；`review.pass` 是该审阅执行者的判断。它们不证明方法正确、独立验证充分或结论可发表。

## 停止、重开与显式恢复

`cancel_science_pipeline` 需要当前 `stateRevision`，关闭新阶段并请求停止当前尝试，保留文件和检查点。返回取消已受理不代表后端已排空；迟到结果不能覆盖取消状态，产物锁等待实际退出才释放。

主会话停止或宿主重开时，活动流程成为 `interrupted`，不会自动重放。先查看 `science_pipeline_status` 和已有文件，再调用 `resume_science_pipeline`，带精确 `stateRevision`。从未开始的 pending 阶段可继续；失败/中断且副作用不明的尝试须明确 `acknowledgeInterrupted: true`。旧尝试未排空时拒绝恢复。

恢复保留已验收阶段及冻结范围，只为中断阶段创建新尝试；中断核查恢复成功后，下游引用最新已验收核查。恢复过程若写入/通知/调度失败，会关闭准入并保留 interrupted 检查点；没有活动后端的 claimed 尝试标明中断，实际后端仍在排空时继续等待。前置条件不符合的恢复请求只报错，不中止正常运行。最多保存 16 个阶段尝试，耗尽后受阻，需核对产物另建流程。`blocked` 不自动恢复，补齐条件后可结束旧团队并建立新流程。

同一启动请求重试不会重复执行，不同内容不能覆盖已有身份。若写完流程后会话指针保存失败，重试会重新关联并保留 interrupted 检查点，仍需显式恢复。团队指针采用原子保存，失败不会伪装启动成功。

## 分析路线写回

最终审阅通过后，宿主按冻结 `routeId/revision` 把交付、执行与审阅事实写回原步骤，并保留案例及其他路线字段。来源标记用于重开去重；如果路线已被修改，保留新路线，流程显示 conflict，需主会话核对，不静默覆盖。

当前流程仅支持有限结果类型与固定阶段。没有通用 JavaScript 工作流、任意 JSON Schema、OS 沙箱、跨进程锁、实时 Steer 或远端严格验收。真实模型成功率、费用收益和科学正确性需要另行评测。

## 内容绑定与批量模板（2026-11-05）

新流程的核查、分析、审阅回执会关联实际输入/产物内容版本。恢复检查原输入及仍有效的已验收产物，`acknowledgeInterrupted` 不允许跳过版本冲突；分析修正可替换本项旧输出，但不改变原输入版本。全部通过后，路线先显示“正在核验内容与写回路线”；核验期间停止会取消并排空投影，新的用户轮次才重新允许处理。内容或路线版本冲突时保留原回执、提示核对，不强行标记 delivered。

`start_science_batch` 在同一 Team 内逐项串行处理 1–8 项，每项最多 4 个输入文件，沿用固定核查、分析、独立审阅和最多两次修正。使用相同的 executors、routeId/revision/stepId、instructions、requireExecution/maxRevisions 参数；用 template/items/outputRoot 代替手工 inputs/outputs。

模板当前固定为版本 1：

- `tabular-ecology`：须给 method、units、missingValues、language（python 或 r）；输出 analysis.py/R、result.json、report.md。
- `figure-reproduction`：须给 method、language、evidencePath、citation、page、targetFigure、transformations；evidencePath 必须声明为每项输入，数据文件也要声明；输出脚本、figure.svg、report.md。先复用已有文献提取产物，不把只读 PDF 等同于理解文献。

例如，在已经确认路线方法后让主 agent 调用：

```json
{
  "routeId": "当前路线 ID", "revision": 1, "stepId": "analysis",
  "executors": {"check":{"agent":"checker"},"analyze":{"agent":"analyst"},"review":{"agent":"reviewer"}},
  "instructions": "按用户已确认的均值统计方案分析，保留原始数据。",
  "template": {"id":"tabular-ecology","version":1,"language":"python","method":"算术均值；不做外推","units":"x 列为 m","missingValues":"出现缺失即阻塞，等待用户确认"},
  "items": [{"id":"site-a","label":"样地 A","inputs":["site-a.csv"]},{"id":"site-b","label":"样地 B","inputs":["site-b.csv"]}],
  "outputRoot":"results", "requireExecution":true, "maxRevisions":1
}
```

宿主在 outputRoot/稳定请求ID/项ID 下隔离输出，并检查真实路径及硬链接别名，拒绝覆盖输入、data/raw 和重叠输出。所有未来项的契约、工具与权限在启动时冻结。暂不宣称批量并行加速。

使用 `science_batch_status`、`resume_science_batch`、`cancel_science_batch` 控制整个批量；恢复/取消的 stateRevision 取返回的 batch.stateRevision。单项 pipeline 控制入口不能绕过批量状态。失败即停；重开不自动执行，已完成项保留，未知文件副作用必须核对并确认。`team_finish` 会取消未完成批量并归档，归档后不能恢复。

所有项通过后，原调度器执行一项固定宿主汇总任务，按同样的 attempt、产物占用、版本复核和正式提交生成 summary.json/summary.md。汇总仅复制已验收指标、路径、版本和来源，不调用新模型、不计算新的科学结论。部分完成不写回路线 delivered。团队状态显示项数、绑定状态及汇总路径；文件仍从现有产物入口查看。协议版本为 8.42；本专项仍是本地未发布改动。


### 合并前复审补充

批量项 ID 的完整32字符范围可用于所有阶段，内部任务名按批量索引隔离，长名称不影响恢复或汇总。输出目录不能仅靠大小写或 Unicode 归一差别区分不同项；宿主会保守拒绝这类别名。恢复等待内容核验时若路线改版，将保持 interrupted 并要求按新路线重新核对，不能沿旧路线自动继续。
