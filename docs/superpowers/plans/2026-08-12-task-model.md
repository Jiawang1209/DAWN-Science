# 任务模型：把项目 / 会话 / 临时会话收成一个「任务」

作者 2026-08-12：

> *「改成 workbuddy 的新建任务……我们可以在任务的对话框里面，设置工作路径。
> 然后，如果在任务里面不设置任何工作目录的话，那么其实就是我们的普通对话。」*

## 1. 它解决的是什么

现在有**三样东西表达同一件事**：

| 现在 | 工作路径从哪来 | 侧栏在哪 |
|---|---|---|
| 项目 | 用户选的文件夹 | 「项目」那一列 |
| 项目下的会话 | 继承项目的 | 项目行下面嵌套 |
| 临时会话 | 服务端分配的 scratch 目录 | 「会话」那一列 |
| 远端会话 | 远端家目录 | 「远端连接」下面 |

**四条路径，四种归属，三处列表。** 而它们的区别只有一个：**工作路径是谁给的。**

作者的模型把它收成一条：

> **任务 = 一段对话 + 一个可选的工作路径。**
> 没有路径 → 普通对话（服务端仍会给一个 scratch 目录，但**那是实现细节，不进界面**）。
> 有路径 → agent 在那儿干活。路径可以是**本地的**，也可以是**某台远端服务器上的**。

## 2. 为什么这是简化而不是换皮

- 侧栏从**三列**变成**一列**（任务），远端连接仍是独立的一区（它是「怎么到那台机器」，不是「活儿在哪」——这条 R4′ 已经定过）。
- 「项目」不再是一个要新建、要删除、要选中的对象；它退化成任务的一个字段。
- **账本不受影响**：Run 仍按容器归集，只是那个容器从「项目」改名叫「任务」。

## 3. 代价，必须先说

1. **库里已有的数据**。`projects` 与 `sessions` 是两张表、两个 id。
   迁移要把每个「项目」变成……什么？它下面可能挂着多段会话。
   **一个项目 = 多个任务共享同一个路径**——所以迁移是
   「把每段会话变成一个任务，把它所在项目的 workspace 抄给它」。
   **老的项目记录不删**（账本还挂在上面），但界面上不再出现。
2. **协议要动**（4.8）：`createTask` / `setTaskWorkspace`；
   `ProjectSummary` 让位给 `TaskSummary`。**旧操作保留一个版本**，
   不要让界面与后端在同一次升级里同时换。
3. **「删除项目」这个动作没有了**——现在删的是任务。
   而「删任务会不会删掉磁盘上的文件」必须比现在说得更清楚：
   路径是用户自己选的目录时，**绝对不能删**。
4. **e2e 的选择器大面积要改**（几十处 `新建会话` / `新建项目`）。

## 4. 顺序（每批都能自己验证）

1. **T1 · 库与协议**：`tasks` 表（id / 标题 / workspace 可空 / connectionId 可空 /
   置顶 / 次序 / 建立时间）+ 迁移；协议加 `listTasks` / `createTask` /
   `setTaskWorkspace`，**旧的 project/session 操作原样留着**。
2. **T2 · 侧栏换成任务列**（一列 + 分区标题），旧的两列下线。
   远端连接那一区不动。
3. **T3 · 任务里设工作路径**：对话框顶部一个入口——
   没设时写「未设工作目录 · 这是一段普通对话」，**说清楚不设意味着什么**；
   设了显示路径，可改。远端任务显示 `机器:路径`（R4′ 已有的那条复用）。
4. **T4 · 迁移已有数据**，旧操作从协议里摘掉。

## 5. 判据

- 新建一个任务、不设路径 → 能聊，**界面上一处都不提「项目」「临时会话」**。
- 给它设一个本地目录 → agent 的读写落在那儿，账本记得对。
- 设成远端路径 → 与 R4′ 那条线合流。
- **升级一个装着老数据的库**：老会话仍然打得开、账本一条不少。
