# Markdown 文件引用与项目文件交付

用户已授权实现两项检查结论，独立分支开发、验证并启动隔离预览，不合并或推送。

## 行为

- 在文件、产物、交付预览中，Markdown 的相对图片与文件链接按文档目录解析，允许在工作区内使用 `../`，支持中文、空格和 URL 编码。图片通过现有受守卫的 `readFile` 读取并以 data URL 显示；脚本链接进入现有只读文件预览，不执行。
- 保留 Markdown 渲染器的消毒、外链与代码块行为。只对具有文件读取上下文的文档启用文件引用；聊天正文不猜测文档目录。拒绝协议伪装、网络共享路径、工作区越界；后端仍是路径与符号链接的权威检查。加载失败就显示错误，切文档或会话后旧请求不能回填。
- 留存副本没有完整引用文件快照，维持原读取语义，不将当前工作区图片冒充历史副本。
- 整理交付选择页增加“从项目添加文件”：按需浏览一层目录，文件名搜索复用有预算的 `searchFiles`，勾选脚本、图表、说明等已有文件后添加。不同会话创建的文件同样可选，仍需显式选择，不自动遍历或纳入全项目。
- 复用现有 `listDirectory` / `searchFiles` / `readFile` 协议和本地会话工作区身份，不新增协议操作。无法用于交付的隐藏路径不供选择；列表截断、失败必须可见。现有最多 60 项交付选择限制在界面提前说明。
- 保持现有保留、交付生成与运行验证行为。本轮不修改模型脚本保存策略，也不重做交付生成。

## 方案取舍

采用文档上下文中的受控文件引用与按需项目浏览。直接开放 `file://` 会绕开受控读取；递归收集全项目会增加等待并误选数据文件；均不采用。

## 验证

先添加能复现相对图片、脚本链接和已有项目文件选择的失败测试，再实现；覆盖中文空格、父目录、越界、读取失败与迟到请求。运行相关测试、类型检查、完整构建、实际 Electron 主流程与原界面回归。在隔离预览中准备分步脚本、图片和 Markdown 示例，保留已有预览资料。
