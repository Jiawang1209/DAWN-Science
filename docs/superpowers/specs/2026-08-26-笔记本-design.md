# 笔记本：坞里一格，看 agent 的内核、在同一台内核里自己敲

> `data-platform` 主线第二轮（第一轮「产物」见 `2026-08-26-产物-design.md`）。作者第一天给的第二张参考图（Claude Science 的 Notebook 面板）里还没做的那一块。
> 作者定的口径：**旁观 + 能在同一台内核里自己敲**；一条时间线混排 Python / R；你敲的会记进对话让 agent 知道。

## 0. 作者定下的

| 问 | 定 |
|---|---|
| 这一格干什么 | **B**：旁观 agent 跑过的每个 cell（代码 + 富输出），并能在同一台内核里自己敲；不是完整可编辑 notebook（不改旧 cell、不重跑、不导出） |
| 两台内核怎么摆 | **B**：一条时间线按执行先后混排，每个 cell 带语言徽标；底部一个输入框 + 语言切换 |
| 你敲的 agent 知不知道 | **B**：记进对话，下一轮随上下文送给模型（没有不可见的行动）；「只看不告诉」开关这轮不做 |
| 数据从哪来 | **从对话转录派生**，不另存、不订阅内核会话 |

## 1. 今天的实际状态（动手前核的）

- 一段 native 对话按语言懒起内核（`src/kernel/挂载.ts` 的 `对话内核`，会话 id 形如 `<对话>::python`），`run_code` 直接 `runtime.write`，**不经中枢的 userTurn**——代码只在 `tool` 项的 `input.code` 里。
- `wiring.ts` 的 `转发` 已把内核的 `kernel_output` 路由进**对话**的转录（`kernelOutput` 项，带 `language`），对话区 `KernelOutputRow` 已能画文本 / 图 / 表 / 报错。给模型的只是 `摘要()` 出来的文字。
- 那台内核会话没被中枢 `track`，`subscribeSession(<对话>::python)` 订不到；也不在 SessionManager 里，`abortSession` 够不着它。
- 独立内核会话（`kind: kernel`）已有结构化 Console、变量面板（`listVariables`）、中断。
- 概览格里已有 `VariablesPanel`。

## 2. 数据：cell 从对话转录派生

一个 cell = 一条「代码」项 + 紧随其后的 `kernelOutput` 项（直到下一条 turn / tool / cell 项）。

| 谁跑的 | 转录项 | 说明 |
|---|---|---|
| agent | 已有 `tool` 项，`name === "run_code"`，`input.language` / `input.code`，`status` | 不动 |
| 你 | **新增转录项 `cell`**：`{ type: "cell", id, language, code, status: "running" \| "ok" \| "error", startedAt, runId? }` | 只有你敲的用它 |

`kernelOutput` 项一字不改。cell 序号 `[n]` 按派生顺序编，纯界面。

## 3. 协议（minor）

- `runInKernel { sessionId, language, code }`：先推 `cell`(running) 进转录，走 `对话内核.执行()`（与 agent 同一台内核，没起就懒起并推 notice「正在起 Python 内核」），结束后按 id 更新 status；账本一条 Run（`origin: user`，`requestType: execute_python | execute_r`，环境快照照挂）。`mutating: true`。
- `interruptKernel { sessionId, language }`：那台内核的 interrupt。被中断的 cell 状态 error，输出末尾「（已中断）」。
- 会话快照加 `kernels: [{ language, state: "starting" | "idle" | "busy" | "exited" }]`（缺省 = 没有内核）；变化经现有 `state`/`item` 之外新增更新 `kernels`（整份换掉，与 `team` 同一纪律）。
- pty / cli / acp 会话：`kernels` 缺省，界面据此说「这种会话没有内核」。

## 4. 告诉 agent

后端每会话一段「不在场时内核里发生的事」缓冲：你每跑完一个 cell 追加一条

```
[用户在 Python 内核里跑了]
```python
deg[deg.padj < 0.01].shape
```
输出：(312, 6)
```

输出摘要用 `run_code` 给模型的同一个 `摘要()`（同一截断口径）。**你下一次发消息时**，把缓冲作为前缀拼进送给模型的文本，然后清空；转录里的用户 turn 仍只显示你自己那句话（cell 已经在笔记本里）。不主动触发模型回合。

## 5. 界面：坞「笔记本」格

坞新房客 `notebook`，标签「笔记本 (N)」，N = cell 数。从上到下：

- **头**：每台内核一颗状态胶囊（未起 / 正在起 / 空闲 / 运行中 / 已退出）；运行中的旁边才有「■ 中断」；右侧「变量 →」切到概览格的变量面板（不重画）。
- **cell 流**：`[n]` · 语言徽标（Python 蓝 / R 绿）· 谁（agent / **你**）· 时刻（· 运行中）；代码块（等宽，超长横向滚）；输出原样复用 `KernelOutputRow` 的渲染（文本 / PNG / 表 / 红底报错），截断沿用「已截断：原 N KB」。
- **提示条**：应用重开过、内核是新的 → 顶上「内核已重起，上面 cell 里的变量已经不在了；再跑一次即可」（判据：转录里有 cell 但快照 `kernels` 缺省或 `exited`）。
- **输入框**：多行；语言选择缺省跟最近一个 cell 的语言（没有 cell 时 Python）；⌘↩ / Ctrl↩ 运行，Shift↩ 换行；运行时禁用并显示「运行中…」；下面一行常驻小字「会记进对话，agent 下一轮知道」。
- 自动滚到底只在本来就在底部时（沿用对话区的 stick-to-bottom）。
- 面板状态（输入草稿、语言）按会话 `key` 重挂，不持久化。

## 6. 失败必须出声（规格 7.5）

| 情况 | 说什么 |
|---|---|
| 解释器没配 | 输入框上方沿用现有那句「还没配 R 的解释器路径，去设置 → 内核」 |
| 内核起失败 / 中途退出 | 胶囊「已退出」+ 原因；cell error；不静默重起（②定案 4） |
| 应用重开、内核是新的 | §5 的提示条 |
| 中断 | 胶囊「正在中断…」→ 空闲；cell 输出末尾「（已中断）」 |
| `runInKernel` 请求失败 | 输入框上方红字 + 重试，草稿不丢 |
| 输出截断 | 「已截断：原 N KB」（现有） |
| 没有内核的会话类型 | 整格一句「这种会话没有内核，笔记本不可用」，不画空清单 |

## 8. 怎么验

- 单测：`cells(items)` 派生（run_code + 后续 kernelOutput 归同一 cell；你的 `cell` 项；混排顺序；没有 run_code 的对话 → 空）；缓冲（攒 → 下一条消息带前缀 → 清空；两次 cell 合并）；`kernels` 快照状态机；协议 schema。
- 后端：`runInKernel` 与 agent 共用一台（先经 `run_code` 定义变量，再经 `runInKernel` 读到）；`interruptKernel`；账本一条 `origin: user` 的 Run。
- e2e（真内核，有 kernelspec 才跑）：agent `run_code` → 笔记本 cell 带输出 → 你敲一句读 agent 的变量 → 新 cell → 下一条消息请求体含前缀（mock 服务器的 `requests` 里断言）；pty 会话 → 「没有内核」。
- 视觉基线：坞多一个标签，先看 diff 再重存。

## 9. 不做（YAGNI）

编辑 / 重跑旧 cell、导出 `.ipynb`、cell 折叠、按语言分页、「只看不告诉」开关、cell 持久化（转录本来就持久）、把笔记本接到独立 `kind: kernel` 会话（它已有 Console）。
