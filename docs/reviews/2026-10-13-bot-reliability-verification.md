# Bot 可靠性与协作界面验收

日期：2026-10-13。分支：`codex/bot-team`。应用版本：0.0.27，协议：8.15。main 仍为 `5c7a1f74489800fbd3636f8c260db8fd1a8beec4`。用户要求先修五项问题、再完善三处界面并测试，不合并；本轮没有提交、合并或推送。

## 五项缺陷

1. **隐藏往返入口**：Bot 不再暴露 `team_send`；只读 `team_status` 保留。公开进展用 `bot_say`，需要回答/交接用受活动轮认证和根预算保护的 `bot_message`。旧 Native 成员邮件入口拒绝非状态调用；旧子 agent 的独立 Team 邮箱不受影响。
2. **取消边界**：Native 调用 `scheduler.stopTask`；仅失效对应任务根及其后代协作。取消排队 B 时，执行中 A 的 signal 未被 abort，A 完成，用户公共消息仍在队列；取消暂停的原任务会中断后代，迟到回复不续接。成员停止和团队停止保持独立。
3. **并发状态**：每轮产生固定 UUID，开始与结束共用；Native 将该 UUID 映射为同一 chip index 后结算、清理。两位 Bot 并发启动并按 A/B 顺序结束，开始 `[0,1]` 与结束 `[0,1]` 一致。实际协作交付后不存在 running chip。
4. **导航丢草稿**：owner、完整 scope、team 三段组成 UI key，组件外保留草稿、收件人、busy、幂等回执、滚动位置。助手页、成员详情和坞文件页切换后恢复；不同范围隔离；失败重试沿用原请求 ID。收件人离队不会静默广播，需重新选人。发送成功后恢复贴底。
5. **历史耗尽容量**：最多 32 项未结束任务、64 项仍有效且未续接的协作；已结束历史不删除。32 项全部完成后可加第 33 项；64 次历史协作后新任务仍可请求。32 活动任务、64 活动协作以及每根 8 次总请求上限继续拒绝超限。

## 三处体验

- 顶部成员区显示固定头像、名字、真实状态：待命、处理中、等待队友、等待执行、需处理、待回答、待批准、已结束。点击选择发言对象；不推测内部思考。280px 窄坞三成员均完整可见。
- 用户气泡使用持久化 conversationTurns 显示逐收件人等待处理/处理中/已回应/处理失败/已取消/已中断；失败保留原因。没有处理元数据的旧消息不虚构送达状态。
- Bot 气泡复用 AgentMarkdown。成果按钮匹配 engine-authored result 的 task、attempt 与 Bot 身份，并只取后端校验过的 task.artifacts；任意路径文字不会自动成为产物。点击复用现有本地/远端预览。嵌套 Markdown 列表不继承外层时间线滚动样式。
