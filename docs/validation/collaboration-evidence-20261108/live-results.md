# 真实模型同题同预算复验结果（2026-11-09）

**结论：目前没有证据证明自动多 Agent 在这批简单任务上更省或更稳。** 编排、冻结、正式验收和分阶段统计确实运行了；模型提交过程仍有明显摩擦。不能将本轮小样本外推到复杂科研或其他模型。

## 执行范围与证据

推理模型是本地目录支持的 `deepseek/deepseek-flash`，HTTP请求使用既有只读凭证和受控转发门；只发送自制CSV与任务要求。运行过程中候选v2保持冻结，原报告comparisonEligible=true。当前修复后的代码是v3，仅修正评测的输入路径识别，不将本轮结果冒充v3重新联网验证。

## 发现、修复与后续工作

**已修复的评测bug：** runner原先只认`path==='input.csv'`。实际某次成功read用了绝对路径，导致正确阻塞漏计。修复复用宿主同样的resolve(workspace,path)身份比较，仍仅接收当前试验的成功read，拒绝其他工作区、失败/写入工具。两个测试先失败后通过；重新完整回归见v3日志。原始v2报告保留，v3只离线复判该路径，不追加API。

以下为后续升级线索，未在这次冻结试验中改动生产行为：

1. 减少模型手抄冻结契约与长证据ID：一次规划漏带acceptance被拒；一次正式提交因重复/缺失引用退回3次，最后又因`carbon_mg_g_mean`代替`mean`触发科学阻塞。可继续沿既有契约和证据目录做宿主绑定与精确字段引导。
2. 把“待补信息”和“审阅未正式提交”展示得更明确：当前澄清问题在评测执行runner记failed；另有一次审阅仅输出文本。这些都不应靠更多额度或降低验收门解决。
3. 为复杂任务再验证多 Agent 的价值：本轮三个小任务不代表真正可并行的大型数据工作。没有授权前不增加题目或调用。

原日志另有一次Electron Network Service自动重启警告；真实试验最终正常结束，保留原始日志，不据此认定历史退出/PTY问题已解决。历史7350/20690ms退出、长Bot/MCP收尾及PTY清理继续OPEN；1500/4000ms不变。

候选保留专项分支未提交、未合并、未推送、未发布；正式App配置/凭证/DB与main内容核对不变。
