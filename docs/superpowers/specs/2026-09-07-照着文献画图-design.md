# 照着文献画图 · 设计

> 2026-09-07。分支 `paper-figure`。
> 作者的话：*「看到别人的图 → 在我的数据上画一张同类的」*，以及
> *「既然加了识图的 LLM，能否在 mlai-science 里做相似图片的检索」*。

## 为什么这一轮几乎不写代码

拆开之后，这条链有四段，**已经通了三段**：

| 段 | 现状 |
|---|---|
| 把图交给 agent | **已有**：粘贴/拖拽附件（`specs/2026-08-25-外部文件附件-design.md`） |
| 认出这是什么图 | **已有，两条路**：多模态模型直接看（`native.ts` 那句「收图的模型不给 `look_at_image`——它自己能看」）；看不了的走视觉端点转述（`specs/2026-08-20-视觉服务-design.md`） |
| 问「这种图怎么画」 | **只差接线**：`MLAI-science` 是只读 MCP，DAWN 有 MCP 那一屏 |
| 在我的数据上画出来 | **已有**：`run_code` 走真内核 |

所以这一轮真正要产出的是**一条接线 + 一份走法**，而不是一个新子系统。
**这不是把活做小，是这件事本来就这么大。**

## 量出来的六件事实（2026-09-07，对着真的 MLAI-science 跑的）

1. **`recommend_figures` 自己做图型对齐。** 给它一句自然语言，它回
   `figure_types: [{id, label, matched}]`——**还告诉你哪个词匹上了哪个图型**。
   → 原本设想的「先 `list_taxonomy` 拿词表让模型挑」是多余的一跳，降级成兜底。
2. **每条命中带 `how_to`**，粒度到 API：
   *「`ax.bar(..., yerr=err, capsize=4, zorder=3)` + `ax.bar_label(fmt='%.3f', padding=2)`；
   y 上限 `local_max+0.3*local_max` 留标注空间」*。
3. **匹配不上时它自己会说**：`figure_types: []` 且
   `notes: ["goal_text 未匹配到任何图型别名，按全部图型做混合检索"]`。
   → 失败是自报的，技能能可靠地接住，不必靠猜。
4. **1538 个案例，1077 个是 draft（70%）。** 这些案例的 `how_to` 以
   `<!-- mlai:notes=draft -->` 开头，是 ingest 自动生成的摘要，**不是精修过的配方**。
5. **「相似」是文字上的相似，不是像素上的。** `rebuild` 用 `BAAI/bge-small-zh-v1.5`（文本嵌入），
   向量建在 caption / step / how_to 上；库里**没有任何图像向量**。
   实测：拿「视觉模型会写出来的那种描述」去 `figures --mode semantic`，
   **第一条命中就是被描述的那张图**（均值柱 + SEM 误差棒 + 原始散点 + Tukey/Dunn 显著性括号）。
6. **`recommend_figures` 没有 `language` 参数**（只有 `search_cases` 有）。要专挑 R 的案例得换一条路。

## 定案

### F1 · 链的形状

```
粘一张图  →  模型写一段**结构化描述**  →  ①怎么画：recommend_figures
                                      →  ②像不像：search_figures --mode semantic
          →  读 how_to  →  run_code 在你的数据上画  →  产物
```

**两个检索入口都用是常态**：前者给配方（`how_to`），后者给参照（caption 相近的图）。

### F2 · 描述要结构化，不许自由发挥（事实 5 的直接推论）

向量建在**精修过的 caption** 上，而那些 caption 的写法是固定的口吻
（「三组各 G1–G4 均值柱+SEM 误差棒+原始散点，组顶标注 ANOVA/Kruskal P」）。
模型的描述越像那个口吻，命中率越高。所以技能要求四行：

```
图型：   分组柱状图
几何：   均值柱 + 误差棒（看着像 SEM）+ 叠加原始数据散点
标注：   组间显著性括号带星号；柱顶写数值
版式：   单面板，三组×四水平，图例在右
```

**这是零成本的提升**：同一次识图，只是让它按格式写。

### F3 · 匹配不上要说出来（事实 3）

`figure_types` 为空时，那批结果是**全库混检**的，可信度低。
技能必须把 `notes` 那句转述给人，**不许把混检结果当推荐念出来**，
并给兜底动作：`list_taxonomy(dimension="figure_type")` 拿受控词表让人挑一个再搜。

**为什么这条重要**：混检也会回五条结果，看起来和成功一模一样——
这正是本项目反复栽过的那种「失败长得像成功」。

### F4 · draft 的 `how_to` 不是配方（事实 4）

七成案例如此。照它写代码之前必须说明：
*「这条是自动摘要（draft），我按它的思路写，不是照抄一份验证过的脚本」*。
不说这句，就是**拿一份草稿冒充配方**。

### F5 · 不许 `get_asset` 把图拉进上下文

`get_asset` 回的是 base64 PNG/JPEG/PDF，几百 KB 直接进转录——
违反项目那条「图不进上下文」（视觉服务的整个设计就是为了避免它）。
比对图型靠 `caption` + `figure_type` + `how_to` 足够。
**人想亲眼看参照图**时，给 case_id 与图的相对路径，让他自己在 MLAI 的图廊里看。

### F6 · R 那条岔路如实写在技能里（事实 6）

要 R：`search_cases(query, language=["r"])`，或者拿到 case 之后看它是 `pipeline.R` 还是 `pipeline.py`。
**这一轮不封装它**——先看实际会不会撞上；撞上了再说。

### F7 · MCP 那台怎么进来

本机 stdio（`src/config/schema.ts` 的 `本机MCP`）：

```yaml
mcp:
  mlai-science:
    command: uv
    args: [run, mlai, serve]
    cwd: /Users/liuyue/Desktop/Github_repos/MLAI-science
```

- **信任开关不进配置文件**：`trusted` / `disabled` 落在本机 settings（`mcp.trusted.<名>`），
  这是既有红线——项目级 `.dawn/mcp.yaml` 会跟着仓库被 clone。
- **写进哪一份**：全局 `providers.yaml`（`userData` 那份），不是项目级 `.dawn/mcp.yaml`——
  `cwd` 是这台机器上的绝对路径，跟着仓库走没有意义。入口就是设置里 MCP 那一屏。
- **答空时先怀疑没 `rebuild`**：`registry.db` 没建时工具照样回，只是空的。
  技能里写明这一条，否则「语料库里没有」与「你还没建库」在屏幕上是同一句话。

### F8 · 技能要先确认工具在不在

这份技能随应用发布（`skills/`，只读），但**它依赖一台并非人人都配了的 MCP**。
所以它的第一步是确认 `mlai-science` 的工具在不在：**不在就说清楚「这台没配，我做不了这件事」并停**，
不许退化成「我凭印象给你写一段画图代码」——那正是这份技能存在的理由的反面
（凭印象写的代码，与语料库里 1538 个跑过的案例，不是一回事）。

## 不做（记下）

- **PDF 抽取**：作者定的——先只做「粘一张图」。等他嫌截图麻烦再说。
- **CLIP 以图搜图**：科学图表这个场景里，人要的是「这种图怎么画」，
  而那份信息在 caption 与 `how_to` 里，不在像素里。
  **判断它值不值得做的依据**：用一阵子，把「我描述了但搜不到、而我知道库里有」的例子记下来——
  有例子才做，没例子就是不需要。
- 图廊嵌进「网页」格；把参考图拉进对话（见 F5）。
