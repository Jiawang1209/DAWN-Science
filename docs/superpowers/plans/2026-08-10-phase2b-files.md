# 阶段 ②-B 详细计划：文件浏览与预览

- **日期**：2026-08-10
- **上游**：作者 2026-08-10 的两段话——

  > *「我们可以通过调用我本地的 R 或者 Python，直接帮我们写代码，分析数据，跑机器学习，
  > 但是这时候我们又需要查看结果，那么就是查看项目文件夹，查看生成的图片，
  > 查看保存好的 png，或者 pdf 文件。**其实这些都是我们作为数据科学平台所需要的。**」*

  > *「我们也需要 hermes 以及类似 claude code app 或者 codex app 的预览文件这种功能。」*

---

## 0. 判据

1. **看得见产出**：agent 跑完一段分析，生成的 png 能在应用里直接看到，不用切到 Finder。
2. **能翻整个项目**：工作区的目录树可浏览，点任意文件能预览。
3. **越界必须失败**：**工作区之外的文件一律读不到**，而且是响亮失败，不是空结果。

---

## 1. 为什么入口有两个，而且主次分明

**产出栏那些文件名，本来就该能点开。**

不变式 5 让我们**已经知道 agent 写了哪些文件**（`filesWritten` 逐次工具调用都记着）——
这是 Hermes 没有的东西。所以最短的路径不是「浏览文件夹找找看」，
而是**从已知的产出直接点进去**。

文件浏览器是它的**补充**：agent 没碰过的数据文件、上一次会话留下的东西、
人自己放进去的 csv——那些只能靠翻。

> **主次颠倒的代价**：只做浏览器，人每次都要自己想「刚才那张图存哪了」；
> 而那个信息我们**本来就有**。

## 2. 与 Hermes 的区别（读设计之后的判断）

Hermes 的 `preview-targets.ts` 与 `artifact-detect.ts` 解决的是**另一个问题**：
- `preview-targets`：消息里的 `[Preview: x](#preview/…)` 链接
- `artifact-detect`：把消息里够大的代码块升格成右栏卡片

**那是「对话内容的预览」**。我们要的是**磁盘产出的预览**——
png 是 matplotlib 写出来的，不在任何一条消息里。

**可以拿的**：右栏承载预览这个**形态**，以及
`previewName()` 那种「从路径里取一个人能读的名字」的小处理。
**不能照搬的**：整套以 markdown 链接为中心的机制。

---

## 3. 安全边界（这一阶段最要紧的一节）

开了「读文件」这个口子，**渲染进程就能问后端要任意路径的内容**。
写错一行就是任意文件读取。

| 规则 | 怎么保证 |
|---|---|
| **只许读工作区内** | 先 `realpath` 再判前缀。**不能只做字符串前缀比对**——`..` 和符号链接都能绕过 |
| **符号链接指到外面 = 越界** | `realpath` 之后再判，而不是判链接本身 |
| **越界响亮失败** | 抛 `UserFacingError`，**不返回空内容**——空内容会被读成「这个文件是空的」 |
| **字节上界** | 文本 512 KB、图片 10 MB；**超了说清多大**，不静默截断 |
| **目录列举有上界** | 一层最多 1000 条，超了明说省略了多少 |
| **默认忽略** | `.git` / `node_modules` / `.dawn` / `__pycache__`；**忽略了要能看见开关**，不是偷偷藏 |

> **不做的**：写文件、删文件、重命名。这一阶段**只读**。
> 写操作要走授权门（阶段 ④），混进来会让一个「看看结果」的功能变成一把刀。

## 4. 批次

| 批次 | 内容 | 判据 |
|---|---|---|
| **F1** | 文件访问层：路径守卫 + 列目录 + 读文件（含 mime 与上界） | 越界的六种写法全部被挡下（`..` / 绝对路径 / 符号链接 / …） |
| **F2** | 协议 `listDirectory` / `readFile` + mock 分支 | 界面能拿到目录与内容 |
| **F3** | 预览面：图 / 文本 / CSV 表格 / 其它（说清是什么、多大） | png 看得见；文本超上界时说清省了多少 |
| **F4** | 目录树 + 新视图；**产出栏文件名可点** | 能翻整个项目；从产出直接点进预览 |
| **F5** | PDF ✅ | 见 §5。**建 CSP + blob `<embed>`**；`frame-src` 是踩出来的 |

## 5. PDF 单独一批的理由 —— 以及这一节此前写错的地方

> **更正（2026-08-10，做 F5 时发现）**：这一节原本写着*「本项目的 CSP 是严格的
> （这正是它安全的原因之一）」*。**那句话是错的——一条 CSP 都没有。**
> `nodeIntegration: false` / `contextIsolation: true` / `sandbox: true` 都在，
> 唯独少了这一层。所以 F5 的「要动 CSP」，实际含义是**先把 CSP 建起来**。

Chromium 自带 PDF viewer，但要用它得让渲染进程加载一个 `file://` 或 `blob:` 的
`<embed>`／`<iframe>`。

三条路，代价差很远：
1. **系统程序打开**（`shell.openPath`）：零风险，但人离开了应用
2. **blob: + `<embed>`**：要在 CSP 里放行 `object-src` 与 `frame-src`
3. **自定义协议**（`dawn-file://`）：要在主进程注册 scheme 并**再写一遍路径守卫**

### 定案：走第 2 条

第 3 条听起来「最干净」，但它会让**路径守卫有两个家**——而 F1 的全部重量
就在那一份守卫上（§3）。两份守卫迟早有一份落后，那时先落后的那一份就是洞。

blob 用的是**渲染进程已经拿到的字节**（经 `readFile` 走同一个守卫取回），
不新增任何读取能力。CSP 里因此只多两条 `blob:`。

### `frame-src` 是踩出来的

只写 `object-src blob:` 时，Chromium 报
*「Framing 'blob:…' violates … "default-src 'none'"」*——
**它把 PDF 的 `<embed>` 当作 framing**，自带阅读器是在子框架里打开文档的。
少了 `frame-src` 的现象是：`<embed>` 在、`src` 是 `blob:`、**里面一片白**，
一个断言都不会红。`e2e/csp.spec.ts` 与 `files.spec.ts` 里那两条盯 console 的
断言就是为这种失败写的。
