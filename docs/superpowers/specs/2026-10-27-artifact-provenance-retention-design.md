# 产物自动来源记录与关键结果留存第一版设计

日期：2026-10-27（Asia/Shanghai）。状态：方案已获用户批准，2026-10-27 至 2026-10-28 已在独立分支完成第一版实现与本地验收；未合并、未推送。

用户确认的方向是“自动来源记录＋关键结果留存”。日常执行记录来源；用户选定重要结果时保存其确定内容。本文最初为只设计阶段形成的规格；用户随后明确批准独立分支按四步实现并逐步验证，要求先不合并或推送。实际交付与限制见 [验收记录](../../reviews/2026-10-27-artifact-provenance-verification.md)。该批准不包含提交、发布或替换安装版。

## 1. 第一版交付目标

研究人员在现有产物面板打开一张图或一份表，可以查看其已记录的运行、实际提交的代码、已知输入身份、环境及来源缺口。点击“保留此版本”后，即使工作区文件被覆盖或删除，仍能打开当时保存的结果及其来源记录。

第一版保证的是“记录可以检查、选定内容可以取回”。输入未归档、内核中有未捕获变量、依赖信息缺失时，明确显示限制。“已保留”“运行成功”“选定输出重跑通过”和“科学结论已核验”分别表达。

验收示例：用样地 CSV 在 Python/R 中生成统计表和图片，保留其中一组结果；修改过滤规则后重跑，能区分两次记录，旧结果仍可预览。仅记录过哈希、未保存内容的普通历史结果，允许显示“内容未留存，无法打开历史版本”。

## 2. 方案选择与范围

比较三种实现方式：

| 方式 | 收益 | 代价与边界 | 本次选择 |
|---|---|---|---|
| 仅给现有清单增加 Run 链接 | 改动较小 | 覆盖后旧内容不可取回，缺少独立版本身份 | 不足以满足关键结果留存 |
| 自动来源元数据＋显式保存关键结果 | 日常低负担，重要结果能取回 | 必须准确区分观察事实、声明和未知 | 采用 |
| 每次执行保存全部文件与完整环境 | 历史覆盖更广 | 大数据成本高，仍不能自动捕获全部依赖 | 后续有实际需要再评估 |

第一版范围：

- 自动接入本地 API 会话的内置文件工具、`run_code`，以及用户在笔记本中执行的 Python/R cell。记录同一路径的新建和覆盖。
- 本地 bash/MCP 只接入已实际观察到的文件变化，保留粗粒度来源；不能精确识别脚本或实际输入时不补猜测。
- 远端、独立 CLI、ACP、子 agent、Bot 等未接入完整记录的路径保留已有清单，并显示本版记录能力限制；不拿宿主文件或父会话证据冒充其来源。根会话调用子任务期间观察到的变化也不直接归给根调用。
- 关键留存支持本地工作区内的普通文件，一次可选择一个或多个；类型不限于图表，受路径和大小预算约束。
- 项目级保存记录，面板默认仍看本会话；同一项目、同一工作区中的跨会话版本能够连接。

内核里只有 rich display、没有落盘文件的图像，第一版保留执行上下文但不直接转换成文件版本；先通过现有方式保存为文件后再留存。

本版不包含任意 Python/R 文件访问监控、变量内存快照、自动方法解释、远端文件自动下载归档、完整数据仓库、论文工作区、图上批注、自动恢复旧文件，以及新的重跑执行器。

## 4. 用户操作与显示

### 4.1 平时分析

用户照常提交任务或运行 cell，自动采集在后台完成，不新增逐次填写表单。现有 `GENERATED` 仍只统计新建文件；覆盖文件不会被重新算作新建。

产物清单保留现有目录与预览；已登记产物的后续写入会更新来源摘要。当前会话覆盖了既有文件但未新建时，显示“本次更新”记录，避免覆盖结果不可见；该记录带来源类型，不伪造出生 Run。输入文件只出现在来源详情，不因被读取而进入产物清单。

预览工具栏增加常驻文字入口“来源与记录”和“保留此版本”。来源区显示当前记录时间、关联运行、实际代码、输入身份、环境采集时间、内容是否留存，以及缺口。进入历史记录后，明确区分“工作区当前文件”和“历史留存副本”；无副本的历史记录仍可查看来源。

### 4.2 保留关键结果

用户选择一个或多个结果，点击“保留此版本”，填写可选名称及备注。界面展示待保存文件、预计大小、来源覆盖情况；默认不复制原始输入数据。用户确认保存后：

1. 后端按选定记录的完整哈希核对当前字节，校验路径、大小和是否仍在写入。
2. 保存选定结果内容，以及相关的代码、环境描述、输入身份和执行摘要，生成不可变清单。
3. 全组保存成功后显示“已保留”；失败不生成看似成功的空记录。

文件已变化时不能把新字节保存成旧版本：返回“当前文件已变化”，刷新后由用户重新选择。历史记录未保存内容、当前也没有匹配字节时，提示“无法留存这份历史内容”。

旧产物没有可信历史哈希时，可选择“留存当前内容”，先采集当前身份再保存，标为“后补留存”；旧 Run 仅保留原有路径关联，不被提升为该内容的已确认生成者。

### 4.3 查看和移除留存

产物面板增加范围选择“本会话 / 项目已保留”。后者支持打开留存组、预览文件和只读来源，不依赖原会话仍存在。第一版只按时间和名称列出，不建设新工作区。

“删除留存副本”需要明确确认，说明仅删除应用内留存及受影响的文件数；不删除工作区原文件。删除后保留最小删除记录，不继续标“已保留”。没有恢复到原路径按钮，防止误覆盖当前结果。

## 5. 自动来源记录的事实边界

### 5.1 输入

以下三类不能混在一起：

- **工具实际读取**：记录成功读取的路径、读取范围和读取期间核对的文件身份。只能证明工具读过，不自动证明后续分析使用了它；部分读取明确显示范围。
- **本次执行声明的输入**：`run_code`/笔记本允许附带可选输入路径。后端在真正执行前核对其身份，执行后再次检查变化。模型提供的输入声明标为声明，用户添加的标为用户指定；文件哈希核对不等于确认程序确实消费该文件。
- **候选材料**：`@`、方案中的路径、对话提及及代码静态解析只能提供候选；不自动形成“使用了此输入”的证据边。

默认不扫描并哈希整个数据目录，不复制原始数据。程序内部动态读取、数据库查询、网络请求和既有变量未被捕获时，输入栏显示具体缺口。相邻时间、同一会话内先读后写都不足以建立因果关系。

可选输入统一使用 `inputPaths`，最多 50 个工作区相对路径，后端去重并校验。笔记本提供默认折叠的“本次输入（可选）”，不阻止未填写时运行。文件读取核对若未拿到工具实际消费的同一字节流，只能显示“读取期间核对的身份”，不能声称精确捕获了被消费字节；核对前后变化则标不稳定。

“可找回输入”单独显示：保存位置只是引用时标为“外部引用，未验证长期可取回”；有可核验不可变归档或留存字节才显示相应状态。哈希不能恢复已被覆盖的数据。

### 5.2 代码、参数与内核

自动保存本次实际提交的完整 cell/命令原文及哈希。可选结构化参数、种子保留声明来源；代码里的实际值以原文为准，不把模型解读写成执行事实。bash 仅记录实际命令，未捕获脚本内容时不能声称固定了该脚本。

用户与 agent 的 cell 共用内核入口采集；在队列内、实际提交前完成输入身份核对，执行结束后采集输出身份，然后才释放本次采集边界。现有 `开始了` 回调为同步通知，不能直接承担异步采集；实现时新增可等待钩子。

记录内核实例/启动代、执行顺序及是否实际开始。沿用现有 Run 表示调用状态，同时额外记录实际提交时刻和 `not_dispatched / dispatched / completed / failed / unknown`，不把入队时间当计算开始，也不把执行失败等同工具传输失败。

每个 cell 默认注明“可能依赖已有内核变量，变量状态未捕获”。同内核先前的执行只作为顺序上下文，不冒充精确变量依赖图。环境只引用已采集快照，注明“内核启动时采集”等实际时点；不承诺运行期间安装包或配置未变化。

### 5.3 输出与归属

支持直接文件工具的成功写入，以及现有探针观察到的新建/改动。直接写入成功且采集期间身份稳定时，记录“已观察到该调用写入”；仅靠工作区差分发现的记录显示“运行期间观察到变化”。

同工作区有重叠写操作、子任务写入，或探针已有 `mayIncludeUserEdits` 时保留归属疑义；不能因为保存了哈希就消除该疑义。检测到同一目标的并发写入、采集中变化时，记录为不稳定/存在竞争，不生成确定生成关系。无法检测的外部编辑仍是限制，应用内路径锁不等于操作系统级排他。

失败运行已写下的文件仍记录，但保留失败状态；停止后内核仍在运行时不把当前字节标为最终结果。采集失败只使来源记录降级，不能覆盖原执行结果。

## 6. 数据模型与身份

文件身份由 `projectId + workspaceScopeId + normalizedRelativePath` 确定；`workspaceScopeId` 固定到实际会话根，区分项目目录、临时会话子目录和执行位置。不同工作区的同名文件不能合并。以后远端扩展再纳入连接身份。

新增以下逻辑记录，沿用 SQLite 与已有 Run/环境存储：

| 记录 | 主要内容 | 约束 |
|---|---|---|
| 文件身份 `ArtifactIdentity` | 工作区范围、路径、类型、首次观察 | 路径是逻辑位置；改名按新路径记录，不推断移动关系 |
| 内容版本 `ArtifactVersion` | 文件身份、完整 SHA-256、大小、首次观察时刻 | 同身份相同字节复用版本；不带可变“最新来源” |
| 执行证据 `ExecutionEvidence` | Run、tool/cell ID、实际代码、内核身份、执行状态、环境引用 | 代码与执行摘要按次保存；不依赖压缩后的对话来还原 |
| 文件观察 `ArtifactObservation` | 版本、执行引用、读取/写入/声明类型、时间、核验强度、缺口 | 同字节多次生成仍有多条观察，完整性不靠版本号表达 |
| 留存组及成员 `RetainedResult` | 名称、选定版本/观察、不可变清单、内容引用、保存状态 | 一组可多文件；历史来源固定到当次观察 |
| 内容对象 `ArtifactBlob` | 项目范围内的哈希、字节数、相对存储键 | 同项目相同字节去重，跨项目不共享生命周期 |

哈希未完成的文件只创建观察，不分配确切内容版本，不用 size/mtime 冒充 SHA-256。A→B→A 的内容变化复用 A 版本，新增第三次观察，显示时间顺序；相同内容的新一次执行也不会被丢掉。

工作区“当前观察”、来源覆盖和存储可用性分别返回。当前文件状态为“匹配 / 已变化 / 已不存在 / 未检查 / 检查失败”；元数据匹配最多显示“尚未完整校验”，不能显示哈希一致。

只保存最近观察的当前指针可以更新；版本、执行原文和已完成留存清单不可覆盖。备注修订追加记录，不重写历史证据。

执行摘要和留存清单不外键依赖会话表的存活；引用 Run/环境的关系不设置删除会话级联。项目移除时，在完成留存删除确认后，按引用顺序删除新索引，再删旧 Run 和项目。留存读取不依赖易失的会话目录。

## 7. 存储、预算与一致性

### 7.1 存放位置与预算

由壳注入 `artifactStoreDir`；桌面端使用应用管理的数据目录，测试使用隔离临时目录。内容不写进用户项目、Git 仓库或原始数据目录。SQLite 保存索引，文件存储保存字节。

第一版工程默认预算如下；实现时提供可注入配置并验证上限，界面显示实际限额，数值不作为性能实测结论：

| 内容 | 建议默认预算 | 超限行为 |
|---|---|---|
| 自动代码原文 | 每次 1 MiB | 保留全文哈希与缺口，原文不截成“完整代码” |
| 自动文件哈希 | 单文件 64 MiB、一次采集累计 128 MiB、等待上限 5 秒 | 停止该项，保留元信息并说明未完成完整校验 |
| 一次采集候选 | 200 个文件 | 明确记录未处理数量/未知范围，不把前 200 个当完整集合 |
| 显式结果留存 | 单文件 50 MiB、每组 200 MiB、每项目留存对象累计 1 GiB | 保存前拒绝超限；不自动删除旧结果，用户可删除留存副本腾空间 |
| 留存复制时间 | 整组 60 秒，可取消 | 失败且不发布留存组；保留必要失败诊断 |
| 随留存固定的日志 | 每次执行头尾各 16 KiB | 显示总量和省略量；不声称保存了全部日志 |

文件采用流式哈希，不把整份文件读入主进程内存；重计算在后台 worker 进行，避免同步哈希阻塞界面。自动采集只处理观察到或明确指定的候选，不再增加全目录扫描；已有探针的上限和盲区也写入缺口。

保留结果时显式选择的 50 MiB 以下文件仍可重新核验，不受前次自动采集超时影响；没有原历史哈希时只能作为后补捕获。自动采集开销与留存预算分别记账。

### 7.2 留存的提交顺序

为每次保存建立请求 ID，整个组的选定观察 ID 和预期哈希在开始后固定。同请求 ID 重试只恢复该请求，不能换一组文件。

1. 建立 pending 请求，验证作用域、路径、配额并预留容量；并发请求共用项目配额锁。
2. 将每个文件流式复制到该请求独享的暂存区，同时计算哈希；对已打开文件和路径在复制前后核验身份，拒绝软链、越界、替换和不稳定读取。保存前正在运行且可能继续写该目标的调用不允许留存。
3. 核对实际哈希与选定记录一致，固定来源清单；内容对象写入并校验后原子发布到确定存储键。
4. 在 SQLite 事务中一次发布全部成员和 ready 清单。只有这一步成功才显示“已保留”。

文件系统和 SQLite 不是跨介质原子事务。崩溃后若对象已发布而 ready 未提交，则是未被引用对象，不能出现在成功记录；重试按请求 ID 恢复。ready 对象丢失或被改动时显示损坏/缺失，不回退到工作区当前文件。

启动时将未完成请求标为中断并核对其已登记暂存路径；只处理本模块拥有的临时文件，不扫描或清理用户项目。不提供自动垃圾回收；用户显式删除留存时，先记录删除意图，再释放无其他引用的内容，失败显示待清理，配额按实际占用计算。

### 7.3 保留与删除规则

删除会话或压缩对话不删除项目级版本记录和已保留结果；留存清单包含独立的代码/环境/执行摘要，原会话不可打开时显示其引用已失效。普通来源引用不承诺保存完整对话。

移除项目的既有流程必须检查留存数量与大小。有留存时不走旧的无提示删除路径；界面明确列出后，只有用户另行确认删除留存并移除项目才执行，取消保留项目。第一版不增加脱离项目的归档系统。

扩展既有 `deletionImpact` 返回留存数量、占用字节和留存集合修订标识；`deleteProject` 显式携带已确认标识，后端在项目操作锁内再次校验，集合变化即拒绝旧确认。删除期间拒绝新的留存请求，避免确认后新保存的结果被一起删除。没有留存的旧调用保持兼容。

自动元数据与本地代码记录按现有数据目录的访问边界保存；不自动上传、分享或读取凭证库/环境变量。留存本来就在磁盘上的代码可能含用户写入的敏感字面量，不宣称已自动脱敏。

## 8. 服务与协议边界

建议新增小模块：`src/artifacts/model.ts`（状态与身份）、`store.ts`（索引）、`capture.ts`（输入/代码/输出采集）、`blobs.ts`（字节保存）、`retention.ts`（显式留存事务）。避免继续把存储、哈希和状态判断塞入 `native.ts` 或 `backend.ts`。

运行包装器和内核队列调用采集服务，使用服务端生成的执行 ID，通过 Run 记账关联。事件订阅仅负责刷新，不能用不受等待约束的事件监听来实现执行前后采集。

新增操作的建议契约：

| 操作 | 输入/用途 | 副作用 |
|---|---|---|
| `getArtifactHistory` | 会话授权范围＋文件身份、分页；读取版本与观察 | 只读 |
| `getArtifactSource` | 确切观察 ID，返回代码、输入、环境与缺口 | 只读 |
| `checkArtifactCurrent` | 文件身份，检查当前文件与已记录版本是否匹配 | 只读；不写入历史或自动留存 |
| `retainArtifactResults` | 会话/项目范围、请求 ID、观察 ID＋预期哈希列表、名称备注 | 写留存及应用管理的字节 |
| `captureAndRetainCurrent` | 旧产物的显式当前捕获请求 | 写后补观察与留存；不修改旧记录 |
| `listRetainedResults` | 项目范围、分页 | 只读 |
| `readRetainedArtifact` | 留存 ID＋成员 ID | 只读；只读已核验对象，不接受任意磁盘路径 |
| `deleteRetainedResult` | 项目范围＋留存 ID＋明确删除确认 | 写删除记录并释放无引用留存字节 |

所有 ID 查询都按项目、实际工作区、会话可见范围重新校验，不能凭猜到的 Run/版本 ID 跨项目读取。只读宿主禁止写留存。权限或执行边界禁止科研文件写入时，查看来源仍可用；显式留存遵循原宿主授权，不借此执行代码、安装依赖或改动科研文件。

分页查询默认 50 条、最多 200 条；留存每组最多 50 个成员。输入/输出观察按执行 ID 和阶段去重，元数据写入在同一次事务中关联到既有 Run；事务失败时不改写历史。自动采集状态分别记录 `pending / captured / partial / failed / interrupted`，中途退出保留中断事实，不能从事后文件补成运行时观察。

扩展现有 `listArtifacts` 的可选来源摘要，同时保留原 `Artifact`/路线引用语义；项目已留存使用独立查询。覆盖、新观察和留存状态变化也必须刷新，不能沿用“仅 `filesCreated` 非空才刷新”的判断。事件仍只通知失效，不另维护一份清单；项目范围的失效同步影响打开的相关会话。

新增协议与 mock/确定性场景在同一实现包维护，`dev:mock` 与 Electron 测试共用同一后端，保持现有协议版本策略。

## 9. 与分析交付和重跑的连接

整理交付时可选择工作区文件或已保留成员，记录确切版本/观察引用和缺口。使用已保留成员时必须读取留存字节；使用当前路径则重新核对身份，不悄悄替换成同名新文件。

独立验证仍使用现有解释器进程与新验证目录，沿用用户授权、写入约定、超时和预先固定容差。第一版不把任意 cell 一键变成可重跑脚本，不在查看来源或保存结果时自动启动分析。

验证报告新增对确切结果版本/留存成员的引用。一个版本重跑通过不会使同路径后来的版本自动通过；报告中比较对象是保留结果时，基准必须来自留存字节。缺少输入字节、脚本、依赖或执行条件时，显示缺口，不把“已保留”变成“可复现”。

## 10. 历史兼容与故障行为

- 升级只增加表和索引，不重写旧 Run、旧 `provenance` 或源文件；旧清单仍能打开。
- 不启动历史全量哈希，不根据今天的文件创建伪造的历史版本。旧记录显示“来源记录不完整”；用户主动后补时标明采集时间。
- 数据库迁移沿用事务机制；失败不能带着半迁移表继续运行，保留原数据并报错。部署迁移前的数据库备份按现有发布恢复策略处理，不在本功能中暗自改写安装版。
- 哈希超时、路径拒绝、目录扫描不完整、磁盘不足、文件丢失、并发变化均返回结构化原因。正常分析执行与采集状态分别显示；不能因来源采集失败谎报分析失败，也不能静默当作来源完整。
- 来源详情加载失败显示重试；切换项目、会话和版本后，迟到的响应不能覆盖当前面板。
- 文件改名、删后重建、同路径被外部修改只记录可观察事实。未保存过的旧字节不可恢复，界面不提供虚假的历史预览。

## 11. 分步实现顺序

每步独立可审查，实施分支使用 `codex/` 前缀；具体施工命令、提交安排和测试清单在设计确认后的执行计划中制定。

1. **版本与留存底座**：数据库迁移、身份/状态、字节存储、预算与事务；用小文件和故障注入验证，不接模型。
2. **本地自动记录**：文件工具及 Python/R 共用采集入口，覆盖用户 cell 和 agent cell、同路径覆盖、输入声明及缺口，保留原 Run/GENERATED 口径。
3. **现有产物面板接入**：来源、历史记录、项目已保留、保存/删除副本和失效刷新；不重做整体布局。
4. **交付与生命周期收口**：按版本读取留存，验证报告引用固定结果；打通会话删除、项目删除、重启恢复与旧数据兼容。

第一版验收范围包含以上四步，不以只有存储底座或只有界面入口作为完成。

## 12. 验收标准

| 场景 | 必须看到的结果 |
|---|---|
| Python、R 各生成 CSV 和图片 | 两条语言路径都有实际代码、Run、文件身份及来源缺口；用真实内核验收 |
| 用户 cell 与 agent `run_code` | 都记录；同内核顺序正确，排队取消不记录为已运行 |
| 覆盖文件、相同字节再生成、A→B→A | 新建统计不变；内容版本与执行观察各自正确，没有重复版本或丢失运行 |
| 一次读取后多次分析 | 读取证据不被无条件挂成所有后续分析的输入 |
| 使用旧变量、动态读文件、声明输入未实际使用 | 明确区别未捕获与声明，不显示完整输入依赖链 |
| `.gitignore` 输出、非 Git 临时工作区、不同会话根 | 可观察的文件被记录；不能串入另一个工作区的同名版本 |
| 留存一组结果，再覆盖/删除原文件 | 仍能读取原留存字节、代码与清单；实际哈希匹配，普通未保存版本不能伪装可预览 |
| 原文件在观察后、复制前或复制中变化 | 拒绝错绑；旧记录和已留存内容保持不变 |
| 同目标并发写入、失败后部分输出、停止但仍运行 | 不确认为稳定的成功产物；歧义与实际执行状态可见 |
| 旧会话升级、后补留存 | 无历史全量捕获、无旧 Run 改写；后补时间与来源限制明确 |
| 删除会话/压缩对话、移除项目、删除留存 | 既定保留规则有效，原始数据不受影响；移除项目不会静默丢掉留存 |
| 断电/终止于各保存步骤、请求重试 | 不出现半组成功；相同请求幂等，损坏对象不从当前工作区偷补 |
| 软链、越界、跨项目 ID、只读宿主、预算耗尽 | 拒绝不合法请求；缺口出声，不自动清旧结果 |
| 查看、保存与切换面板 | 不触发代码执行、不读取其他项目；迟到响应不串项目 |
| 已留存结果用于交付验证 | 比较固定字节，报告绑定版本；新版本不能继承旧版本的验证通过状态 |

单元/集成覆盖身份、迁移、状态、路径、哈希、原子发布、预算和引用；相关 Electron 覆盖真实文件、保存/删除/重开和现有清单及视觉基线；Python/R 真实内核分别验证采集边界与已有变量限制。实现阶段运行类型、单测、构建和相关 E2E；本文件本身不代表这些检查已经通过。

完成门：已选关键结果在工作区变化后仍能独立取回；来源字段不伪造；未捕获输入、未留存历史内容、未验证重跑均有明确状态。科学结论正确性需要任务自身的独立判据，不由留存系统裁定。
