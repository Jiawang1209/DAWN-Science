## 作者拍板(本轮对话)

| 问 | 定的 |
|---|---|
| 协议层 | **官方 SDK `@larksuiteoapi/node-sdk`**(锁版本)。与微信自实现不同但同一条判断逻辑:看协议面大小与依赖干净度——设备流与 WS 长连接只有 SDK 有,自实现不值;微信的 ilink 只有五个 HTTP 接口且官方实现绑在 OpenClaw 宿主上,才选了自写 |

## 一、绑定:设备流扫码即建应用

- 远程助理屏飞书卡 → 「添加机器人」→ `lark.registerApp` 设备流出二维码 URL
  (界面自己画,与微信同款)→ 飞书扫码 → 应用自动创建 → resolve
  `{client_id, client_secret, user_info.open_id, tenant_brand}`。
  `tenant_brand === "lark"` 自动切国际域(dsh-feishu 的做法)。
- 应用声明(写死在代码一处,**权限即文档**):名字 DAWN-Science;scopes v1 最小集
  `im:message.p2p_msg:readonly`、`im:message:send_as_bot`、`im:message.reactions:write_only`;
  事件 `im.message.receive_v1`。CardKit 相关(`cardkit:card:write`、`im:message:recall`)
  第二批随卡片一起加(增量授权那条 dsh-im 的路先不修,真踩到再说)。
- **凭据洁癖**(dsh-im 三条全抄):`app_secret` 只进钥匙串(键 `feishu:appSecret`,
  与 `weixin:botToken` 同一条 credentials 端口);不进设置表、不进协议响应;
  SDK 错误文本不透传给界面(防 secret 印进日志)。`app_id`/`open_id`/域/绑定时刻/
  会话映射这些不是秘密,进 settings(`feishu.*` 键,对称 `weixin.*`)。

## 二、收发

- **收 = `WSClient` 长连接**(零公网暴露,桌面应用天选):`im.message.receive_v1`,
  连接健康位(`onReady/onReconnecting`)进状态卡——「连着 / 重连中」如实显示。
  SDK 锁版本;dsh-im 给 WSClient 重连竞态打过运行时补丁,**风险写进 sdk.ts 头注**,
  真撞到再处理,不预防性打补丁。
- **只认扫码那个人**(`open_id`),别人发来不回、记一条日志(平移微信);**只私聊**
  (群消息事件都不订)。只收 `message_type === "text"`(图片等后批,微信有图是因为
  ilink 带完整 CDN 协议;飞书 v1 不接 `im:resource`)。
- 收到即打 Reaction「处理中」(OnIt),结束换 DONE / ERROR(dsh-feishu 的口径)。
- **发 = 纯文本**:`im.v1.message.create`(`receive_id_type: open_id`,私聊直达);
  复用微信的攒段(≥200 字或静默 3s)与切段(飞书单条按 9000 字、优先按换行——
  dsh-feishu 的 splitText 口径)。
- **去重**:内存 Set + settings 持久环形(上限 1000)——WS 重投与重启重放都挡住。

## 三、语义:整套平移微信,不抽象

绑定专属会话「飞书 · DAWN-Science」、斜杠命令(`/会话 /用 /新建 /停 /在哪`)、
三种通知(跑完>60s / 出错 / 等点头,前台不推,开关持久)——`FeishuChannel` 与
`WeixinChannel` **同构各自实现**。v1 不抽统一 Channel 接口:dsh-im-bot 用两个通道
换一个抽象,代价是飞书能力被抹平成交集、接口画饼无人实现——**两个通道不值一笔抽象税,
第三个通道进来再抽,且必须带 capability 声明**。

## 四、落位与协议操作

- `src/channels/feishu/`:
  - `sdk.ts`:SDK 的注入面——把 `registerApp` / `WSClient` / `im.message.create` /
    `messageReaction` 包成窄接口,**假实现可整体替换**(单测与 e2e 都靠它;
    与微信 `client: (baseUrl) => IlinkClient` 同一手法)。
  - `channel.ts`:同构 `WeixinChannel` 的骨架(状态机 unbound/logging_in/bound/stale、
    轮询→改为长连接、通知、斜杠命令、绑定会话)。
- 协议操作 7 个(对称微信 8 个,飞书扫码无配对码,没有 SubmitCode):
  `feishuGetStatus / feishuStartLogin / feishuCancelLogin / feishuUnbind /
  feishuBindSession / feishuGetNotify / feishuSetNotify`(118 → 125)。
- 远程助理屏:飞书卡从「还没接」换成真的(二维码/已绑定/解绑/绑定的会话),
  形制照微信卡;通知开关两通道共享一份界面、各自持久(`feishu.notify`)。

## 五、顺手捎上的微信小修(dsh-im 对账发现)

1. 出站媒体 `client_id` 从 randomUUID 改**内容哈希的确定性 id**——重试不重发(幂等)。
2. `getupdates` 超时不抛错,回空集保游标(现在超时会走进连败退避)。

## 六、判据(三条准入规则)

| 规则 | 怎么满足 |
|---|---|
| 新协议操作补 mock | e2e 走 `sdk.ts` 的假实现分支(环境变量 `DAWN_FAKE_FEISHU`,与 `fakeSsh`/`DAWN_FAKE_ILINK` 同一套惯例):假设备流即刻 confirmed、假 WS 可注入消息 |
| 可判定规则进扫描 | 新按钮文案自动落进中英子串扫描 |
| 主路径自己验 | 单测:假 sdk 走完设备流状态机、收发/去重/只认绑定人/攒段切段、微信两处小修;e2e:添加机器人 → 状态卡 confirmed → 注入一条假飞书消息 → 会话里出现且回复送回假 WS → 通知开关持久 |

## 七、不做什么

- 群聊、多机器人、多工作区(dsh-im 的规模,DAWN 一人一机器人,与微信对称)。
- CardKit 流式卡片与按钮菜单(第二批;斜杠命令已覆盖菜单职能)。
- 增量授权修复、图片/文件收发(`im:resource` 后批)、webhook 模式。
- 统一 Channel 抽象(见 §三)。
