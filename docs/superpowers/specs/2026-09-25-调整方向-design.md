# 调整方向：排着的话要么等、要么马上改做、要么到坞里问（学自 Codex）

2026-09-25 · 分支 `redirect-queue` · 作者逐条定的（见 §1 末）

## 1. 要解决什么

09-23 做了待发条（spec `2026-09-23-待发消息-design.md`）：忙着时回车 = 排队（`followUp`），
Cmd/Ctrl+回车 = 插队（`steer`）。09-25 作者真机用下来：

1. **「插队」用起来就是排队。** `steer` 要等**当前这一步**跑完才送进去——agent 正在跑一段 50 秒的脚本，
   插的那句就挂 50 秒。人看到的是「它还在按老的做，我的话一直挂着」。作者：*「现在的插队，感觉和排队似的」*。
2. **想马上改做，没有路。** Codex 的「调整方向」是：一发，手上这一步停下，按新话接着做。
3. **想旁边问一句，要先知道坞、点开坞、点另开一段**，三步才开始说话（侧边对话 09-24 刚做完）。

**另外查出一个 bug（作者：「之前有 bug 的话，我们还是要修掉」）：**
`run_code` 的 `execute` 不收中止信号（`src/tools/run-code.ts:135`，签名里没有 `signal`），
按「停止」时 pi 的 `abort()` 要等这一轮真停下（`waitForIdle`），而 pi 的 agent loop 在等工具的 `execute` 返回（`pi-agent-core/dist/agent-loop.js:507`）、工具在等内核跑完——**停止键按下去，这一轮要等那段代码自己跑完才停，内核里那段照跑**（2026-09-25 写实现计划时对着 pi 的代码查实；原先写的「pi 不等了」不对）。调整方向要「停掉这一步」，这个必须先修。

作者定的（2026-09-25）：
- 调整方向 = **停掉当前这一步**，按新的去做；停止不真停内核的 bug 一起修。
- **只留一种排队**（选项 A）：等这一轮做完再送。`steer`（这一步做完就送）去掉；想马上改做就用调整方向。
- 到坞里问 = 点了在坞里开一段新会话，这句是它的第一句；坞里那段同样有排队、调整方向。
- 实现走**做法一**：后端一个操作做完「中断 → 停 → 送进去 → 其余照排」，不由界面串三次请求。

## 2. 交互

```
agent 正在跑……（run_code：打印 1…100）

┌ 待发 · 2 ─────────────────────────────────────────────┐
│ 排队中  别打了，改成只打偶数      [调整方向] [到坞里问] [取回] │
│ 排队中  顺便画个图                [调整方向] [到坞里问] [取回] │
└──────────────────────────────────────────────────────┘
┌ 输入框 ──────────────────────────────────────────────┐
│ 回车排到这一轮后面 · Cmd/Ctrl+回车调整方向               │
└──────────────────────────────────────────────────────┘
```

点「调整方向」之后：

```
▸ run_code  已中断                  ← 打印到 37 的输出留着
你：别打了，改成只打偶数             ← 这句从待发条挪进转录
agent：好的，改成只打偶数……          ← 马上接着做
待发 · 1：顺便画个图（仍在排队）      ← 其余排着的不动，排到新这一轮后面
```

- **待发条每条三颗常驻按钮**：调整方向 / 到坞里问 / 取回（悬停才出现的等于不存在）。标签只剩「排队中」。
  「插队」按钮、「插队中」标签删掉。按钮文案互不为子串（设计契约扫描）。
- **键盘**：忙着时回车 = 排队；**Cmd/Ctrl+回车 = 直接调整方向**（不经待发条）。提示行照写这两个键。
  忙着且框里有字时发送键的无障碍名是「排到后面」（不变）。
- **调整方向**：
  - 当前这一步停下：`run_code` 给内核发中断；bash 等 pi 自带工具走 pi 的中止。已经吐出来的输出留着。
  - 这句作为一条用户发言进转录，agent 马上起新的一轮。
  - **其余排着的照排**，排到新这一轮后面——不退回输入框（与「停止」不同：停止是「不做了」，调整方向是「换个做法接着做」）。
  - 按下那一刻这一轮刚好自己跑完了：照常把这句当新的一句发出去，结果一样。
  - 那条已经不在单上（刚好被送走了）→ 说一句，不静默。
- **到坞里问**（只在主区的待发条上有；坞里那段自己的待发条**没有这颗**，它本来就在坞里）：
  - 这句从主区待发单上拿走（原文 + 原图），坞自动打开到「对话」格，在同一个地方另开一段（与坞格「另开一段」同一条路），
    这句就是它的第一句。主区不动。
  - 坞里本来挂着一段 → 新开的替换它；原来那段不丢（侧栏里、坞格「同处」清单里都在）。
  - 另开失败 → 这句**放回主区输入框**并出声，不丢。
- **停止**：行为不变（排着的撤回输入框），但**现在真的停内核**。

## 3. 哪些会话有

**只有 native。** 待发单本来就只有 native 有；acp / cli / 内核 / pty 行为不变。
远端会话的 native agent 一样有（`run_code` 在远端内核上时，中断走同一条内核通道）。

## 4. 分层

依赖决策（规格 §4）：坐在 pi-coding-agent 的 `AgentSession` 上——
① 用 `abort()`、`prompt(…)`、`prompt(…, { streamingBehavior: "followUp" })`、`clearQueue()`；
   pi 把中止信号作为工具 `execute` 的第三个参数传下来——已核对：`@earendil-works/pi-agent-core` `types.d.ts:367`
   `execute(toolCallId, params, signal?: AbortSignal, onUpdate?)`。
② 放弃：不再用 `streamingBehavior: "steer"`；不自己实现「只停一个工具、这一轮不停」（pi 没有这个口子，做法三已否）。
③ 不变式挂在：native 运行时一个方法 `redirect()` 里按顺序做完四步；`run_code` 的中止信号钩到内核中断。

### 4.1 修 bug：`run_code` 响应中止

`createRunCodeTool` 的 `execute` 收 `signal`；`signal` 触发且这段 cell 还没跑完 → 对**那台内核**发中断
（与笔记本「中断」按钮、协议 `interruptKernel` 同一条路），工具结果照实写「已中断」+ 已有输出。
这一条单独能测：跑 `sleep` 的 cell，中止，内核回到空闲、cell 标 interrupted。

### 4.2 运行时 `redirect(sessionId, 那句)`（`src/runtime/native.ts`）

1. 忙不忙：不忙 → 当普通一句发出去，结束。
2. `clearQueue()` 拿回 pi 单上所有待发（镜像同步清），把「那句」从中去掉（按 id；是 Cmd+回车来的就不在单上）。
3. `abort()`，等 pi 真的停下（中止信号 → 4.1 中断内核）。
4. `prompt(那句)` 起新的一轮；第 2 步留下的其余几条按原先后以 `followUp` 重排（镜像 id 不变，界面上那几条不闪）。

任何一步失败：那句与其余几条**都不许丢**——能重排的重排，重排不了的按 `withdrawn` 交回界面放回输入框，并出声。
与现有「先撤待发单、再中止」（`abort()` 的注释）同一个理由：中止与撤单之间 pi 可能把一条送进去又开一段。

### 4.3 协议（**8.0，破坏性**）

- `writeToSession.behavior`（原写作 `sendMessage`，协议里没有这个名字）：`"steer" | "followUp"` → `"followUp" | "redirect"`。`redirect` = 不经待发单，直接走 4.2。响应多可选 `withdrawn`（重排不上的那几句，界面放回输入框）；非 native 会话带 `redirect` → `invalid_request`。
- `editQueue.action`：`"remove" | "steer"` → `"remove" | "redirect"`；响应的 `withdrawn` 由一条改成数组（调整方向时交回的可能不止一条）。
- 待发单 `QueuedMessage.behavior` 只剩 `"followUp"`；`tool` 项加可选 `interrupted: true`（停止 / 调整方向时被停下的那一步，界面标「已中断」，笔记本那格标「（已中断）」）。
- 删掉 `steer` 是收窄请求取值，按 `version.ts` 的先例（433 行那条）升 major，不留一个没人调的值躲版本。
- **mock 同一次改动补上**（硬性准入规则 1）：`scripts/mock-inference-server.mjs` / e2e 夹具要能演「忙着 → redirect → 新一轮」。

### 4.4 界面

- `queued-strip.tsx`：三颗按钮；`onEdit` 的 action 改成 `"remove" | "redirect"`，另加 `onToDock?`（缺省 = 不画那颗，坞里那段就不给）。
- `views.tsx` 输入框：Cmd/Ctrl+回车 忙时发 `behavior: "redirect"`；提示行文案。
- `App.tsx`：主区的 `对话回调` 给 `onToDock`：`editQueue remove` 拿回原文原图 → 走坞格「另开一段」那条路（`另开到坞`）
  建好后把这句作为第一句发进新那段 → `打开坞里的对话`。坞里那段的 `对话回调` 不给 `onToDock`。
- i18n：新句进 `en.ts`（「调整方向」→ "Redirect"，「到坞里问」→ "Ask in dock"）。

### 4.5 写实现计划时补定的（2026-09-25，对着代码核过）

- **中断等不到**：`run_code` 发了中断、内核 10 秒还没回到空闲（卡在不理 SIGINT 的 C 扩展里）→ 先把工具结果交还 pi
  （这一轮必须停得下来），结果里如实写「发了中断，内核还没停下，它可能还在跑」。不无限等。
- **排着还没轮到的那段**（前面有你在笔记本里敲的一格在跑）被中止 → 马上交还，轮到它时也不写进内核（`对话内核.执行` 收 `signal`）。
- **「已中断」怎么标**：运行时在 `abort()` 期间（停止与调整方向都是）结束的工具一律带 `interrupted`——bash 与 `run_code` 同一个判据，
  不靠认结果文字。
- **还在准备的那条**（等图片转述 / 撞在「以为在跑」的缝里、还没交给 pi）点调整方向 → 说「这句还在准备，稍等」，不动它。
- **两次调整方向挨得太近** → 运行时里排成一个接一个做，后一次等前一次停稳。
- **非 native 会话**：界面只给 native 会话「调整方向」（`canRedirect`）；别的会话 Cmd/Ctrl+回车与回车一样是排队，提示行不提它。
- **mock（准入规则 1）**：假模型加「慢慢跑」分支——这一句带「慢慢跑」→ 先说「我先跑一段慢的。」再调 `sleep 20` 的 bash。
  `dev:mock` 里人按得到调整方向，e2e 也用它（不跟模型赛跑）。
- 运行时与会话管理里没人调的 `steer()` 一并删掉（与协议删 `steer` 同一个理由）。

## 5. 测试

- 单元：`run_code` 中止 → 内核中断（假内核通道记下 interrupt）；`redirect` 四步的顺序与失败不丢话；协议 8.0 的两个枚举。
- e2e（假模型 + 真内核那一档照现有 kernel 用例的写法）：
  1. 忙着时点待发条「调整方向」→ 转录里那步标已中断、那句出现、新的一轮开始、其余那条仍排队中。
  2. Cmd+回车 直接调整方向。
  3. 「到坞里问」→ 坞打开到「对话」、新会话第一句是那句、主区标题不变、主区待发单少一条。
  4. 停止时内核真的停了（跑 `sleep 30` 的 cell，停止后几秒内内核空闲）。
  5. 三颗按钮 `opacity === "1"`；坞里那段待发条没有「到坞里问」。
- 视觉基线：待发条出现在某张基线里的话，看 diff 后重存。

## 6. 不做

- 「只停一个工具、这一轮不停」（做法三）。
- acp / cli 会话的调整方向。
- 调整方向时让 agent「知道自己被打断了」的额外提示词——先看真机效果，不先猜。
