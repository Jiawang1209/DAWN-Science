# 右侧坞与文件面板（本地 / 远端 · 预览 · 传输 · 删除）

> 2026-08-17 · 分支 `feat/远端文件` · 状态：**设计已定，未实现**

## 为什么做这件事

作者 2026-08-17：*「我现在 ssh 到服务器上了，我想看看服务器上的图片能否搞一个
文件预览，上传和下载的功能。」* 以及：*「我觉得现在的文件窗口不好看，
应该学习一下 codex，放到右上角。」*

### 今天的实际状态（动手前量的，不是猜的）

| 事实 | 说明 |
|---|---|
| SFTP 的**壳**在，但**从没跑过** | `RemoteExecutor` 上有 `readFile` / `writeFile` / `readdir`，走真 SFTP 句柄——但**今天一个调用点都没有**（②-B 时写下，一直没人用） |
| 而且它与假 SSH **已经对不上** | 假 SSH 的 `readdir` 返回的 `attrs` 是个字面量对象，**没有 `isDirectory()`**；而 `RemoteExecutor.readdir` 正在调它。**这条路一跑就抛**——没人发现，因为没人跑过 |
| 文件面板完全不知道远端存在 | `listDirectory` / `readFile` 两个操作拿 `projectId` 查项目 `workspace`，用**本地 fs** 读 |
| 远端会话挂在隐藏的临时项目下 | 那个项目的 workspace 是**本机的 scratch 目录** |

**所以「传输这一层是现成的」这句话不成立**：现成的是形状，不是能跑的代码。
排期上要按「新写」算，不是按「接上去」算。

余下三条合起来是一个已经存在的 bug：**在一段远端会话里打开「文件」，
看到的是本机的一个临时目录**。它不报错，就是安静地给你看错东西——
而这正是这个项目最忌讳的那类失效。

预览那一半的功力都在：三态（图 / 文本 / 其它）、CSV 读成表、PDF 交给 Chromium、
路径守卫在 `files/access.ts`。**缺的是「这些字节从哪儿来」，不是「怎么显示」。**

而形态上的毛病同样具体：现在的「文件」是**占满整屏的一个视图**，
右上角一个「返回」。于是**看文件的时候对话没了**——
而看图的真实场景恰恰是「模型刚跑完，我想边看图边说下一步」。

---

## 一、右侧坞

学 Codex 桌面版：顶右角一个切换菜单，选中的那一块占住右边一栏，**与对话并排**。

坞里三个房客：**审阅 / 浏览器 / 文件**。

**本分支只做两个**：

| 房客 | 现在有什么 | 本轮 |
|---|---|---|
| **文件** | 预览三态、CSV、PDF、路径守卫 | ✅ 搬进坞 + 远端 + 传输 + 删除 |
| **审阅** | **已经有了**——「变更」pane（`panels.tsx`，不变式 5 的用户可见面） | ✅ 搬进坞（基本只是换位置） |
| **浏览器** | **一点都没有**（全项目 0 处 `webview` / `WebContentsView`） | ⬜ 单开一轮 |

**浏览器为什么单开**：它要决定用 `WebContentsView` 还是 `webview`、要不要给 agent 用、
cookie 与凭据怎么隔离。那是一整套自己的安全面，混进这一分支会把它拖成一次大改。

**底部终端不动。** 作者明确：*「不，我就要文件预览和上传，下载，不要终端。」*
终端 dock 已经在底部工作得好好的，把它挪进右侧坞是纯粹的搬迁风险，换不来任何东西。

### 侧栏那个「文件」入口怎么办

**改成打开坞，不再是一个全屏视图。** 留着两个入口指向同一个东西，
就是「两处长得一样的东西，等于没有判据」的又一例。

## 二、看哪台机器：**跟着会话走，不给切换器**

作者：*「我在本地的话，我查看的肯定就是本地文件夹的文件，
我要是登陆的服务器的话，那么看的就是服务器的文件。」*

**没有「本机 ｜ gs191」这种切换器。** 你已经用「开哪段会话」表达过这个选择了，
再让你选一次是多余的。

### 树根跟着入口走

| 从哪儿进来 | 树根 |
|---|---|
| 项目收纳 | 项目文件夹（`project.workspace`） |
| 会话收纳 | 那段会话自己的目录 |
| 服务器收纳 | 那台机器的**家目录** |

这条规则顺手否掉了「记住上次看哪儿」——**不需要记，入口本身就带着答案**。
少一份要存的状态，少一处会不一致的地方。

### 面板顶上必须写明是哪台机器

**这是硬要求，不是装饰。** 不写的话本地与远端在屏幕上长得一模一样,
而那正是今天那个 bug 的形状：它安静地给你看本机的目录，你根本没机会发现。

---

## 三、定位：**只做跳转，不做搜索**

一个路径输入框：输 `/data/liu/out` 回车就过去。远端认 `~` 与 `$HOME`。

**刻意不做文件名搜索**（作者选的甲）。理由是代价差一个数量级：

- **跳转**本质上是一次 `readdir`，本地远端都是**一次调用**。
- **搜索**在 SFTP 里**没有原语**。要么我们自己递归走目录（一个 `~` 底下几十万个文件的
  服务器会走到天荒地老），要么在服务器上跑 `find`——那是在别人的机器上起一个
  可能跑很久、很吃 IO 的进程。**能做，但要有上界，而且截断了必须说出来。**

等真的点累了再做，那时也会更清楚要搜的是「当前目录下的名字」还是「整台机器」——
这两个的做法完全不同。

## 四、传输

### 上传

系统「选文件」对话框 → 传到**树上当前这个目录**。

**不长第二棵树。** 上传天生是两头的事，而另一头永远交给系统对话框——
这与 composer 里那颗「上传文件」现在的做法是同一条路。两棵树的话，
「我现在看的是哪边」就得靠人一直盯着。

### 下载

树上选中 → 落到**设置里那个默认下载目录**。

设置里在「工作目录」那一块加一格「下载目录」，**默认值取 `app.getPath("downloads")`**。

> **不按平台写死路径。** `~/Downloads` 与 `%USERPROFILE%\Downloads` 是那类
> 会坏在别人机器上的东西（ACP 那条 `launch.ts` 刚栽过同一类）；
> 而且 `app.getPath` 跟得上用户改过的系统下载目录。

### 进度与取消

**两者都要，而且这里有个实现事实**：现在用的 SFTP `readFile` / `writeFile`
**没有进度回调**。要进度得换 `fastGet` / `fastPut`（`ssh2` 提供，带 `step` 回调）。

所以 `RemoteExecutor` 上**新增两个方法**，不是改现有的——
小文件预览继续走 `readFile`，正经传输走 fast 那一对。

### 取消之后那半个文件必须消失

**下载先落到临时文件，传完才改名到最终位置**（同一目录内改名是原子的）。

不这么做的话，取消或断线会在下载目录里留下一个半截文件——
**而它跟完整的那个长得一模一样**。哪天拿它去跑分析都不会发现。

### 同名冲突：三选一，且**没有两个是同义词**

| 选项 | 行为 |
|---|---|
| **覆盖** | 写掉旧的 |
| **另存一份** | 自动改名成 `fig1 (1).png`，两个都留着 |
| **取消** | 什么都不做 |

> 作者原话是「覆盖 / 替换 / 取消」。**「覆盖」与「替换」是同一个意思**，
> 摆在一起人会愣住想「这俩有啥区别」。设计契约里那条
> 「没有一个按钮文案是另一个的子串」就是为这类事立的
> （2026-08-12 一天被同名文案咬了三次）。

## 五、预览：**远端预览就是一次下载**

SFTP 得把字节拉过来才画得出图。所以远端预览与正经下载**共用同一套进度与取消**。

由此多一条：**超过某个大小先问一句**——
「这个文件 820 MB，要传过来看吗？」，而不是默默拉半天。
（本地预览的上界照旧走 `files/access.ts` 那一份，不另开一套。）

---

## 六、删除：**文件和目录都能删**

作者：*「本身删除动作也需要谨慎，这个是理所应当的。自己要为自己的数据负责。」*

### 本地删和远端删不是同一个操作

| | 按钮文案 | 确认框里说什么 |
|---|---|---|
| **本地** | **移到废纸篓** | 「可以从废纸篓找回来。」 |
| **远端** | **永久删除** | 「gs191 上没有废纸篓，删了找不回来。」 |

本地走 Electron 的 `shell.trashItem`（**可恢复**），远端只有 SFTP `unlink`（**没了就是没了**）。
同一颗按钮、同一个「删除」二字，一边可恢复一边不可恢复——
这次的代价是数据，所以**文案必须不同**。

`shell.trashItem` 跟现成的 `openPath` 走**同一条注入缝**（`main.ts` 传给 `wiring`），
不用新开一层。

### 不设「树根以下」的限制

设计过程中我提过这条限制，**当场收回了**：它与本设计另一条
「远端不糊假边界」自相矛盾。你就是那个账号本人，SFTP 已经能碰它能碰的一切，
再画一条我们自己的线是演戏。

**改成给信息，而不是给禁止。** 确认框把你需要为之负责的事实摆全：

- 哪台机器
- **完整绝对路径**（不是相对的 `out/`——那句话在两台机器上可以指两个地方）
- 目录的话：**多少个文件、多大**

### 数不完就如实说

远端遍历可能很慢。**给遍历一个上界与超时**，没数完就说
「**至少** 5,000 个文件（还没数完）」——**编一个数字比不给数字更坏**。

### 正在预览的文件被删掉

预览要**清空并说一句**。留着一张已经不存在的图，是这个项目最不能忍的
那种「看起来一切正常」。

## 七、账本：**改变世界的操作要记一条 Run**

DAWN 的立身之本是不变式 5——这个结果是怎么来的，账本上要查得到。

| 操作 | 记不记 | 为什么 |
|---|---|---|
| **上传** | ✅ `file_upload` | 它是对那台机器的一次写入，与 agent 改一个文件没有性质区别。不记的话账本上有个洞：**数据是什么时候、从哪儿进去的，只有你自己记得** |
| **删除** | ✅ `file_delete` | 同上，而且不可逆 |
| **下载** | ❌ | 只读，不改变任何东西 |
| **预览** | ❌ | 同上 |

Run 上带：目标机器、绝对路径、字节数、成败。**失败也记**——
「它试过往一个只读目录传东西」本身就是事实。

## 八、失败必须出声（规格 7.5）

这一片上容易静默的地方，逐条点名：

| 情形 | 必须说什么 |
|---|---|
| 目标目录没有写权限 | 「**权限不够**」，不是笼统的「上传失败」 |
| 连接断了 | 说清是连接断了，并且**半截文件已经清掉** |
| 远端目录读不了 | 说清是哪个路径、什么错 |
| 遍历没数完 | 「至少 N 个（还没数完）」 |
| 文件太大 | 先问，不默默拉 |
| 预览的文件被删了 | 清空预览并说一句 |

## 九、协议与分层

| 层 | 改动 |
|---|---|
| `src/remote/ssh.ts` | 新增 `fastGet` / `fastPut`（带 `step` 进度）、`unlink` / `rmdir`、`stat`；**并修掉 `readdir` 那处 `isDirectory()`** |
| `src/remote/fake-ssh.ts` | **同一次改动里补齐**（准入规则 1）：`isDirectory()`、`fastGet` / `fastPut`（要能报进度、要能被打断）、`unlink` / `rmdir`、`stat`、只读目录（验「权限不够」那条）、以及**目录与文件的区分**——现在的假 SFTP 只有一张扁平的 `路径 → 内容` 表 |
| `src/protocol/operations.ts` | `listDirectory` / `readFile` 要能指向一台机器；新增传输与删除操作；**版本 minor+**（纯新增） |
| `src/workbench/backend.ts` | 按「这段会话在哪台机器上」分流到本地 fs 或 `RemoteExecutor` |
| `src/ui/state/` | 坞的状态（开着没有、当前房客、宽度）。**不持久化「开着没有」**——它是一个窗口此刻的样子；**持久化「上次是哪个房客」与宽度** |
| `src/ui/files.tsx` | 搬进坞、加机器标识、路径框、传输与删除的动作 |

**新增协议操作必须在同一次改动里补 mock 分支**（准入规则 1）。

## 十、怎么验

| 判据 | 怎么做 |
|---|---|
| **`RemoteExecutor` 那三个方法真的能跑** | 它们至今零调用点，且与假 SSH 对不上。**第一条判据就是让它们跑起来** |
| 远端树真的是远端的 | e2e 走假 SSH 服务器（`fake-ssh.ts`，本轮要补齐），断言树上出现的是服务器那边造的文件 |
| **今天那个 bug 不再犯** | 一段远端会话打开文件面板，**不得**出现本机 scratch 目录的内容 |
| 机器标识 | 面板顶上那行必须写着机器名——**用 `getComputedStyle` 量可见性**，`toBeVisible()` 对 `opacity: 0` 仍算可见 |
| 取消不留半截文件 | 传到一半取消，断言下载目录里**没有**那个文件名 |
| 同名三选一 | 三个按钮的文案**没有一个是另一个的子串**（设计契约那条扫描） |
| 上传/删除进账本 | `readRuns` 断言有 `file_upload` / `file_delete`，且带路径与机器 |
| 删除文案本地远端不同 | 两种会话各点一次，断言确认框里的字不一样 |
| 权限不够说得对 | 假 SSH 造一个只读目录，断言屏幕上是「权限不够」 |

**每条新判据先证明它在修复前是红的**（变异测试）。

## 十一、不做什么（YAGNI）

- **重命名、新建目录**——那是往「文件管理器」滑的第一步。我们要的是
  「看结果 + 传文件 + 清干净」三件事。
- **文件名搜索**（见第三节）。
- **浏览器**房客（单开一轮）。
- **把终端搬进右侧坞**（作者明确不要）。
- **双栏对拖**（左本地右远端）——一棵树 + 系统对话框已经够，
  两棵树只会让「我在看哪边」变成一件要盯着的事。

---

## 十二、风险

1. **远端目录很大时的第一次 `readdir`**。几万个条目的目录会让面板卡住。
   要有上界与「省略了多少」的说明（不静默截断）。
2. **传输中连接断了**。半截文件的清理必须在断线路径上也走到，
   不能只在「用户点取消」那条路上。
3. **搬家的回归面**。文件面板从全屏视图变成坞里的一格，
   视觉基线会动——**红了先看 diff 图**，别条件反射重存。
4. **假 SSH 服务器覆盖不到的东西**。`fake-ssh.ts` 是我们自己写的，
   它的 SFTP 行为与真 OpenSSH 不完全一样。**至少要拿一台真机走一遍**
   （ACP 那一轮的教训：从没跑过真适配器时，纸上的形状全是假设。
   而那一轮真适配器一接就露了三个纸上验不出来的问题）。
5. **这一层的代码量被低估的风险**。开工前我说过「传输基本是现成的」，
   量完发现那三个方法从没跑过、且与假 SSH 对不上。
   **写下来的代码不等于跑过的代码**——这条在本项目已经是第三次了
   （419 个测试全绿却点不动、1647 个测试全绿而菜单没有底板）。
