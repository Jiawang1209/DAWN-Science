# 照着文献画图

**目标不是「描述这张图」，是让他手上的数据变成一张同类的图。**
描述只是中间步骤——它存在的唯一理由是拿去检索。

## 什么时候用

- 用户粘/拖了一张图（文献截图、别人的报告里的图），说「这种图我也想画」「帮我画一个类似的」
- 用户描述了一种图（「带误差棒和显著性标记的分组柱状图」）并问怎么画
- 已经有数据、卡在「用什么图、怎么画」这一步

## 什么时候不要用

- **`mlai-science` 那台 MCP 没配**——见下面第 0 步，那时要停下说清楚，不要凭印象写画图代码
- 用户要的是**读懂**这张图说明了什么（那是看图与解读，不是复现）
- 图型很简单且他已经说清了要什么（一条折线、一张散点）——直接画，别绕一圈检索

## 第 0 步：确认工具在不在

**先看 `mlai-science` 的工具在不在**（`recommend_figures` / `search_figures` / `get_case` / `list_taxonomy`）。

**你看到的名字带服务器前缀**：`mlai-science__recommend_figures`。前缀就是这台在设置里的名字——
本文按 `mlai-science` 写；他起了别的名字，前缀就是那个。

不在就**停下来说清楚**：

> 「这件事要 mlai-science 那台 MCP（你的案例库）。它现在没接上，
> 我可以凭经验给你写一段画图代码，但那和照着 1538 个跑过的案例做不是一回事。要我先凭经验写吗？」

**不许悄悄退化成「凭印象写一段」**——那正是这份技能存在理由的反面。

## ① 把图描述成检索得动的四行

案例库的向量建在**精修过的 caption** 上，而那些 caption 有固定的口吻：

> 「hCD45/CD4/CD8 三组各 G1–G4 均值柱+SEM 误差棒+原始散点，组顶标注 ANOVA/Kruskal P 与 Tukey/Dunn 两两显著性括号」

**你的描述越像这个口吻，命中率越高。** 所以按四行写，不要自由发挥：

```
图型：  分组柱状图
几何：  均值柱 + 误差棒（看着像 SEM）+ 叠加原始数据散点
标注：  组间显著性括号带星号；柱顶写数值
版式：  单面板，三组 × 四水平，图例在右
```

看不清的就写「看不清」——**别编**。「误差棒是 SD 还是 SEM」看不出来是常事，
写「看着像 SEM，图里没说明」比替他决定要好。

## ② 两个入口，通常两个都用

| 想要什么 | 用哪个 | 它给你什么 |
|---|---|---|
| **这种图怎么画** | `recommend_figures(goal_text=四行描述)` | 命中的案例 + `how_to`（到 API 粒度的做法） |
| **有没有长得像的** | `search_figures(query=四行描述, mode="semantic")` | caption 相近的图，一图一条 |

**先 `recommend_figures`**：它自己会把描述里的词对到图型上，并在
`figure_types: [{id, label, matched}]` 里告诉你**哪个词匹上了哪个图型**。

## ③ 两句必须说出口的话

**这两句不是客套，是判据。少说一句，你就是在把一份草稿当配方交付。**

### `figure_types` 是空的 → 这批结果不可信，要说

**判据是 `figure_types` 空不空，不是「有没有 notes」**——`notes` 两种情况下都有：

```json
成功： "figure_types": [{"id":"bar_chart","label":"柱状/条形图","matched":"分组柱状图"}],
       "notes": ["图型过滤：bar_chart, metric_comparison；候选图 12，案例 2"]

没匹上："figure_types": [],
       "notes": ["goal_text 未匹配到任何图型别名，按全部图型做混合检索"]
```

**混检也会回五条结果，看起来和成功一模一样。** 所以这时要：

1. 原样转述那句 `notes`；
2. 用 `list_taxonomy(dimension="figure_type")` 把受控词表拿回来，请用户挑一个（或你挑一个并说明理由），再搜一次。

### `how_to` 以 `<!-- mlai:notes=draft -->` 开头 → 它是自动摘要，不是配方

**库里 1538 个案例有 1077 个是 draft（七成）**，所以这是常态，不是例外。遇到时说：

> 「这条是自动生成的摘要（draft），我按它的思路写，不是照抄一份验证过的脚本。」

## ④ 在他的数据上画

拿 `get_case(case_id)` 取回 `pipeline.py`（或 `pipeline.R`）与 `notes.md`，然后：

- **改的是数据来源与列名，不是画法**——画法正是他要的那个东西；
- 用 `run_code` 在**他的数据**上跑，不要只把代码贴给他；
- 跑不通就说哪一步跑不通（缺包、列名对不上、分组数不同），**不要把报错吞掉换一种画法**；
- 出图落成产物（项目里 `outputs/figures/`），并说清楚这张图是照哪个 `case_id` 做的。

## 不要做的两件

- **不要 `get_asset` 去拉参照图。** 它回的是 base64 图片，几百 KB 直接进对话——
  这个工作台的整个视觉设计就是为了避免图片进上下文。
  用户想亲眼看参照图时，把 `case_id` 和图的相对路径给他，让他自己在 MLAI 的图廊里看。
- **不要替他决定统计检验。** 案例里用 Tukey 不等于他的数据该用 Tukey——
  照着画图可以，照着做统计要先问。

## R 的岔路

`recommend_figures` **挑不了语言**（没有 `language` 参数）。要 R 的案例：

```
search_cases(query="…", language=["r"])       # 案例级检索，能挑语言
```

或者拿到 case 之后看它带的是 `pipeline.R` 还是 `pipeline.py`。

## 库是空的怎么办

工具都在、但什么都搜不到时，**先怀疑语料库还没建**（`uv run mlai rebuild`），
再怀疑「库里真没有」。两者在屏幕上是同一句「没找到」，但
**没建库时 `figure_types` 往往也是空的**——两个都空，先去查库。
