# 视觉重做 · 材质与深度

> 分支 `visual-refresh`。2026-09-10 定案。
>
> **一句话**：颜色体系不动，补上缺的三样——**深度、排版跨度、动效**。
> 功能一行不改。

---

## 0. 为什么做

作者的原话是*「界面非常的简陋，没有那种高级的感觉」*。

这句话第一反应会被当成配色问题。**量完之后可以确定不是。**

我们的颜色体系是这个仓库里最讲究的一层：13 档中性灰（暗端刻意排密）、
文字层次 70/50/30（对齐 CDP 实测的 WorkBuddy）、描边由前景兑透明所以
一套百分比同时管亮暗、组件里裸色值 0 处且有扫描测试拦着。
作为对照，参考过的 PlotCase 有 **695 个互不相同的十六进制色值**、
**零个令牌层**、**`prefers-color-scheme` 出现 0 次**。

真正缺的东西量出来是这样：

| 量到的 | 说明 |
|---|---|
| `backdrop-filter` **0 处** | 毛玻璃完全没有 |
| `--dawn-shadow-sm` 被调用 **1 处** | 中间档等于没在用 |
| `--dawn-shadow-float` **10 处**，全给浮层 | 深度只发生在弹出来的东西上 |
| `box-shadow` **25 处** vs `border:` **62 处** | **界面靠描边分层，不靠深度** |
| 应用底 | 平色，无渐变 |
| `transition` **10 条**，全 `ease`/`ease-out` | 零自定义缓动曲线，零进场动画 |
| 字号 18 / 15 / 14 / 13 / 12 | 跨度 **1.5×**；用得最多的一档是 12px（116 处），另有 53 处写死的 11px |

**结论：面与面之间只有一根线。** 深度的语汇我们其实写得很好
（`--dawn-shadow-float` 那三层「单一顶部光源 + 负扩散」是对的），
**问题是它只用在浮层上，没用在日常的面上**。

## 2. 一条早就定好的规矩，不要重新发明

**暗色不能照搬亮色的阴影**——黑影压在黑底上等于没画。

**这件事 2026-08-23 已经做过了**，写在 `tokens.css` 暗色块里：

```css
--dawn-shadow-sm:
  inset 0 0 0 1px color-mix(in srgb, var(--theme-gray-0) 5%, transparent),
  0 1px 2px color-mix(in srgb, #000000 35%, transparent);
```

注释注明学自 WorkBuddy 的 `inset 0 0 0 1px #ffffff14`，理由是
*「亮描边模拟顶部受光的边缘，投影负责把面从背景里抬起来，缺一不可」*。
`design-contract.test.ts` 的 `ALLOWED` 白名单里 `--dawn-shadow-` 也早就在列，
配的注释是*「阴影 —— 暗色靠内嵌白发丝线，亮色靠投影，形状根本不同」*。

**所以这一轮不需要任何规矩变更。** 我们要做的是**把这个已经对的机制铺开到中间档**，
并补一件它还没有的事：**方向性顶边高光**。

现在暗色是一整圈 `inset 0 0 0 1px`（四边一样亮）。真实的顶部光源只照亮上边缘，
所以再加一道 `inset 0 1px 0`。这是 macOS 一直在做的事，也是「贵」和「有边框」的分界线。

## 3. 令牌改动（`src/ui/tokens.css`）

### 3.1 深度 · 五档

现有 `--dawn-shadow-float`（浮层，3 层）与 `--dawn-shadow-sm`（1 层）之间是空的。补两档。

**亮色**——单一顶部光源，`x=0`，负扩散随模糊增大（沿用 float 已确立的规则）：

| 令牌 | 值 | 谁用 |
|---|---|---|
| `--dawn-shadow-sm` | *（不动）* `0 1px 2px 黑6%` | 行、chip、小控件 |
| `--dawn-shadow-md` **新** | `0 1px 2px 黑6%, 0 6px 16px -4px 黑6%` | **代码块、工具卡、消息气泡** |
| `--dawn-shadow-lg` **新** | `0 2px 4px 黑5%, 0 10px 24px -6px 黑8%` | 输入卡、坞里的面 |
| `--dawn-shadow-float` | *（不动，3 层）* | 浮层、命令面板、菜单 |

#### 第五档：`--dawn-shadow-md-bordered`（2026-09-10 实现中作者定的）

**21 个内容面里有 16 个的描边是主题色，不是中性灰。** 那是作者 2026-08-23 定的：
*「卡片里面应该是白色背景，然后边框使用绿色的线」*——**不是随手写的一根线**。

把它们一起转成 `md`，等于用「浮起来」换掉「绿边」。作者看过亮暗三版对照后选的是
**两个都要**：绿线留着，卡片也浮起来。

那样做有个只有画出来才看得见的后果：**暗色下会出两圈**。`md` 在暗色里的一圈
是 `inset 0 0 0 1px`，它会画在绿边外面 1px 处，一圈绿一圈白。
**这正是第一轮那条扫描存在的理由。**

所以第五档 = `md` **去掉 `inset 0 0 0 1px`**：

| | 值 |
|---|---|
| 亮色 | **与 `md` 完全相同**（亮色的 md 本来就没有 inset） |
| 暗色 | `inset 0 1px 0 白7%, 0 8px 22px -6px 黑45%` —— 只剩顶边受光与落地 |

**亮色下两个令牌一模一样，为什么还要两个名字？** 两个理由：
① 暗色那一支需要一个地方安放差异；
② **让调用点自己说清楚「我这条 border 是故意的」**——
`--dawn-shadow-md` 配 border 是 bug，`--dawn-shadow-md-bordered` 配 border 是设计。
名字承担了这个区分，扫描才能只拦前者。

> **扫描的正则要跟着改，这一点不改就会自伤。**
> 原来是 `--dawn-shadow-(md|lg)\b`，而 `\b` 在 `--dawn-shadow-md-bordered` 的
> `md` 与 `-` 之间**也匹配**——新令牌会被自己的规则拦下。改成 `(md|lg)(?!-)`。
> **两半都要验**：旧违规仍被抓、新令牌被放行。只验一半等于悄悄开了个口子。

---

> **`lg` 必须留在 `float` 之下——这一版是实现后审查改过的。**
> 初稿写的是 `0 14px 32px -8px / 9%`，它比 float 的远层（`0 12px 28px -8px / 10%`）
> **还散**：浮层开在输入卡上面时，上面那层的阴影反而比下面那层大，
> **它就不再像"浮在上面"**。梯子搭反了不是口味问题。
> 四档现在两个维度都单调：
>
> ```
> blur   2  →  16  →  24  →  28        sm / md / lg / float
> alpha  6% →  6%  →  8%  →  10%
> ```

> **只新增两档，不加 `xs`。** 第一版这里排了个 `--dawn-shadow-xs: 0 1px 2px 黑5%`，
> 而 `sm` 是 `黑6%`——**差 1% 的两个令牌在屏幕上分不出来，等于没有判据**
> （CLAUDE.md 那条「两处长得一样的东西」）。`sm` 现在只被调用 1 处，
> 它本来就是空着的那一档，直接用它。

**暗色**——同名令牌，换机制。每一档都是「内描边勾形状 + 顶边高光 + 黑影落地」：

| 令牌 | 值 |
|---|---|
| `--dawn-shadow-md` | `inset 0 0 0 1px 白7.5%, inset 0 1px 0 白7%, 0 8px 22px -6px 黑45%` |
| `--dawn-shadow-lg` | `inset 0 0 0 1px 白9%, inset 0 1px 0 白8%, 0 10px 26px -6px 黑50%` |

暗色的「高一档」由**两件事**一起说：投影更小更淡，而**那圈内描边更亮**
（7.5% → 9%；float 那圈由 `--dawn-stroke-float` 承担，14%）。
**亮描边才是暗色里表达高度的主力**，投影只负责落地。

顶边高光只加在 md 与 lg 上——xs/sm 太小，加了会变成一条突兀的亮边。

> **`--dawn-stroke-float` 与新阴影不共存。** 暗色的 inset 已经是一圈描边，
> 元素本来那条 `border` 必须同时去掉，否则叠成两圈（这条 2026-08-23 已经踩过一次，
> 注释里写着「不再往阴影里塞 inset」）。**凡是换到 md/lg 的元素，一并去掉它的 `border`。**

### 3.2 毛玻璃 · 两档

`backdrop-filter` 现在 0 处。新增两个令牌，**只准用在这三种地方**：侧栏、右侧坞、浮层。

| 令牌 | 值 |
|---|---|
| `--dawn-blur-panel` | `blur(14px) saturate(150%)` |
| `--dawn-blur-overlay` | `blur(20px) saturate(180%)` |

配套的半透明面是**新开的一档 `--theme-surface-glass`**（仍在种子层）：

```
亮  rgba(255,255,255,.50)     暗  rgba(255,255,255,.028)
```

> **它不是把 `--theme-surface-sidebar` 改半透明改出来的**（初稿是那么写的，会闯祸）。
> 那个令牌**四条规则共用**：`.sidebar`、`.dock-content`、`.composer-footer`，
> 还有 **`.turn.user .bubble`——用户消息气泡，在对话区里**。
> 改共用的那个，气泡会跟着变半透明，**而这一节上面刚说过对话区里的面要用实色**。
> 一条测试都不会红，基线也只显示"变了"——**一个令牌担四个角色，就没有判据可言**。

**降级必须出声地不出声**：`@supports not (backdrop-filter: blur(1px))` 里
把这些面改回不透明的实色。不做模糊时半透明会漏出乱七八糟的东西。

**那个块写在 `tokens.css`，不是 `styles.css`**（实现时改的）：它重新定义的是
**种子层令牌**，而种子只有一个家。放进 `styles.css` 就等于这个值有两处定义，
将来 grep `tokens.css` 的人会看到半透明那一版，不知道另一个文件里有块在覆盖它——
`--dawn-code-size` 那次就是这样（量表里记着 13px，界面上一直是 12px）。
于是分工是：**模糊用在 `styles.css`，降级归 `tokens.css`**，守它的那条扫描各查一边。

### 3.3 应用底 · 极淡渐变

```
亮  linear-gradient(158deg, gray-50, #e7ebf3)
暗  linear-gradient(158deg, gray-900, gray-1000)
```

仍然只改种子层的 `--theme-surface-app`，派生链不动。

### 3.4 字号 · 跨度 1.5× → 2.2×

现在四档（18 / 14 / 13 / 12）加两个游离的 15（chat）、13（code）。新增两档：

| 令牌 | 值 | 谁用 |
|---|---|---|
| `--dawn-fs-display` **新** | `22px` / `letter-spacing: -.021em` | **会话标题**（当前没有标题，这一屏要新长出来） |
| `--dawn-fs-title` | 18px | *（不动）* |
| `--dawn-chat-size` | 15px | *（不动）* |
| `--dawn-fs-sub` | 14px | *（不动）* |
| `--dawn-ui-size` | 13px | *（不动）* |
| `--dawn-fs-meta` | 12px | *（不动）* |
| `--dawn-fs-badge` **新** | `11px` | 徽章与胶囊 |
| `--dawn-fs-label` **新** | `10px` / `.12em` / `uppercase` / **常规字重** | 分组标签（「会话」「服务器」「扩展」） |

> **这一档不加粗——原本写的是 `600`，实现时看图改掉的。**
> 5 倍放大对比之下，`10px + semibold` 的中文**比原来 11px 常规的还糊**：
> 加粗在这个字号上把字腔填死了，「展」字内部的笔画糊成一团。
> 拉丁字母的小字需要加粗撑住形状，**中文不需要，而且会反效果**——这个产品是中文优先的。
>
> 去掉之后它仍然一眼是标签：**小（10 对正文 13）、灰（text-3 对 text-1）、宽（.12em）**，
> 三个信号够了。这也正是当初写下「**别为中文单独加粗，那会让标签抢它介绍的正文**」那句话的意思——
> 只是规格自己的定义里带着 `600`，等于一边说别加粗一边把加粗写进了定义。

**`badge` 不是新角色，是一个一直没有名字的旧角色。** 2026-08-23 立四档时的注释
写着*「11px 只给徽章与胶囊」*——那句话是对的，但没给它令牌，于是它在
`styles.css` 里被写死了 **53 次**，连既有的字号扫描都得为它开一个
`(11|10|9)px` 的口子。**给它名字，就是为了关掉那个口子**（见 §7）。

### 3.5 动效 · 一条曲线，三个时长

现在 10 条 `transition` 全是 `ease`，没有个性。

```
--dawn-ease:      cubic-bezier(.22, 1, .36, 1)    /* 快出慢入 */
--dawn-dur-fast:  120ms   控件三态（沿用现值，不动）
--dawn-dur-base:  180ms   面的显隐、坞的开合
--dawn-dur-slow:  260ms   进场
```

**DESIGN.md「动效」那一节的三条约束继续有效且优先**：功能性过渡约 100ms、
动效跟随状态永不延迟状态、热交互上不 `transition-all` 动布局几何。
新曲线只用在**非热路径**上——浮层进场、坞开合、消息进场。

新增一条进场动画：新消息 `opacity 0→1` + `translateY(4px→0)`，`--dawn-dur-slow`。
**必须尊重 `prefers-reduced-motion`**（这是 DESIGN.md 已有的硬规矩）。

## 4. 分三轮，每轮独立可验、可合并

一次改完等于 `styles.css` 6667 行同时动，红了无法定位。

| 轮 | 动什么 | 判据 |
|---|---|---|
| **① 令牌层** | 只改 `tokens.css`：新增 md/lg/xs、blur、display/label、ease/dur。**不动任何调用点** | `npm test` 全绿。视觉基线**几乎不动**（新令牌还没人用）——如果动了说明改错了 |
| **② 面的归位** | `styles.css`：62 处 `border:` 里**围出内容面的那些**换成 `--dawn-shadow-md/lg` 并删掉那条 border（判据见下）；侧栏/坞/浮层上毛玻璃 + `@supports` 降级；应用底渐变 | `npm test` 全绿、e2e 非视觉全绿。**视觉基线 10 张全红是预期的** |
| **③ 排版与动效** | 会话标题（新长出来的一屏元素）、10px label 铺开、53 处 11px 收编、缓动曲线与进场动画、新增那条 font-size 扫描 | 同上 + 新扫描测试绿 |

每一轮结束都要过 **CLAUDE.md 第 3 条**：改了主路径必须自己验一次（`npm run dev:mock` 或 e2e），
**「测试绿了」不等于「能用了」**。

### 哪些 `border` 该变成 elevation

62 处不是全都要改。**判据是那条线围出来的是什么：**

| 改 | 不改 |
|---|---|
| **内容面**——代码块、工具卡、消息气泡、坞里的面板、输入卡 | **分隔线**——`border-top` / `border-bottom` 单边的，那是尺，不是面 |
| 这些东西的语义是「一块浮起来的内容」 | **表单控件**——`.control` 的描边是可点击的信号，去掉就没有交互暗示了（DESIGN.md §表单控件一律走 `.control`） |
| | **表格线、树的缩进导线** |

一条 `border` 四边俱全 **且** 里面装的是内容（不是可输入的控件）→ 改。其余不动。

## 5. 边界：什么不动

| 不动 | 为什么 |
|---|---|
| `src/protocol/`、`src/main/` | 这是视觉改动，碰到就是越界 |
| `src/ui/state/` | 界面状态与持久化 |
| 任何 `run_code` / 内核 / 远端 / 会话逻辑 | 同上 |
| 颜色体系本身：13 档灰阶、70/50/30、描边兑透明 | **它是对的**，这一轮不重开 |
| 主题色系统（`state/accent.ts` 一键换色） | 阴影是中性的黑/白兑透明，与主题色无关，天然不冲突 |
| `.dawn-dark` 只覆盖种子的规矩 | 阴影早在白名单里，无需破例 |
| 信息架构（页面 / 路由浮层 / 工作面 三类） | DESIGN.md §信息架构，这一轮不碰 |

**判据不是我说了算**：

```
npm test                    全绿          ← 功能没动的证据
npm run test:e2e            非视觉全绿     ← 交互没动的证据
npm run test:e2e:visual     ②③ 轮全红     ← 视觉动了的证据（这个红是对的）
```

`npm test` 只要红一条，就说明越界了，不是「顺手优化了一下」。

## 6. 视觉基线的处理

②③ 两轮会让 `e2e/__screenshots__/` 那 10 张全红。**这是预期的，但不能条件反射地 update**（CLAUDE.md 有明文纪律）：

1. 先看 `test-results/<用例>/<名字>-diff.png`，**确认红的是我们想改的地方**
2. 用 `npm run test:e2e:visual:update`（已带 `=all`，别手敲不带的那句）
3. **重存之后必须再验一遍。** 若某张重存完仍稳定红，
   把验证那一轮的 `-actual.png`（**稳定化之后**的帧）拷成基线，再验两遍

毛玻璃这一轮有个新风险：**`backdrop-filter` 的合成结果可能逐帧抖动**。
如果某张基线因此永远稳不下来，处理方式是**给那个元素 `mask`**，
不是调阈值——阈值是 0，那个 0 是试出来的，理由写在 `e2e/visual.spec.ts` 里。

## 7. 新增的可判定规则（CLAUDE.md 第 2 条要求）

在 `tests/ui/design-contract.test.ts` 同一次改动里加：

1. **收紧既有的字号扫描**（**不是新增一条**）—— 那条 `it("文字字号只有四档…")` 从
   2026-08-23 就在了，它只是开着 `(11|10|9)px` 的口子，
   因为 **11px 是个真实角色却一直没有名字**。§3.4 给了它 `--dawn-fs-badge`，
   收编 53 处调用点之后，口子就能关上。图表刻度与欢迎页那颗「D」字形保留豁免——**它们不是文字**。
2. **用了 `--dawn-shadow-md/lg` 的规则里不许再有 `border:`** —— 暗色 inset 与 border 会叠成两圈（§3.1）
3. **`backdrop-filter` 必须有配套的 `@supports not` 降级块** —— 不做模糊时半透明会漏（§3.2）

第 2、3 条是这一轮**新踩出来的坑的自动化形式**，不是抄来的规则。
