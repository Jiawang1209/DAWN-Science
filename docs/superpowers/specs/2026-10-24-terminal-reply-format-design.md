# DAWN 终端回复呈现设计

状态：待用户确认；尚未修改产品代码。分支：`codex/terminal-reply-format`，基线为本地 main `367d2f61`。

## 目标和范围

改进现有 DAWN 模式的回复可读性：正文 Markdown、生成进度、工具执行摘要和留白。继续只有一个终端输入；保留真实 Shell、已有模型/密钥、权限确认、图片缩略图、原图续问和返回同段会话。

本轮不重做整个终端编辑器，也不改模型提示词去伪造“更像某个 CLI”的回答。新格式先留在功能分支，完成后打开真实 Electron 预览；不推送、不替换安装版。

## 三种路线

1. **推荐：重做输出呈现，保留当前输入。** 复用项目已有终端 Markdown 渲染能力，改造 Agent 输出事件的显示，范围集中、可以单独验收。
2. **只给现有原始日志着色。** 改动最小，但依然要读原始 Markdown，不能解决正文和工具混杂的问题。
3. **完整 TUI 与编辑器重做。** 可以扩展多行编辑、菜单和快捷键，但涉及输入、滚动、图片与屏幕生命周期，单独立项更合适。

## 推荐的呈现

- 启动信息收为简短的产品名、模型、目录与帮助提示，避免占据大量空行。
- Agent 正文有明确的段落起点；标题、强调、列表、引用、代码和表格按终端列宽排版，长路径和中文不能挤出窗口。
- 按完整 Markdown 段落持续输出；尚未完成的段落用底部一行显示正在生成的片段，完成后正式排版。代码块和表格闭合后统一排版，避免未完成语法反复改写历史行。不是等整轮结束才出现所有内容。
- 工具启动显示工具名和关键操作；结束显示成功/失败及少量结果摘要。省略明确计数；有完整输出路径则显示路径，其余过程可通过“返回会话”继续查看。
- 异常、权限确认和提问保持明确，不能被折叠成普通进度；不把失败显示成成功。
- 图片继续使用现有缩略图与点击放大；图片输出前提交当前正文，避免重绘清掉图片占位。

## 实现边界与验收

正文与工具输出在渲染前仍按不可信数据清除终端控制指令；渲染器只生成受控的样式。单行进度仅更新自己的当前行，不清空已有历史，不切入另一套全屏界面。非交互管道不输出动态进度或颜色控制序列；`NO_COLOR` 不输出颜色。

验证包括宽窄窗口、中文/长路径、代码/表格、流式段落、长回复、工具成功/失败/省略、取消/继续提问、权限问答、图片和返回会话；使用真实 PTY 与 Electron 验证，固定模型用例与真实模型体验分开记录。
