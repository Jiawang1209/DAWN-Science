# 定时任务整轮结束判据修复

用户已授权按全仓审查的第一项问题独立开分支修复、验证并合并本地 main，再另开分支处理下一项。本切片只修定时运行结算，不改变计划规则、协议或界面设计。

当前后端把 agent 文本的 final 当作任务终态；native 每次模型迭代都产生 turn_end，因此工具链还未完成就可能记成功。采用事件中枢已有的 on回合收尾（runtime idle）作为唯一正常结算信号。相比扫描文本或轮询运行时，这条入口已有真实生命周期与本轮失败信息，且与桌面通知一致。

- 中间发言收口后运行仍 running，占用容量与同一定义的重叠位置。
- 整轮结束有失败原因时记 failed/agent_error，保留真实原因；否则记 succeeded，摘要取最后一条 agent 发言。没有文字时省略摘要，不据此伪造失败。
- 退出、取消、超时、写入失败保留既有终态。结算时清理状态/整轮结束订阅、计时与 abort 监听；迟到事件不能改写终态。
- 取消/超时先认领终态，再请求运行时中止，避免同步 idle 抢先记成功；已取消的任务不再发送提示。
- 不增加工具成功即科学验收的承诺。succeeded 只代表模型请求完整结束且没有该轮终止失败。

验收：真实后端+SQLite 的确定性事件回归先红后绿；真实构建 Electron 验证多轮工具链期间持续运行，最终回复和后续失败分别正确结算；再做类型、全量单测、完整构建、相关 Electron 回归。仅本地合并，不推送、不替换已安装应用。
