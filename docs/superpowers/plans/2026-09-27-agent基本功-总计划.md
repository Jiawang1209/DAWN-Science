> 分支 `agent-basics`（2026-09-27 自 main `862ab53` 开出）。本文件只管**顺序、共同纪律与收口**；
> 每件事的做法在各自的 spec + plan 里，执行时按那一份逐个 Task 打勾。

**缘起**：2026-09-27 与作者对照 Codex app / Claude app 盘点差距。结论是：
DAWN 领先的是「活的内核」那条线（笔记本、远端内核、产物与账本、案例库），**不去追它们的广度**；
落后的是**长时间干活时的基本功**——几项顶尖 app 都已是标配、我们要么没有、要么有却看不见。
作者原话：「把刚才我们讨论的，我们都要做了。」

## 共同纪律（七份 plan 都适用，冲突时以本节为准）

1. **一件事做完、全套验证过，才开下一件。** 不交叉推进——七份计划各自会动 `src/ui/views.tsx`、
   `src/ui/App.tsx`、`src/protocol/*`、`scripts/mock-inference-server.mjs`，交叉推进就是互相踩。
2. **协议版本号**：每份 plan 写的是「执行时的下一个次版本」。按上表顺序执行，
   每件事在 `src/protocol/version.ts` 的历史里各占一段；**不要预先占号**。
3. **每件事收口时**：`npm test`、`npm run typecheck`、`npm run test:e2e`（全套，不是只跑新 spec——
   改共用判定必须跑全套，09-15 的教训）全绿；视觉基线红了**先看 diff 图**再决定（CLAUDE.md 那条纪律）。
4. **每件事自己跑一次真链路**（`npm run dev:mock` 人肉看）——「测试绿了」不等于「能用了」。
   驱动 Electron 演练时**隐藏窗口**。
5. **每件事一条 `docs/DEVELOPMENT_HISTORY.md` 记录**（各 plan 的最后一个 Task）；
   `CLAUDE.md` 文档入口表同批加一行。
6. commit 信息写英文，**不加任何 Co-Authored-By 行**；**只 commit 不 push**。
7. 每份 spec 顶部有「需要作者定的」——**执行按推荐默认值走**，但开工前先把那一节念给作者听；
   作者改了主意，先改 spec 再改 plan，然后才动代码。
8. 读到的行号是 `862ab53` 上的；前一件事做完后会漂，按引文里的代码找，不按行号找。

## 七份之间的交叉点（写完七份后对过一遍）

- **恢复历史那一段是三家共用的**：「会话全文搜索」（点结果跳到老轮次）、「子 agent 看得见」（重载后芯片回来）、
  「上下文用量与压缩」（压缩前的轮次重开后消失）都要动恢复历史的同一段代码（`待补结果` 那一段）。
  按顺序做不会踩；**后做的那份开工前先重读这段的现状**，别照计划里的引文硬贴。
- **压缩是现存的静默 bug，不只是新功能**：pi 0.86 的自动压缩默认开着（`settings-manager.js`
  `compaction?.enabled ?? true`），而 `native.ts` 的 `translate()` 对压缩事件一声不吭。
  「上下文用量与压缩」的第一步就是让它出声。
- **回退 × 压缩**：回退依赖轮次边界；压缩把早先轮次折成摘要后，回退到压缩线之前的轮次必须明说做不到，不许静默失败。
  压缩先做，回退后做——**回退那份负责补这条判据**（开工时在它的 plan 里加一条用例）。
- **回退 × 先出方案**：批准的方案文件不在回退的「agent 改过的文件」里被误删——先出方案那份负责加一条用例。
- **桌面通知 × 子 agent**：子 agent 的过程更新**不许进** hub 的 `全听`（否则每个子 agent 都会触发飞书/微信/桌面「跑完了」）；
  两份都写了这条，以「子 agent 看得见」里的判据为准。
