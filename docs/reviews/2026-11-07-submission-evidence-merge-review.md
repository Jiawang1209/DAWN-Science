本轮按用户明确授权，对上一轮未提交的正式提交反馈、工具证据摘要、版本预览和轻量评测进行复审；发现问题就修复补测，确认没有阻塞问题后本地提交并合并 main。禁止推送、发布、替换正式 App。本轮没有新增真实模型调用；上轮真实对照的 18 次请求和 0 个完整配对结论保持不变。

## 已修复的具体遗漏

1. **终态反馈仍鼓励重试。** 已取消、已正式提交、核验中和工具未排空的调用曾共用“可修正后再次提交”的提示。反馈现在区分 correctable / draining / validating / cancelled / sealed，明确 retryable，sealed 回传既定状态；宿主冻结、取消和验收判断没有放宽。
2. **被拒调用复用旧 ID 的证据冲突。** 托管 Bot 先真实读取，再用同一 ID 调用越界读取时，错误标签没有进入冻结证据列表，提交仍可能引用上次成功证据。被拒调用现在保留 error/not_observed 元数据并撤销该 ID 的旧执行观察；已经 sealed 后不再修改证据。正式验收进一步要求每个引用 ID 恰好对应一条实际记录，重复成功 ID 同样不能作为唯一证明。
3. **失败与取消丢失已有诊断。** 子任务缺少正式提交、模型失败、父侧取消曾只保留错误/用量，丢失已知工具摘要。失败协议携带有界 trace，子进程执行器、Team 适配器和统一编排逐层保留。强制停止排空期间只接受诊断 done，不再处理 RPC、纠偏或过程事件；丢弃迟到正文、回执和版本，不把诊断当科学验收。
4. **取消摘要必须绑定当前结果代次。** 统一编排以 resultEpoch 标识已结算结果。排队或未附新结果的取消会清除“当前结果”绑定，保留历史结果原文；冷读取仍只读。活动任务 A1 完成、另一成员 B 占位、A2 排队后取消的场景，不再把 A1 摘要显示为 A2 的取消诊断。重启 interrupted 继续隐藏无法证明属于本轮的旧摘要。
5. **报告相对图片和脚本链接失效。** 当前文件预览重新接入已有 FilePreview 的工作区读取上下文，稳定绑定 owner 和异步选择代次；图片经守卫读取，脚本链接只预览、不执行。历史副本仍不回退读取当前工作区引用。读取中或失败时也可收起预览，迟到结果不会重新打开，焦点回到原产物行。

上述问题均有先失败再通过的回归日志，保存在 [本轮证据目录](../validation/submission-rereview-20261107/)。两个独立审查分别覆盖运行/持久化与 UI 隔离/预览；复核曾额外发现“停止后已在缓冲区的 done 被丢弃”和“同一个子成员的排队取消保留上次绑定”，均已补测试后修复。最终独立复核没有发现剩余阻塞问题；这不等于保证所有环境无缺陷。
