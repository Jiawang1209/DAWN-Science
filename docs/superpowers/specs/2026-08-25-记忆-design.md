## 定位

DAWN 今天没有跨会话记忆:会话历史是原始记录、账本是事实层、AGENTS.md 靠人写。
本格补「学到了什么」这一层:**账本答"发生过什么"(观察),记忆答"我们学到了什么"(经确认的结论)。**
与不变式 4(长驻 agent 的会话内投影)是相邻的两个问题——这里只做跨会话,投影另议。

## 一、轨道:五轨裁成三轨,全部确认制

| 轨 | 落位 | 作用域 |
|---|---|---|
| 用户档案 user | `~/DAWN/memories/USER.md` | 全局 |
| 全局事实 memory | `~/DAWN/memories/MEMORY.md` | 全局 |
| 项目关键记忆 key | `<工作区>/.dawn/memory/KEY.md` | 项目;条目可标 `[branch:]` 只在对应 git 分支注入 |

比 dsh 更保守的一刀:**三轨统一确认制**——模型只能提议,用户采纳才落盘
(dsh 主会话能直写全局轨,我们不留这个口子)。界面直写 = 人即确认者。
日志轨(daily/project)v1 不做:它依赖模型每轮自觉(dsh 自认的局限),且账本已在观察层记事实。

KEY 进工作区的代价要在界面写明:进仓库就对协作者可见;私人向记录引导放全局轨。

## 二、存储格式(照抄 dsh 验证过的部分)

- `\n§\n` 分隔条目;头文法(程序维护,顺序固定):`[id:8hex]?` → `[YYYY-MM-DD]` →
  `[branch:a,b]?` → 正文。**`[id:]` v1 只留格式位不生成**(为将来合并留锚,解析要认识它)。
- **程序盖戳**:时间戳、分支标记写入时由程序实时取(`git branch --show-current`,1s 超时,
  失败不标注);模型手写的日期/分支前缀剥掉重盖——声明 vs 观察,与不变式 5 同一条神经。
- **三件安全带**(文件就是给人直接编辑的):
  1. **drift guard**:全文件重写(改/删)前验磁盘内容 round-trip 过解析器,不过 →
     备份 `.bak.<ts>` 并响亮拒绝;append 免检但拒绝「文件存在却读空」。
  2. **目录锁**:锁文件带 pid,先探存活(`kill(pid,0)`)再看 mtime 超时;进程内可重入。
  3. **写入威胁扫描**:「忽略之前的指令」类提示注入正则,拦下说明白。
- 归档:`*-archive.md` 同格式冷存储,不注入,可转正;先归档后删除,宁重复不丢失。

## 三、注入(依赖决策:坐哪一层)

- **坐 pi `DefaultResourceLoader` 的构造参数 `appendSystemPrompt` 这一层**(`native.ts`
  装配 resourceLoader 处):建会话时渲染快照拼进系统提示词。放弃了:改 pi 内部、
  会话中途热注入(dsh 靠宿主的变更检测注入,pi 没有这条缝,不发明)。
- 快照内容:用户档案 + 全局事实 + 本项目 KEY(按当前 git 分支过滤:无标记 = 全部分支;
  有分支时把分支名一并注入,模型知道自己在哪条分支)+ **固定文本**的提议职责
  (出现长期有效的重要事实 → `memory_propose`;不要自己写时间戳)。
- **确认的记忆下一段会话生效**——与「插件开关下一段会话生效」同一条已有契约,界面写明。
- v1 **只注入主会话**;子 agent 与团队成员不注入(保守起步,注入面越大污染面越大)。

## 四、工具面(插件册第三张卡「记忆」,走 `包成pi工具`)

| 族 | 工具 | 干什么 |
|---|---|---|
| propose | `memory_propose` | 提议一条(target 三轨之一 + content + 可选 branches)→ 建议队列,回执写明「等用户确认,采纳后下一段会话生效」 |
| read | `memory_list` | 查存量(filter / recent / limit;key 可按分支过滤) |
| skill | `skill_propose` | AI 写完整 SKILL.md(frontmatter 校验、kebab-case 名、体积上限)→ `~/DAWN/memories/pending-skills/<名>/` 待确认;与技能库重名拒 |

走插件册自动获得整包/分族开关(`plugin.memory.*`)与设置插件卡,零新机制。
建议队列 `~/DAWN/memories/SUGGESTIONS.jsonl`:同轨同内容(空白归一)去重记 hits——
反复浮现的事实攒频次,确认时有权重可看。

## 五、确认界面:设置「记忆」屏

- **待确认区**:记忆建议 + 待装技能混排;每条 [采纳][归档][拒绝];记忆建议采纳时可改文案、
  可改轨(技能不能变记忆);hits 显示。技能批准 = 目录移入 `~/DAWN/skills`(接现有技能管理
  三档),拒绝 = 删。
- **三轨浏览区**:增删改(改只动正文,头元数据程序保)、归档/转正、key 按项目切
  (取当前会话工作区;没有活跃项目时 key 区如实说明)。
- **角标**:侧栏设置入口 + 记忆屏行带待确认数(看不见的能力等于不存在)。
- 协议操作(workbench,真后端服务,同 `listPlugins` 先例不需要 mock 分支):
  `memoryOverview`(角标数 + 三轨概要)、`memorySuggestions`(队列)、
  `memoryResolve`(采纳/归档/拒绝,采纳可带 content/target 覆盖)、
  `memoryEntries`(单轨读)、`memoryWrite`(界面直写/改/删/归档/转正)。

## 六、判据(三条准入规则逐条对)

| 规则 | 怎么满足 |
|---|---|
| 新协议操作补 mock | 模型协议:假模型点名调 `memory_propose` / `skill_propose` 的分支进 `mock-inference-server`(与 e2e 共用);workbench 操作由真后端服务(同 `listPlugins`) |
| 可判定规则进扫描 | 新按钮文案自动落进子串扫描(中英两侧) |
| 主路径自己验 | 单测:round-trip / drift guard / 锁 / 盖戳剥重 / 分支过滤 / 队列去重计 hits / SKILL.md 校验;e2e:提议 → 角标 → 采纳 → **新开会话的系统提示词里真有那条**(问会话状态,不靠屏幕);技能批准后出现在技能屏 |

## 七、不做什么

- 日志轨(daily/project)、审查节奏器、`memory_suggest` 独立工具(propose 即建议)。
- dsh 式 git 同步(KEY 进 git 已覆盖)、条目身份证生成(格式位保留)。
- advisor 影子评审、`[dsh-only]` 标记、渐进式披露(`[summary:]`)——记忆多了再说。
- 会话中途热注入;模型侧 replace/remove(改删走界面)。
- COI/广播/画板/待办等 dsh 顺风车模块——DAWN 各有自己的路。
