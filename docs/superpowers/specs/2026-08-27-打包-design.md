# 打包：macOS / Linux / Windows 三平台独立安装包

> 分支 `packaging`。作者 2026-08-27 的要求：**「给一个新电脑上搞，打包成独立软件」**——三个系统各出一个能在干净机器上直接装、不要求先装 Node 的安装包。
> 学自 Hermes `apps/desktop/`（electron-builder + asarUnpack + notarize 三件套，`stage-native-deps.mjs` 那份「spawn-helper 被过滤掉就静默崩」的教训）。读设计不复用代码。

## 0. 定下的

| 问 | 定 |
|---|---|
| 工具 | **electron-builder 26**（Hermes 同款；forge 的原生模块处理要自己写更多） |
| 产物 | mac：`dmg` + `zip`（arm64、x64 各一）；win：`nsis` 安装器 + `portable`；linux：`AppImage` + `deb` |
| asar | **v1 关掉（`asar: false`）**。理由见 §2；日后要开再按 Hermes 的 `asarUnpack` 清单开 |
| 签名 | **v1 不签**：没有 Apple Developer ID / Windows 证书。安装文档写清怎么过 Gatekeeper / SmartScreen；有了证书只需填两个环境变量 |
| 在哪打 | **各平台在各自的机器上打**（`npm ci && npm run dist`）。跨平台交叉打包不承诺：原生模块的预编译件是按安装时的平台拉的（本机 node-pty 就没有 linux 的） |
| 数据目录 | 打包后 `userData` 从 `Electron/` 变成 `DAWN Science/`。**首次启动一次性迁移**作者机器上的旧数据（§4） |
| 图标 | 先用脚本生成一个占位（深色圆底白「D」），作者有正式图标再换 `build/icon.png` |

## 1. 今天的实际状态（核过的）

- `npm run app` = esbuild 把 `src/electron/main.ts`、`subagent/child.ts`、`preload.ts` 打成 `dist/electron/*`，vite 出 `dist/ui/`，`skills/`、`agents/`、`scripts/dawn-mcp-server.mjs` 拷进 dist；然后 `electron dist/electron/main.js`。**从来没有打过安装包**，仓库里没有 electron-builder、没有图标、没有 CI（也没有 git remote）。
- 原生模块四个，全是 N-API 预编译、**按平台目录自选**：`better-sqlite3`（`prebuilds/<platform>.node`，八个平台齐）、`node-pty`（`prebuilds/<platform>/`，本机只有 darwin + win32）、`zeromq`（`build/<os>/<arch>/…/addon.node`，三平台齐）、`ssh2` 的 `cpu-features`（可选，没有就走纯 JS）。
- 子进程全走 `process.execPath` + `ELECTRON_RUN_AS_NODE=1`（Spike F 定的）：子 agent（`dist/electron/subagent-child.js`）、ACP 适配器、`dawn-mcp-server.mjs`。**打包后它们从磁盘按路径读文件**——pi 读 skills 目录、MCP server 被 spawn、`import.meta.dirname` 算相对路径。
- `import.meta.dirname` 在 `main.ts` 里算 `../ui/index.html`、`../skills`、`../agents`、`preload.cjs`、`subagent-child.js`、`dawn-mcp-server.mjs`——**都在 `dist/` 同级**，打包只要把 `dist/**`、`skills/**`、`agents/**` 带上、目录结构不变即可。
- 运行时外部依赖（**装完软件之后仍然要用户自己装的**）：Python + `ipykernel`（笔记本/`run_code`）、R + IRkernel（可选）、git（项目 git 事实）、ssh（远端会话，只要 `ssh2`，不要求本机 ssh 命令）、Node.js（**只有** ACP 适配器 `npx claude-code-acp` 那条要）、Chrome（浏览器插件走 CDP 接真浏览器）。**软件本身不要 Node**。

## 2. 为什么 v1 不用 asar

asar 是个只有 Electron 自己 fs 钩子认得的归档。我们有三类东西必须在**真实磁盘**上：
1. 原生 `.node` 与 `spawn-helper`（Hermes 踩过：spawn-helper 没解出来，终端一开就崩）；
2. 被 `spawn` 出去的脚本（`subagent-child.js`、`dawn-mcp-server.mjs`）与它们 `import` 的整个 pi + node_modules；
3. pi 按目录扫的 `skills/`、`agents/`。

`ELECTRON_RUN_AS_NODE` 的子进程**能不能**透过 asar 读文件，Electron 文档说得含糊，我没验过——而验错的代价是「本机能用、装出去点什么都没反应」（本项目 419 绿那次的同款）。**不验的东西不进 v1。** 关掉 asar 的代价只是文件多、首启慢一点，接受。

## 3. electron-builder 配置（`electron-builder.yml`）

```yaml
appId: science.dawn.app
productName: DAWN Science
executableName: DAWN Science
artifactName: DAWN-Science-${version}-${os}-${arch}.${ext}
directories: { output: release, buildResources: build }
asar: false
files:
  - dist/**
  - skills/**
  - agents/**
  - package.json
  - "!**/*.map"
  - "!node_modules/playwright-core/.local-browsers/**"
# electron-builder 自动只带 dependencies、剪掉 devDependencies
mac:
  category: public.app-category.developer-tools
  target: [{ target: dmg, arch: [arm64, x64] }, { target: zip, arch: [arm64, x64] }]
  hardenedRuntime: true
  gatekeeperAssess: false
  entitlements: build/entitlements.mac.plist
  entitlementsInherit: build/entitlements.mac.plist
  identity: null            # 不签；有证书时删掉这行并设 CSC_LINK / CSC_KEY_PASSWORD
win:
  target: [nsis, portable]
  signAndEditExecutable: false
nsis: { oneClick: false, allowToChangeInstallationDirectory: true, perMachine: false }
linux:
  category: Science
  target: [AppImage, deb]
  maintainer: DAWN Science
```

`build/entitlements.mac.plist`：`allow-jit`、`allow-unsigned-executable-memory`、`disable-library-validation`（原生模块 + 子进程要）。

`package.json` 新脚本：

```
"dist":        "npm run build && electron-builder --publish never"      # 当前平台默认目标
"dist:mac":    "npm run build && electron-builder --mac --publish never"
"dist:win":    "npm run build && electron-builder --win --publish never"
"dist:linux":  "npm run build && electron-builder --linux --publish never"
"pack":        "npm run build && electron-builder --dir"                # 只出解包目录，冒烟用
"test:packaged": "node scripts/test-packaged.mjs"                        # 起 release/ 里的解包产物，真点一下
```

## 4. 首启迁移旧数据（只为作者这台机器）

打包后 `app.getPath("userData")` = `~/Library/Application Support/DAWN Science/`（win：`%APPDATA%\DAWN Science`，linux：`~/.config/DAWN Science`）。作者现有的一切在同级 `Electron/` 下（`dawn.db`、`providers.yaml`、`credentials.json`、`models.generated.json`、`kernels/`）。

`main.ts` 启动、开数据库**之前**：`app.isPackaged && !exists(<userData>/dawn.db) && exists(<同级>/Electron/dawn.db)` → 把上面那几样**拷**（不移）过来，控制台与首屏 notice 各说一句「已从旧目录迁入设置与会话」。抽成纯函数 `迁旧数据(旧, 新)` 放 `src/electron/migrate-userdata.ts`，单测覆盖：新目录已有 db 不动、旧目录没有不动、拷完清单对。**任何 `DAWN_*` 环境变量指定了路径时不做**（e2e、dev:mock 都走那条）。

## 5. 图标

`scripts/make-icon.mjs`：用 Electron 的 `nativeImage`（`ELECTRON_RUN_AS_NODE` 拿不到，所以用 `electron scripts/make-icon.mjs` 跑）把一段 SVG 渲成 `build/icon.png`（1024²）。electron-builder 会自己派生 `.icns` / `.ico`。SVG：`--dawn-accent` 那个绿的圆底 + 白色粗体「D」。**这是占位**——文档里写明换法。

## 6. 打完必须自己验（硬规则 3）

`scripts/test-packaged.mjs`：`npm run pack` 之后，用 Playwright `_electron.launch({ executablePath: release/<平台>-unpacked/... })`，隔离的 `DAWN_*` 目录 + mock 推理服务器，断言：`.app-shell` 出现 → 新建临时会话 → 发一句 → 收到假回复 → 打开「终端」（node-pty 的 spawn-helper 真起了）→ 打开设置「内核」（zeromq 加载了，列出 kernelspec 不报错）。**四个原生模块各碰一次。** 只在当前平台跑；mac 上跑完才算 mac 的包能用。

## 7. 装到新电脑上（写进 `docs/打包与发布.md`）

| 平台 | 装 | 第一次打开 |
|---|---|---|
| macOS | 开 dmg 拖进 Applications | 未签名：右键 → 打开；或 `xattr -cr "/Applications/DAWN Science.app"`。Sequoia 起要去「系统设置 → 隐私与安全性」点「仍要打开」 |
| Windows | 跑 `…-setup.exe` | SmartScreen「更多信息 → 仍要运行」 |
| Linux | `chmod +x *.AppImage && ./…AppImage` 或 `sudo dpkg -i …deb` | AppImage 需要 FUSE2（`libfuse2`） |

之后要用什么装什么（§1 最后一条那张表）；软件里每一处「没有 X」都会明说（笔记本：「还没配 Python 解释器」；ACP：「找不到 npx」）。

## 8. 不做的

- 自动更新（`electron-updater`）：没有发布渠道。
- 签名 / 公证：没证书。配置里留好位置。
- CI 矩阵：没有 remote。文档给出 GitHub Actions 的三平台矩阵样板（`.github/workflows/release.yml`），推上去就能用。
- 把 Python / ipykernel 打进包里：那是另一个项目。
