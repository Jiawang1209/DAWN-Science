# 视觉重做 · 材质与深度 —— 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 DAWN 的界面补上缺失的三样——**深度、排版跨度、动效**，颜色体系与功能一行不动。

**Architecture:** 全部改动坐在**视觉层**：`src/ui/tokens.css`（唯一允许写死颜色的文件）与 `src/ui/styles.css`（引用令牌）。分三轮：**① 令牌层**只加定义不动调用点；**② 面的归位**把 22 个内容面从「一根 border」换成 elevation，并给侧栏/坞/浮层上毛玻璃；**③ 排版与动效**把字号跨度从 1.5× 拉到 2.2×、铺开缓动曲线。每一轮独立可验、可合并。

**Tech Stack:** CSS 自定义属性 + `color-mix(in srgb, …)` · Vitest（`tests/ui/design-contract.test.ts` 做可判定规则的扫描）· Playwright（`npm run test:e2e` / `:visual`）

**规格：** `docs/superpowers/specs/2026-09-10-视觉重做-design.md`
**分支：** `visual-refresh`（已开，规格已提交在 `86af609`）

## 读这个计划之前必须知道的五件事

1. **`tokens.css` 是唯一允许出现裸色值的文件。** `styles.css` 与所有 `.tsx` 里写 `#rrggbb` 或 `rgba()` 会被 `tests/ui/design-contract.test.ts` 当场拦下。现状是 0 处违规，别破这个。

2. **`:root.dawn-dark` 只准覆盖种子层**，同样有扫描拦着。白名单是：

   ```js
   const ALLOWED = /^--(theme-|mix-|dawn-(danger|success|warning|on-accent|shadow-|stroke-float))/
   ```

   **`--dawn-shadow-` 已经在列**，所以本计划新增的 `--dawn-shadow-md/lg` 在暗色里重新定义是**合法的、不需要改白名单**。理由已经写在 `tokens.css` 里：*「阴影 —— 暗色靠内嵌白发丝线，亮色靠投影，形状根本不同」*。

3. **暗色的深度有两条互斥的路，不能混用：**

   | 路 | 一圈描边由谁承担 | 元素上还能有 `border:` 吗 |
   |---|---|---|
   | `--dawn-shadow-float` | `--dawn-stroke-float`（一条**真的 border**） | **必须有** |
   | `--dawn-shadow-sm` / 新的 `md` / `lg` | 阴影里的 `inset 0 0 0 1px` | **必须没有**，否则叠成两圈 |

   本计划新增的 md/lg 走**第二条**。这就是为什么 Task 5 要加一条扫描测试。

4. **`var()` 不许带回退值**（`var(--x, 8px)` 会被拦）。**`font-weight` 只走 `--dawn-weight-*`**。**`border-radius` 只走 `--dawn-radius-*`**。写新 CSS 时照这三条。

5. **「测试绿了」不等于「能用了」**（CLAUDE.md 第 3 条）。每轮结束有一个 `npm run dev:mock` 的人肉验证步骤，**不许跳**。419 个测试全绿的那一版打开之后点什么都没反应，这事发生过。

- [ ] **Step 4: 加暗色两档**

在 `src/ui/tokens.css` 的 `:root.dawn-dark { … }` 里找到这一段的结尾：

```css
  --dawn-shadow-sm:
    inset 0 0 0 1px color-mix(in srgb, var(--theme-gray-0) 5%, transparent),
    0 1px 2px color-mix(in srgb, #000000 35%, transparent);
```

在它**之后**插入：

```css
  /**
   * md / lg 走的是 `--dawn-shadow-sm` 那条路（**一圈 inset 在阴影里**），
   * **不是 float 那条**（float 的一圈由 `--dawn-stroke-float` 上一条真 border 承担）。
   * 两条路不能混：元素同时有 `border` 和 `inset` 就是两圈。
   * **凡是用了 md/lg 的规则必须没有 `border:`** —— design-contract 里有扫描拦着。
   *
   * 多出来的那道 `inset 0 1px 0` 是**方向性顶边高光**（2026-09-10 新增）：
   * 真实的顶部光源只照亮上边缘。一整圈一样亮读起来是「有边框」，
   * **只有上边亮才是「有厚度」**——这是 macOS 一直在做的事，也是贵与不贵的分界。
   */
  --dawn-shadow-md:
    inset 0 0 0 1px color-mix(in srgb, var(--theme-gray-0) 7.5%, transparent),
    inset 0 1px 0 color-mix(in srgb, var(--theme-gray-0) 7%, transparent),
    0 8px 22px -6px color-mix(in srgb, #000000 45%, transparent);
  /**
   * 同样压到 float 之下（float 的远层是 `0 12px 32px -8px / 55%`）。
   * 暗色这边「高一档」由**两件事**一起说：投影更小更淡，而**那圈内描边更亮**
   * （7.5% → 9%；float 那圈由 `--dawn-stroke-float` 承担，14%）。
   * 亮描边才是暗色里表达高度的主力，投影只负责落地。
   */

    inset 0 0 0 1px color-mix(in srgb, var(--theme-gray-0) 9%, transparent),
    inset 0 1px 0 color-mix(in srgb, var(--theme-gray-0) 8%, transparent),
    0 10px 26px -6px color-mix(in srgb, #000000 50%, transparent);
```
