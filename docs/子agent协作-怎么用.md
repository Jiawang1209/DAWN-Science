# 子 agent 协作与恢复

2026-11-04 专项升级。在启用普通子 agent 的内置模型会话中，通过自然语言要求 DAWN 后台分工、继续追问或查看状态即可。模型可用以下工具；不需要手写进程命令。

| 工具 | 用途 |
|---|---|
| `subagent` | 原有 single / parallel / chain，同步收取一批结果 |
| `start_subagent` | 后台启动名册中的一个子 agent，立即返回 childId / messageId |
| `send_subagent_message` | 向同一父会话的子 agent 排队发后续指令，续同一份转录 |
| `list_subagents` | 查看普通子任务、Team 成员和 Bot 的身份、执行状态、最后结果及能力 |
| `wait_subagents` | 按 revision 等待变化，最长 60 秒，避免反复查询 |
| `interrupt_subagent` | 停止点名子级的当前执行，保留身份和转录 |

例如：“让数据审查员后台检查这批数据，只读原始数据，列出缺失值与单位问题。完成后把结果交回主对话。”“继续问刚才那位审查员：核对这些变量的单位来源。”“查看所有子任务状态，等待结果后再汇总。”执行范围、原始数据保护、输出目录和交付要求仍应在派单里写清。

## 状态与结果

启动或发送工具返回的 queued 是消息接收回执，不是完成证明。当前实现将后续指令排队到当前轮结束后处理；能力列表明确标为 steer=false，不提供运行中实时 Steer。普通子级不能创建嵌套团队；Team/Bot 的队友提问与交接沿用原有工具。

completed 只表示执行后端正常返回。产物是否存在、数值是否正确、科学结论是否成立，需要另行核验。failed、cancelled、interrupted 都不能按完成汇总。结果通知不分享内部 thinking。

普通子任务、Team 成员和 Bot 共用每个父会话默认 4 个活动执行名额；同一子级不会并行写同一份转录。原有单批 8 个任务、团队成员/任务限制以及 Bot 产物路径排队继续生效。这里的限制不是跨会话/跨进程的全局预算。

## 看过程与继续问

后台子任务仍显示在原有 chip 与右侧子 agent 坞中，过程和转录沿用既有存储。主 agent 通过新协作工具发起的后续消息会把结果回送主会话；你在坞里手动“接着问”的答复仍只留在子对话，不改变原有交互语义。

父会话忙时结果留在待送队列。父空闲后，结果以宿主生成的持久回执确认接收，正常完成或失败的结果可以唤醒主 agent 汇总。取消和宿主中断的通知不会自动启动父 agent 重做任务。

## 停止与恢复

点名中断会停止当前轮并暂停该普通子级的剩余消息；再次明确发送指令可继续。主会话停止或回退时会暂停子任务与自动回送；关闭会话会取消未开始消息、请求取消执行，并等待后端收尾。记录与转录不删除。即使保存暂停状态失败，也先请求取消，并明确报告保存失败。

重开时，已完成消息不重跑，尚未确认的结果通过父回执去重补送；确定尚未开始且未暂停的消息可接续。上次正在执行的消息标为 interrupted 并暂停该子级，要求先核对可能已有的产物，再发送新的继续指令。不会自动重放结果不明的文件操作。旧团队执行中的任务也会明确标记中断，保留原始记录。

旧会话没有编排状态文件时，从既有 subagent meta.json / transcript 和当前团队恢复索引，不改写原转录。转录缺失时拒绝冒充续接的新会话。编排状态损坏、未知版本或父身份冲突时明确报错并保留文件，不用空状态覆盖。

## 当前边界

普通子进程仍使用现有工具白名单与共享工作目录。这次统一了生命周期和协作，不等同于 OS 沙箱、独立 worktree 或逐文件写权限隔离。Bot 继续使用既有权限、项目范围与产物锁。Windows 后代进程的完整清理仍需真机验证。

结构化工作流、条件 pipeline、外部 agent 后端及运行中 Steer 是后续阶段；本次不声明它们已实现。真实模型的任务成功率、成本和科研正确性需要另行对照测试。
