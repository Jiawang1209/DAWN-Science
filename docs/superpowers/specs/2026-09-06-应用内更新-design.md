# 应用内更新 · 设计

> 2026-09-06。分支 `self-update`。回答 `plans/2026-09-05-下一步.md` §二，
> 并落实作者当天提出的更高要求：*「照搬 codex app 以及 claude app —— 点击之后直接基于本机的系统版本，
> 下载对应的版本，然后直接安装。并且 API-Key 应该是直接自动地替换为新的了。」*

## 为什么现在做

v0.0.2 已经在 GitHub Releases 上（四平台十个包，公开）。**而应用里没有任何一个地方提到过版本**——
`src/` 里一处 `app.getVersion()` 都没有。于是每一份发出去的包都是死路一条：

1. 装了 0.0.2 的人**不会知道 0.0.3 存在**；
2. 就算知道了，换一版之后**钥匙串不认上一版的密文**，API key 与 SSH 口令要重填一次
   （`scripts/rehearse-update.mjs` 演练的正是这一条）。

这两件合起来，使这一轮发布的价值只有一次。

## 量出来的四件事实（2026-09-06，本机 macOS 26 · arm64 · 真的下了 0.0.2 那个包）

1. **Releases API 匿名可用**：`GET /repos/Jiawang1209/DAWN-Science/releases/latest` → `200`，
   `x-ratelimit-remaining: 57`（匿名 **60 次 / 小时 / IP**）。返回 `draft:false, prerelease:false`，
   十个资源名与 `electron-builder.yml` 的 `artifactName` 模板严格对应
   （`DAWN-Science-0.0.2-mac-arm64.zip` …）。
2. **node 的 `fetch` 下下来的包不带 `com.apple.quarantine`**——只有一个无害的 `com.apple.provenance`。
3. **把解出来的 `.app` 放进一个 Applications 目录、走 LaunchServices（`open`）起，正常启动**：
   `packaged=true`、后端 20 ms 装配完、`钥匙串预热 · 加密可用 · 16 ms`，**全程零系统弹窗**。
   包本身是 `adhoc, linker-signed`，`spctl` 评估 rejected——**但 Gatekeeper 只对带 quarantine 的东西执法**，
   这就是第 2 条为什么是地基。
4. `app.getVersion()` 读的是包里的 `Contents/Resources/app/package.json` → `0.0.2`。**版本号不用另外注入。**

第 2、3 条成立，才有「不签名也能做出 Claude / Codex 桌面版那个行为」。**它们是实测的，不是推断的。**

## 为什么不是 electron-updater

macOS 上它走 Squirrel.Mac，**要求新旧包用同一张证书签名**，未签名直接拒绝。
Claude 桌面版与 Codex 桌面版的顺滑正是这么来的——**签名买的**（Developer ID $99/年 + 公证）。

这一轮不买，改为自己下、自己换、自己重启（U3），并自己解决 key 继承（U5）。
**代价如实记下**：证书能把「替换、quarantine、Gatekeeper、钥匙串」四件事一次性变成不存在，
代码上只剩一个开关。哪天要长期往外发包，那笔钱省掉的正是本规格里最容易出错的那一半。

## 定案

### U1 · 一个状态机，两个入口

更新这件事只有一份真相，界面两处都读它：

```
        checking ──失败──→ failed（原话带着）
   idle ────→ ├─ latest（已是最新）
              └─ available ──→ downloading ──→ ready ──→ applying ──→〔重启〕
                     ↑              │失败
                  ignored ←─────────┘
```

**侧栏底部一行**（`ready`/`available` 且未被忽略时才存在，在「设置」上方，**常驻可见、带文字**——
不是悬停才出现的裸图标；这条纪律在这个项目上栽过两次）：

```
 ──────────────────
 ↑ 有新版本 0.0.3
 ⚙ 设置
```

点开的卡片按状态换动词：

| 状态 | 卡片 |
|---|---|
| `available`（能自装） | `0.0.3 已发布 · 你在 0.0.2` / **[下载并安装]** / `查看发布说明 ↗` / `[这一版不再提醒]` |
| `available`（装不了，见 U3） | 同上，但主按钮是 **[打开下载页 ↗]**，并写明装不了的原因（deb 要 root / 便携版换不了自己） |
| `downloading` | 进度条 + `后台下，你接着干活` + `[取消]` |
| `ready` | `0.0.3 已就绪` / **[重启并更新]** / `[稍后]` |
| `failed` | **把原话写出来**（`GitHub 没应：超时 10 秒` / `下载中断：读到 12 MB / 共 223 MB`）+ `[重试]` |

**设置 → 关于**（永远在，没新版时也在）：当前版本 · `[检查更新]` · `[✓] 启动时自动检查更新`。
被忽略的版本在这里照样看得见（`0.0.3 已发布（你选择了不再提醒）`）——
**忽略是「别在侧栏烦我」，不是「把这件事从世界上抹掉」。**

### U2 · 什么时候查

- **启动后 5 秒**查一次，且**距上次查不足 24 小时就不查**（匿名限额 60 次/小时；开发期一天重启几十次也不能把它打爆）。
- 关于那格里点 `[检查更新]`：**无视节流，立刻查**。
- **失败的两种待遇不同**（规格 7.5 的分寸）：自动那次失败**只进 `startup.log`** 的 `[更新检查]` 行——
  它没人要求过，不该打扰；**手动那次失败必须在界面上出声**并带原话——那是人刚刚亲手要的。
- 关掉 `启动时自动检查` 之后**一个字节都不发**。

### U3 · 换包：四个平台能到哪儿，如实说

| 平台 | 判据 | 做法 | 能到哪 |
|---|---|---|---|
| macOS | 总是 | 下 `-mac-<arch>.zip`，解开，`mv` 换掉 `.app`，`relaunch()` | **全自动**（事实 2、3 验过） |
| Windows 安装版 | 无 `PORTABLE_EXECUTABLE_FILE` | 下 `-win-x64.exe`，`spawn(装, ["/S"])`，退出 | 全自动，SmartScreen 可能拦一次 |
| Windows 便携版 | 有 `PORTABLE_EXECUTABLE_FILE` | 运行中的 `.exe` 被系统锁着 | ✗ → 下载页 |
| Linux AppImage | 有 `APPIMAGE` | 换掉那个文件 + `chmod 755` + `relaunch()` | 全自动 |
| Linux deb | 无 `APPIMAGE` | 装它要 root | ✗ → 下载页 + `sudo dpkg -i` |

「能不能自装」由**环境变量与路径可写性**判定，不由猜测判定：
`process.env.APPIMAGE` 与 `process.env.PORTABLE_EXECUTABLE_FILE` 都是 electron-builder 自己设的，
mac 那条判 `.app` 的父目录可写。

换包的三条纪律：

1. **先备份再替换**：旧的 `mv` 成 `<name>.app.old-<旧版本>`，新的 `mv` 到位，任何一步失败**原样滚回**；
   `.old-*` 留到下次启动才删（滚不回时人还能自己把它改回来）。
2. **app 在哪儿就换哪儿**：从 `app.getPath("exe")` 上溯，**不假定 `/Applications`**。
3. **权限不足要说是权限**：不许报成「更新失败」——那句话会把人送去查网络。

### U4 · 不自动重启、不静默安装

下载在后台、**换包只在人点了 `[重启并更新]` 之后发生**。

Claude 桌面版敢在后台悄悄换，是因为它背后没有状态。**我们这里随时有内核跑着、有远端会话连着、
有半小时算不完的一段代码**——被一次更新掐掉是不可接受的。这一条是与「照搬」明确的分歧，理由写在这里。

### U5 · key 交接：这是「照搬」缺的最后一块

根因：钥匙串的 ACL 认二进制，新版 `.app` 是另一个二进制，**解不开上一版加的密文**。签名能解决，不签名则要自己接：

```
旧版（还活着，还解得开）
   ├─ 解开 credentials.json 的每一条
   └─ 写 userData/handoff.json（0600）
         密钥 = HKDF(机器 ID ‖ userData/.handoff-salt)，AES-256-GCM
              ↓  换包 · 重启
新版首启（在钥匙串预热之后，不在启动路径上）
   ├─ 先试自己解不解得开 credentials.json → 解得开就直接删掉 handoff，不用它
   ├─ 解不开 → 解 handoff → 用自己的 safeStorage 重新加密 → 落回 credentials.json
   └─ 立刻删掉 handoff.json
```

**安全边界如实写出来**：这一层加密**不是真的保密**——能读这台机器上这个用户文件的人就能解它。
它买的只是「这份东西不在磁盘上摊着」。所以：只在换包那一刻写、新版首启立刻删、`startup.log` 记一行。

**机器 ID 取不到、safeStorage 不可用、解不开**——任何一条不成立就**不交接**，
并且**不拦更新**：退回今天的行为（新版提示重填），但必须出声，不许假装接过去了。

**时机不能提前**：钥匙串不能在启动路径上碰（2026-08-28 那次几十秒空白就是这么来的），
所以交接挂在「钥匙串预热完成」之后，与那条日志同一时机。

### U6 · 两个接缝，真假共用一份（准入规则 1）

```ts
interface 发布源 { 查最新(signal): Promise<发布一条 | undefined> }
interface 安装器 { 能自装(): 自装结论; 下载(资源, onProgress, signal): Promise<string>; 换包(包路径): Promise<void>; 重启(): void }
```

- 真：`github发布源(owner/repo)` + `本机安装器()`。
- 假：`DAWN_UPDATE_FEED=<url>` 指向一个 GitHub 形状的 JSON（**HTTP 真的走一遍**，
  不是塞一个假对象——解析、超时、状态码这些正是要验的）；`DAWN_FAKE_UPDATE_INSTALL=1` 的假安装器
  下载照真下，换包只写一个标记文件，重启不真重启。
- **`npm run dev:mock` 与 `npm run test:e2e` 共用这一份**。

### U7 · 判据（准入规则 3）

- 单元：版本比较、24 小时节流、忽略版本、**十个资源 × 平台矩阵**的挑选（含三条「装不了」的退让）。
- e2e：假发布源 → 侧栏那行出现 → 点下载 → 进度 → `[重启并更新]` 出现（假安装器）→ 点「不再提醒」那行消失且重启后不回来。
- **真机（唯一算数的那条）**：本地打两个真包（`0.0.9-a` → `0.0.9-b`），**在 a 里点更新，起来是 b，
  不重填 key 直接能发一句真的**。这一轮刚吃过「照同一个形状做不是判据」的亏，不重复吃。
- `rehearse:update` 保留旧那条（**没有 handoff 时仍然要说「解不开，需要重新填写」**——
  新功能不许把旧的判据吃掉），另加交接那条。
- **视觉基线不动**：e2e 默认不给 `DAWN_UPDATE_FEED`，侧栏那行不出现，十张图一张不变。

### U8 · 协议 7.32

新增六个操作：`checkUpdate`（`force`）、`getUpdateState`、`setUpdatePrefs`（`auto` / `ignore`）、
`downloadUpdate`、`cancelUpdate`、`applyUpdate`；下载进度走**现有那条 IPC 通道的第四种载荷**
（与 `RemoteUpdate`、`remoteList` 同一个模式，在会话那句判据之前按形状分派）。纯新增，故 minor。

持久化落 `userData/update.json`：`{ auto, lastCheckedAt, ignored?, ready? }`——
**机器写的状态不进 `providers.yaml`**（那份是给人手写的）。

## 不做（记下，别当成漏了）

- **不自动重启、不静默安装**（U4，与「照搬」的明确分歧）。
- **不做差分/增量包**：223 MB 全量下，一年下不了几次。
- **不做回滚界面**：`.old-<版本>` 留一份，真出事从 Release 页重装。
- **deb 与 Windows 便携版不自更新**（U3），只给下载页。
- **这一轮不签名**。买证书的收益写在上面「为什么不是 electron-updater」里，是一笔随时可做的交易。
- **Windows 与 Linux 的换包这台机器上验不了**：代码写、单测覆盖、如实标注「未在真机验过」，
  与 08-21 那一批老账放在一起等真机。**不许写成「已支持」。**
