# 共用科研审查规范

依据实际文件、代码和运行记录审查；区分已经检查的事实、条件性判断及尚未验证的部分。复用用户已经给出的设计、参数和执行范围，不要求每次分析自动走完整审查。

## 什么时候用

- 核对研究设计、样本量、过滤过程、方法与参数、图表或文字结论。
- 审查脚本能否独立重跑、重跑结果如何比较。
- 统计顾问、审查员、Methods 撰写员或交付技能交接同一份分析。

## 什么时候不要用

- 普通概念解释、单次读取或改图，不强制展开整套检查。
- 用户尚在讨论路线，不借审查启动分析、安装依赖或生成交付。
- 只需要整理最终文件时使用 analysis-delivery；本技能本身不代替分析、改稿或交付。

## 共用底线

1. **先看执行授权与实际工具。** “只审不运行”时只做静态审查；拥有 bash、数据或 README 运行命令均不代表获准执行。已有明确执行授权不反复询问。没有执行工具就交回需重算的事项，标为未运行；不借其他工具绕过角色限制。
2. **保护当前状态。** 不重启、不清空用户正在使用的内核；不改原始数据、原图、既有结果或用户手改文件。授权的验证使用独立状态和新输出目录，先检查脚本真实写入目标。按 [审查清单](references/checklist.md) 核对解释器、依赖、超时和本次进程清理；条件不足就报告限制。
3. **先设计，再判断。** 区分观测行数与独立实验单位，确认分组、配对、重复测量或嵌套。关键信息不足时给条件性判断，不能仅凭列名或案例图型确定方法。
4. **数字与证据能对账。** 核对输入/过滤/输出、单位、各分析有效样本量、表格/图注/正文。数值比较说明预先采用的容差及理由；图表核对数据与渲染。文件哈希不同不能单独证明科学内容不同，也不为通过而放宽标准。
5. **分别报告运行和发现。** 静态审查、部分运行、独立完整重跑、运行失败分别说明；问题写实际位置、证据、影响与建议。未运行不写成已验证，无参照不宣称结果一致，运行成功不等于科学结论已获独立核验。具体格式与场景见 [报告与判断示例](references/reporting.md)。

## 专业分工与资源边界

stat-consultant 负责设计与方法建议；data-auditor 负责数据问题；reproducibility-reviewer 负责输入到产物的可追溯与独立重跑；reviewer-two 负责论断与证据的距离；methods-writer 只写实际有依据的方法和结果。按任务选相关部分，不默认启动其他角色。

主会话沿技能目录提供的实际位置读取参考。子 Agent 使用 resource_search 查询 scientific-review，再按返回 ID 用 resource_read 读取正文和目录内参考，需要时按 nextOffset 续读。项目/全局同名版本及 manual/off 沿用当前可见范围；不可用时如实说明，不绕过开关读取自带副本。技能或参考不是执行授权，也不能增加工具。

审查报告默认在回复中交回。仅用户要求保存且实际具备写入能力时，新建报告文件；无写入工具就把报告交回主 Agent，不用 bash 保存审查报告或修改分析脚本来绕过角色边界。具备执行能力的角色在获准独立重跑时，可由既有受审脚本生成仅限本次新验证目录的产物与运行日志；这不增加任意写入权限。不能因检查结束自动修改分析、安装环境、发布或清理文件。
