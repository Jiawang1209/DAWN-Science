# 科研数据查询

在新建的 API 模型会话中，可直接使用「科研数据 · GEO」。设置 → 插件中可独立关闭整个插件，或分别关闭查询、保存功能。默认开启，明确关闭的旧设置保留；改动在新会话生效。ACP/外部 CLI 不因此新增工具。

## GEO

可以提问：

> 查询与 drought 相关的 Arabidopsis GEO 数据集，返回前 5 条实际记录。列出 GSE 编号、研究题名、实验类型、物种、样本量和来源，缺失信息标明未提供。

> 查看 GSE29235 的实验设计和平台，保留来源和查询时间，不要推断对照分组。

> 把刚查到的 GSE 详情保存到 outputs/datasets，生成 JSON 和 Markdown 清单。

`geo_search` 支持关键词或 Entrez 表达式，强制查询 Series（GSE），单页 1–20 条。`geo_get_series` 按 GSE 精确查询，从 GEO SOFT brief 补充实验设计；仅获取元数据，不下载 SOFT 数据表、补充文件或原始数据。样本编号和标题最多显示 40 条，来源缺失或截断会明确提示；不声称已获取全部逐样本特征。

`geo_save` 只接受同一会话实际查询返回的 recordId；最近 100 条在运行期缓存，重启后应重新查询。每次在 `outputs/datasets/records-*` 下新建 `records.json` 和 `数据清单.md`，不覆盖旧文件。产物可以在侧栏预览。记录保留数据库原始字段值、来源链接、API 请求、查询条件、时间和警告。

远端会话只查询，本地会话可保存。先出方案/讨论模式只查询；保存经过现有文件写权限门。不自动判断数据质量、实验设计合理性或分析可行性。零结果与错误分开报告。

NCBI 查询在当前应用进程共用串行队列，每 500 毫秒最多启动一次请求。单响应最多 2 MiB，每个网络请求最多 20 秒，可停止，不自动重试、翻页或跟随重定向。公共服务可限流或拒绝访问。

接口：[GEO 程序访问](https://www.ncbi.nlm.nih.gov/geo/info/geo_paccess.html)、[NCBI E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25497/)。
