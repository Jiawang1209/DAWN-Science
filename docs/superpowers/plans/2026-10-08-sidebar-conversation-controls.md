# 侧栏与会话切换交互开发计划

**分支：** `codex/sidebar-conversation-controls`（基于 `main` / 0.0.21）

## 目标

让主区会话页签可拖动排序；侧栏会话行右键可直接打开与“…”相同的菜单；统一侧栏「最近 / 项目 / 服务器 / 会话」标题与计数列；在待发消息操作区增加「新增会话」，顺序为「调整方向 → 到坞里问 → 新增会话 → 取回」。

## 方案

- 「新增会话」与「到坞里问」都从当前 native 会话分叉完整历史，并沿用同一 agent、当前模型，以及本地/远端执行位置；前者在主区打开，后者在坞里打开并把待发内容作为下一条用户消息发送。原会话保持独立。

- 会话页签拖动复用现有 `reorderSessions` 后端接口，顺序由会话所属项目保存；只允许在当前同一项目或同一服务器分组内排序。
- 侧栏右键复用 `SessionRow` 的现有菜单内容与菜单遮罩，只增加指针位置打开入口；点击“…”维持原有行为。
- 分区标题行使用固定列布局，让折叠箭头、类别图标、标题和计数分别对齐；补几何断言验证标题与计数左缘。
- 待发条为每条待发消息添加「新增会话」，复用当前项目/服务器的新建流程并分叉当前会话上下文；原待发消息仍留在原会话。

## 实施与验收

1. 先为页签拖动排序、侧栏右键菜单、待发条新增会话写失败测试，再实现最小行为。
2. 扩展侧栏 E2E 几何检查，确认四个分区标题与计数分别对齐；新增主区页签拖动和队列操作顺序的真实 UI 用例。
3. 运行相关 Vitest、Playwright 用例、`npm run typecheck`、`npm run build`，并将结果写入 `docs/DEVELOPMENT_HISTORY.md`。
4. 不改动 `main` 主目录现有本地修改；仅在本分支 worktree 开发。

## 完成记录（2026-10-08）

- 组件与双语聚焦测试 15/15 通过；相关 Electron E2E 19/19 通过；类型检查、Electron/UI 构建和差异空白检查通过。
- 全量 Vitest 首轮 4151 通过、10 跳过、5 失败。之后修复了新增英文按钮文案的子串冲突，并用 `tests/ui/i18n.test.ts` 与相关 UI 组件测试复测通过。全量运行中的另外 4 个 `app-default-client` 用例在未修改的更新状态渲染路径因测试桩缺少 `更新回执.状态` 失败；本轮没有改动该路径。
- E2E 首次重载断言没有重新选择活动会话，已调整为重载后从项目列表打开会话再检查持久顺序；侧栏断言改为精确定位归档入口。首次 E2E 测得远端行两个间距各比既有 10px 目标多 1px，因此保留现有远端布局并容忍 1px 取整误差；新需求的标题和计数列仍按像素精确检查。
- 用户补充确认两种开新会话都必须继承当前上下文。实现使用 Pi 原生 transcript fork，保留完整对话分支、当前 agent/model 和本地或远端执行位置；DAWN 首次快照也恢复 fork 历史，避免模型已继承而界面仍呈空白。新的 E2E 覆盖主区“新增会话”和坞内追加问题两条路径。
