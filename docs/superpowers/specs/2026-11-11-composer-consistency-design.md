# 输入卡等高与原生文本右键菜单

用户要求：新分支整改主区/侧边输入卡；移动分栏或调整窗口时保持等高，文字允许换行；选中文字右键可使用常规编辑菜单。

根因：文本区使用 field-sizing: content；底栏在 600px 以下从一行变两行，360px 以下配置项会再产生一行。此前等高测试扣除了底栏高度，未覆盖完整卡片。

采用共享固定文本区（三行正文加内距，跟随正文字号）、统一两行底栏；真实文本和占位文字都换行，超出文本区滚动。窄栏模型名可截断，但模型、推理、上下文和发送入口保持可点，不再额外换行。保留原有中文输入法与引用高亮机制。相较按左右草稿动态同步高度，此方案不依赖另一侧会话；相较仅补最小高度，此方案覆盖长草稿与宽度变化。

Electron 主窗口监听 context-menu，按 Chromium 的 isEditable/selectionText/editFlags 构建原生角色菜单。编辑区提供撤销、重做、剪切、复制、粘贴、删除、全选；正文选区提供复制。不可执行项禁用，无选区的非编辑区域不弹菜单，已有文件/会话自定义右键菜单继续处理自己的事件。采用原生角色保留系统快捷键、剪贴板、撤销栈和粘贴处理。

验收：完整卡片与文本区在主/侧、280–720px 侧栏和多种窗口宽度等高；短文、自动折行、40 行草稿、清空、切换主侧均保持高度；控件不越界；原生菜单通过真实右键事件生成并执行复制/剪切/粘贴/撤销，正文只能复制。仅本地分支，不发布、不替换已安装程序。
