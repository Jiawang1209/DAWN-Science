## 1. 要解决什么

科研里「先想清楚再动手」不是礼貌，是方法：切分怎么做、用什么检验、拟合哪几个模型、画哪几张图、结果落在哪——**这些要在看到结果之前定下来**，
否则就是看着 p 值挑方法。现在的 DAWN 只有一条路：一句话发出去，agent 立刻开跑。想让它先说方案，只能在提示词里求它「先别动」，
而它照样可能顺手 `run_code` 一段、写一个文件——**靠提示词管住的门等于没有门**（权限三档那份 spec 的定案 1 同一个道理）。

要的是：

1. 一个**看得见**的开关，开着时 agent 只能看、不能改——**由代码拦**，不由提示词求。
2. agent 交出一份**结构固定**的分析方案：问题与假设、数据与切分、统计检验与模型、图、产物落位。
3. 你看、改、批；批了才开始执行。
4. 批准的那一版**存进项目**，是一份轻量的预注册；做完之后能和实际产出对一对。

```

│ 先出方案 · 这一段只看不改，方案批了才动手                    [退出]     │

```

- 开关在权限那颗**左边**：它和权限一样说的是「这一段怎么干活」，归右手那一组。
- 开着时输入卡顶上一条带子，**文字说清**这一段现在只看不改（不能只靠开关的按下态——那是形状，读屏与扫一眼都读不出含义）。
  带子上一颗「退出」，与开关同一个动作。
- 非 native 会话：开关灰着，右边一行小字「这个 agent 不归 DAWN 管工具，先出方案用不了」（D7）。
- 空态屏：同一颗开关，按下只是记住「第一句按先出方案发」；会话建出来、第一句发出去之前打开。选的 agent 不是 native 时同样灰着写原因。
- `/plan`：斜杠菜单多一项「先出方案」。选了把草稿换成 `/plan `；发出 `/plan 问题` = 打开开关 + 把「问题」发出去；只发 `/plan` = 只打开开关。
- ⌘K：一条「先出方案：打开 / 关掉」，不可用时照样列着、写原因（命令面板的规矩）。

### 2.2 方案卡（转录里的一条，`plan`）

agent 调 `propose_plan` 交方案，转录里出现一张卡（不画成工具行——一件事一个样子）：

```
┌ 方案 · 第 2 版 ─────────────────────────────────── 等你看 ┐
│ 吸烟与肺功能：分层线性模型                                     │
│                                                            │
│ ## 问题与假设                                                │
│ ……（markdown 全文，长了折叠，「展开全文」）                     │
│ ## 数据与切分  ## 统计检验与模型  ## 图  ## 产物               │
│                                                            │
│ [照这个做]   [改一改]   [不做了]                               │
│ 想让它重写：直接在下面说，它会交新的一版。                         │
└────────────────────────────────────────────────────────────┘
```

- **三颗按钮常驻**（悬停才出现的等于不存在）。文案互不为子串（设计契约扫描）。
- **照这个做**：存档（§4.4）→ 这张卡变「已批准 · analysis/plans/2026-09-27-吸烟与肺功能.md」→ 开关自动关（D5）→
  替你发一句「照批准的方案做：`analysis/plans/…md`……」开始执行。这句话是**你的一条发言**，进转录、看得见。
- **改一改**：卡片就地变成编辑框（markdown 原文），两颗按钮「照改过的做」「收起」。批的是**你改过的那一版**，
  存档头上记 `edited_by_user: true`，替你发的那句说「我改过，以文件为准，先读它」。
- **不做了**：卡片标「没采用」，开关关掉，什么都不存。
- **想让它重写**：不需要按钮——开关还开着，你在输入框里说哪里不对，它交第 3 版；第 2 版的卡标「已被第 3 版取代」、按钮灰掉。
- 按钮只在**最新那一版、还在等你**时能按；agent 正在说话时灰着（与案例卡片「照这篇做」同一个规矩）。

### 2.3 方案的形状（`propose_plan` 收什么）

```
propose_plan({ title: string, plan: string /* markdown */ })
```

`plan` 必须有这五个二级标题（顺序不限），缺哪个就回 `isError` 并点名缺哪个，模型改了再交：

```
## 问题与假设
## 数据与切分
## 统计检验与模型
## 图
## 产物
```

`## 产物` 下每一行一个产物，路径写在反引号里：``- `figures/roc.png` —— 测试集 ROC``。对照就从这一节取路径。
可选 `## 风险与备选`。路径落位照科研目录约定（给模型的指引里说；不在工具里校验——那是方案的内容，归你审）。

**只有 native**（本机与远端都有）。ACP / CLI / 终端 / 内核会话：D7。

## 4. 分层

依赖决策（规格 §4）：坐在 pi-coding-agent 的 `AgentSession` 上——

① 用到的导出符号：自定义工具 `execute(toolCallId, params, signal, onUpdate, ctx)` 的返回里 `terminate: true`
   （`@earendil-works/pi-agent-core` `types.d.ts`：「Hint that the agent should stop after the current tool batch」）——交完方案这一轮就停；
   `setActiveToolsByName`（只在方案期启用 `propose_plan` / `inspect_data`，与 `read_main_session` 同一条路）；
   工具定义的 `promptGuidelines`（`pi-coding-agent` `extensions/types.d.ts`：「appended to the default system prompt Guidelines section when this tool is active」）——
   **方案期的指引跟着 `propose_plan` 的启停进出系统提示**，不另改 `appendSystemPromptOverride`（那个在建会话时算一次，改不动）。
② 放弃了什么：不做「方案期停用写工具」（它们照样看得见，调了被拒、理由说清——Claude Code 的做法；停用会让模型以为自己没有这件工具，出了方案期又要恢复一张表）；
   不用 pi 的扩展系统（授权门不走它的理由见 `native.ts` `ToolGate` 的注释）；不接 ACP 的 plan 模式。
③ 不变式挂在：`native.ts` 建会话时**所有**自定义工具再套一层 `方案期门`（在权限门外面、先判）——判据是纯函数 `src/policy/plan-mode.ts`。
   设计契约扫描盯着「交给 pi 的 `customTools` 只能是包过的那一份」。

### 4.1 方案期的门（`src/policy/plan-mode.ts`，纯函数）

**默认拒**：不在名单里的工具一律拒，拒绝理由告诉模型「现在是先出方案，只能看；把要做的写进方案」。新加的工具不表态就拦——宁可多拦，不可漏放。

| 工具 | 方案期 |
|---|---|
| `read`、`look_at_image`、`read_main_session`、`propose_plan`、`inspect_data` | 放 |
| `bash` `powershell` | **拒**（2026-09-28；原为「只放看得懂的只读命令」名单，审查找到二十来条绕过后删掉）。看目录、搜文件用 `ls` / `grep` / `find` |
| `ls` `grep` `find`（pi 的类型化工具，不过 shell） | 放（2026-09-28） |
| MCP 工具 | 服务器声明 `readOnlyHint: true` 的放（再过原来的 MCP 门）；其余拒（D6） |
| `run_code` | 拒，理由指向 `inspect_data`（D1） |
| `write` `edit`、office / browser 插件、`subagent`、团队七件、`memory_propose` `skill_propose` 等 | 拒 |

**批准之后**（不在方案期了）多一条（D3）：`write` / `edit` 的目标、bash 的写入与删除目标（复用 `permissions.ts` 的 `写入目标()` / `删除目标()`）
落在**已批准的方案文件**上 → 拒。这条与方案期无关，一直生效。
2026-09-28 收紧：大小写不敏感的盘上按不敏感比、目标过 `realpath`；bash 目标看不清且提到 `plans` / 方案文件名 → 拒；写类插件的路径参数同样判。
门之外还有指纹 + 存档 + 核对恢复（§0 下方 2026-09-28 那条注）。

门的顺序：`方案期门` → 权限门（`gatedTools` 里那道）→ 工具本身。方案期被放行的 bash 照样过权限门（远端、硬拒照旧）。

### 4.2 `inspect_data`（`src/tools/inspect-data.ts`）

- 参数：`language: "python" | "R"`，`path?`（相对工作区）或 `variable?`（内核里已有的变量名，只认标识符），二选一；`sheet?`；`rows?`（默认 5，最多 20）。
- 代码**写死在我们这边**，参数以 base64（Python）/ 十六进制（R）塞进去——与环境快照那条路同一个做法，不拼字符串进代码。
- Python：`pandas` 读 csv / tsv / xlsx / parquet，或取 `globals()[变量名]`；打印形状、`dtypes`、缺失、前 N 行、非数值列的取值个数与前十个、`describe()`。
  整段包在一个函数里、跑完 `del`，**不在内核里留任何名字**。R：`local({ … })` 里做同样的事（`read.csv` / `read.delim` / `readxl::read_excel`（有才用）、`str`、`summary`、`colSums(is.na())`、`head`）。
- 跑在**同一台对话内核**（`对话内核.执行`）：远端会话数据在服务器上，这样才看得到；内核里已经读进来的表也能直接看。
- 收中止信号（与 `run_code` 同一套：排着的不跑、跑着的发中断）。
- 笔记本里也记一格（`notebook-cells.ts`：代码栏写 `# inspect_data：<路径或变量>`），「没有不可见的行动」。

### 4.3 `propose_plan`（`src/tools/propose-plan.ts`）

- 校验五个标题；缺 → `isError` 点名。
- 通过 → 交给运行时 `收方案()`：版本号 +1，之前还在等的那一版标「已被取代」，发 `plan` 事件；
  结果文字「方案第 N 版已交给用户，这一轮到此为止，等用户回话」，**`terminate: true`**。
- `promptGuidelines` 就是方案期指引：只看不改、`inspect_data` 看结构不看结果、方案的五节、产物路径照科研目录约定、交完就停。

### 4.4 运行时（`src/runtime/native.ts` + `src/runtime/plan-book.ts`）

- 每段会话一本「方案簿」：阶段（`off` / `planning`）、每一版的记录（`planId` = 那次 `propose_plan` 的 toolCallId、版本、标题、正文、状态、存档路径、批准时刻、改没改过）。
  **落盘在会话目录 `plans.json`**：重启续接后，开关状态、卡片状态、已批准文件的保护都还在。
- 会话开关 `dawn.plan`（boolean，category `plan`）：`configOptions` 里常驻；`setConfigOption("dawn.plan", "1" | "")` 切阶段，
  同时启停 `propose_plan` / `inspect_data`。**这就是开关的唯一后端入口**——与权限那颗走 `dawn.permission` 同一个做法，不另开协议操作。
- `answerPlan(planId, "approve" | "discard", 正文?)`：
  - 只认**最新、还在等**的那一版；否则抛（「这一版已经不是最新的了」/「这一版已经批过了」）。
  - approve：正文 = 你改过的或原文 → 路径 `analysis/plans/<YYYY-MM-DD>-<标题>.md`（重名加 `-2`…，只用 `wx` 打开，不覆盖任何已有文件）→
    写文件（头上一段 YAML：标题、批准时刻、会话、模型、版本、`edited_by_user`）。本机 `mkdir -p` + `writeFile`；远端 `mkdir -p` 走执行器、
    先 `set -C && : > <p>` 原子地占名字（noclobber，`O_EXCL`）再 `writeFile`（2026-09-28 审查：`test -e` 再写不是原子的）。
    写成功才改状态；写失败原样抛，**卡片不变、开关不动**。写下文件之后哪一步抛（存档、簿存不下），写下的文件与存档都删掉再抛。
  - 一段会话同时只答一次（双击批准、批准与「不做了」挤在一起：后来的抛「这一版方案已经在处理了」，后端归 `conflict`）。
  - 「改过」比的是两头去掉空白的正文。存档与轮基线都**按 `planId` 取名**（不按方案文件名）。
  - 文件名的标题部分：NUL 与控制字符去掉，按**码位**截到 40。
  - 阶段回到 `off`、发 `config_options`、发 `plan` 事件。
- `history()`：记录里有的 `propose_plan` 调用还原成 `plan` 条目（状态取记录），它的结果不再单独成一条工具行；记录里没有的照旧当工具行（不编状态）。
- `stop()` 不清方案簿（落盘的，下次续接要用）。停止时**等在跑的那一轮自己收完尾**（收轮核对要用这一轮的底，最多等 10 秒）再扔底。
- 主会话 `noExtensions: true`（2026-09-28 审查，安全）：pi 扩展注册的工具不经过方案期门与权限门，DAWN 一件扩展都不用。

### 4.5 协议（**minor**，纯新增）

- 转录条目新增 `plan`：`{ type: "plan", id: "plan:<planId>", planId, version, title, markdown, status: "proposed" | "approved" | "superseded" | "discarded", savedPath?, approvedAt?, edited? }`。
- 新操作 `answerPlan { sessionId, planId, action: "approve" | "discard", text? } → { savedPath? }`，`mutating: true`，要写权（与 `writeToSession` 同一条租约规矩）。
  非 native → `invalid_request`；不是最新那版 / 已经答过 → `conflict`；查无此版 → `not_found`。
- 开关不加操作：走已有的 `setSessionConfigOption`（`dawn.plan`）。
- 版本：**执行时的下一个 minor**（别的分支也在升，写计划时不钉数字）。
- **mock 同一次改动补上**（硬性准入规则 1）：假模型在请求的工具表里看见 `propose_plan`、且最后一条是用户话 → 回一次 `propose_plan`，
  正文是一份五节齐全的方案（产物两项）；最后一句用户话带「照批准的方案做」→ 回一次 `write`，写方案里的第一项产物（对照能显示「1 / 2」）。
  用户话带「偷跑」且在方案期 → 回一次 `write`（演「被门拦下」）。`dev:mock` 与 e2e 共用。

### 4.6 转录中枢与界面

- 中枢：`plan` 事件 → 按 id 覆盖那条 `plan` 条目；`propose_plan` 的 `tool_start` / 成功的 `tool_end` 不画工具行（失败的照画，模型要改）。
- 导出 markdown：方案条目写成「> 方案第 N 版（已批准 · 路径）」，已批准的把正文整段放进去——实验记录里要有它。
- 界面：`plan-card.tsx`（卡片三态 + 对照）；`views.tsx`（附栏开关、带子、`/plan`、`TranscriptRow` 的 `plan` 分支）；`App.tsx`（`answerPlan` → 发执行那句；空态「第一句按先出方案发」；⌘K）。

## 5. 测试

- 单元：
  - `protocol/plan.ts`：标题检查、产物解析（反引号、通配、没有这一节）、对照（已生成 / 还没有 / 计划外 / 批准前的不算）、文件名。
  - `policy/plan-mode.ts`：名单逐项；bash 只读判定（放的、拒的各一串，含 `find -delete`、`sort -o`、`>`、`$(…)`、`python -c`）；MCP 只读提示；已批准文件的保护（write / edit / bash 重定向 / `rm` / `mv`）。
  - `inspect_data`：代码里不出现原始路径字符串（只有编码后的）；变量名不是标识符 → 拒；中止 → 中断（照 `run-code.test.ts` 的慢内核）。
  - `propose_plan`：缺标题 → isError 点名；齐了 → `terminate: true`、交给运行时。
  - 运行时（真起 pi 会话，照 `side-tool.test.ts`）：开关启停两件工具、方案期 `write` 被拒而 `read` 放行、批准写文件 + 阶段回 off、重名不覆盖、`plans.json` 续接、`history()` 还原。
  - 后端：`answerPlan` 分码、租约、非 native。中枢：`plan` 覆盖、`propose_plan` 不画工具行。
  - 界面：方案卡三态、按钮常驻、改一改、对照清单；`/plan` 前缀拆分；⌘K 那条。
- 设计契约：工具名扫描加上两个新文件；**`native.ts` 交给 pi 的 `customTools` 只能是 `方案期包过的`**。
- e2e（假模型）：①开关 → 说一句 → 方案卡出现、没有工具行 → 照这个做 → 文件真在 `analysis/plans/`、开关关了、那句执行话进转录、对照「1 / 2」；
  ②方案期「偷跑」→ 那次 `write` 被拒、文件不在；③改一改 → 批的是改过的正文；④不做了 → 什么都不存；⑤ACP 会话开关灰着且有字；⑥三颗按钮 `opacity === "1"`。
- 视觉基线：方案卡与开关不在十四张基线的任何一屏里；附栏多一颗开关会动「对话」那几张——**看 diff 再决定**。

## 6. 不做

- 方案期停用写工具（见 §4 ②）。
- 自动判断「这个问题该不该先出方案」。
- 方案文件被人手改后的核对（D3 备选）。
- 多版本方案之间的 diff 视图。
- 定时任务的先出方案。
