# 实时纠偏与有界科研批量执行

基线：本地 main `6f6c7251`。在 `codex/live-steering-parallel-science` 隔离工作区实现；不自动提交、合并、推送、发布或替换安装应用。

## 目标与设计

1. **运行中纠偏**：新增与排队续聊语义分开的 steer 控制，复用统一编排身份和现有子进程／会话。回执区分 accepted（宿主接收）、applied（真实用户消息进入模型上下文）、interrupted/unknown（未确认生效）。限制消息大小和待处理数量，固定 requestId 幂等，绑定当前执行代次，禁止跨轮误投或恢复后静默重放。能力不支持时明确拒绝，不伪造成功。保留现有 interrupt 的停止与排空语义。科学冻结契约不能通过该入口改写；尚未证明冻结上下文兼容的科研执行拒绝实时纠偏，要求停止并派生新批次。
2. **有界并行批量**：每项保存独立 pipeline 检查点，通过原 Team reducer 和 scheduler 推进；默认串行，显式并发上限 2。复用冻结契约、内容版本、复用判定、文件锁、最终汇总及路线 CAS。不得通过放松 workspace-exec 锁换取并行。保持同一成员／Bot 串行；普通子 agent 的两个只读槽使用同一冻结执行者定义的独立会话，Bot 不克隆；独立检查与复核可交错，分析仍受原锁约束。失败停止新派发、取消排空所有已启动项，恢复只重做不确定项。所有项通过后只生成一次宿主汇总，再投影到分析路线。
3. **观测、评测与展示**：沿用 evaluate:science，增加真实纠偏回执和相同科学工作量的 serial/bounded 对比；记录墙钟时间、请求数、实际重叠、取消／恢复和最终内容一致性。离线确定性 provider 只控制模型回复，文件、子进程、冻结验收与锁走真实路径；不将结果称为真实模型质量或费用收益。

## 执行阶段与验收

- A：先为控制链路补失败测试，再实现父子协议、真实 SDK steer、统一控制回执和现有界面显示。演示长工具执行中收到纠偏、工具边界后 applied、点名取消排空；测试重复请求、旧代次、关闭、取消竞态、恢复不重放、冻结科研拒绝。检查不支持的后端不会宣称支持。
- B：先为两项不同进度、单项失败、取消、多活动项恢复、复用项跳过、最终汇总只运行一次补失败测试，再引入逐项检查点和有界调度。接入批量工具与现有状态卡；保持旧持久化数据兼容。演示真实阶段重叠及持锁等待，并展示所有输出和汇总。
- C：扩展既有评测入口；同输入比较 serial=1 与 bounded=2，不保证加速。完成 typecheck、单元测试、构建、相关 Electron E2E、独立代码审查；修复发现的问题并补回归。保存评测和阶段截图／运行轨迹，更新开发历史及验收报告。

## 实施约束

- 不引入第二套权限／任务状态机，不加载用户科研模型或运行用户案例代码，不调用付费真实 provider。
- schema 新字段可选以兼容历史；新协议分支同步模拟后端和测试。
- 每项管线最多原有尝试数；并行失败不能释放仍被活动后端持有的锁或在排空前恢复。
- 复用内容验证保持原规则；控制文本绝不悄悄进入可复用科研历史。
- 每阶段向用户展示实际结果，不能以测试数量代替效果。
