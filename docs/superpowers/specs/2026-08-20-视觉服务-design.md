# 视觉服务：让不能看图的模型看图

2026-08-20 · 作者要的：*「给 deepseek 添加一个视觉，放在设置里面的模型选择里面，
做一个选择框，是否添加视觉，选择之后才能调用。」* 并给了一张他用过的插件截图
（OpenAI Chat Completions / API 地址 / 模型名称 / API 密钥 / 测试视觉模型）。

**作者定的两条边界**：
- 视觉服务是**全局一份**，谁的目录里没声明收图谁用——不是 DeepSeek 专属。
- 走**做法 A**：一份视觉客户端，接两个缝（贴图转述 + `看图` 工具）。

## 1. 配置

`ProviderRegistrySchema` 加一个可选段 `vision`（`providers.yaml` 同一个文件）：

```yaml
vision:
  enabled: true            # 那个选择框；false 或整段缺失 = 一切如旧
  api: openai-completions  # 目前唯一取值；字段留着是给下一种协议的位
  baseUrl: https://…/v1
  model: qwen3.7-plus-…
```

- **密钥不进文件**：OS 钥匙串，键名 `vision`。响应里只有 `hasSecret`，
  永不回显（与 provider / MCP 同一条纪律）。
- `enabled: true` 但 baseUrl/model/密钥缺任何一样 → **状态是「未配置」，
  两个缝都不接**，界面写清缺哪样。缺失不等于能用。

## 2. 视觉客户端（一份，两处用）

`src/runtime/vision.ts`：`描述图片(images, 提问?) → Promise<string>`。
一次 OpenAI Chat Completions 调用（`image_url` + data URI），`fetch`，不引新依赖。

- 失败三种各自出声：超时（上界 60s）/ 非 200（带端点回的原话，截断要说明）/
  回空。**不静默回退**（规格 7.5）。
- 转述提问词**内置不做配置**（作者认可）：面向数据图表那一句
  （读坐标轴、图例、数值趋势）。调用方可换（`看图` 工具把模型的提问传进来）。

## 3. 缝一：贴图转述（native.ts `writeWithImages`）

现有 `明确不收` 分支（`model.input` 不含 `"image"`）今天只 notice 一句。改成：

- 视觉**可用** → 先 `描述图片`，把描述并进这一轮文字发出去；
  notice 改说「这 N 张图已由 <model> 转述给模型」。
- 视觉**不可用**（没勾/没配）→ 原句原样。
- 视觉**调用失败** → notice 说失败原因，**这一轮照发**
  （作者 2026-08-13 定过：对话是要有的）。
- 模型收图 → 这个分支根本进不去，一字不变。

## 4. 缝二：`看图` 工具（`toolsFor`）

- 只在「视觉可用 **且** 当前模型不收图」时注册——收图的模型自己能看。
- 入参：工作区相对路径 + 可选提问。本地读盘、远端走 SFTP（现成通路）。
- 大小上界沿用预览那套（`IMAGE_MAX_BYTES`），超了如实拒绝。
- 与内核/MCP 工具一样进 `外部`，**套溯源、两条 return 都带**
  （`toolsFor` 提前返回那个坑本仓库踩过，见该函数注释）。

## 5. 设置界面

「模型」那一屏加一张卡（照作者截图）：协议（下拉，暂只一项）/ API 地址 /
模型名称 / API 密钥（占位「已保存；留空表示不修改」）/ **「启用视觉」勾选** /
右上「已就绪 · 未配置」徽章 / **「测试视觉模型」**按钮——发一张内置诊断小图
真调一次，成败原样显示。

## 6. mock 与测试（准入规则 ①②③）

- `mock-inference-server.mjs` 加视觉分支：确定性回复；dev:mock 与 e2e 共用。
- 单元：schema、密钥不落盘、`描述图片` 三种失败、缝一的三种走向、
  缝二的注册条件（收图模型不注册）。
- e2e：设置卡配好 → 测试按钮 → 「已就绪」；贴图给不收图的假模型 →
  对话里出现「已转述」。跑真实构建产物。

## 放弃了什么

- **做法 C（伪装模型收图、拦 pi-ai 载荷）**：伸进 pi 内部，升级即断，
  违反分层定案（pi 是运行依赖，坐它上面，不挖它里面）。
- **每 provider 一份视觉配置**：作者选了全局一份。
- **转述提问词做成配置**：又一个没人改的框。
