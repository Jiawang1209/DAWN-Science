## 回归中修正的问题

- 代码执行长于五秒时，采集预算误把分析耗时算入哈希时间；改为只累计身份计算耗时。
- 多文件复制中后一个失败时，不先发布前一个对象，避免普通失败产生半组可见结果。
- 原生 `run_code` 的旧文件探针位于内核队列外；改为从同一队列内的采集事实刷新原清单，避免重复扫描和混入排队时间。
- 内核来源曾关联根聊天的机器快照，随后又暴露异步探测尚未完成的问题；现在等待已有启动探测，按真实内核实例引用 Python/R 各自环境，并绑定对应 Run。真实 Electron 回归同时核对语言、环境 kind 和 Run 引用。
- 保存后刷新保持同一选中 ID，来源 effect 未重新请求；补充刷新依赖。旧选择的迟到错误不覆盖新选择。红绿日志见 `dawn-artifact-ui-refresh-red.log` / `green.log`。
- 未接入的本地运行时不再以“支持但空清单”表达自动采集能力；项目留存副本仍可查看。对应 `dawn-artifact-runtime-red.log` / `green.log`。
- 固定来源清单补入选定执行的输入身份及缺口；后续输入观察不改写该清单。对应 `dawn-artifact-manifest-red.log` / `green.log`。

## 证据边界与后续事项

- 自动采集限于本地 API/Notebook 已接入路径。远端、独立 CLI、ACP、Bot 和子 agent 没有本版同等自动来源保证；不使用宿主或父调用证据补齐它们。
- 输入声明、读取工具观察、执行期间变化分别记录。已有变量、动态 I/O、数据库与网络依赖没有完整捕获；不会据此承诺一键可重现。
- 原始输入默认不复制。未保存字节的旧版本只有身份与记录，无法凭哈希恢复。文件没有可信历史来源时，后补留存只证明此刻内容。
- 日志为有界摘要，代码超过预算只留完整哈希，超预算或失败保留明确缺口。默认留存上限：50 MiB/文件、200 MiB/组、1 GiB/项目。
- SQLite 与文件系统不具备跨介质原子事务。测试模拟中断请求及恢复，未做各发布时刻的物理断电实验。崩溃后未引用对象不会被列为成功留存，仍计入项目配额；本版没有自动垃圾清理。只清理数据库已登记的暂存任务。
- 路径与描述符检查拒绝常规越界、软链及复制期间身份变化；本版不构成 OS 文件系统沙箱。
- 确定性模型 Electron 用例证明工具、文件、状态和 UI 接线；真实 Python/R 证明实际解释器及文件链路。这些证据均不代表任意科研分析的正确性或生产环境全面验收。
- 没有执行发布、安装包替换、远端部署或主目录集成。保留本地分支与未提交工作树供审阅；不合并、不推送。
