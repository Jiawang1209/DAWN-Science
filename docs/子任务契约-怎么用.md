# 子任务契约与产物占用

2026-11-04 专项。适用于内置模型会话中的本地普通 subagent、旧 Team 和本地托管 Bot。原来的文本派单、single/parallel/chain、后台工具与坞内续问继续可用。

## 结构化派单

在 `start_subagent` 或 `subagent` 的单个任务上增加可选 `contract`；parallel/chain 的每个条目可各自指定。`team_create.tasks`、`team_add_task` 也使用同一契约。

```json
{
  "agent": "reviewer",
  "task": "只读检查 input.csv，核对单位与缺失编码，把阻塞和实际读取证据返回主对话。",
  "contract": {
    "version": 1,
    "access": "read-only",
    "inputs": ["input.csv"],
    "outputs": [],
    "requireReview": true
  }
}
```

`version` 当前为 1；省略时按 1。inputs/outputs 为工作区相对文件路径，不接受绝对路径、`..`、URL 或目录通配符。inputs 是输入声明，不代表逐文件读取沙箱；输入的路径别名和硬链接也不能作为写入目标。输出可以是尚未生成的文件。声明的 inputs 须在启动前就绪，验收时也会复核；缺失、越界、非文件或无法核验时阻塞，不启动模型或子进程。

默认 access 为只读。需要写指定文档或脚本时使用 `workspace-write` 并声明 outputs。需要实际运行分析或 shell 时使用 `workspace-exec`；它继承父权限快照和现有风险规则，不能自动取得额外批准。不要把这个模式当作逐文件或网络隔离。

`requireExecution: true` 要求实际执行已完成的工具证据，须配 workspace-exec；`requireReview: true` 要求审阅证据。两者缺省为 false。交付脚本可以不要求执行，执行分析则应明确要求执行证据，防止把“只写了脚本”当成分析完成。

## 子级如何交回结果

宿主在提示词中给出固定 JSON 格式，子级最后一条 assistant 答复须仅包含该对象，不加代码围栏。普通子级使用最后一条答复，不把中途解释与 JSON 拼在一起。

```json
{
  "summary": "已读取数据，单位仍需确认",
  "blockers": ["温度列未注明单位"],
  "deliverables": [],
  "execution": {"state": "not_run", "note": "仅做读取"},
  "verification": {
    "state": "issues",
    "note": "实际读取中发现单位缺失",
    "toolCallIds": ["本轮真实 read 调用的 ID"]
  }
}
```

execution 与 verification 沿用分析路线的词汇。执行完成、失败或审阅声明必须引用本轮实际且类型相符的工具证据。被拒的调用不是执行证据；模型编写“已经运行”也不是证据。真实 shell 的退出/输出观察沿用主运行时的做法，并写入 Pi 工具结果 details。

宿主回执分为：

- `accepted`：格式、声明产物、必要执行/审阅证据通过当前契约检查。
- `blocked`：有阻塞、明确执行失败或审阅问题，或缺少调用方要求的执行/审阅状态。
- `invalid`：格式、引用、声明路径、产物存在性等不符合契约。

文件状态继续区分 `exists`（只确认文件存在）和 `observed`（本轮成功工具有写入观察）。两者都不证明科学正确；一次 read 的审阅记录也不等于独立科研审查。对科学结论仍需专门核验。

blocked/invalid 不会作为成功放行 chain 或 Team 下游。Bot 的契约文件验收在释放写占用之前完成；主对话拿到宿主回执，而不是只听子级自称成功。失败不自动重跑，需核对已有产物后明确继续。若初次派单因输入未就绪而从未启动、没有转录，补齐输入后应另建任务，不冒充续接已有对话。

## 冻结范围与续接

任务创建/首次执行时冻结父权限档、工具范围、inputs/outputs 与契约。普通后台子级后续消息和坞内续问继续沿用原设置；改变契约或扩大范围需另建任务。定义文件不能通过提示词扩大范围。Team 的新任务可以从当前父策略创建新的设置，已经在执行的任务保留自己的快照。

设置同时随编排记录与普通子级运行元数据保留；重建新索引时恢复原范围，不把旧任务提升为全权限。未知版本、畸形设置和互相冲突的记录明确拒绝，保留文件。取消/重启后仍不重放结果不明的操作。

索引重建也保留已有成功/阻塞回执和失败原因，包括尚未启动模型的输入检查失败；损坏回执明确拒绝恢复，不推定成功。

只读和限定写入只开放受控工具；不能借 team_send/bot_message 让队友代做越界执行。公开陈述及只读状态/资源查询沿用既有能力；需要更大执行范围时把阻塞交还主会话。

## 产物占用的实际边界

本地普通子任务、旧 Team 和 Bot 共享原 BotOutputLocks 实例，按真实工作目录与规范化输出路径协调：

- 只读任务不占写名额，不提供读取一致快照保证。
- workspace-write 只占声明文件，不相交的输出可并行。
- 同一工作目录内的符号链接与现存文件硬链接别名共用占用，不因路径名称不同并发覆盖。
- 允许 shell 或写集合不明的旧任务保守独占该工作目录，可能降低并发度。
- 取消排队不启动后端；失败、取消、关闭会释放占用，后端须真正退出后才能归还。

这是已接入的子任务写者之间的进程内协调，不阻止人工编辑器、未接入占用的主会话写操作或其他进程。不是跨进程锁、独立 worktree 或 OS 沙箱。workspace-exec 沿用既有执行权限规则，不声称可封住任意 shell 的所有副作用。

远端严格契约目前明确拒绝，不用本机同名文件冒充远端核验。远端原有未使用契约的执行路径保留；本专项不为其新增本地范围保证。Windows/Linux 真机清理与真实模型成功率另行验证。
