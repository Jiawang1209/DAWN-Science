# 交付比较保留身份和数值原文

用户已确认全仓审查 F2 的修复方向并授权本分支修复、验证和本地合并。本切片复用既有核验入口，不改变协议或增加字段角色编辑器。

根因：CSV 在比较前统一转 Number，JSON.parse 也先丢掉数值精度。仅设置零容差不能恢复已丢失的身份或末位。三个候选方案：只补 id 列规则会漏掉未知列和大整数；引入新的逐列类型协议/编辑器扩大了本次修复；采用保守默认规则和原始数值比较可以修复现有记录并保留小数容差。本次采用第三项。

契约：
- 表头与行序沿用现有完整比较；文本和含前导零的 CSV 数字保持原值精确匹配。
- 明确可识别的编号/编码/类别/分组/标签字段按原值比较；样本量字段精确数值比较。
- 未声明角色的数值采用保守规则：任一值为整数时精确比较，不将差异当作浮点误差。整数形式的连续测量值也受此约束。
- 其他小数保留既定相对容差公式。先比较十进制规范值；零容差或 Number 无法忠实保留其十进制原文时使用精确比较，避免精度折叠或下溢掩盖差异。
- JSON 使用运行时现有 reviver context.source 保留数值原文；数组和对象递归沿用同一规则，数值类型与字符串不混同。不具备原文支持时明确未比较，不冒充通过。
- UI 文案写明保守规则，不再声称已识别任意语义类别。未引入任意自定义字段的完整语义类型系统，也不宣称科学结论正确。

验收：CSV/JSON 编号、前导零、类别、整数边界和十进制末位先红后绿；连续小数容差与既有行序/样本量回归保持。真实 Python 独立重跑验证失败状态及证据保留；真实 Electron 确认变动输出显示核验失败。完成类型、全量单测、完整构建和本地 main 复验后，下一项另建 SSH 生命周期分支。
