# 远端 R 内核 · 实施计划

**Goal:** 远端会话里 `run_code` 能在服务器自己的 IRkernel 里跑——探测 → 选 → 出数、出图、变量面板有东西 →
断开收干净，与 Python 那条同一套体验；并且这条路在 mock / e2e 下有判据兜着。

**Architecture:** 生产代码里 R 的分支其实早就写好了（`远端启动命令` 有 R 分支、`探测命令` 认 R、
扫残留正则认 `-R-`），缺的是**没有任何东西跑过它**，而一跑就发现 IRkernel 不自己写 connection.json。
所以真正要新增的是「挑端口 + 写连接文件」这一步，以及 R 专有的就绪判据。规格：
`specs/2026-09-05-R远端-design.md`（定案 R1–R5）。

**Tech Stack:** TypeScript / Node 22；base R（`serverSocket`）；vitest；Playwright（e2e 走真构建产物 + 假 SSH + 真 IRkernel）。

**分支纪律：** 只在 `remote-r` 上提交。**never checkout / switch / stash**。commit 英文，不加 Co-Authored-By。

**验证纪律（CLAUDE.md 准入规则 3）：** 每个任务跑自己的测试；T3 之后 `npm run typecheck`；
T5 跑 `npm run build` + `e2e/remote-kernel.spec.ts`；T4 里有一次 `dev:mock` 人肉看。

### Task 1: 挑端口 + 写连接文件（纯字符串 + 解析，注入 exec）

- [ ] **先写失败的测试** `tests/remote/kernel-launch.test.ts`：
  - `挑端口并写文件脚本(文件, key)` 生成的命令里：`umask 077` 在写之前；文件名与 key 都过 `单引号`；
    R 代码里没有裸的双引号把 shell 引号闭合掉。
  - `解析端口(stdout)`：五个 `DAWNPORT_*` 齐全 → 返回 `{shell_port,…}`；`DAWNRC=3` → 抛「挑不到空闲端口」；
    少一个键 → 抛（**不许把缺失当 0**）；MOTD 里混进 `{}` 不影响。
- [ ] **实现**：`挑端口并写文件(exec, {文件, key})`，一条命令回 `DAWNPORT_shell=…` ×5 + `DAWNRC=0`。
- [ ] **判据**：`npx vitest run tests/remote/kernel-launch.test.ts`

### Task 2: `起远端内核` 的 R 分支（定案 R1 / R2）

- [ ] **先写失败的测试**（注入 exec，不碰真机器）：
  - R：先发挑端口那条、再发起内核那条，**顺序有判据**；返回的连接信息就是我们写下的那五个端口 + key。
  - R：起来就死（第一次 `活着` 回 0）→ 抛 `远端启动失败`，`日志尾` 里有 `.log` 的内容。
  - R：`活着` 连续 N 次为 1 → 返回，**期间一次都不去读 connection.json**（那条判据对 R 无意义）。
  - Python：**一个字节都不许变**——老用例全绿是这一条的判据。
- [ ] **实现**：R 分支走「挑端口 → 写文件 → 起 → 轮询活着」；key 用 `randomUUID()`。
- [ ] **判据**：`npx vitest run tests/remote/`

### Task 3: 假服务器真起 IRkernel（准入规则 1，定案 R4）
