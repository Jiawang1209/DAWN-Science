## 实际行为

默认以 1440px 窗口的 300px 侧栏、480px 面板为参照；正文占用剩余空间。侧栏适度增长并受 300–420px 约束，极窄桌面窗口还会进一步限制其上限。面板在宽屏可超过旧的 720px，但受当前可用空间和最大量程约束。

| 窗口 CSS 宽度 | 默认侧栏 | 默认正文 | 默认工作面板 |
|---:|---:|---:|---:|
| 900 | 300 | 296 | 280 |
| 1280 | 300 | 529 | 427 |
| 1440 | 300 | 636 | 480 |
| 1920 | 400 | 856 | 640 |
| 2560 | 420 | 1263 | 853 |
| 3840 | 420 | 2116 | 1280 |

每行另有既有的 24px 网格间隔与右内距。表中为默认三栏完全展开的稳定值；侧栏折叠和手动拖动会改变分配。

- 手动调宽保存占窗口的比例。缩小窗口只约束当下显示，拉宽时恢复比例；重载和真实重启后也能恢复。
- 旧像素偏好作为兼容参照；新偏好独立保存在 `dawn.global.workbench-proportions`，不覆盖旧记录。
- 网格、顶栏导航、拖动条的实际宽度/上下界、文件单双栏判断使用同一计算结果。
- 小窗口不再把文件面板压成细条；默认 900px 时正文与文件面板共同承担缩窗限制。
- 文件“加宽/收窄”与单双栏排布分开判断，避免自动双栏下收窄无效、单栏加宽后缺少恢复入口。恢复默认保存精确的 1/3 比例，避免跨尺寸取整漂移。

## 首次失败与处理

- 原实现真实复现：窗口 1440→1920px，侧栏仍为 300px；`e2e-red.log` 和 trace 保留。
- 首次宽度预算漏算了网格间隔的实际值。按现有 8px×3 修正为 24px；真实 900px 截图进一步暴露面板过窄，增加正文与面板共同收窄的规则。相关红绿证据为 `narrow-red/green`、`wide-sidebar-red` 和后续通过日志。
- 原加宽按钮把双栏等同于已加宽；新默认比例下出现“收窄无效果”或没有恢复入口。新增真实用例先失败，再修正回调判断；`file-resize-red.log` 和最终 Electron 证据保留。
- 设置测试仍在 1400px 窗口等待固定 480px，改在 1440px 参照窗口验证同样的 480px；拖动测试改检查当前实际边界。上传测试需先扩到 1440px 才验收两栏，1280px 按 300px 侧栏、420px 正文和 24px 间隔放不下 560px 两栏。原来的不溢出、内容完整性、传输结果及控件尺寸判据保留。
- 动态三栏过渡使旧用例比较了不同动画帧的盒子；量尺寸前等待实际网格动画结束，保留全部边界断言。
- 首次全量检查报 7 个文件失败：新增 CSS 变量没有登记令牌、使用了不允许的 `var()` 回退；另有隔离内核目录为空造成的内核启动失败。CSS 已登记到 `tokens.css` 并移除回退；只读复制既有 Python/R 注册文件到私有测试根。正式注册没有修改，随后定向 144 条和完整全量复验均通过。
