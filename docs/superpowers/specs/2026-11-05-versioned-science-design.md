## A. 版本化阶段交接

### 数据与兼容

新增浏览器安全 FileVersion（path、sha256、bytes，及可选 observationId/versionId）和 TaskVersions（version:1、inputs、outputs）。TaskSettings 可带 versions.inputs，TaskReceipt 可带 versions。模型 TaskResult 不接受这些宿主字段。冻结输入与 contract.inputs 必须一一对应；比较内容身份仅使用 path/hash/bytes，观察记录 ID 不参与比较。

原记录缺少版本字段时保留原语义，明确为 legacy/unbound；不凭当前文件补造过去版本。新 start_science_pipeline 默认在受控哈希完成后冻结输入版本。纯 reducer 继续可读取旧定义；新的模型入口和模板批量要求绑定。定义与三阶段基础设置保留同一初始输入快照；审阅任务使用最新已 accepted 分析回执的输出版本，修正分析仍使用原输入版本。

### 采集、提交与验收

复用 artifacts/blobs.fileIdentity 的 worker、路径检查、文件身份前后校验、字节/时间上限和取消。每阶段最多 64 个文件，单文件 64 MiB、累计 256 MiB，采集顺序执行；超限、缺失、路径不安全、采集失败或取消均不静默退化。超大真实数据需另行确定支持范围，不用 mtime 冒充内容哈希。

1. 后端在原产物锁内、启动模型前核对冻结输入；不一致直接 blocked，不启动模型。
2. 正式 submit 进入 validating 状态，禁止并发新工具/重复提交；参数错误可恢复本轮。异步采集结束后再次核对 signal、活动调用与终态，封存输入和输出版本。合法版本冲突封存 blocked，禁止通过 revise 绕过。
3. 普通子进程 done 回传封存版本；父端解析并复核当前文件与这些版本，缺失版本证明不得满足新版本契约。本地 Bot 同样在原占用内复核，取消仍等待原后端清理。
4. 实际桌面装配通过可选宿主 recorder 把版本交给 ArtifactStore.observe，复用 artifact_versions；CLI/独立测试没有数据库时仍保留真实哈希，版本观察 ID 保持缺失，不构造虚假记录。

只读科学核查/审阅继续预约声明输入，分析和宿主汇总继续使用原写占用。哈希绑定并不阻止外部编辑，不自动复制大数据或留存所有文件字节；既有留存功能继续负责不可变字节交付。

### 恢复与路线

显式恢复前核对原输入、已 accepted 且仍作为交接依据的输出版本；不一致保持 interrupted/blocked，不能通过 acknowledgeInterrupted 接受不同数据。未开始的分析产物不要求预先存在，中断分析留下的未验收输出不冒充 accepted 版本。正常受控修正允许覆盖同项声明输出，旧版本和回执保留。

路线完成投影在原 CAS/去重基础上，先在受控读占用内复核版本，再同步写回。异步投影有父会话生命周期、取消及 drain；主会话停止后不能迟到写路线。路线冲突不覆盖新路线，版本冲突不把当前文件标为已核验。旧未绑定流水线仍可按原版本规则投影。

## B. 模板与有界批量

### 模板契约

宿主内置、版本化注册表，不接受任意脚本/Schema。工具可列出模板及所需条件。每次启动冻结模板 id/version、用户批准方法、数据背景、输入和角色选择。

- `tabular-ecology@1`：已有表格/生态数据，明确方法及单位/缺失值规则；输出分步脚本、结果 JSON、方法报告。核查报告问题应阻塞。
- `figure-reproduction@1`：已有文献证据文件和绘图数据，明确文献标识、页码/目标图及允许转换；输出分步脚本、SVG 图和复现说明。文献提取与科学方法选择由既有路线/证据流程完成，不以读取 PDF 字节代替证据核验。

脚本语言首版 Python/R，生成路径由宿主确定；输入和其他项产物不在 outputs 中。输出在用户选择的结果根目录下进一步以稳定请求身份/项 ID 隔离，禁止原始数据目录、路径别名及输出重叠。

### Team 批量状态

新增 team.scienceBatch，保存版本、冻结公共定义、项目项、当前项、已结束项的 pipeline 快照、批量状态/修订、汇总任务身份。当前项仍使用 team.pipeline；阶段任务 ID 加项命名空间。每项原 pipeline 的推进、归档和下一项建立同一次 team.json 原子写入。

失败策略固定 fail-fast：blocked/unknown failure 停止后续项，保留所有已验收项。正常重开标 interrupted，不自动执行。恢复只继续中断项或宿主汇总；保留已完成项，不重跑。专用 start/status/resume/cancel_science_batch 管理生命周期；原 pipeline 的 resume/cancel 不能绕过批量状态，通用 Team/Bot 消息和派单保护继续覆盖。

全部项 accepted 后创建一个明确的宿主汇总任务，使用原 Team attempt、编排准入、写占用和结算，由固定宿主处理器执行而非额外模型。汇总仅消费 accepted 回执与匹配版本的产物，生成 JSON 与 Markdown 索引，保留每项指标、问题、产物路径/哈希和来源，不推导新的科学结论。中断汇总不自动重放，需按原未知效果规则恢复。

批量路线只在全部项及汇总通过后投影一次，引用所有项目来源和交付；部分完成不能写 delivered。公共快照输出可展示事实，排除内部冻结配置；沿用原团队界面补批量进度与汇总入口。

## C. 评测基线

同一组合成输入、批准方法、输出要求、确定性 localhost 模型配置与宿主验收，分别运行单 agent 和多 agent 两种软件路径。使用真实 Pi/工具/文件与既有 observation，不用模型自报结果判分。

首批用例：正常表格、单位缺失阻塞、一次审阅修正、输入版本变化、停止后恢复。公共验收检查正确交付/应阻塞、数值与证据、原输入未改、版本一致及无重复阶段。记录每项成功、错误接受、调用数、可见 token/partial/unknown、耗时、返工和宿主记录的干预次数，保存配置/数据集/源码身份以便重现。

命令输出独立 JSON/Markdown；标明 deterministic-local，只证明软件路径与测量口径，不据此声称真实模型成功率、费用或并行加速。提供相同条件的真实任务记录格式；不自动调用真实服务商，不填不存在的费用/usage，不引入整个流程 token 预算系统。
