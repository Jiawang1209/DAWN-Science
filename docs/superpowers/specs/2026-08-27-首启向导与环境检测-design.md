# 首启向导与环境检测：装上就能聊、就能算

> 「开箱即用」第二轮（第一轮是 `2026-08-27-打包-design.md`：装得上）。作者 2026-08-27 定的口径：
> **key 用户自己申请；Python / R 用用户机器上的解释器，缺包就引导装；两门语言都检测、都引导。**

## 0. 定下的

| 问 | 定 |
|---|---|
| 模型 key | 用户自己的。向导第一步就要，填完立刻可聊 |
| Python / R | **不打进包**。探测机器上的解释器，列候选让人选；缺内核包就给出**按环境定制**的装法 |
| 装包怎么装 | 「在终端里帮我跑」：命令在坞里现有的终端**可见地**跑，进程退出后自动重探、装成了自动回填路径。另给「复制命令」 |
| 准入 | 向导只要求 key。Python / R 都可带 ✗ 离开（只用一门的人不该被另一门拦）。真用到时按现有那句「还没配 X」出声 + 一键回向导 |
| 向导出现条件 | 没有任何凭证 **或** Python 与 R 都没配。出现在主区整屏，可跳过；设置里新开「环境」一格是同一个组件 |
| git / Node | 只检测、只展示，不引导：git 缺了概览里的「变更 / 分支」降级成一句话；Node 只在 ACP 适配器要用时才相关（下一轮把适配器打进包，不再要求） |

## 2. 探测：协议操作 `probeEnvironment`

```ts
probeEnvironment: {
  request: z.object({}).strict(),
  response: z.object({
    python: z.array(解释器候选), r: z.array(解释器候选),
    git: z.object({ found: z.boolean(), version: z.string().optional() }),
    node: z.object({ found: z.boolean(), version: z.string().optional() }),
    probedAt: z.string(),
  }).strict(),
  mutating: false,
}
解释器候选 = {
  path: string,                       // 绝对路径（已 realpath）
  source: "settings" | "PATH" | "kernelspec" | "homebrew" | "pyenv" | "conda" | "venv" | "framework" | "windows",
  version?: string,                   // "3.11.9" / "4.3.2"；起不来就没有
  kernelPackage: "present" | "missing" | "unknown",   // ipykernel / IRkernel
  managed?: "homebrew" | "system" | "conda" | "pyenv" | "venv",  // 决定装法口径
  problem?: string,                   // 起不来时它自己说的（末尾几行）
}
```

- **候选从哪来**（去重后按 `settings` > `kernelspec` > 其它 排）：
  - Python：`settings.interpreter.python`；PATH 上的 `python3` / `python`；`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`；`~/.pyenv/versions/*/bin/python`；`~/miniconda3|anaconda3|miniforge3/bin/python` 与其 `envs/*/bin/python`；`~/.venv*/bin/python`、`~/DAWN/venv/bin/python`；kernelspec 的 `argv[0]`；Windows：`py -0p` 的输出、`%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`、`%USERPROFILE%\miniconda3\python.exe`。
  - R：`settings.interpreter.r`；PATH 上的 `R` / `Rscript`；`/opt/homebrew/bin/R`、`/usr/local/bin/R`、`/Library/Frameworks/R.framework/Resources/bin/R`；Windows：`C:\Program Files\R\R-*\bin\R.exe`。
- **每个候选真起一次**（并发 4、单个 8 s 超时，超时 = `unknown` + `problem: "8 秒没应答"`）：
  - Python：`<path> -c "import sys,json; ok=True\ntry:\n import ipykernel\nexcept Exception: ok=False\nprint(json.dumps({'v':'%d.%d.%d'%sys.version_info[:3],'k':ok,'prefix':sys.prefix,'base':sys.base_prefix}))"`。`prefix != base` → venv；路径含 `conda` → conda；`/opt/homebrew` 或 `Cellar` → homebrew；`/usr/bin/python3` → system；`.pyenv` → pyenv。
  - R：`<Rscript> -e 'cat(paste(R.version$major, R.version$minor, sep="."), requireNamespace("IRkernel", quietly=TRUE))'`。
- git / node：`git --version` / `node --version`（PATH），2 s 超时。
- 探测是纯读；结果不存，每次进向导 / 环境格重探（几秒），按钮「重新检测」。

## 3. 装法口径（按 `managed` 定，一处函数 `装内核包的命令(候选)`，可测）

| 候选 | Python 给 | R 给 |
|---|---|---|
| venv / pyenv / 普通 | `<path> -m pip install ipykernel` | — |
| conda | `<conda 的 bin>/conda install -y -n <env> ipykernel`（认不出 env 就退回 `<path> -m pip install ipykernel`） | `conda install -y r-irkernel` |
| homebrew / system（PEP 668） | 两句：`<path> -m venv ~/DAWN/venv` 与 `~/DAWN/venv/bin/python -m pip install ipykernel`；**装成后回填的是 venv 那个 python**，界面上明说 | — |
| R 任何来源 | — | `<Rscript> -e 'install.packages("IRkernel", repos="https://cloud.r-project.org"); IRkernel::installspec()'` |
| Windows | 同上，路径与 `Scripts\python.exe` 的差别在函数里处理 | 同上 |

## 4. 「在终端里帮我跑」

- 开坞里的终端（已有 `shell` pty），把命令**原样写进去并回车**——人看得见每一个字。不新造执行通道。
- 命令末尾拼 `; echo "__DAWN_SETUP_DONE__ $?"`（Windows：`; Write-Host "__DAWN_SETUP_DONE__ $LASTEXITCODE"`）；主进程订阅那段 pty 的输出，见到哨兵即重探：装成了 → `setInterpreter` 回填（PEP 668 那条回填 venv 的 python）→ 向导那一行变 ✓；没成 → 那一行红字「没装成，终端里有原因」，命令留着。
- 不自动跑两次；人可以在终端里自己接着敲。

## 5. 界面

### 5.1 向导（主区整屏，`.setup-wizard`）

见 2026-08-27 对话里那张图。三段：① 模型 key（服务商下拉 + key 框 + 保存，走现有 `setCredential`）；② Python；③ R；末尾一行「其它：git ✓ 2.43 · Node ✗（只有 ACP 适配器要）」。右上「先跳过，之后在设置里改」，右下「开始使用 →」（只看 ①）。

每门语言那段：候选单选列表（路径 · 版本 · 内核包 ✓/✗/?），「手动填路径…」，选中项缺包时下面出装法 + [在终端里帮我跑] [复制命令]，装成后自动填进设置。一个候选都没找到 → 「这台电脑上没找到 Python。装一个（python.org / Homebrew / conda），装完点重新检测」+ [手动填路径…]。

### 5.2 设置 → 「环境」

同一个组件，去掉「开始使用」那颗，多一颗「重新检测」。原「内核」屏保留两个路径框（手动口），顶上加一句「不确定填什么？去「环境」看这台电脑上有哪些」。

### 5.3 出声的地方对齐

- 底部红字「还没有填任何 API key」→ 点它进向导 ①。
- 笔记本 / `run_code`「还没配 Python 的解释器路径」→ 句末加「去检测 →」进向导 ②。
- 概览里 git 缺失：「没装 git，装了就有变更与分支」。

### 5.4 什么时候出现

`app` 启动后界面拿到 `getCredentials` 与 `getInterpreters`：没有任何凭证 **或**（python 与 r 都空）→ 主区显示向导而不是空态；`localStorage["dawn.global.setupSkipped"]` 记跳过（跳过后底部红字仍在，那是回来的路）。e2e / dev:mock 跑的是 `DAWN_SKIP_CREDENTIAL_GATE` + 未配解释器 → **夹具要把 `setupSkipped` 预置为 true**，否则全部用例的第一屏都变了（本项目 2026-08-12 那种「十几条同时红」）。

## 6. 失败必须出声

| 情况 | 说什么 |
|---|---|
| 候选起不来 / 超时 | 行内 `?` + 悬浮/展开它自己说的末尾几行 |
| 一个都没找到 | §5.1 那句 + 手动填 |
| 装包跑完没成 | 红字「没装成，终端里有原因」，命令留着 |
| PEP 668 | 明说「这是 Homebrew/系统管的 Python，直接 pip 会被拦；建议单独建一个环境」，回填的是 venv |
| 探测本身抛错 | 向导顶上一条红字 + 重试；不拦 ① |
| Windows 上没有 `py` | 只按目录找，找不到就 §5.1 那句 |

## 7. 验证

- 单元：候选枚举（假文件系统）；解析 python/R 的探测输出；`装内核包的命令` 五种口径；哨兵行解析。
- e2e：夹具造两个假 `python`（一个 import ipykernel 成功、一个失败）放进 PATH → 向导列出两个、状态对；点「在终端里帮我跑」（假命令 `true`）→ 哨兵回来 → 路径回填进设置；跳过 → 底部红字仍在、点它回向导。
- 打包产物冒烟（`test:packaged`）加一项：探测不炸、至少列出本机 python。
- `dev:mock` 人肉看一次向导形态。

## 8. 不做的

- 不打包 Python / R；不自动装（只可见地跑用户看过的命令）。
- 不管 Jupyter 以外的 R 内核方式。
- ACP 适配器不要求 Node、Win/Linux 真机验证、签名——各自另一轮。
