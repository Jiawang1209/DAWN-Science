# 本轮复验的固定观察口径

## 待验证假设

1. 可信目录和引用能减少 acceptance 遗漏/弱化，且不把模型建议变成用户批准。
2. deliveryGuide 的精确键和本轮证据选择能减少正式提交退回；保持原科学验收，错误结果不得因为引导更方便而放行。
3. 缺单位方案可明确进入 awaiting-info，补充答案只生成新方案，采纳前不执行。
4. 生产目录与评测共享同一确认来源/工厂/查询路径后，收益不再只是评测注入的特例。

## 必须分别报告

| 指标 | 分母/依据 | 不允许的混算 |
| --- | --- | --- |
| 有效方案/编译率 | 自动安排的已启动组、实际提案与宿主编译结果 | 澄清问题不当成格式错误，也不算已执行方案 |
| 合格交付率 | 全部已启动数值题组；accepted 后独立真值/版本核对 | 不只统计成功组；早停失败仍在分母 |
| 正确阻塞 | 缺单位题真实成功读输入、正式 blocked、没有推断结果 | awaiting-info 不计正确 blocked，不与答错混称 |
| 正式提交摩擦 | 宿主 observation 的 submissionAttempts/invalidSubmissions 与实际反馈 | 纯文本不当正式提交；SDK未执行与宿主退回分开 |
| 成本比较 | 同题同 repeat、双方均合格配对的请求/耗时/可核验用量 | 不完整/失败早停不制造节省；token不称费用 |
| 阶段用量 | 规划/执行/审阅的互斥 scope、请求门与结算回执 | 缺失/partial不当0，不重计缓存读取 |
| 取消/未运行 | 信号、请求门在途、宿主终态和输入字节/输出检查 | 中止请求已接收不等于执行排空；未运行不装作正确 |

上一轮真实148次、两个双方均合格配对，仅作为原错误类型和参考，不并入本轮样本。新额度尚未明确时请求0。目录有check/analyze/review三项不预设必须派3个Agent。

## 固定边界

真实提案为三题、单/自动各重复2次、每组25、全轮最多300，自动工作18/审阅7，失败不重跑。只有最终候选冻结且收到新增额度后联网；源码或配置变化使当前比较失效，按原guard停止后续组。历史退出超时与PTY问题继续OPEN，不改1500/4000ms。
