# agent 的浏览器（③）

## 为什么有这份文档

作者 2026-08-18：*「浏览器房客是干啥的，是按照 codex 模仿来做的打开浏览器页面吗？」*
一查，`2026-08-17-远端文件与右侧坞-design.md` 里那句「坞里三个房客：审阅 /
**浏览器** / 文件」**是我编的**——那份文档每条决定都带作者原话，唯独它没有；
而且它与规格 `2026-08-06` §4「非目标」里那条**「内嵌浏览器 → 不做」**直接打架。
勘误已记在那份文档第十二·六节 ③。

作者当日定的形状：

> *「我们改为 Codex 的『浏览器』是给 agent 用的（browser use），
> 跑在隐藏的 webview 里，不是给人开网页的一栏。」*

**这与那条「非目标」不冲突，理由要写下来**（和当初推翻 `files/access.ts`
那条「只读」禁令同一个规矩）：那一行来自 wispterm，指的是**终端里内嵌一个
给人用的浏览器**——一个 UI 表面。这里要的是**给模型用的一件工具**，
它没有可见表面。**两件事共用一个词，不共用一个判断。**

## 一、Codex 那边的形状（量出来的，只读文件名）

边界照 `docs/REFERENCES.md`：**读事实，不读表达**——下面全部来自
`«REF»cx_app_learn/webview/assets/` 的 `ls`，**没有读任何 bundle 内容**。

| 文件名 | 说明 |
|---|---|
| `browser-use-settings-*.js` | 一个「**browser use**」的设置页 |
| `hidden-browser-use-webview-host-*.js` | **hidden** |
| `hidden-background-webview-host-*.js` | **hidden** |
| `thread-browser-panel-tabs-*.js` | 152 字节，**且没有对应的 CSS chunk** |

对照组说明这条判据有效：`pdf-preview-panel` 与 `terminal-panel`
**各自都有独立的 CSS chunk**，browser 一个都没有。

**能得出的结论**：他们的浏览器跑在隐藏 webview 里，有自己的设置页。
**不能得出的**：它内部怎么驱动、给模型摆了哪些工具、cookie 怎么隔离——
那些在 JS 里，不读。**这份 spec 不假装知道它们。**

## 二、先量：我们今天有什么

| 问 | 量出来的 |
|---|---|
| pi 自带浏览器工具吗 | **没有**。`pi-coding-agent` 内置工具只有 `bash` / `edit` / `find` / `grep` / `ls` |
| 有没有接第三方工具的缝 | **有**。`src/mcp/客户端.ts`（官方 SDK 的 `Client` + `StdioClientTransport`）→ `native.ts:698` `toolsFor` → pi 的 `customTools` |
| 那条缝支持什么 | **只有 stdio、只有 tools**（`客户端.ts` 头注：resources / prompts 与 HTTP/SSE 都明确不做） |
| 起服务器的超时 | 60 秒（`npx` 首次要下包，20 秒不够——那次实测写在注释里） |
| 工具怎么命名 | `<服务器名>__<工具名>`，双下划线分隔；**工具名里不许再有 `__`**（`名单.ts` 有校验） |
| 门在哪 | `policy/permissions.ts`；**默认拦，除非那台被过目过（`trusted`）** |
| `trusted` 存在哪 | `settings` 的 `mcp.trusted.<名>`——**不许进 `providers.yaml`**（`config/schema.ts:315`：*「那是个漏洞」*） |
| 密钥怎么给 | 配置里只**声明**要哪几个环境变量，值进钥匙串 |
| 外部工具写的文件进账本吗 | **进**（`a849587`，2026-08-18 刚补的）。`beginExternal()` 一律观察 |

**结论：一台浏览器 MCP 服务器今天就能接上，一行代码都不用写。**

## 三、于是第一步不是写代码，是配一台

用户动线全部现成（`e2e/mcp.spec.ts` 那几条已经在验）：

1. 侧栏「MCP 服务器」→ **粘一段 JSON**（`{"mcpServers": {...}}`）
2. 按「试一次」→ 真的起进程、说协议、**把它有哪些工具列出来**
3. 拨「信任」开关 → 模型才调得动

候选两台（都是 stdio）：`chrome-devtools-mcp`、`playwright-mcp`。

> **一条实测的量**：本文档写作时所在的这台机器上接着一台 `chrome-devtools`
> MCP，它摆出来的是 **29 个工具**（`navigate_page` / `click` / `fill_form` /
> `take_snapshot` / `take_screenshot` / `evaluate_script` /
> `list_network_requests` / `list_console_messages` / `performance_*` /
> `lighthouse_audit` …）。**这是那一版的表面，不是所有浏览器服务器的通例。**

**29 个工具是一笔要摆到台面上的代价**，见第七节。

## 四、要害：**浏览器的溯源是 URL，而 URL 事后验不了**

这是这份 spec 唯一真正难的地方，也是唯一只有我们答得出的地方。

### 今天账本能答什么

刚补完那一轮之后：

| 事实 | 有没有 |
|---|---|
| 「调用了 `browser__navigate_page`」这件事 | ✅ 一条 Run，`request_type = tool_call:browser__navigate_page` |
| 它写了哪些文件 | ✅ `files_written`（`git status` 差集，观察出来的） |
| **它去了哪个 URL** | ❌ **没有**。`runs` 表**没有存工具入参的列**（`store/schema.ts:70`） |

入参只在**转录**里。而转录与账本在这个项目里是**两层**：
转录是「说了什么」（声明层），账本是「发生了什么」（事实层）。
**不变式 5 的全部重量就在这条分界上。**

### 为什么不能照搬「文件」那一套

内置工具那条能把「声明的路径」并进账本，**是因为跑完可以 `stat` 一下**——
声明只是候选，**存在与否是观察**。那不是转述。

**URL 没有对应的 `stat`。** 模型说它去了 `https://…/data.csv`，
我们**没有任何独立于它的证据**能确认这件事。硬记下来，账本上就会出现
一条长得像事实、其实是转述的记录——**那正是不变式 5 明令禁止的东西**。

### 三条路，代价与诚实度都不同

| | 做法 | 账本上那条记录的性质 | 代价 |
|---|---|---|---|
| **甲** | 什么都不记 URL | 诚实，但**「这份数据哪来的」答不出** | 0 |
| **乙** | 记入参，**并标明它是声明不是观察** | 诚实且有用。先例现成：`may_include_user_edits` 就是这种「如实标注不确定」的字段 | 一列 + 一处界面措辞 |
| **丙** | **我们自己发请求**（隐藏 webview / 自己的抓取层） | 观察级事实：请求是我们发的，我们看得见 | 一整套自己的实现与安全面 |

**建议乙作为第一步**，理由是它把「我们知道什么」如实摆出来，而且成本极低；
**丙留给第五节那条触发线**。

> **乙 的界面纪律**：`files_written` 与「声明的来源」**不许长得一样**。
> 前者是观察，后者是转述——**两处长得一样的东西，等于没有判据**
> （这个项目 2026-08-12 一天被咬三次）。措辞要说得出区别，
> 比如「它说它去了 …」而不是「它去了 …」。

## 五、什么时候才值得自己做隐藏 webview

**先写下触发线，免得将来靠感觉决定。** 满足其中任意一条才动手：

1. **URL 溯源必须是观察级的**——即作者说「『它说它去了』这句话不够，
   我要知道它真的去了哪儿」。这是最可能先到的一条，因为它直接顶着不变式 5。
2. **需要共享登录态**：要访问一个必须登录的数据库/期刊站，而
   「让用户在一个我们控制的浏览器里登一次」是唯一可行的动线。
3. **装不动**：`npx` 拉不下来、Chromium 装不上，在目标用户（科研机器、
   内网、无外网的集群）上成了常态。**这一条要有真实反馈才算数，不是预判。**

**在那之前，自己做一个浏览器是拿最贵的做法解决一个已经有解的问题。**

## 六、门：`trusted` 是不是太粗了

现在的门是**每台服务器一个开关**。对一台浏览器服务器，拨开之后模型就能去
任何地方。要不要细到域名？

**先说事实**：门的签名是 `gate(name, params, { workspace, remote })`——
**它看得见入参**，所以「只许这几个域名」在我们这一层做得到，不需要改架构。

**但第一版不做**，理由与「文件名搜索」那次同一条：

- 域名白名单的**默认值**才是要害。默认全禁 → 每次都要人来拨，
  那这个工具在实际使用里等于不存在；默认全放 → 白名单只是摆设。
- 而**「这台服务器能干什么」本来就该在拨开关那一刻看清楚**——
  「试一次」已经把 29 个工具列出来了，那才是知情的时刻。

**记下来的一条**：如果将来真要做，做成**「问一次人」**而不是「静默拦」——
`mcp-tool.ts` 那条注释写着拒绝要回 `isError` 让模型学到，但一次
「要不要让它访问 example.com」的询问需要主进程↔界面的往返，
**那条往返今天还不存在**（`Settings.tsx` 的权限那一节已经如实写着这件事）。
**不存在的能力不该看起来存在。**

## 七、代价，逐条摆出来

| 代价 | 大小 | 说明 |
|---|---|---|
| **29 个工具挤进上下文** | 大 | 每一轮都要把它们的名字与 schema 发给模型。**pubmed 那台有几个工具我没量过，别拿它当对照**。**要量一次**：接上前后 `context-usage` 那一屏的差 |
| 名字变长 | 小 | `chrome-devtools__list_network_requests` 这类。`工具全名` 的双下划线约定扛得住 |
| Chromium 体积 | 中 | `playwright-mcp` 会拉一个浏览器二进制。**这与 Playwright 进 devDependencies 是同一笔账**（`phase1b-prime-desktop.md` §117 已经算过一次） |
| 首次启动慢 | 中 | `npx` 下包。我们的超时是 60 秒，**并且会如实说「它还在下载」还是「它坏了」** |
| **真实 Chrome 的登录态** | **大** | 某些配置会让服务器接管**用户自己那个** Chrome——于是模型继承了全部已登录会话。**这一条必须在文档里写死：默认用独立的 user-data-dir，不接管用户的浏览器** |
| 每次调用一对 `git status` | 小 | 刚补的溯源。`bash` 早就在付同样的账 |

## 八、不做什么

- **不做给人开网页的一栏。** 那是被勘误掉的那个东西。
- **不自己写浏览器自动化**（第五节那三条触发线之前）。
- **不做域名白名单**（第六节）。
- **不把 URL 当事实记**（第四节甲/乙之别）。
- **不替用户装东西。** 装 `chrome-devtools-mcp` / `playwright-mcp` 是用户
  在自己机器上的决定；我们最多在文档里给出那段 JSON。

## 十、怎么验

| 判据 | 怎么做 |
|---|---|
| 那条缝真的吃得下一台浏览器服务器 | 批 0 手动走一遍；**只有真的接上才算**（ACP 那轮的教训：纸上的形状全是假设） |
| 工具真的被执行了 | 照 `e2e/mcp.spec.ts` 那条「有物证」的写法——**屏幕上「看起来调了」证明不了任何事** |
| 上下文代价 | 接上前后各量一次 `context-usage`，**差值写进文档**。超出预期就要重新考虑第七节第一行 |
| 声明与观察分得开 | 界面上那两处文案**没有一个是另一个的子串**，且措辞说得出「它说」与「我们看到」的区别 |
| 不接管用户的浏览器 | 配置样例里**必须**带独立 user-data-dir；文档里写清楚不带的后果 |

## 十一、这份 spec 自己的一条限制

**第一节之外，关于 Codex 的一切都是推断。** 我们只看了文件名。
「他们怎么把 29 个工具的上下文代价压下去的」「他们的 webview 用什么隔离
cookie」——**这些都不知道，而且不打算去知道**（那要读 bundle，越界）。
遇到同样的问题时，我们自己解，并把理由写在自己的文档里。
