## 0. 需要作者定的

下面每条都给了推荐默认，**计划按默认往下做**；作者改哪条，计划里对应的那一步跟着改。

| # | 问题 | 推荐默认 | 另一种 |
|---|---|---|---|
| 1 | 装好之后默认开不开？ | **三种都开**（做完 / 出错 / 等你点头），外加「正看着那段对话时不弹」也开。与微信 / 飞书的 `NOTIFY_DEFAULT` 同一张表 | 默认全关，设置里自己开 |
| 2 | 窗口在前台、但人看的是**另一段**对话时，弹不弹？ | **弹**。那段的回复 / 权限卡此刻不在屏上，侧栏那个未读点太小；Codex 也是这样 | 只在窗口不在前台时弹（与微信「在电脑前就不推」同一口径） |
| 3 | 「做完了」要不要时长门槛？（微信是 60 秒，`DONE_MIN_MS`） | **不要**。桌面通知只在人没看着时才弹，3 秒的一轮你切走了也想知道 | 沿用 60 秒 |
| 4 | Dock 上的数字数什么？ | **还没看的那几段**：弹过通知、之后还没在前台看过它的会话数；看了就减。权限卡被答掉（在哪答的都算）那段也减。**Windows 没有数字**，改成任务栏按钮闪，回到窗口就停 | 数通知条数；或者不做角标 |
| 5 | 哪些会话会弹？ | native / acp / cli 对话、坞里的侧边对话、远端会话都弹；**定时任务**只弹一条「定时『X』跑完了 / 失败了」（不再另弹一条普通的「做完了」）。**不弹**：终端（pty）、纯内核会话、子 agent 与团队成员（它们是队长那一轮里的子进程，队长那一轮收尾时一起报） | 定时任务不弹 |
| 6 | 通知里的字用哪种语言？ | **跟界面语言走**：界面启动时与切语言时报给后端（存进同一把设置键）；界面还没报过就按系统语言 | 永远中文 |
| 7 | `dev:mock` 用真通知还是假通知？ | **假的**，与 e2e 同一份（准入规则 1），控制台打一行 `[桌面通知·假]`；要看真横幅就 `DAWN_FAKE_NOTIFY=0 npm run dev:mock` | 默认真的 |
| 8 | 微信 / 飞书的「跑完」「出错」要不要也换成这次的判据（§3.1）？ | **这一轮不动**，下一轮单独做（它们各有自己的 e2e，一起改风险翻倍） | 这一轮一起换 |
| 9 | 设置里要不要一颗「发一条试试」？ | **要**。macOS 可能静静拦掉未签名应用的通知，而 Electron 查不到授权状态——人只能靠亲眼看一条 | 不要 |
| 10 | 带不带声音？ | **系统默认**（不静音，也不加开关）；人在系统设置里能关 | 默认静音 |

## 1. 要解决什么

作者用 Codex app / Claude app 的习惯：让 agent 跑一个长任务，切去干别的，**做完了、出错了、要你点头了**，右上角弹一条，点一下就回到那段对话。

DAWN 现在：

1. **电脑上什么提醒都没有。** `src/electron` 里一处 `Notification` 都没有；只有绑了微信 / 飞书才会推到手机上。
2. **「问一句」那一档最吃亏。** 权限卡最多等 5 分钟（`src/runtime/native.ts`：「最多等 5 分钟；会话中止也算拒」），人切走了就看不见卡，回来时这一步已经按拒绝处理了。
3. 侧栏已经有未读点（`标未读`），但窗口不在前台时看不见。

## 2. 交互

### 2.1 什么时候弹

| 时刻 | 判据（§3.1） | 标题 | 正文 |
|---|---|---|---|
| 做完了 | 这一轮真收尾（runtime 的 `idle`），没失败、没被人按停止；收尾后 1 秒内这段没再动 | 「<会话标题>」做完了 | 回复的前 120 字；没有文字就写「（没有文字回复）」 |
| 出错了 | 这一轮收尾前出过一条标了 `failed` 的系统提示；或会话非零退出 | 「<会话标题>」出错了 | 那条提示的前 120 字 |
| 等你点头 | 快照里出现一张新的权限卡（按 `requestId` 去重） | 「<会话标题>」在等你点头 | 卡上标题的第一行 |
| 定时任务 | 调度器报这一次结束 | 定时「X」跑完了 / 失败了 / 取消了 | 摘要或错因的前 120 字 |

**不弹**（`quietWhenFocused` 开着时）= 窗口在前台 **且** 那段就在屏上（主区那段，或坞里挂着的那段）。
窗口不在前台、或人看的是别的段 → 弹（§0 第 2 条）。

### 2.2 点通知

```
  ┌──────────────────────────────────────────┐
  │ DAWN Science                        现在  │
  │ 「清洗 RNA-seq 表」做完了                  │  ← 点这里
  │ 已经把 12 个样本的低表达基因滤掉，结果在…   │
  └──────────────────────────────────────────┘
                       │
                       ▼
  窗口恢复、到最前 → 主区切到「清洗 RNA-seq 表」（侧栏那行的未读点同时消掉）
  那段正挂在坞里 → 打开坞的「对话」格，主区不动
  那段已经被归档 / 删掉 → 窗口照样回来，说一句「那段对话已经不在了」
```

### 2.3 角标

```
macOS Dock                     Windows 任务栏
 ┌────┐                          ┌────┐
 │ D ②│  ← 两段还没看             │ D  │  ← 按钮闪（橙色），回到窗口就停
 └────┘                          └────┘
```

- 弹一条通知 → 那段记为「没看」。
- 窗口在前台且那段在屏上 → 划掉（回到前台那一刻、主区 / 坞里换段那一刻各判一次）。
- 那段的权限卡被答掉（在哪答的都算，包括微信里回「同意」）→ 若它是因为权限卡记的，划掉。
- 会话被删 / 归档 → 划掉。
- 「发一条试试」不计入。

### 2.4 设置里的一格

设置「外观」下面新加一格「**桌面通知**」（与「外观」同属应用级偏好，放一起）：

```
┌ 设置分类 ─────────┐┌ 桌面通知 ──────────────────────────────────── [收回] ┐
│ ◐ 外观            ││                                                     │
│ 🔔 桌面通知   ◀── ││  一轮做完            这一轮收尾时弹一条。       [✓] 开 │
│ ▭ 文件引用        ││  出错                模型调用失败、会话异常退出。 [✓] 开 │
│ ▤ 用量            ││  等我点头            「请求批准」档下弹出权限卡时。 [✓] 开 │
│ …                 ││  正看着那段时不弹    窗口在前台、那段就在眼前时不弹。[✓] 开 │
│                   ││  ─────────────────────────────────────────────────  │
│                   ││  试一下              macOS 可能拦下未签名应用的通知， │
│                   ││                      按一下看它弹不弹。   [发一条试试] │
│                   ││                      已发出——没看到的话，去系统设置   │
│                   ││                      的「通知」里允许 DAWN Science。  │
└───────────────────┘└─────────────────────────────────────────────────────┘
```

- 四个开关的形状与微信 / 飞书那组一字不差（`{ done, error, permission, quietWhenFocused }`），缺省全开。
- 系统不支持（`Notification.isSupported()` 为假）→ 开关照画，上面一行 `caveat`：「这台系统不支持桌面通知」（失败必须出声，规格 7.5）。
- 开关改了立刻存；存失败回滚并出声（与微信那组 `审查 debug J8` 同一个做法）。
- 图标：新画一颗实心的铃（16×16，与设置里其它图标同一套壳）。

## 3. 判据（为什么不照抄微信那套）

### 3.1 与微信 / 飞书通道的对照

| | 微信 / 飞书（`src/channels/weixin/channel.ts` 的 `该不该通知`） | 桌面通知 |
|---|---|---|
| 听什么 | `events.onAnyUpdate`（每段会话每条更新） | **同一个**，外加中枢新开的一个口 `on回合收尾` |
| 权限 | 快照里 `pendingPermission`，按 `requestId` 去重 | **照搬** |
| 非零退出 | `state === "exited" && exitCode !== 0` | **照搬**，但 pty / kernel 会话不算 |
| 跑完 | agent 那条 `turn` 的 `final` | **换成 runtime 的 `idle`**。理由：`final` 在**每一次模型响应**后都会立一次（`src/runtime/types.ts` 里 `idle` 的注释：「pi 在每次模型响应后都发一次 `turn_end`——877 次工具调用对应 877 次」），一轮里调三次工具就是三个 `final`；桌面通知没有 60 秒门槛挡着，照抄会一轮弹好几条 |
| 出错 | **任何**一条 `notice` | **只认标了 `failed` 的**。理由：「已换到 X 模型」「MCP：…」「视觉转述失败，按原样发出」也都是 `notice`，照抄的话换一次模型就弹一条「出错了」 |
| 设置形状 | `{ done, error, permission, quietWhenFocused }`，存成设置表里一把键的 json | **同一个形状**，多一个可选 `lang`（§0 第 6 条）；键 `desktop.notify` |
| 在前台 | `isForeground()`（`BrowserWindow.getFocusedWindow() !== null`） | **同一个函数**，再加「那段在不在屏上」（后端从 `setSideSession` 已经知道主区与坞里各是哪段） |

微信 / 飞书这一轮不动（§0 第 8 条）。

### 3.2 「真收尾」从哪来

runtime 的 `idle` 今天**到不了中枢之外**：`SessionTranscripts.ingest` 的 `switch` 里没有 `case "idle"`，它被静静吃掉了（只有账本 `run-recorder` 认它）。所以：

- 中枢加一个口 `on回合收尾(cb)`：`ingest` 收到 `idle` 时叫一声，带上 `{ sessionId, kind, 失败? }`。
- `失败` 从哪来：runtime 的 `notice` 事件加可选 `failed: true`（**只是 runtime 内部类型，协议里的 notice 条目不变**）。中枢收到带 `failed` 的 notice 就记在这段上，`idle` 时交出去并清掉。
- 标 `failed` 的六处（都在 `idle` 之前发、都是「这一轮失败了」）：native「模型调用失败」、claude CLI「外部 CLI 报告这一轮失败」、codex CLI 的 `turn.failed` 与 `failure()`、cli 运行时「外部 CLI 这一轮没跑起来」、ACP「ACP 这一轮失败了」。

### 3.3 不是「做完」的收尾

- **人按了停止**：后端已经有 `停止次数`（`abortSession` / `stopSession` 各加一）。一轮开始（用户那条 `turn` 到）时记下，收尾时对一下，变了就不报。
- **调整方向 / 排着的下一句接着跑**：收尾后等 1 秒（`收尾静候毫秒`），这 1 秒里这段又来了用户话或 agent 输出 → 作废。

## 4. 分层

依赖决策（规格 §4）：

- **坐在 Electron 的 `Notification`（主进程）上**：① `new Notification({ title, body })`、`.show()`、`on("click" | "close" | "failed")`、`Notification.isSupported()`；`app.setBadgeCount(n)`（macOS / Linux）；`BrowserWindow.flashFrame(bool)`（Windows）；`app.setAppUserModelId("science.dawn.app")`（Windows 上不设 toast 不出来，值与 `electron-builder.yml` 的 `appId` 一致）。② 放弃：渲染进程的 Web `Notification`（它在窗口隐藏 / 未聚焦时的行为随平台而变，而且 e2e 抓不到）；通知上的按钮（`actions` 只在 macOS 有，「允许 / 拒绝」直接在通知上按——不做，点通知回到那张卡）。③ 不变式挂在：**全应用只有 `src/electron/desktop-notify.ts` 一个文件碰系统通知**（设计契约扫描），假通知与真通知走同一个 `点了`。
- **判断在后端（node 下可测）**：`src/workbench/desktop-notify.ts` 的 `桌面通知器`——听中枢、读设置、问「在不在前台 / 在不在屏上」，决定弹不弹、记角标。它不 import electron，出口靠注入（与 `isForeground`、`openPath`、`trashItem` 同一个注入缝）。
- **文案**：通知器只交 `{ msgid, args }`；出口按语言翻（`src/ui/i18n/en.ts` 的 `EN` 表，键是中文原文）。electron 层 import 一份数据表，不 import 界面逻辑。

### 4.1 点通知那条路

```
主进程：Notification 'click'（或 e2e 调 __dawn桌面通知.点(i)）
  → 点了(sessionId)：窗口 restore / show / focus（隐藏窗口的 e2e 里不 show）
  → webContents.send(事件通道, { workbenchProtocolVersion, openSession: sessionId })   ← 第五种载荷
渲染进程：client 按形状认出 openSession（在会话更新那句判据之前）→ App：
  坞里那段 → 打开坞里的对话；在任务名单里 → 标未读(false) + 切主区；都不在 → note 一句
  切主区会触发 setSideSession → 后端 桌面通知器.看见了() → 角标减
```

## 5. 协议

**minor 递增**（写这份规格时是 8.0；**执行时取当时的下一个 minor**——别的计划在并行，不写死数字）。全是新增：

- `desktopGetNotify` → `{ done, error, permission, quietWhenFocused, lang?, supported }`
- `desktopSetNotify({ done?, error?, permission?, quietWhenFocused?, lang? })` → 同上
- `desktopTestNotify({})` → `{ shown, reason? }`
- 事件通道第五种载荷 `OpenSessionPush = { workbenchProtocolVersion, openSession }`

**mock 同一次改动补上**（硬性准入规则 1）：

- `scripts/mock-inference-server.mjs` 两句暗号：「演一次失败」→ 这一问 401（会话里出「模型调用失败」）；「演一次权限」→ 先说一句、再调一条 `curl` 本机 9 号端口的 bash（「请求批准」档下弹权限卡；放行也只是一次立刻拒连的本机连接）。「做完了」任何一句都行。
- 系统通知这一侧的假的：`DAWN_FAKE_NOTIFY=1` → 不碰系统，记进主进程 `globalThis.__dawn桌面通知`；**e2e 夹具与 `dev:mock` 都开它**（同一份）。

## 6. 测试

- 单元：中枢 `on回合收尾`（idle 交出、failed 记账与清空、pty 也报但带 kind）；`桌面通知器` 的判定表（三种 × 前台 / 在屏上 × 开关）、静候作废、停止不报、权限去重与划掉、角标、定时、忘掉、文案都在 `EN` 里；出口（假：记录、点、前台；真：Windows 闪、macOS 数字、`failed` 出声、拿着引用）；后端三个操作与持久化、`setSideSession` 触发「看见了」；client 认第五种载荷；设置面板。
- 设计契约：`new Notification(`、`setBadgeCount(`、`flashFrame(` 只许在 `src/electron/desktop-notify.ts`。
- e2e（`e2e/desktop-notify.spec.ts`，真实构建产物 + 假通知）：做完弹 + 角标；在前台且在屏上不弹（同一条里再证管线活着）；点通知切回那段、角标清零；出错；等你点头 + 答掉后角标清；关掉「一轮做完」后不弹且重开还关着；「发一条试试」。
- 视觉基线：设置分类里多一行，「设置」「设置栏」四张会变——看 diff 后重存。

## 7. 不做

- 通知上的「允许 / 拒绝」按钮（只 macOS 有；点通知回到卡上答）。
- 按会话静音、免打扰时段。
- 微信 / 飞书判据的统一（§0 第 8 条，下一轮）。
- 应用没开着时的通知（DAWN 不常驻后台）。
