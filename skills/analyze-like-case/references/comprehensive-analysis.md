# 综合需求与分析路线

仅在用户提出综合分析需求、完整路线或“需要哪些分析”时读取。单项案例检索沿用技能入口的简洁路径。

## 1. 理解目标与数据起点

复用本会话已有的研究目标、数据起点、分组/重复或配对关系、语言/环境偏好及执行范围。不要把示例中的数据条件当成用户事实。

- 只影响细节的未知：给带条件的初步路线，并继续有价值的检索。
- 会改变主路线的未知：集中询问最多三个关键问题，已知信息不重复问。
- 用户先看概览时：可给分支路线，不要求先交全部数据，也不执行代码去摸底。

例如扩增子需求，应区分原始 FASTQ 与已有 ASV/OTU、分类和样本信息表，区分 16S 与 ITS；用户已有的输入决定从哪里开始。没有输入时不要猜样本数、分组、原始数据处理步骤或路径。

## 2. 先组织领域路线

由模型依据目标与起点形成领域步骤，用 S1、S2 等稳定编号。每步解释：回答什么问题、需要什么输入、预期输出、前置依赖、适用条件。用户修改路线时保留未变化的编号，说明受影响的步骤。

区分：当前目标的基础步骤、满足条件时适用的步骤、研究问题驱动的拓展。未知实验设计时，不把“基础”解释为任何研究都必须用某个固定统计检验。

**领域步骤不等于 MLAI 的建模阶段。** `recommend_pipeline` 的预处理、训练、评估等只用于适合建模的子问题；生态、组学等综合流程不能直接照抄它的固定阶段。

扩增子问题的组织示意是：输入准备与起点确认 → 群落概览 → 多样性相关问题 → 分组差异相关问题 → 环境关联相关问题 → 研究目标驱动的拓展。具体顺序和方法依赖研究设计；已有 ASV 表时不能默认再从原始测序处理开始，也不能把所有拓展分析列成必做项。

## 3. 逐步找真实依据

为每个步骤组织具体查询，并按技能入口的规则使用实际工具与受控过滤。不能只把整段综合需求查询一次就交回一堆相似标题。

- 默认每步展示 1–2 个代表候选，首次综合回复最多 8 个不同案例；优先覆盖当前起点能做的关键步骤。其他步骤明确标为“尚未展开”。用户要求全面盘点时可分页深入，并说明范围。
- 没命中时，可换同义表达、查询模式，或说明后放宽主题过滤；用户明确的语言等硬条件不随之移除。
- 使用 `search_chunks`、`recommend_figures` 的实际方法片段，或少量只读 `get_case` 核对候选覆盖范围。`search_chunks` 不支持任意 case_id 定向查询，不编造参数。
- 区分统计/分析内容与单纯绘图。图型和题目相似不能证明输入、任务或实验设计相同；输入要求只能来自实际读到的内容。
- 某步没有适合案例时仍保留该步的用途与前提，标明缺口；不能为了填满路线强配案例。

证据状态分两维：

| 维度 | 可使用的状态 |
| --- | --- |
| 检索状态 | 已查找到、已查未找到、调用失败、尚未展开 |
| 内容核对 | 仅元数据初筛、已核对相关内容、输入或设计仍待确认 |

模型给出的路线和方法建议与工具返回的案例事实分别说明。“查到”不等于“已读全文”，“verified”不等于“已在用户数据上验证”。只读片段或发生截断时标出核对范围。

## 4. 回答与卡片选择

按需要使用以下结构，避免长篇工具流水账：

1. 简短确认对目标、数据起点和关键未知的理解。
2. 路线表：步骤、目的、输入/前置条件、预期输出、适用性、候选标题或检索状态。
3. 候选清单：先说明本轮实际推荐的不同案例数量，再列工具返回的完整 ID、原始标题、语言、对应步骤、推荐理由、覆盖范围与核对程度。用标题指代案例，不再新编 C1、C2 编号；数量按实际推荐去重统计，不与检索总命中数混用。
4. 说明未展开、缺少适合案例或待核对的部分。
5. 邀请用户选步骤或案例，也允许调整路线或继续找。

同一案例跨步骤复用时只列一次完整 ID和一张卡片，在清单中记录所有对应步骤。每步都能对回真实候选或明确的检索状态，不虚构 ID，不把任意案例包装成整套流程。

当前卡片统一出现在回复底部，路线表与候选清单负责表达对应关系。不要承诺分组卡片、批量勾选或前端路线状态管理。只有本轮查到并在正文提到的案例才有卡片；后续展开某步要重新检索或读取其候选。

## 5. 后续选择

- “展开 S3”：解释 S3、补检索和候选，默认不执行。
- “看这个案例标题”：按标题对回完整 ID，核对代码和说明，解释适用性；查看不等于执行。旧回复中的 C 编号仍按当时的清单解析。
- “照这篇做”：按完整 ID 对回对应步骤，再遵守原有执行范围。
- 一篇涉及多个步骤、序号来自不同清单或上下文不足时，澄清具体歧义，不猜。

沿用技能入口的“选择后”规则。用户尚未选的其他步骤保持待选择；此前“先讨论、暂不运行”的要求继续有效。数据和授权足够时，直接完成已经授权的选定范围，不反复要求批准普通动作。
