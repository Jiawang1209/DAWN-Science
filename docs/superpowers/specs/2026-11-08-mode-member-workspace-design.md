# 编排选择与成员协作入口设计

日期：2026-11-08；基线 main `d0b6ca78`。用户已同意上一轮优先级 1、2，并要求详细计划、建立 /goal 后开发。

## 要解决的问题

1. 用户不知道小任务是否值得拆、多步任务能否并行、需要独立审阅时如何安排。
2. 协作台、流程工作台、子任务续问和 Bot 成员对话入口分散，打开以后难回到刚才的成员和详情。

## 选择与收益

采用小范围增量方案：本地、可解释的任务结构建议 + 共用成员入口 + 返回定位。全面自动规划需要额外模型成本且尚无收益证据；重建多 Agent 聊天会重复订阅与权限实现。这两种方案本轮不采用。

建议根据用户明确提供的任务块数、前后依赖、共用写入目标、独立审阅要求生成，不从随意关键词推断研究含义。候选为单任务、并行委派、串行交接、科研流水线。信息不全则提示补充；共用写入不推荐并行。要求独立审阅时保留现有科研流水线和审阅预留，不能用手选单任务取消该要求。

用户可以修改选择；“放入任务草稿”追加说明到当前所属会话草稿，绝不发送或自动启动。明确说明这是给模型的执行建议，并非执行约束或自动模式切换。实际执行仍由已有工具、冻结契约、预算、产物锁、验收和恢复机制负责。会话已有任务不会被切换模式。

## 成员界面

在协作台和展开详情共用一块成员入口：名称、角色（有记录才显示）、本轮身份、所属任务、可查看的内容和可用操作。普通 subagent 进入原来的过程/续问/实时纠偏/停止面板；团队成员查看当前团队快照中的邮箱（明确是消息而非完整逐步转录），需指挥时准备给队长的草稿；Bot 复用现有只读成员会话，不在展示入口直接激活对话。

只有 owner、child、team、member incarnation 全部匹配才关联成员。历史旧成员不得借用同名新成员邮箱或 Bot 会话。普通任务 index 必须安全非负整数；磁盘快照可读，不凭它声明当前可控制。宿主现有 inspect 决定子任务实际可续问、纠偏或停止。

从协作台打开普通子任务时记录窗口内返回来源，返回后恢复 owner、选中成员和 tab；若原来为展开工作台，先退出 modal，再打开成员，回来恢复展开与详情焦点。切换 owner 或从其他入口打开时清除该来源，不能返回到另一会话。Bot 只读面沿用现有任务保护和权限边界。

## 观测与评测

复用 evaluate:science 脚本入口，新增无需 API 的规划矩阵子命令，记录每个场景建议、原因、最终选择、审阅保留、并行冲突避免。覆盖小任务、独立块、前后依赖、共用输出、独立审阅、显式偏好、信息不足。该矩阵证明规则覆盖，不证明付费模型收益。旧真实模型 24 次试验保留，不再消费旧剩余额度。
