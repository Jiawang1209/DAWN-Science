# 应用内更新 · 实施计划

**Goal:** 装了旧版的人在应用里就能看见新版、点一下下完、点一下装上重启，**API key 不用重填**——
Claude / Codex 桌面版那个行为，不买证书做出来。

**Architecture:** 三层各自可测：①**纯判断**（版本比较、按平台挑资源、能不能自装、节流）；
②**两个接缝**（`发布源` / `安装器`，真假共用一份，准入规则 1）；③**装配**（backend 六个操作 + 侧栏一行 + 关于一格）。
key 交接是独立的一小块，挂在钥匙串预热之后，**与更新流程解耦**（没更新过也能自己跑，也能自己测）。
规格：`specs/2026-09-06-应用内更新-design.md`（定案 U1–U8）。

**Tech Stack:** TypeScript / Node 22 / Electron 43；zod（协议）；vitest；Playwright（e2e 走真构建产物）。
无新增运行时依赖——`fetch`、`node:crypto`、`ditto`/`unzip` 都是现成的。

**分支纪律：** 只在 `self-update` 上提交（从 `main` 开）。**never checkout / switch / stash**。
commit 写英文，不加 Co-Authored-By，**不推**。

**验证纪律（准入规则 3）：** 每个任务跑自己的测试；T3 后 `npm run typecheck`；
T4 与 T8 各有一次 `npm run dev:mock` 人肉看；**T9 是唯一算数的那条**（两个真包，真更新一次）。
