# 可见的增量科研交付与可执行验收

基线 main ce5ae5dd；专项 codex/incremental-science-acceptance。用户明确要求先制定方案、创建 /goal 后直接实施，并要求每次迭代展示实际效果；不重复请求开工批准。复用既有单实现主线、版本/契约/Team/锁/恢复，不推送、不发布，不自动提交或合并本批改动。

## 交付与取舍

本轮按依赖顺序交付三个可见里程碑：A 模板验收（防止未验收结果被复用）；B 派生批次与局部重跑；C 对照评测与完整演示。每个里程碑都有真实本地 Pi/Electron 或真实文件运行证据，展示实际界面/输出，不以效果图冒充实现。沿用现有团队面板，增补每项决策、规则、来源和当次执行统计，不新建复杂工作台。

比较过三种实现：全局自动缓存需要跨会话授权和完整依赖失效，当前成本高；原批次就地修改会混淆冻结契约和旧证据；选择显式引用同父会话的已结束源批次、派生新批次并逐项判定。旧回执和原始文件不改写，不伪造新执行/新审阅。复用表示采用可追溯历史交付，不声称当次重新计算。

## A. 受限、可执行、版本化验收

1. 在现有模板上增加可选结构化 validation@1；新批次总有基础规则：脚本/报告非空；表格结果为有效对象、有限数值和有效样本量；图表为有效 SVG、尺寸/viewBox合理、不含脚本/外链/事件属性，报告保留声明文献来源。规则由宿主执行，TaskResult 不能自报通过。
2. tabular-ecology 的数值核验须明确 dataPath、column、metric(mean/sum/min/max)、unit、missing(block/drop)、absoluteTolerance。不给这些参数时只做基础验收，UI必须写明“数值核验未配置”，不从 method/units 自由文本猜测统计方法。
3. 复用 files/table.ts 引号/分隔符解析与 artifacts/fileIdentity 的 readBytes。完整读取上限8MiB/单表、100000行、明确累计读取预算；禁止把预览200行当整表。列不齐、重复/缺失列、非数值、非有限值、空样本及被截断数据明确失败。JSON/SVG/报告各2MiB；读取沿原锁和取消通道，不新增脚本执行权。
4. 核验 result.json 的 n、unit、所选指标，并与正式 data.metrics、sampleCount 交叉检查；容差有限非负。失败以 blocked、明确 expected/actual/ruleId 交回，不能进入独立审阅。通过后仍保留原独立审阅，程序验收不代替科学认证。
5. TaskContract 冻结受限 acceptance 参数及规则版本；TaskReceipt 只增加宿主 acceptance 回执。正式提交、父端、Bot验收与复用重核共用一个异步封装，在原占用内运行；取消不封存，missing/stale proof不放行。原未配置契约继续兼容，不追补历史验收。
6. 规则只覆盖已明确支持的结构和统计量，不把任意方法都宣称验证完毕；本轮不运行模型任意生成的测试代码，不做全模型JSON Schema引擎。

## B. 显式派生与局部重跑

1. 扩展 start_science_batch 的可选 reuseFrom={teamId,stateRevision,forceRerunItems?,acknowledgeInterrupted?}，其余路线、模板、项与执行者继续使用既有请求。仅同父会话/同工作区源批次、状态 completed 或 blocked、没有活动旧执行可引用。interrupted 沿旧显式恢复，不在运行时偷取未完成项；未知副作用继续要求既有确认语义。
2. 新批次有新请求ID、独立新输出根目录、自己的 route CAS 和总结任务。当前指针可从明确引用且已排空的终态源批次转到新批次；不隐式覆盖其他活动团队。所有异步边界后复核 signal、源修订、当前指针与路线修订。
3. 每项签名包括：完整模板与验收版本、用户指令、原输入路径+hash+bytes、路线的科学语义、执行者定义/模型、冻结工具与权限、受支持环境证据与宿主版本。单独保存输出版本。更换输入、方法、规则、脚本、执行环境或权限时，对相应项给出失效原因并重跑；跨项目、缺证明、未知环境不猜测复用。
4. 环境证据复用 kernel/environment 的已有探测代码与解析/指纹。只执行固定的元数据探测，不执行模型代码；固定语言解释器、超时/输出限制、取消和包清单完整性检查。记录准入环境，并在分析正式验收时核对；仅可证的受控执行环境参与复用。未核实或执行命令不能关联时标未知并重跑。测试/演示使用实际 Python 探测，不能注入假环境冒充真实效果。
5. 候选必须整项 check/analyze/review 均完成、accepted分析与独立pass审阅匹配，原产物当前hash一致，规则重核通过。只有完整项复用；不从失败分析或部分阶段拼出通过结论。只读引用原文件，保留原环境、回执和taskId来源；新批次不追加写原文件。
6. 新Team保存可验证的已完成项投影及其闭合历史任务，标记 reusedFrom；不把复制历史任务排入执行，不把历史调用/token算入当次工作。当前item推进复用原reducer，逐项跳过已验收复用项后运行必需项。稳定索引防ID冲突；最多8项及原文件/尝试上限不变。
7. 新增每项 decision={reused|rerun,reason,source?}、验收摘要及当次观察。汇总既能包含历史项也能包含新执行项，保留来源、版本及“当次未执行”标识；最终仍重核全部输入/产物/总结并按新路线CAS。取消、重开、未知效果确认和汇总恢复继续沿既有机制，不自动重放。

## C. 展示与收益证据

团队面板在现有位置展示：项名、复用/重跑/受阻原因、规则通过/失败、expected/actual、来源批次、版本短hash；顶层显示复用数、当次执行数。内部冻结设置和路径权限仍不进入公共UI。协议8.43可选字段，旧记录显示未做本规则验收，不冒充数值正确。

沿用 npm run evaluate:science，保留原5对基线，增加局部修复/重复批次/输入或方法或环境改变/篡改产物/错误数值等场景。独立宿主真值相同，统计修复阶段的增量请求、真实执行/复用数、错误复用/错误放行、可见用量和耗时，同时保留共同前置成本。结果仅支持确定性本地软件路径，不能外推真实模型质量或费用。

每个里程碑展示真实截图和可点击报告/产物；最后演示“首批A通过、B数值错误→程序拦截→派生批次A复用、B重跑→统一汇总”，另示篡改文件会使复用失效。截图和录制使用隔离测试项目及本地推理，明确标注合成数据/软件验收，保留复现命令。
