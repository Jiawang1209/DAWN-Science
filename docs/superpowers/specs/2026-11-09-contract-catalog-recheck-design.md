# 科研契约目录生产接入与真实收益复验设计

## 已确认的方向与范围

用户确认先覆盖真实收益复验和可信契约目录生产接入，展示只补必要入口与反馈；会话级统一轨迹随后另开阶段。不扩大 Agent 数量，不增加嵌套层级，不另建调度器。冻结科研任务保持“停止 → 新方案或新批次 → 重新验收”。本轮写设计、计划并建立 goal；模型新额度须单独明确，不沿用旧轮额度。

基线为本地 main 5e64595b（功能提交 ad23c80f）。专项分支 codex/contract-catalog-recheck-20261109。正式 App、配置、凭证和数据库不替换或写入；当前授权不包含本轮 commit、merge、push、发布或实耗模型调用。

## 方案选择

采用“已确认的科学模板 → 宿主目录 → 只读规划 → 原批准执行”的增量接入。仅增加提示词不能防止冻结字段被重抄或遗漏；新调度器会复制权限、锁和恢复事实，故均不采用。真实复验先锁定题目和指标，等产品接入完成后冻结一次候选再运行，不为前后两个实现默认重复花费。

## 最小产品切片

从自动安排区域进入可折叠的“科研任务约束”，选择现有 tabular-ecology@1，填写/确认本会话输入、输出根、方法、单位、缺失值规则、可选数值核验和独立审阅要求。已有分析路线只提供当前 routeId/revision/stepId 与声明路径候选，不把路线状态或文字说明当成已批准科学规则。用户确认后仅保存规划来源，不批准执行、不生成科研产物、不启动团队。

本轮完整贯通本地 Native + Python 表格模板。R、图表复现、远端与 ACP 保留原功能入口；不宣称新目录接入已覆盖它们，也不为它们新增科学判据。自由任务未选择可信来源时继续原完整 contract 路径。任务块数仍由任务和方案决定，核查/分析/审阅目录条目不是必须派出的三个成员。

## 契约来源与权限

复用 ScienceTemplateSchema、scienceTemplate()、pipelineStageContract()、TaskContractSchema 和 planContractCatalog()。在现有 plans.json 添加可选且独立验证的 planningContext；它只保存用户确认的模板参数、owner、来源修订和目录指纹，不保存队列、运行代次或执行状态。旧文件没有该字段时按无目录处理；该字段损坏时禁用目录并显式提示，不丢弃旧批准记录。原批准 executionSnapshot 和产物内容版本仍是执行与验收的权威。

目录内容及 owner 由宿主获取，模型不能传入或覆盖。宿主根据确认参数构造精确合同；未知引用、不同 owner、旧修订、混合引用与完整 contract 均沿现有校验拒绝。存在确认来源时，完整 contract 输入同样不能削弱它；不是只保护 contractRef 写法。单位/方法/阈值变化须重新确认并生成新方案，不改已批准合同。输入文件内容继续在批准时由原 freezeApprovedPlan 捕获，执行前按原机制核对。

## 工具与运行时装配

pi 的 customTools 在创建会话时装配，不能假定事后塞入回调就会更新模型看到的目录。选择始终注册的只读 get_plan_contracts 查询作为动态目录入口：只有方案期且拥有当前确认来源时返回目录；无来源明确返回 unavailable 并指导完整合同路径。propose_plan 保留原工具名、最终完整合同存档和批准路径；有宿主目录能力的会话支持 contractRef 输入，但无来源时引用不可解析，不向模型伪称已有目录。

查询返回来源版本、可读模板摘要与精确引用，不返回原始科研数据、凭证或新权限。不调用 session.reload() 来更新目录，避免重设工具/权限/模型；现有只读规划提示仅说明按需查询。在 propose_plan 与批准时核对实际来源修订，并将来源绑定保存为该版方案内部元数据；手工改过方案也须通过同一约束，不依靠模型复述来源。来源变化后的旧待批准方案提示“来源已变化，请重新安排”；已批准任务沿原快照运行，不能静默换合同。

## 必要展示

自动安排显示“未选择可信目录 / 来自已确认模板 / 信息待补 / 来源已变化”及确认参数摘要；确认按钮与“照这个做”明确分开。只读查看目录不派任务。保留顶部编排入口、Esc/按钮返回、原完整 contract 路径、团队管理、文件、产物、版本和工具记录入口。每阶段用真实 Electron 和隔离模拟配置展示，不用手绘图冒充运行效果。

## 复验与结论边界

拟新增最多 300 次真实请求：short-known-mean、carbon-missing、unknown-unit，单执行者/自动安排各重复 2 次，共 12 组，每组 25 次；自动组工作 18（含规划与目录查询后的模型请求）、独立审阅 7 次，互不借额度。只读目录查询不另计模型请求，但它导致的下一次推理计入请求门。模型路由相同、题目输入与宿主判据一致；“同预算”指请求上限相同，不承诺实际 token/费用相同。

最终复验必须走与产品相同的确认来源构造和目录查询；不能继续只验证评测专用 planningContracts 注入后就宣称生产贯通。原回调保留用于旧评测/夹具兼容。规划、执行、审阅、失败、取消和在途均纳入原观测；缺失用量为未知，累计 token 不是实际费用。待确认不计成功或正确 blocked；未知单位不得生成推断数值文件。

报告如实保留失败/不完整配对；收益仅在双方合格配对上比较成本，完整交付率按全部已启动试验给出。历史 148 次报告仅作错误类型参考，不覆盖、不更改成绩，不把不同候选或时点当随机对照。单模型、小样本不能证明复杂科研普遍收益。

## 风险与完成条件

重点验证 owner/route revision/plan version/attempt/epoch 隔离、迟到取消、确认与批准竞态、产物锁、停止排空、旧文件恢复及旧入口。历史偶发退出超时、长 Bot/MCP 收尾和 PTY 清理保持 OPEN；1500/4000ms 原预算不变。完成要求产品最小切片、离线与桌面验收、审查、真实复验的诚实报告及阶段效果齐备；模型额度未确认或凭证不可用时，真实部分明确未完成。
