# 团队（team-board）· 设计定案

> 2026-08-22。学自 `NanmiCoder/dsh-agent-teams`（MIT），解读在 `ccb_hive_code_learn/dsh-agent-teams-解读.md`。
> 分支 `team-board`。第一档 + 第二档一起做了。

## 要解决的事

`subagent` 工具只有 `single / parallel / chain`：每个任务一个一次性进程，chain 只能线性。科研里的活常是 DAG
（取数 → 清洗 → 两路分析 → 合并出图），而且同一个「人」常要做第二轮。模型也不知道该怎么分工。

## 形状

```
队长 = 当前会话（7 个 team_* 工具，pi customTools，坐在 subagent 旁边）
成员 = 名册里的子 agent 当人设 + 各自一个子进程 + 各自一份可续的 pi 会话目录
任务 = 带依赖、带 attempt 令牌；调度器事件驱动派活
真相 = <会话目录>/teams/<id>/team.json（+ members/<name>/ 会话、current 指向活着的团队）
```

| 层 | 东西 | 在哪 |
|---|---|---|
| 状态机 | 建队 / 加人 / 加任务（依赖只能指向已建的）/ 领取（依赖齐、一人一活）/ 结算（出示令牌、终态不可覆盖）/ 转派（令牌作废）/ 邮箱 / 结束 | `src/team/state.ts` |
| 一轮 | 起子进程、递规格（`member` 段：会话目录 + 是否续）、回答它的 `call`、收 `done` | `src/team/runner.ts` + `subagent/child.ts`（stdin 按行、`SessionManager.continueRecent`、`team_send` / `team_status` 两个 RPC 工具） |
| 调度 | `踢一下`：每个空闲成员先送信、再领就绪任务；并发 ≤ 4；一轮结束按令牌结算，对不上就丢并寄系统消息给队长；`等变化` 给 `team_wait` | `src/team/scheduler.ts` |
| 队长工具 | `team_create`（一次给齐）/ `team_add_task` / `team_reassign`（to=captain 接管）/ `team_update_task` / `team_send` / `team_status` / `team_wait` / `team_finish` / `team_remove_member` | `src/team/tools.ts` |
| 协议 | 7.22：快照多 `team`，更新多一种 `team`；没有新操作 | `protocol/events.ts` |
| 界面 | 坞里一格「团队」（成员 / 任务含依赖、attempt、结果 / 消息）；对话流仍是子 agent chip（toolCallId = `team:<id>`）；`/` 菜单第一项「组一支团队」→ `/team ` | `ui/team-panel.tsx`、`slash-menu.tsx` |
| 账本 | 每一轮发 `subagent_start/end`，一条 Run，什么都没另写 | `runtime/native.ts` |

## 定案

1. **进程边界不变**（不变式 1）。「可续聊」= 同一个成员下一轮起新进程、`continueRecent` 它那份会话文件；不是同进程里留一个活着的子会话。dsh 的成员在同一个 harness 进程里，**这一点不借**。
2. **attempt 令牌照抄**：转派 / 接管 / 取消 / 移除都换令牌；迟到的结果被拒且出声（寄一条系统消息给队长）。它的验证脚本压过 50 次迟到写入，我们的 `tests/team/scheduler.test.ts` 用真子进程压了一遍。
3. **成员的工具只有两个**（`team_send` / `team_status`）。任务的领取与结算**由调度器做**，不靠模型「走仪式」——dsh 自己承认「成员不总是严格走工具仪式」，那就别指望。成员的最后一条回复就是结果。
4. **`team_wait` 是我们加的**：队长的一轮里等进展，不用反复 `team_status` 空转（dsh 让队长轮询）。
5. 一个队长同时一支团队；结束是归档（`finishedAt`），不删；重开会话时 `current` 指向的团队快照会推一遍。
6. 上限：8 成员、32 任务、并发 4、一轮输出 64 KB、一轮 30 分钟。
7. **成员各自的模型**（作者 2026-08-22 要的）：`team_create` 成员项可选 `model: "provider/model"`，建队时对着模型目录核一遍（不在就拒、列出有的）；**缺省跟队长当前模型**，队长协议里写明只在人明确要求不同分工用不同模型时才给。优先级：成员 → 子 agent 定义里的 `model` → 队长。坞里成员行写着它的模型。
8. **不借**：浮层面板（有坞）、鲸鱼头像、`/agent-teams` 的命令管线（我们是 `/` 菜单一项）、dsh 的任何包。

## 验证

- `tests/team/state.test.ts` 14 条：依赖、领取、令牌、终态、转派、移除、消息、代入、落盘。
- `tests/team/scheduler.test.ts` 6 条，**真子进程**（假脚本按暗号行事）：按依赖派活与并发、续会话标志、成员互发消息、迟到结果被丢、中止与失败、等变化。
- `e2e/team.spec.ts`：假模型调 `team_create`，两个真成员进程按依赖跑完，坞里那一格、对话 chip、磁盘真相三处对得上。
