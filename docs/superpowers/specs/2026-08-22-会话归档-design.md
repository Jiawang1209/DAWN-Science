# 会话归档：藏，不是删（session-archive）

> 学自 `MichengAI/dsh-archive-manager` v0.1.8（Apache-2.0；本地副本 `ccb_hive_code_learn/dsh-archive-manager`，
> 解读全文 `dsh-archive-manager-解读.md`）。思路借、代码自己写。
> 作者 2026-08-22：「先做，实在不行我们还能撤回」。问过「会影响侧栏吗」——没归档过就一个像素都不变。

## 问题

会话一多侧栏就满了，而唯一的办法是删。另外发现一个真 bug：「删除会话」确认框说「删掉这个会话与它的对话记录」，
实际只删数据库那一行，`<workspace>/.dawn/sessions/<id>`（pi 的 jsonl、工具输出转储）一直留在用户仓库里。

## 定案

### 归档 = `sessions.archived_at` 一列

- 有值就是藏起来了：`listByProject` 不列、任务列表（侧栏「会话」那一列从任务长出来）不列、上移下移的邻居查找跳过它。
- **记账位不动**：`sort_order` / `pinned` 原样留着，取消归档回原项目原位置。没有「归档目录」，不搬文件。进程不停。
- `countByProject` 仍把归档的算上——删项目时要说真数。

### 入口

- 会话行「⋯」→「收进归档」；多选模式的三条批量条都多一颗「收进归档」。
- 侧栏「远程助理」下面一行「已归档 N」，**只在 N > 0 时画**：看不见的能力等于不存在，但永远空的入口是噪音。
- 「已归档」屏：按项目分组、按标题 / 项目搜、每行「放回去」「删除」，顶上「清空归档」（先问）。点一行 = 放回去并打开（归档了的不在侧栏名单里，对话屏找不到它的摘要）。
- 归档当前正在看的那段：选中清掉，不留一个指向空的选中。

### 删会话的顺序（照它的）

停进程 → 删记录 → 删任务 → **最后**会话目录进废纸篓。记账那些失败了目录还在、可重试；目录没了再失败就找不回来。
进废纸篓而不是 `rm`：与删文件一个口径。响应多回 `transcriptTrashed` + `problem`，界面没进废纸篓要出声。

### 名字（按钮文案互不为子串的规矩）

「收进归档」「已归档」「放回去」「清空归档」——「取消归档」会与「取消」撞，「归档」会与「已归档」撞。

### 协议 7.18

`SessionSummary.archivedAt`；`setSessionArchived` / `listArchivedSessions` / `deleteArchivedSessions`；`deleteSession` 多回 `transcriptTrashed` / `problem`。

## 不借

替换宿主服务、墓碑、投影缓存——我们是 SQLite 单一真相，删了行就没了。对话内容搜索是第二档。
