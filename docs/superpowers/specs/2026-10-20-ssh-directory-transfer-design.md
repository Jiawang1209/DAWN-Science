# SSH 目录批量传输

2026-10-20：用户已确认研究报告中的方案 B，并授权在 `codex/ssh-data-transfer` 开发和打开实际预览；不合并、不推送。

本规格采用 `docs/reviews/2026-10-20-dsh-ssh-transfer-review.md` §4 的使用过程、数据保护、模块边界与验收要求。该报告是完整设计正文；本文件固定实现契约。

- 用户在远端文件面板选择上传文件夹或下载当前／选定文件夹；上传以源目录名落在目标目录内，下载使用设置中的下载目录。根目录同名时另存，文件冲突由用户逐项处理。
- 主进程负责枚举、每台服务器最多三条文件流且大文件最多一条的调度、持久化任务描述与结果、取消和失败项重试；不传整文件到渲染进程。
- 普通文件与空目录保持层级；链接和特殊文件明确跳过，拒绝异常条目与越界链接。扫描受深度／条目预算限制且可取消。
- 每批次及文件有独立身份、进度、状态与错误。关闭面板和切换聊天不终止任务；分页明细。重启将未终结状态改为 interrupted，不自动续传。
- 新增 `startDirectoryTransfer`、`listTransferBatches`、`getTransferBatch`、`cancelTransferBatch`、`retryTransferBatch`、`resolveTransferConflict`。旧单文件操作保留；原有多文件上传改为等待完成，避免失去跟踪。
- 覆盖使用服务器支持的 POSIX rename 扩展，扩展不支持时保留旧文件并失败。上下行临时文件提交前验证字节数和可检测的源变化；不把大小校验称为哈希校验。
- 取消保留已完成文件，清理半成品；清理失败及残留路径可见。传输闲置和元数据请求都有超时。只手动重试失败项，不自动重放远端命令。
- 任务描述落在数据库同级的 transfers 目录，不保存凭证；进程重启状态明确。沿用上传记账。
- 验证包括故障注入单测、后端协议测试、组件测试、真实 Electron 上下行／取消／失败／重试流程、亮暗窄窗口，以及文件落盘内容。真实服务器吞吐另行标注未验证。
