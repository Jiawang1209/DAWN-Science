## 用户确认的呈现

历史问题只用 `❯`，不显示“你／你：”；助手用正文前的轻量圆点，不逐轮重复品牌。保留唯一 `> DAWN` 输入、输入上方提示、底部居中的累计统计。参照用户提供的实际终端截图，正文用短段落、必要的小标题和重点强调，路径与命令沿用 Markdown 着色，不把简单问答排成固定模板。

成功工具默认一行摘要，Tab 展开或收起原命令及输出；失败始终展开，截断和完整输出位置始终可见。历史工具补齐失败和上游截断元数据；即时工具合并 SDK 与事件预算两层截断状态，有 SDK 原始输出路径时优先保留它。

## 回复来源边界

终端输入经内部请求上下文标记来源，排队、转述、调整方向与重排保留各自来源。终端指引仅在 SDK `transformContext` 的模型请求边界投影，不写入原消息或持久化系统历史，不改模型、工具、权限、图片和原会话 ID；GUI 后续输入沿用原指引。模型身份使用当前实际模型，终端自然回答不主动带 provider 配置后缀。

真实 SDK 假流测试覆盖 CLI→GUI 与 GUI→CLI 的同一运行队列，检查实际请求的系统指引、工具清单、模型身份变更及持久记录未受污染。不是通过替换 `session.prompt` 模拟 SDK 队列。
