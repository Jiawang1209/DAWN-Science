# 设置右栏 —— 设置先当一条栏，想看全了再展开

分支 `settings-panel`。作者 2026-09-16 提的两件事，一大一小，都落在设置里。

## 从哪来

作者的原话，两句：

> *「设置里面的 MCP 服务器，我其实希望你能在后面增加上数字，类似我们的 skills 后面增加配置好的数字。」*

> *「我们点击设置的时候，其实设置页面整体就弹出来了，其实我想要的是初始是类似于点击面板后的效果，
> 然后也有一个按钮，可以展开。展开到现在版本的这种状态（设置页面整体弹出来）的效果。」*

第二句里有一个**必须先纠正的误解**，不纠正就会做错形状：他说的「面板」（`RightDock`）
**不是浮层**，它是 `.body` 网格里真实的一列，把对话**挤窄**而不是盖住。
所以「像面板那样」= 真的占一列，不是从右边滑出来一块盖在对话上。
这一条当面给他看过线框，他据此选的 B。

## 定下来的四件事（逐条给作者看过线框）

| | 选项 | 作者选的 | 为什么 |
|---|---|---|---|
| 住哪儿 | 坞里第 N 格 / **自己一栏** / 浮层 | **自己一栏，与坞互斥** | 坞那七格说的都是「这段会话产出了什么」，设置是全局的，混进同一条标签条语义不齐 |
| 窄栏里怎么摆 | **下钻** / 一长条 / 顶部下拉 | **下钻：名单 → 那一项** | 它是现在那两栏「在时间上错开」，不是换结构；一长条正是 2026-08-12 被否掉的形状；下拉把十四项藏起来 |
| 关掉之后 | **记得回程** / 不记 | **记得** | 「开着文件面板顺手看眼设置再关掉，面板没了」是最容易被当成 bug 的那种。代价只有一个字段 |
| 天生要宽的几块 | **全在窄栏铺开** / 带 ⤢ 直接整页 | **全铺开** | 行为只有一种；而「哪几块真会坏」是**能量出来的**，不该现在猜 |

展开之后的样子，作者补了一句：*「展开之后，也应该和现在版本的状态是一致的。」*
—— 整页设置一个像素都不改，窄栏只是它的另一个形状。

## 一条规则管住右边

> **设置活着的时候，右边那一列归设置；设置一关，上一位房客回来。**

展开到整页时那一列**空着**（作者选的）。这一条与 `right-dock.ts` 里记着的
「坞不随左半的屏切换而收起」**不一致**，是这一轮明确改掉的：选项里写明了「与现版不同」，作者据此选的。
理由说得通——设置此刻是主角，右边再挂一栏是分心。

状态机（右边那一列）：

```
                点设置            ⤢ 展开
   [房客 X] ──────────────▶ [设置栏] ──────────▶ [空着 · 主区整页设置]
       ▲                        │  ▲                     │
       │          ✕             │  └─────────────────────┘
       └────────────────────────┘        ⤡ 收起
           （X 可以是「没有」——来时右边空的，走时右边就空的）
```

## 状态：只新增三样

宽度与那条缝**直接用坞的**（`--dawn-dock-w`，`RIGHT_DOCK_MIN 280` / `DEFAULT 380` / `MAX 720`）。
互斥之后右边同时只有一位房客，两套列宽只会打架；而且宽度是「**这个人喜欢右边多宽**」，
不是「设置喜欢多宽」——与侧栏宽度、主题同一类。

| 新状态 | 持久化 | 作用域 key | 为什么 |
|---|---|---|---|
| 设置栏开没开 | ❌ | — | 它是**这个窗口此刻的样子**，不是偏好（与 `$rightDockOpen` 同一条） |
| 当前是哪一项 | ✅ | `dawn.global.settings-section` | 「我上次在看模型服务」是偏好；它不属于某段会话或某个项目 |
| 被顶掉的是谁 | ❌ | — | 只为这一次回程活着，重启之后无意义 |

作用域必须写进 key，是 `state/view.ts` 立的纪律（搞错作用域 = 一个会话的东西渗进另一个）。

## 右栏里长什么样

```
┌──────────────────────────────┐     ┌──────────────────────────────┐
│ 设置              展开   ✕   │     │ ‹  模型服务        展开   ✕  │
├──────────────────────────────┤     ├──────────────────────────────┤
│  ⬚ 外观                   ›  │     │  服务商                      │
│  ⬚ 文件引用               ›  │     │  ┌────────────────────────┐  │
│  ⬚ 用量                   ›  │ ──▶ │  └────────────────────────┘  │
│  ⬚ 工作目录               ›  │     │  API Key                     │
│  ⬚ 模型服务               ›  │     │  ┌────────────────────────┐  │
│  ⬚ ACP 适配器             ›  │     │  └────────────────────────┘  │
│  ⬚ 内核                   ›  │     │                              │
│  扩展                        │     │                              │
│  ⬚ Skills           12    ›  │     │                              │
│  ⬚ 记忆              3    ›  │     │                              │
│  ⬚ 子 Agent         22    ›  │     │                              │
│  ⬚ 插件              4    ›  │     │                              │
│  ⬚ MCP 服务器        3    ›  │     │                              │
│  ⬚ 远程助理               ›  │     │                              │
│  ⬚ 关于                   ›  │     │                              │
└──────────────────────────────┘     └──────────────────────────────┘
        一级：名单                          二级：那一项
```

- 名单**沿用 `settings-nav-item` 现成的长相**、现成的「扩展」分组标题、现成的 `side-count`
  行尾计数。同一种东西不该有两种样子。
- `‹` 只在二级出现。标题就是那一项的名字——它替代了整页里「一直亮着的那一列」
  所回答的「我在哪一块」。
- **`sections` 那个数组一份两用**：整页与窄栏读同一份、同一个「当前选中」。
  这是下钻方案唯一真正的技术理由，也是「展开后停在同一项」的自然结果，不是额外做的一件事。

## 入口与回程

| 动作 | 结果 |
|---|---|
| 侧栏「设置」、命令面板 | 开设置栏（**不再切 `view`**），停在上次那一项 |
| `openSettingsSection(id)` | 开设置栏并**直接钻进那一项**（不是停在名单上） |
| `⤢ 展开` | `view = "settings"` 整页，**停在同一项**；右边那一列空着 |
| 整页上新增的 `⤡ 收起` | 回设置栏，`view` 回对话，仍是同一项 |
| `✕` | 关掉设置，那一列**还给上一位房客**（没有上一位就空着） |

**一处例外，而且必须显式接线**：连不上时 `ConnectionSurface` 那颗「打开设置」**直接给整页**。
那时主区本来就没有对话，挤出一条栏来挤谁？——更硬的理由是那条路上**根本没有那一列**：
连不上时 `App.tsx` 走早退分支，屏幕只有顶栏 + `ConnectionSurface` + 状态栏，
`.body` 那个网格压根没渲染。接错了的症状不是「样子不对」，而是**点了什么都不发生**。

**一条不变式**（2026-09-16 实现时量出来的）：**窄栏开着的时候，坞必定是关着的**——
那一列只有一个位置。`开设置栏` / `展开设置` / `收起设置` 都要守住它。

## MCP 那个数（作者的第一件事）

`count` = **开着的台数**，即 `servers.filter(s => !s.off).length`。

口径与 Skills 一致（`设技能数(开着的.length)`）。三种读法都摆给作者看过，他选的这一种：

- **配置了几台**（`servers.length`）——不随开关跳，但与旁边 Skills 那个数不是一回事。
  同一个位置上两个数用两种口径，正是这个项目吃过亏的那类「没有判据」。
- **连上的几台**（`state === "ready"`）——**会骗人**：`state` 在手动点过「测试」之前一律是
  `unknown`，所以多数时候这个数是 0。一个长期显示 0 的数字比没有更坏。

顺带：**插件**也加一个同口径的数——`listPlugins` 回的每个插件带着 `on: boolean`，
所以「开着几个」这件事是现成的，不用加协议。它是「扩展」组里唯一一个能数却没数的。
（`记忆` 那个数是「待确认几条」，语义本来就不同，不动。）

## 窄栏里那些内容

**先量，再改。** 把十四块在 380px 下逐个渲染出来看一遍，**只修真的坏掉的那几块**。

已知的事实：设置里这些面板**没有一个用固定列宽的网格**（`grid-template-columns` 在
设置相关的选择器上一处都没有），基本是竖着堆的，所以大概率没几块要改。
`--dawn-page-max-w: 75rem` 是上限不是下限，不构成障碍。

真量出来有两三块怎么改都难看，那时再单独给它们加「点一下直接整页」——
那是一条**有证据**的例外，不是一条预支的规则。

## 怎么验

e2e（`e2e/` 新增一支）盯五条：

1. 点设置 → 右边出现设置栏，**对话还在**（不是被顶掉）。
2. 名单 → 点一项 → 换成那一项；`‹` 回名单。
3. `⤢` → 整页，**选中项不变**；`⤡` → 回栏，**选中项仍不变**。
4. 坞开着 → 点设置 → 坞让位 → `✕` → **坞自己回来**；来时右边空的，走时右边空的。
5. `MCP 服务器` 行尾那个数 = 开着的台数（关掉一台，数字掉一个）。

第六条**放在 e2e 里，不放静态扫描**：「窄栏里不许横向溢出」是布局结论，
读 CSS 判不出来。做法是把设置栏调到 380px、逐项打开，断言
`scrollWidth <= clientWidth + 1`——这一条同时就是上面那句「先量，再改」的自动化形式：
它会**替我们指出**哪几块真的装不下，不必现在猜。

视觉基线可能要加一张「设置栏开着」的图；按 `visual.spec.ts` 现有的五屏×明暗的口径走。

## 不做的

- **不把设置塞进坞的标签条**。那七格是「这段会话产出了什么」，设置不是。
- **不改整页设置一个像素**。作者明说了要一致。
- **不给窄栏另造一套宽度/缝/记忆**。坞那一套照用。
- **不预先假设哪几块内容要宽**。先量。
