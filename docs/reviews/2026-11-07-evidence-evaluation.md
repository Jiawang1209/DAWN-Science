## B · 看得见且不随续问漂移的交接

兼容原 v1 recentMessages；v2 增加指定当前分支已完成正文 ID、路线步骤 ID 和最多 4 个当前父会话已结束、带 accepted 回执及版本的历史子任务 ID。宿主解析权威来源，模型不能自填证据内容；子身份按 parent/kind/address 校验，不接受外来来源。只读目录工具不会启动任务。

正文 1–8 条、16 KiB；总信封含 SHA/大小字段最多 64 KiB，超限拒绝。v2 指纹覆盖时间、选择、正文与引用，仍走原 handoff SHA/null 绑定；续问、重试、重启不重新采集，丢失/篡改/换选择拒绝。引用只记录历史版本身份，明确当前文件未重新核验；路线记录不是用户批准。冻结科研契约及独立审阅继续使用原路线/契约/版本，不接收普通对话快照，不扩大权限。

实际 Electron/Pi 流程已经验证：早期单位/方法/数据保护消息与后续当前消息不同，仍按所选 ID 进入真实子转录；来源及路线修订显示在原运行总览；续问与重启后的 handoff.json 字节一致。界面由原始 JSON 调整为可读标题、目标、目的、输入输出，原文保留折叠检查。此桌面流程使用本地确定性推理，不能称为真实模型选择交接材料的质量验证。

## 代码审查及修正

实现者自审加一次独立只读代理审查。独立审查未发现可确认的跨父会话放行、契约扩权或 SHA 绕过，定位两处评测记录缺陷：

1. Pi 执行器取消通常返回失败结果而非 reject；单组因此落为 failed。改为取消信号优先映射 cancelled，真实子进程中途取消先红后绿。
2. 多组取消跳过成功分支的用量采集。改为原排空结束后统一读取已领取阶段，保留前驱已知用量和产物版本。共享离线夹具显式提供工具用量；第一阶段完成/第二阶段取消回归覆盖真实 Team。

同批补齐未收完 HTTP 正文的 deadline：原来仅 abort controller 不能结束正文迭代，现在主动结束本次 owned 请求；默认 90 秒上限不变，关闭等待 active 归零。并发 31 次仅转发 30、重试到限、无权限请求、在途关闭和部分正文超时均有测试。另补中文 UTF-8 恰 16 KiB、总信封恰 64 KiB 的冻结回读及 +1 拒绝。

原始红灯、桌面失败 trace 和截图保留。前两轮桌面用例分别触发了既有“先不执行”边界、完成后工具组折叠，另一轮定位器匹配了正文和路线两个 pre；测试改用明确恢复执行指令与实际完成 chip/指定正文，没有绕过产品授权、改超时或改变分组行为。复跑生成的 9 个旧演示文件已备份到本轮 legacy-demo-refresh 后按 Git 原字节恢复，未改旧视觉基线。
