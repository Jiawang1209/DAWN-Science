# 照着文献画图 · 怎么装

> 规格 `superpowers/specs/2026-09-07-照着文献画图-design.md`。
> 技能本身随应用发布（`skills/figure-like-this/`），**要装的只有那台 MCP**。

## 一、把语料库准备好（在 MLAI-science 那个仓库里）

```bash
cd <你的>/MLAI-science
uv sync
uv run mlai rebuild        # 建 registry.db 与向量；首次约数分钟
```

**不 `rebuild` 的后果不是报错，是空**：工具照样答，只是什么都搜不到——
与「库里真没有这种图」在屏幕上是同一句话。所以先跑它。

## 二、在 DAWN 里加这台 MCP

设置 → **MCP 服务器** → 添加：

```json
{
  "mlai-science": {
    "command": "uv",
    "args": ["run", "mlai", "serve"],
    "cwd": "/Users/liuyue/Desktop/Github_repos/MLAI-science"
  }
}
```

三件要知道的：

- **`cwd` 必须写**：`uv run` 要在那个仓库里才找得到它的环境。不写就用会话的工作区，起不来。
- **这台写进全局那份**（`userData/providers.yaml`），不是项目级 `.dawn/mcp.yaml`——
  `cwd` 是这台机器上的绝对路径，跟着仓库被 clone 走没有意义。
- **信任开关要你自己拨**（那一屏上的开关）。它不在配置文件里，这是既有的红线：
  项目级名单会跟着仓库被 clone，**别人的仓库不该能声明「这台我信得过」**。

加完点**测试**。实测（2026-09-07，这台机器）：

```
起用了 972 ms
9 个工具：mlai-science__search_cases / semantic_search / search_figures / search_chunks
         / recommend_pipeline / recommend_figures / get_case / list_taxonomy / get_asset
```

**模型看到的是带前缀的名字**（`mlai-science__recommend_figures`），前缀就是你给这台起的名字。

## 三、怎么用

粘一张文献里的图，说「这种图我也想画」。技能 `figure-like-this` 会：
把图描述成四行 → `recommend_figures` → 读 `how_to` → `run_code` 在你的数据上画 → 落成产物。

## 四、搜不到时，先分清是哪一种

| 症状 | 多半是 | 怎么确认 |
|---|---|---|
| 什么都搜不到，且 `figure_types` 也空 | **库没建** | 去仓库里跑 `uv run mlai rebuild` |
| `figure_types` 有值，但结果不对路 | 描述写得不像 caption 的口吻 | 按四行结构重写；或 `list_taxonomy` 拿词表挑一个图型 |
| `figure_types` 空、`notes` 说「未匹配到任何图型别名」 | 这类图库里可能真没有 | 那批结果是全库混检，**不要当推荐用** |
| 工具一个都看不到 | 那台没起来 / 没拨信任 | 那一屏上点「测试」，它会把子进程的 stderr 尾巴给你 |

## 五、这一轮明说没做的

- **PDF 抽取**：现在要你自己截图。等你嫌麻烦再做（规格「不做」那一节）。
- **以图搜图（CLIP）**：现在的「相似」是文字上的相似——向量建在精修过的 caption 上。
  值不值得做，看你能不能攒出一批「我描述了但搜不到、而我知道库里有」的例子。
