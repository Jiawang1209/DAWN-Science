# 内核启动期清理验证

基线 main 2e4c26a0，独立 codex/kernel-startup-cleanup。用户授权逐项修复、验证后本地合并，再另开分支。

## 修复

对话内核以清理代次使旧启动和执行队列失效。收() 同步登记屏障，已运行内核立即停止，启动中的实例完成后独立回收；晚到实例不入表、不报“起来了”、不执行代码。解释器读取期间清理则不发 start。清理与正在执行的 Promise、监听和反查统一收尾，逐语言记录停止失败。重复清理共享同一回收；清理结束后允许明确的新请求懒起。

收全部与有活内核计入启动/清理中资源。跨对话清理仍保留晚到实例的所有权，不让旧 Promise 的 finally 先删掉它。NativeRuntime.stop 在第一个 await 前开始清理，并在退出前等待；模型会话已经不在时仍回收名下内核。

自审补上两项竞争：已运行的 Python 不能因 R 还在启动而延迟停止；“起来了”同步回调若触发清理，不再挂晚到转发监听。没有新增协议、改变 UI 或内核重连策略。
