## 一、事实（都量过，不是读来的）

**DeepSeek 那边**（官方文档）：收图的是 `deepseek-flash`（DeepSeek V4.1 Flash），
base64 / 外链 / Files API 三种喂法，JPEG·PNG·GIF·WebP，每张最多约 1024 token，
单请求 600 张封顶，**图只能挂在 `user` 消息上**。`deepseek-v4-pro` 不收图。
实验 id `deepseek-v4-flash-vision-exp` 已废弃，请求被路由到最新 Flash。

**我们这边**：pi 的模型目录按版本冻在包里，两版对比——

| | `deepseek-flash` | `deepseek-v4-flash` | `deepseek-v4-pro` |
|---|---|---|---|
| pi-ai **0.84.1**（装着的） | 没有这条 | `input:['text']` | `input:['text']` |
| pi-ai **0.86.0** | `input:['text','image']` ✓ | **没有这条** | `input:['text']` |

pi 的 changelog 原话：*"advertise `deepseek-flash` for DeepSeek V4.1 Flash instead of
**retired** Flash aliases"*——**旧 id 是 DeepSeek 自己退休的**，不是 pi 改名。

## 二、要升的是三个包

`package.json` 里还钉着 `@earendil-works/pi-agent-core: ^0.84.1`。只升 `pi-ai` 与
`pi-coding-agent` 的话它会把 `pi-ai@0.84.4` 一起拖进树里，**两份 pi-ai 并存**，
typecheck 当场红在 `spikes/a-pi-embed.ts:72`（`MistralConversationsCompat` 在一版里有、
另一版里没有）。三个一起升到 0.86.0 之后 `npm ls @earendil-works/pi-ai` 只剩一条。

**0.86.0 的三条破坏性变更我们一条都不沾**（逐条核对过调用面）：

| changelog 里的 | 我们 |
|---|---|
| 自定义 provider 的流输入 `Context` → `TranscriptContext` | 不写自定义 provider（坐第三层，见 [[pi-layering-decision]]） |
| `ToolCall.arguments` / `ToolResultMessage` 收紧成 JSON 值 | `JsonValue` 是我们自己的（`src/tools/office/shape.ts`） |
| `user_bash` 改 fail-closed | 不用 `user_bash` |

我们只从 pi 进口 10 个符号：`Credential`、`CredentialInfo`、`CredentialStore`、
`getBuiltinModel`、`getBuiltinProviders`、`loadSkills`、`Model`、`parseFrontmatter`、
`resizeImage`、`ThinkingLevel`。

## 三、退休 id：12 条红，一个根

升完单元 **12 failed / 2919 passed**，4 个文件，全是夹具里写着 `deepseek-v4-flash`：

```
Error: provider "deepseek" 没有模型 "deepseek-v4-flash"。
       该 provider 可用的模型：deepseek-flash, deepseek-v4-pro
```

`wiring.test.ts` 那几条报的是 `createTask 执行失败`，同一个根——夹具的 agent 指着那个 id。

**这条错误信息本身是好的**：`resolveModel`（`src/runtime/native.ts:1890`）注释写着
「无静默回退」，撞上的人会拿到正确答案。所以这一轮**不需要**再造一套出声机制。

### 换 id 不是全局替换

`tests/config/models-json.test.ts` 里有两处必须想一下：

1. 「继承注册表的 input」原先拿两个**都只收文字**的模型验——等于只验了一个方向。
   现在一边一个：`deepseek-flash` 说收图、`deepseek-v4-pro` 说只收文字。**判据变强了。**
2. 「`vision: true` 对注册表认识的模型同样生效」**必须挂在只收文字的模型上**。
   挂在 `deepseek-flash` 上的话，代码把这个开关整个忽略掉它也是绿的——
   那正是本项目那条「两处长得一样，等于没有判据」。已改成 `deepseek-v4-pro`。

其余 40 多处是纯夹具，机械替换。`src/` 里的旧 id **只改两处示例**
（`src/team/tools.ts` 给模型看的描述、`src/subagent/definitions.ts` 的示例 frontmatter）；
**叙述历史的注释一律不动**——那些记的是当时发生过的事，改了就是篡改现场。

## 五之二、e2e 第一轮那 8 条红，三类

**① 六条是我自己把 mock 漂开了。** 改了 `e2e/fixtures.ts` 里 yaml 的模型 id，却没动
`scripts/mock-inference-server.mjs` 那份假目录——于是 e2e 里那个模型不再来自假目录，
**落到了 pi 的真注册表上**，跟着拿到真实的 1M 窗口、thinking 档位、收图声明。
症状散成四种（上下文面板的数、会话设置那颗按钮、「没有声明支持图片」、「已转述」），
**根只有一个**。这正是 CLAUDE.md 规则 ① 说的：mock 与真实契约必须在同一次改动里一起动。

**② 一条是 pi 真的换了路径。** Anthropic 协议：

```
0.84：<baseUrl> + /messages
0.86：<baseUrl> + /v1/messages?beta=true      ← "beta=true" 在 0.84 的包里一次都搜不到
```

假服务器原先 `req.url.endsWith("/messages")`，带上 query 当场不认，掉进 OpenAI 那支，
pi 的 Anthropic 解析器读完报「stream ended without a stop reason」——**症状离原因很远**。
改成按路径判。夹具里那家的地址也去掉了 `/v1`：**假服务器路径宽松，但夹具照真实契约写**，
否则 e2e 绿着的那条路在真机上是 `/v1/v1/messages` → 404。

> **这条会打到真实用户**：谁把 Anthropic 协议的自建端点按老习惯填成 `https://x/v1`，
> 升级后就是 404。**待作者定**：在设置里出声，还是替他把末尾 `/v1` 削掉？
> 我倾向前者——削掉是替用户猜，猜错的那天没人知道是我们改的。

**③ 一条是早就错着的判据，与本轮无关。**
`remote-kernel` 的「图从服务器回来」：画图代码写的是 `matplotlib.use("Agg")` + `plt.gcf()`。
**放进真内核量过，它只吐 `text/plain`**——现在的 ipykernel + matplotlib 3.11 不会自动挂上
inline 格式化器。后果是这条判据的绿红**跟本机装没装 matplotlib 恰好相反**：没装的走
`IPython.display` 退路是绿的，装了的（作者这台）永远红。09-18 把它记成「本机 matplotlib 环境」，
**方向记反了**。现在换成人在 Jupyter 里真会敲的那两句：`%matplotlib inline` + `plt.show()`，
4.5 秒出图（原先是等满 90 秒超时）。

## 六、这轮的一条纪律

**「升个版本」不是一个小改动，它是换地基。** pi 是运行依赖不是参考项目
（[[pi-layering-decision]]）：它的模型目录、类型、工具契约全都随版本走。
这次运气好——三条破坏性变更都在我们没坐的那几层上，而这件事**是逐条核对出来的，
不是假设出来的**。
