本轮基于 main `8ee42490`，在 `codex/plan-execution-workbench-20261108` 隔离工作区开发。未提交或合并，未推送、发布或替换正式 App。正式 `providers.yaml` 与 `credentials.json` 前后 SHA-256 一致。实现计划见[详细计划](../../superpowers/plans/2026-11-08-plan-execution-workbench.md)，操作说明见[使用说明](../../任务安排与成员会话-怎么用.md)。

## 实际变化

| 用户动作 | 现在实际发生什么 | 使用的原实现 |
|---|---|---|
| 生成安排 | 当前会话模型选择任务、执行者、文件、依赖和契约；数量由任务决定 | 只读 `propose_plan`、原方案 Markdown |
| 采纳安排 | 一次事务保存批准状态、执行快照、指纹和退出方案模式；具体执行者与权限固定 | 原 `plans.json`、原方案文件/存档 |
| 开始执行 | 直接创建精确映射的团队任务，不再发一句话重新分工 | 原 Team DAG、OrchestrationService、子进程执行器 |
| 前置任务完成 | 下游核验已验收产物版本，再入场；外部输入保持批准时版本 | 原 TaskSettings、内容版本、正式提交和宿主验收 |
| 查看成员 | 中文职责与成员身份分开显示，区分同一 agent 的多次分工；状态、验收和版本摘要集中呈现 | 原 RunOverview、执行代次、四个详情页及旧成员入口 |
| 停止/重开 | 仅操作所属方案；排空、拒绝迟到结果，重开暂停，查看不重放 | 原取消、attempt、恢复与产物锁 |
| 结束旧安排 | 排空后取消尚未完成任务，保留任务/回执和文件，释放未使用审阅预留 | 原结束团队与预算账本 |

新执行绑定支持本地 Native + 现有本地 subagent，最多 8 个执行成员；任务数量不预设为三。旧 Markdown 和旧执行入口继续兼容。新自动安排使用通用 Team DAG；科研专用流水线及其路线同步/修正循环仍从原入口执行，本轮没有自动生成这些循环或增加 CLI 后端适配器。

## 代码自审与修复

本轮按仓库规则单线自审，没有使用独立审查 agent，也不声称完成独立审查。修复并补测：

1. 批准只发自然语言造成执行与方案脱节：新增冻结快照与显式执行，重复启动幂等。
2. 只交任务摘要会丢掉正文中的方法/单位：随冻结任务交接完整已批准上下文。
3. 后台核验时停止或切会话可能迟到启动：宿主取消代次 + UI 所属会话/挂载代次双重检查。
4. 方案保存失败后内存仍“已批准”：恢复待批准记录；原子文件替换；批准与离开方案模式同事务。
5. 旧 Team 增成员、增任务、转派可能改变批准安排：绑定团队拒绝这些修改；成员邮箱派单明确报错，避免收下消息但不执行。原普通团队邮箱不变。
6. 缺少执行工具、路径经符号链接越界、输入产物嵌套/共写、无依赖读取前置产物：批准前拒绝。审阅须只读并覆盖前置产物，仍使用原科学判据。
7. 新入口原本没有独立停止/结束按钮：补所属方案的控制，不依赖主模型正在输出，也不停止其他团队。方案离开当前分支后仍允许停止其所属团队，重新启动仍要求有效的当前分支批准。
8. 展开视图选中任务却不打开详情、进度区挤占详情网格：补打开/焦点路径与跨列布局，实机断言左右位置。
9. 摘要沿用上一执行代次的版本数量：只有当前代次结算匹配才展示。
10. 审阅预留：复用同一账本，恢复核验后才能再花，结束排空后释放未用预留，不退还已消费额度。
11. 评测中的动态“当前剩余”提示曾被一并冻入执行者定义：冻结提示改为仅说明总额，当前余量以宿主账本为准；真实请求分区和原动态流水线提示保持原逻辑。离线以实际本地请求消费 2 次后验证，冻结提示不再冒充当前余量。

本轮没有修改远端终端实现、退出超时阈值、正式安装/更新机制或原始用户数据。历史风险保留，见下文。

## 真实 API：没有证明多 Agent 提效

范围与授权见[复验范围](live-proposal.md)，结果见[原始报告](live-01/research.md)、[请求计数](live-01/request-gate.json)及[冻结清单](live-01/research-manifest.json)。使用实际当前模型 `deepseek/deepseek-flash`，同一自制 `carbon-missing` 任务、同一科学模板/产物/独立真值与 15 次分组上限。多执行者通过新批准安排编译器进入原 Team；固定核查/分析/审阅属于评测控制条件，不是产品默认任务块数，未测模型自动拆分质量。

| 路径 | 实际请求 | 结果 |
|---|---:|---|
| 原单执行者 | 14/15 | 合格交付，宿主提交 3 次、退回 2 次；独立文件真值通过 |
| 新绑定多执行者 | 11/15 | 核查通过；分析用尽共享 11 次额度，未正式交付；审阅未开始 |
| 总量 | **25/30** | 1 次额度外请求被拦截，没有转发；无 SDK 自动重试或整组重跑 |

单组内部根据宿主退回修正提交仍计入 15 次额度；不等于重新运行一次试验。独立审阅 4 次未被分析挪用，失败没有被报为已完成；但合格配对为 0，不能得出质量、速度、费用或效率优势。单次试验又与本地回归有并行时段，不用耗时比较作收益结论。下一步应根据真实工具轨迹减少重复读/执行、及时正式提交，再申请新额度复验，不能直接扩大预算宣布成功。

真实试验运行期间候选/配置保持冻结。其后最终自审补了 UI 代次显示、结束入口、批准原子事务和冻结预算提示；离线与桌面覆盖产品实现，预算提示另有 17 项评测专项通过。真实报告只对应其清单中的候选，未冒充对这些后续收尾修复的再次联网验证。发现冻结预算文案过时不能证明它就是本次未交付的原因；不得据此反算修复后的效果。
