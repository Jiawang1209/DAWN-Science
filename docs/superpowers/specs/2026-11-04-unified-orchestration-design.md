# DAWN 统一编排、持续协作与恢复设计

日期：2026-11-04。基线：43dd7bdc / 0.0.44。用户授权：制定具体方案、创建 /goal 并直接开始执行。隔离分支 codex/unified-orchestration；不推送、合并、发布或替换安装应用。此前长期路线图继续保留，本计划是此次用户明确提优先级的专项。

## 目标与方案选择

目标是让普通 subagent、旧 Team 成员、托管 Bot 共用任务身份、并发准入、生命周期与恢复规则，让主 agent 能发现、继续和中断普通子 agent，并可靠接收其后续结果。

选择增量协调层：在现有执行器外增加 session-scoped OrchestrationService。另两个选项是继续分别扩展三套机制（短期改动少，恢复/取消规则继续分叉），或重写主循环为插件框架（成本和回归面大，浪费已有 Pi/Bot 实现）。Pi 继续负责模型循环与转录；现有 Team 状态机继续负责任务依赖、attempt 令牌和 Bot exchange；BotOutputLocks 继续负责产物路径占用。协调层只负责共同生命周期与消息准入。

## 身份和持久化

新增 src/orchestration，按父会话构造服务；持久状态写入 <sessionDir>/orchestration/state.json，原子替换，格式带 version 和 ownerSessionId。采用 Zod 验证磁盘边界，未知版本/损坏/父身份冲突必须报错，绝不退回空状态覆盖文件。

子级 ID 从父会话和明确的后端地址生成：普通子任务用 toolCallId + index，团队/Bot 用 teamId + member（含成员加入代数，避免移除重加串线）。记录后端类型、显示名、地址、执行代数、状态、任务文本和最后结果；不写凭证、模型二进制或复制科研数据文件。任务文本中包含的内容会随消息保存。父会话是授权范围，模型不能通过填写 parentId 越界。

P0 的状态区分 idle、queued、running、completed、failed、cancelled、interrupted。completed 仅表示执行后端正常返回，不表示产物验证或科学结论通过。执行 epoch 防止旧轮次结算覆盖新轮次。一次执行只持有一个共享容量名额；等待队友的 Bot 延续仍沿用 scheduler 释放当前轮次的方式，不持有名额等待另一个成员。

## 执行与关闭

统一执行入口接受 AbortSignal，排队期间取消不启动后端，活动执行取消向既有后端传递信号。所有注册到同一父服务的后端共享默认 4 个执行名额；每个子级至多一轮。保持现有单批 8 个任务及 Team 成员/任务上限。

关闭先同步关闭准入，取消排队与活动执行，再等待后端清理后释放状态；并发 close 共用同一 Promise。停止和中断不删除转录。跨父会话/跨进程的全局容量不在此次保证范围内。

## 持续协作

保留 subagent 的 single/parallel/chain 和现有返回内容；增加明确的后台启动与主 agent 控制工具。队列消息与运行中引导必须按能力如实区分：首个切片保证持久排队、当前轮结束后续同一份转录，不把排队称为实时 Steer。主 agent 可以读取状态与结果，避免只存在于开发者内部。

用户在坞里发起的旧续问仍仅进入子转录，不自动回送主 agent；模型发起的协作消息与后台任务具有明确 resultId，结果作为带来源的上下文回主会话。原始 thinking 不通过通知共享。Team/Bot 控制继续走其现有身份与任务检查，不允许普通子 agent 冒充 Bot 或队长。

## 恢复与副作用

启动时将上次 running 的执行对账为 interrupted，并保留原因、已完成结果与转录。绝不将未知执行自动标成功或自动重跑。消息以 requestId 去重，相同 ID 不同内容报冲突；已执行消息不因发送者重试而再次运行。

父结果通知采用先持久化、再投递、最后确认；只有父历史出现通知的稳定标记才记 delivered。父忙时延后，结束或重开后再尝试。确认失败保留待送；关闭后停止自动唤醒父会话。

旧会话没有 orchestration 文件时正常工作；旧 subagent meta.json/transcript 和 team.json 不改格式、不迁移删除。后续索引从现有地址补建，缺少权威身份时展示不可续接原因，不能凭名字匹配另一个运行。
