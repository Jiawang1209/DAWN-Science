## 一句话

**dsh 快，是因为它在数据发布这一层就限了频率，每一帧只处理「尾巴」。它的样式好看，是因为把「过程」降级成了一行灰字。**
我们在这两件事上的起点都不差（perf-render 做过一轮，工具也已经会折叠），差距主要在**传输层**和**过程的收纳方式**。

---

## 一、响应速度

| | dsh | DAWN | 差距 |
|---|---|---|---|
| 增量怎么传 | 瞬态 `live-chunk` 事件，只传**增量**；落盘的是压缩后的流 | 每个 token 都把**到目前为止的整条**（含思考）推一遍，主进程与渲染进程各做一次 zod 校验（`events.ts:1003-1030`、`:1193`；`client.ts:247`） | **大**。传输和校验量都随回复长度平方增长，回复越长越慢 |
| 限频放在哪 | 数据层：token 标为 `animation-frame`，三帧 rAF 合一次（约 20Hz）；结构事件立即发布，并取消挂起的帧（`assembly.ts:140-156`） | 渲染进程槽里 33ms `setTimeout` 合并（`transcript-slot.ts:112`）；主进程和后端不限 | 中。限频位置对了一半，但上游已经把整条传过来了 |
| 订阅粒度 | 每个节点一个源；列表只订阅引用稳定的 `order`，流式时只有增长的那一格重渲染 | `App` 已不订阅 `$items`，行已 memo；但 `ConversationView`（**含输入卡**）每次落字都整体重跑，`分组转录` 等每次全量扫描 | 中 |
| 流式 markdown | 自研增量解析：只重解析最后 2 块，冻结块缓存为 React 元素，key 用源码偏移 | streamdown（按块 memo，但每次对全文重新切块） | 小到中。量过再说 |
| 代码高亮 | 进视口才高亮（全局共享一个 IntersectionObserver）；流式时只 tokenize 追加部分 | streamdown 自带 shiki，每回复约 41 次异步回来的提交（perf-render 量的） | 中 |
| 长对话 | **没有虚拟列表**：历史按轮分页（50 条）+ 完成的轮用 `hidden="until-found"` 折起 | 只渲染最近 40 块 + 常驻「更早的 N 条」 | 相当。我们的做法更看得见 |
| 用户消息上屏 | 点击那一帧就本地回显，再 `nextPaint()`、再序列化 | 等后端 `userTurn` 推回来才出现，这之前只有等待记号 | **明显，而且肉眼可感** |
| 贴底 | ResizeObserver 驱动；「在跟随」与「正在动画」分开记；读者一有手势就打断 | `use-stick-to-bottom` + 回到底部浮标 | 相当 |
| 首开 | 插件预取、vendor 分包、React 之前先出纯 DOM 启动页 | 单个 1.4MB 主包，无 `React.lazy` | 小（Electron 读本地盘，收益有限） |
| 性能预算 | **进 CI**：240 轮合成历史，测首开 / 翻页 / 流式时打字；每个阈值都配一个零余量的反例，证明它真的会拒 | perf-render 手工量过，不进 CI | 中。这是「数字不回退」的唯一保障 |

**结论**：「感觉快」最直接的两处是**用户气泡即时上屏**和**增量传输**。前者改动小、立刻能看见；后者是长回复越写越卡的根因。

## 二、对话样式

| | dsh | DAWN |
|---|---|---|
| 用户消息 | 右对齐淡蓝气泡，20px 圆角，宽度 = 列宽 × 0.702 | 右对齐，侧栏色，`1rem 1rem 0` 有方向的圆角，82% |
| agent 消息 | 无气泡、**无头像**，14/24 | 通栏，**有**首字母头像 + 名字，15/26.25 |
| 条间距 | 分三档：过程行之间 6、正文与邻居 12、轮头 16 | 统一 40px |
| 工具 | **一行 24px 灰字**，没有线也没有底；hover 时加深，图标换成箭头 | 12px 行，左侧 2px 线，右边耗时 + 状态字 |
| 连续工具 | 连同思考收成一组，**标题写成一句话**：「已读取文件并搜索代码」；运行中是进行时「正在运行命令 · npm test」，每个标题至少停 150ms | ≥2 条折成「运行了 N 条命令 / 调用了 N 次工具」 |
| 整轮 | 做完后顶部一行「**已完成，用时 1m12s ⌄**」，点一下收起整轮过程，只留答复 | 没有整轮这一层 |
| 思考 | 「思考 · 首行摘要」，**按段落推进**（不逐字跳），右端渐隐加扫光 | 「[Ns] 思考中 / 想了一下」，展开看原文 |
| 运行中 | 转录尾部「深度求索中，用时 23s」+ 鲸尾动画 + 扫光 | 等待记号（秒数），发言末尾三点 |
| 代码块 | 无边框淡底，**sticky 标题栏**，纯文字「复制 → 已复制」 | panel 底 + shadow-md，28px 头部 |
| 线与阴影 | 几乎全是 0.5px 发丝线，描边画在 box-shadow 里；消息和工具完全平面，只有浮层带阴影 | 09-10 视觉重做后：阴影分五档，玻璃只给浮层 |
| 字号 | **一根轴**：所有尺寸 `calc(Npx + delta)`，调字号时图标和行高一起变 | 固定令牌 |
| 输入卡 | 28px 圆角浮卡；上沿一条**固定 36px 的渐隐带** | 已有 |
| 展示密度 | 四档（简洁 / 标准 / 详细 / 完全展开），由一张**策略表**驱动 | 无 |

**最值得学的一条**：**把过程分成「一轮」和「一组」两层来收纳**。组标题写成一句人话，轮做完只剩一行「已完成，用时 X」。答复是主角，过程是配角。

## 三、反馈

| | dsh | DAWN |
|---|---|---|
| 发送之后 | 本地回显气泡 + 尾部运行条（计时） | 等待记号（计时），**气泡要等后端回来** |
| 失败 | **钉在那一轮**：红点 +「本轮运行失败」+ 人话原因 + 等宽错误码 | 一条 `failed` notice（`.caveat`） |
| 截断 | 琥珀点 +「发送『继续』可以让模型接着写」 | 没有专门处理 |
| 模型重试 | 转录里一行「正在重试（2/5）· 8s」，展开看原因 | 看不见（pi 内部自己重试） |
| 断线 | 侧栏底部一颗可点的胶囊；重连中至少停 800ms，恢复后绿勾停 2s | 本地 IPC 不断线；远端 SSH 另有自己的一套 |
| 审批 | 接管输入区；**Enter = 允许一次，Esc = 拒绝**（避开输入法组字） | 卡片在输入框上方，但没有键盘快捷键 |
| agent 提问 | 倒计时「30 秒后继续工作」+「慢慢回答」；超时了卡片仍能答 | 没有「agent 问你」这种工具 |
| 停止 | Esc 在 500ms 内连按两次，只认同一会话、同一轮 | 停止键 / Esc |
| 危险操作 | 按两下：第一下变成带字的「确认停止」，3 秒不点就撤销 | 用确认框 |
| 侧栏状态 | **等你操作 > 运行中 > 完成未读 > 空闲**；等你时，行尾时间换成「待审批」 | 运行点 +「跑着」+ 未读点；「等你点头」在侧栏看不出来 |
| 统计 | 输入框下两颗统计：tok/s、缓存命中率；详细档加 TTFT | 每轮 token 用量 + 上下文仪表 |
| 逐条操作 | 复制、分支、👍👎；**没有**重试、编辑、回退 | 复制、修改、回到这句之前、用量（我们更全） |
| 系统通知 | 任务完成**不**弹通知 | 做完 / 出错 / 等你点头都弹，还有 Dock 角标（我们更全） |

## 四、按投入产出排序的建议

**A 档：小改动，立刻有感**

1. **用户气泡即时上屏**：发送那一帧就在本地插一条回显，等 `u{n}` 到了再按 requestId 对账替换；失败时撤下，原话退回输入框（这一步现在已经有了）。
2. **失败钉在轮上**：`failed` notice 改成「红点 + 本轮运行失败 + 人话原因 + 等宽原始错误」；截断时（`stopReason=length`）告诉用户「说『继续』可以接着写」。符合规格 7.5「失败必须出声」。
3. **审批卡键盘化**：焦点在卡上时 Enter = 允许一次、Esc = 这一轮先不做，排除输入法组字和长按重复。
4. **侧栏「等你点头」**：状态优先级加一档「等你 > 跑着 > 未读」，等你时，行尾时间换成「待批准」。通知已经会弹，但回到侧栏时应该也能看出来。

**B 档：中等改动，治长回复越写越卡**

5. **增量传输**：新增协议 `itemDelta`（按 id 追加文本或思考；`final` 时仍推整条作为对账），校验只校增量；主进程按帧合批。**这是协议变更**：按硬规则 1，同一次改动里要补 mock 分支，协议号跟着升。
6. **输入卡搬出 `ConversationView`**：让它不再每 33ms 跟着重跑。perf-render 当时写了「量了再看」，这次 dsh 的「流式时打字」基准就是现成的量法。
7. **进视口才高亮**：一个共享的 IntersectionObserver。需要先看 streamdown 给不给这个口子，不给就只能在外面包一层。

**C 档：设计改动，要作者先拍板（涉及样式，按惯例配图）**

8. **过程两层收纳**：组标题写成一句话（「读了 3 个文件、跑了 2 条命令」/ 进行中「正在运行 · pytest」，至少停 150ms）+ 整轮做完一行「已完成，用时 X ⌄」。
9. **思考按段落推进**，右端渐隐加扫光，替代现在只有秒数在走。
10. **条间距分三档**：6 / 12 / 16 加轮与轮之间更大的一档，替代统一 40px。过程行会因此紧凑很多。
11. **性能预算进 e2e**：合成 N 轮历史，量首开和「流式时打字」，给阈值配零余量的反例。
12. **一根字号轴**：设置里调正文字号，图标和行高跟着变。

## 五、不学的，和为什么

- **hover 才出现的操作行**（dsh 只让最后一轮常驻）：跟我们「悬停才出现的东西必须另有入口」冲突，而且作者两次反馈过「没有这个功能」。我们现在常驻，保持。
- **Chat / Trajectory 双视图**：对调试有用，但我们的定位是「agent 干活、你旁观」，时间线属于开发者视角，不急。
- **没有重试 / 编辑 / 回退**：我们已经有，而且比它全。
- **任务完成不弹系统通知**：我们有，保持。
- **Esc 连按两次停止**：会和我们「Esc = 停止」的现有习惯打架；要改得作者定。
- **无头像**：我们的头像承载「这一轮是哪个模型」（`item.by`，换过模型的历史不改写），不能简单去掉。
