# 真实任务评测与证据交接设计

用户已授权先制定方案并直接执行，第 1、2 项在一条主线完成；当前 API 模型的联网评测整轮最多 30 次请求。不自动提交、合并、推送、发布，不替换正式 App 或修改正式数据。

## 方案与取舍

采用现有实现的增量扩展。另建编排器会重复取消、锁和恢复责任；全量继承父历史会增加成本并污染独立审阅。因此保留 OrchestrationService、Pi 子进程、Team 流水线、TaskSubmission、内容版本与恢复边界，增加两个薄层。

1. 成对任务评测：保留 evaluate:science 默认确定性基线，增加显式 research 模式。任务为公开可分享的自制科研代表性数据，不读取私有项目；数据含缺失/负值及非目标字段，分别考察按批准规则统计和单位不明时阻塞。single / multi 使用同输入、模型、方法、输出和宿主真值。实际走 Pi、正式提交与原 Team 核查→分析→独立审阅。联网试验是小样本 pilot，不证明普遍质量提升。报告保存失败、不完整、未知用量、消耗、版本、源指纹，不把少完成任务当收益。
2. 证据交接：兼容原 recentMessages。新增可指定已完成正文 ID、路线步骤、当前父会话下已结束且带 accepted 回执的子任务。宿主从权威源构造 v2 冻结快照，禁止模型自填引用内容；对话内容排除思考、工具原文和未完成回复。路线是记录而非批准，回执/产物版本明确是历史身份，不声称当前文件仍有效；后续正式执行仍走原内容核验。快照不能用于冻结科研契约或独立审阅。来源目录工具只读，不唤醒任务。

## 有界与恢复

- 原 v1 指纹、16 KiB 正文上限及数据保持兼容；v2 总信封最多 64 KiB，最多 8 条正文、一个路线步骤、4 个历史子任务引用。超限拒绝，不静默截断正文。
- v2 指纹覆盖选择、来源、正文、引用与时间；既有 bindHandoff/null 标记保持唯一冻结门，续问/重启不重新采集。丢失、篡改、外来来源和选择变化均拒绝。
- 所有执行沿用原权限、产物锁、epoch 与取消排空；交接引用不会扩大文件访问或预算。
- 联网通过仅监听 loopback 的计数转发器，凭证只在内存，最多 30 次实际转发（重试也计），无自动重置、无原文请求日志；取消/到限关闭原执行，不借结束进程伪造通过。当前模型配置只读，凭证读取复用现有实现。
- 历史 Close context 超时与页面提前关闭继续未定位跟踪；正常退出回归和故障注入均不能关闭历史项。

## 阶段展示与验收

A：任务清单、独立真值、配对可比性及 30 次上限红→绿；展示离线结果和联网试验实际结果。

B：扩展交接单元/真实子进程；展示早期消息 ID 和历史回执进入快照、续问/重启字节不变、跨会话/篡改拒绝；真实 Electron 运行总览展示来源与历史版本。

C：类型、构建、完整 Node/UI、独立内核及相关 Electron，最后代码自审；冻结候选指纹，报告实际验证和未覆盖边界。文档和源码留专项工作区，等待后续用户验收。
