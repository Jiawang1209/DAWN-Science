# 照着案例分析 · 设计

> 2026-09-14。分支 `case-analysis`。与 `2026-09-07-照着文献画图-design.md` 是同一个案例库的另一半：
> 那一份是「按图找画法」，这一份是「按需求找案例，再照着案例分析我的数据」。

作者的话：

> *「首先可以通过提出需求……比如：我要进行转录组分析，可以给我什么案例？比如我要进行随机森林分析，
> 给我什么案例？返回真实的案例。」*
> *「可以基于案例内容，直接对数据进行分析和可视化（把案例当作真实的代码库）。」*

## 为什么这一轮几乎不写代码

| 段 | 现状 |
|---|---|
| 按需求检索案例 | **已有**：MLAI-science 的 `search_cases`（任务/算法/语言过滤）、`recommend_pipeline` |
| 读案例代码 | **已有**：`get_case` 回 `pipeline`（`pipeline.R` 或 `pipeline.py` 全文）与 `notes` |
| 让人看案例的真图 | **已有**：MLAI 服务自带图廊 `/gallery/case/<case_id>`；消息里的链接点开进坞「网页」格（`127.0.0.1` 放行） |
| 在我的数据上跑 | **已有**：`run_code` 走真内核，本机或服务器 |
| DAWN 连 MLAI | **已有能力**：远端 MCP（streamable HTTP + 钥匙串里的请求头），也可 stdio |

缺的只有：**一份走法（技能）**，与**这台机器上把那台 MCP 配进 DAWN**（装法文档）。

## 作者定的两条（2026-09-14）

1. **读代码当参照，直接写你的。** 不把案例的示例数据搬进项目、不先原样复现一遍。
   顺带满足「服务器上不放任何文件」：远端会话里写到服务器上的只有 agent 给他写的那份脚本。
2. **你挑，agent 等你。** 第一段返回案例后**停下**；他说「照第 N 个」才进第二段。两段是两次对话。

## 量出来的事实（2026-09-14，对着真 MLAI-science，stdio 起的同一套工具）

1. **库**：1565 个案例，draft 已清零（09-11 精修收官）。09-07 规格事实 4「七成是 draft」已过时。
2. **自然语言 vs 任务过滤**：`search_cases("转录组 差异表达分析")` 前六条里混进两篇纯画火山图的教程
   （`task=eda`）；加 `task=["differential_expression"]` 后五条全是真做差异分析的（DESeq2、DEGseq、EBSeq…）。
   → **需求能对上受控任务 id 时要加过滤**，否则画图教程会冒充分析案例。
3. **算法过滤管用**：`search_cases("随机森林", algorithm=["random_forest"], language=["r"])` 三条全是 R 的 RF 案例。
4. **受控词表的维度名是复数**：`list_taxonomy` 认 `tasks` / `algorithms` / `stages` / `libraries` / `figure_types` /
   `category` / `language`；传 `task` 回 `{"error": "unknown dimension 'task'"}`。**`search_cases` 的过滤参数却是单数**
   （`task=` / `algorithm=`）。两边写法不同，技能里要写明，否则第一步就撞错。
5. **一条命中约 500 字**，带 `title`、`language`、`task`、`algorithms`、`figure_types`、`status`。
   **有的标题没有信息量**（有一篇就叫 `20221223`）——列给人看时不能只念标题。
6. **`get_case` 的体积差两个数量级**：DESeq2 那篇 6.6k 字；`FigureYa179AMDAplot` **12 万字**，
   其中 `manifest.data` 5.8 万、`assets` 3.7 万（395 个数据文件的清单），`figure_limit=0` 也缩不下来。
   pipeline 本身：中位数 5.5k 字节，p90 1.8 万，最大 14 万。
   → 只在人挑定之后取**一次**；体积大时要照实说，不能假装读完了。
7. **本机那台 HTTP 服务在跑**（`127.0.0.1:8765`，`/healthz` 回 1565 个案例，`/gallery` 200），要 Bearer token。

## 定案

### C1 · 一份新技能，不并进 figure-like-this

`skills/analyze-like-case/SKILL.md`。触发条件完全不同（一个是粘了图，一个是说了需求），
合进一份会让 description 变含糊、模型更难挑对。两份在「第 0 步：工具在不在」上写法一致。

### C2 · 第一段：需求 → 3–5 个真实案例 → 停

1. **对上受控词表**：从需求里抽「任务」「算法」「语言」。拿不准任务 id 时 `list_taxonomy(dimension="tasks")`。
   **语言缺省跟当前会话的内核走**（会话里已经起了 R 内核就 `language=["r"]`）；他没说、也没内核时两种都列并标明。
2. **检索**：`search_cases(query=需求原话, task=[…], algorithm=[…], language=[…], limit=8)`；
   机器学习类需求（分类/回归/生存）可再用 `recommend_pipeline` 补「分阶段该看哪几篇」。
3. **过滤后为空**：去掉过滤再搜一次，并**说清楚**「按 `<任务>` 过滤没有，下面是不过滤的结果，可能混着画图教程」。
4. **列给人看**，每条写：序号、标题、语言、它做了什么（用 `task`/`algorithms`/`figure_types` 翻成一句人话，
   **标题没信息量时这一句是唯一的说明**）、图廊链接 `http://127.0.0.1:8765/gallery/case/<case_id>`。
5. **停下**，问他挑哪个。**不许**顺手 `get_case`、不许开始写代码。

### C3 · 第二段：他挑定之后

1. `get_case(case_id, figure_limit=0)` **取一次**，读 `pipeline` 与 `notes`。结果特别大（几万字）时说一句
   「这篇带了 N 个数据文件，清单很长，我只看了代码与笔记」。
2. **先看他的数据**（列名、分组、样本量、缺失）——用已有的读文件与 `run_code`，不重复造。
3. **说清差距再动手**：案例的输入长什么样、他的数据长什么样、要改哪几处（读入、列名、分组、参数）。
   差得太远（案例是 counts 矩阵、他给的是已算好的 logFC 表）就说「这篇不适用」并建议回第一段换一个，**不硬套**。
4. **在他的仓库里写一份新脚本**（不是把 pipeline 原样拷进来），开头注释写明照的 `case_id` 与标题；
   用 `run_code` 在他的数据上跑；出图落 `outputs/figures/`，成为产物。
5. **跑不通就说哪一步不通**（缺包、列名、分组数），不吞掉报错换一种做法。
6. **统计方法不替他决定**：案例用 DESeq2 不等于他的实验设计适合 DESeq2——照做可以，有疑点先问。

### C4 · 不做

- **对话里的案例卡片（带缩略图）**：作者 09-14 选了只做技能。等用出「文字列表看不过来」再说。
- **`get_asset` 拉图 / 拉示例数据**：图不进上下文（09-07 F5）；示例数据不搬（定案 1）。
- **自动挑案例一气呵成**：定案 2。

### C5 · 装法（这台机器）

DAWN 设置 → 技能与插件 → MCP → 粘贴 JSON：

```json
{ "mlai-science": { "url": "http://127.0.0.1:8765/mcp", "headers": { "Authorization": "Bearer <token>" } } }
```

那一屏只把**请求头名**写进配置，值存进钥匙串（`mcp:mlai-science:Authorization`），**不进配置文件**。
token 必须是 MLAI 那台服务**启动时**用的那一个：09-14 实测 `local-data/mcp_token` 里的值对正在跑的那台回 401，
两者不是同一个——连不上先查这里（状态码会写在错误里）。
名字必须叫 `mlai-science`——技能按这个前缀认工具；叫别的名字，技能第 0 步会找不到。
不想常驻服务时，照 09-07 的 stdio 写法也行，两份技能都不在乎是哪种传输。
