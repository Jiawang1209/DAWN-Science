# 会话内代码工作区：交互设计草案

日期：2026-11-15

分支：`codex/ide-capability-research`

状态：供用户查看效果的设计草案；未接入产品，不代表功能已经实现。

## 目标

让科研人员在同一段 DAWN 会话中完成 AI 生成脚本、人工修改、保存、选区运行和查看结果。保留现有项目导航、会话页签、模型与权限上下文，让脚本编辑成为会话的连续操作。

## 布局与入口

采用同一个会话容器的三种布局：

1. 对话优先：保持现有左侧项目、中央对话、右侧文件/产物/笔记本的关系。对话代码卡片和脚本预览增加“在工作区编辑”。
2. 边聊边改：当前会话保持在中央左侧，右侧展开脚本编辑器，下方放控制台和运行结果。没有额外创建 AI 会话。
3. 代码优先：编辑器获得主要宽度，当前会话缩到右侧；可暂时收起对话专注编辑。返回对话时保留文件草稿、光标与运行记录。

顶部已有的会话页签继续表示“哪一段会话”；对话/代码入口只改变当前会话的布局。现有右侧坞的“对话”表示另一段会话，不能用它冒充当前会话，也不能把另一段会话的输入与编辑上下文混入。

原型默认从对话开始，点击代码卡片即可体验三种布局之间的衔接。原型以窄屏重排展示适配意图，不代表当前桌面产品已经支持这些宽度。

## 编辑与 AI 衔接

- 脚本拥有独立页签、未保存标记和明确的保存动作。切换文件或布局保留草稿。
- 会话中的代码首次进入工作区时创建草稿，并保留消息来源；若相同来源已经有人工修改的草稿，返回时打开现有草稿，不能覆盖。
- 编辑器选区进入当前会话的原输入框，附带文件位置、行范围和该次草稿快照。沿用当前会话模型、权限和历史。
- AI 修改返回差异建议。用户采纳后只更新草稿，不自动保存或运行。
- 接受建议前核对草稿基线。用户在建议生成后改动了草稿时，要求基于最新内容重新生成或合并，不能静默覆盖。
- 产品实现时应保留完整聊天输入能力；原型只演示预置的“统计段加缺失值处理与样本量”流程。

## 运行与分析

- 有选区时运行选区，否则运行当前脚本；运行按钮与快捷键采用相同规则。
- 复用会话已有的 R/Python 执行通道。底部终端沿用现有 PTY 所属关系，不将 Shell 命令作为 Python/R 内核代码。
- 控制台、变量、图表与运行记录集中在编辑器下方，按需切换；已有产物、文件、Notebook 和审阅能力仍有各自入口。
- 每次执行记录实际提交的代码快照、范围、文件、会话与语言内核。没有保存也能运行草稿，但必须明确显示执行的是草稿。
- 文件保存状态与运行状态分开：选区运行不能标成整份脚本已验证；编辑后，旧结果提示需要更新。
- 选区运行仅使实际创建的变量可用；没有执行读取数据或初始化时，应展示真实内核错误。

## 状态归属与实现边界

现有接线依据为 `src/ui/App.tsx` 的会话页签、`ConversationView`、`RightDock`、`TerminalDock` 和 Notebook 的 `runInKernel` 调用。`src/ui/script-preview.tsx` 当前仍是只读预览。

项目/本地或远端身份/规范化路径共同确定文件编辑对象；会话 ID 与语言确定运行上下文。切换会话不能悄悄把另一个会话的内核变量和运行记录带过来。共享同一文件时，AI 建议仍需核对当前草稿版本。

未来实现应让当前会话只挂载一份对话视图和输入状态，通过布局调整位置；不能通过额外挂载一份对话视图来获得“侧边 AI”，以免产生两份输入、重复订阅和不同步历史。

本轮只制作可交互设计，未选择编辑器库、增加后端读写协议或变更产品运行行为。真实保存还需要文件权限、外部改动冲突、另存为与远端失败处理。语言服务、调试器和完整 Notebook 文档编辑不属于本轮设计的交付内容。

## 原型与检查

交互原型源文件：`docs/design-previews/code-workspace.html`。这是由对话预览环境承载的页面片段，不是产品入口。

已在浏览器检查：对话进入并排编辑、展开工作区、返回对话后草稿保留、Python/R 页签草稿独立、选区运行演示、AI 差异预览与采纳、保存状态与旧结果提示、专注编辑、变量面板。三种布局在 1024、736、500、320 像素下未出现外层横向溢出；检查到的浏览器运行错误为零，查看了浅色和深色效果。

所有数据、输出、保存与 AI 修改均为本页演示。没有运行真实脚本、写入用户项目文件、启动内核或调用真实模型。原型的预置输出不用于验证代码的计算正确性。
