## 2. 使用流程与职责

### 2.1 主对话：队长与交付入口

用户说“组一个 Bot Team，检查数据、做混合模型、画图并检查脚本”，主对话执行：

1. 确认当前任务、项目或临时工作区、远端连接与输入文件。
2. 从已配置的 Bot 中选择可用成员，沿用各自配置的模型；未配置模型时沿用当前主对话的可用模型，不擅自更换为其他收费模型。
3. 展示一张紧凑的 Team 任务卡：成员、职责、任务依赖、状态。
4. 启动就绪任务；上游产出到位后再启动依赖它的下游任务。
5. 接收成员结果、处理阻塞与失败；用户可以补充要求、停止或调整分工。
6. 交付汇总：结论、使用的方法、脚本与注释/说明文件、图表路径，以及失败或未完成事项。

不增加独立“总管 Bot”。创建 Team 不代表无限循环自发协作；任务范围由用户目标和队长的任务表约束。

### 2.2 坞：Bot 管理与直接交流

- 列表显示名称、专业职责和真实运行状态；没有 Bot 时提供创建入口。
- 创建/编辑字段：名称、职责说明、工作指令、模型、启用状态；可从已有专业角色创建，也可自定义。
- 点选 Bot 进入直接对话，复用 ConversationView；顶部同一行提供名称、当前项目、返回列表和关闭入口。
- 任务/历史通过次级入口查看，不在狭窄坞里叠加第二个常驻侧栏。
- 同时只显示一位 Bot 的对话；切换面板或关闭坞不会停止后台任务，也不会删除历史。
- 现有团队面板继续显示依赖、成员、消息与任务结果。Bot 面板中的任务链接可以定位到对应团队。
- 名称过长省略并可查看完整名称；亮暗主题、窄坞、自适应页签及键盘操作遵循现有组件规则。

### 2.3 `/`：确定性委派入口

- 斜杠菜单增加 Bot 分组；保留技能、子 agent、`/team`、`/plan`、`/compact`。
- 选择某个 Bot，只在草稿中加入目标，不立即发送。显示友好名称，实际保存稳定 botId。
- 建议明确命令形式：`/bot:<botId> 检查这个模型`；菜单负责插入，用户无需记忆 ID。
- 主对话发送此命令后，后端直接建立该 Bot 的任务，不只拼接“请调用某助手”交给模型猜测。
- 没有活跃 Team 时建立当前主对话的单成员 Team；已有 Team 时给同一 Bot 成员追加任务，或添加该成员。
- 主对话正在执行时仍可委派；成员结果进入主对话持久结果队列，当前轮结束后送达，不强制中断当前工具。
- 第一版 `/bot:` 只在主对话启用，坞内直接对话不再嵌套建立 Team；不可用入口显示具体原因。
- 修改未发送草稿、取消选择、切换主会话不得误发；已派任务不因随后切换页面而换项目。

## 3. 数据与上下文边界

### 3.1 身份不等于会话

推荐模型草案如下，所有类型在实现时与 Zod 协议和持久字段一起定义：

```ts
type BotProfile = {
  id: string;
  name: string;
  role: string;
  instructions: string;
  model?: { provider: string; model: string };
  enabled: boolean;
  createdAt: string;
  updatedAt: string;
};

type BotScope = {
  workspace: string;
  projectId?: string;
  connectionId?: string;
};

type BotSessionBinding = {
  botId: string;
  scopeKey: string;
  kind: "direct" | "team";
  teamId?: string;
  ownerSessionId?: string;
  sessionId: string;
};
```

- BotProfile 是长期身份，不包含某个项目的聊天内容或运行状态。
- direct 记录按 `botId + scopeKey` 续接；用户另开对话时保留旧记录，仅变更当前绑定。
- team 记录按 `botId + scopeKey + teamId` 续接；与直接聊天分开，不同时把两个任务写进同一条模型消息流。
- scopeKey 由后端根据真实工作区、项目和连接生成；不信任 UI 自报路径。远端目录规范化使用现有远端路径规则。
- 无项目时使用当前主会话的 scratch 工作区；不得恢复旧项目目录、附件或记忆。
- 同一团队内 botId 唯一。现有非 Bot 团队成员保持原行为，不被自动迁移为 Bot。

### 3.2 共享任务资料，不默认共享全部私聊

每个任务固定记录：目标、必要的主对话背景、明确输入、期望产物、输出目录、上游任务结果和所属 scope。

- 默认不向团队成员复制 Bot 私聊全文，也不复制主对话全部历史。
- 全局用户偏好与项目记忆复用现有确认制；第一版不增加 Bot 自动提炼和自动写入全局记忆。
- Bot 工作指令属于长期配置；只对新启动的执行轮生效，运行中使用创建任务时的配置快照。
- 同一项目共享文件并不意味着共享 Python/R 变量；每个执行会话使用自己的内核。
- 队长为成员分配明确的产物路径，依赖任务按顺序运行；运行中的成员不能同时领取相同输出文件的写任务。文件占用按规范路径和 scope 判断，终态释放。
- 归档 Bot 后保留历史；运行中的 Bot 不能直接删除。第一版使用停用/归档入口，避免级联删除项目记录。

## 8. 第一版范围与讨论建议

第一版完成三个入口共用 Bot 身份、项目内直接交流、确定性委派、自动组队、结果回传及脚本/说明交付。自由群聊、Bot 自动互相拉人、自动写长期记忆、定时自主工作、ACP/CLI 团队成员和 DSH 插件兼容不纳入首版。

建议后续讨论优先围绕真实使用：哪些助手需要长期固定、哪些分工能并行、最终交付是否减少了人工返工。无需一次创建所有内置专业角色，也不以成员数量或消息数量作为成功指标。
