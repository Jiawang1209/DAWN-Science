原生1280×808启动截图保留。首个交互窗口在选择隐藏团队入口时误把更多菜单的 menuitem 当成 tab，REPL等待超时重置；随后仅终止已记录PID46954，保留其隔离root。第二个窗口使用现有菜单helper启动，在核查、分析、独立审阅和版本验证后成功复现产品暂停显示遗漏，截图07保留。期间两次辅助断言分别因为重复“产物”页签选择器和把空总览误认为不存在而失败；改成主坞 data-dock-tab 定位和断言空总览的真实内容后通过，未修改产品来迎合错误断言。

随后交互脚本在同一单元先使用后重新var声明appWindow，REPL桥接把旧变量置空。通过已有overview.page()取回实际页面并保存排空截图；窗口关闭后macOS进程仍保留，单独终止已知隔离PID47448。最后重新从修复后main启动并保留可操作窗口。上述脚本/宿主中断不当作正常退出计时，也不纳入53次桌面退出统计；历史退出与PTY问题继续OPEN。

实际产品缺陷：批准方案已暂停且在途0，下游pending被聚合成整体active。先补测试复现，再修正只读成果投影；不改调度、恢复或锁。只有精确绑定当前taskAttempt的真实运行/收尾进程能覆盖暂停展示。恢复记录保持history，不用暂停标记猜测排空或取消。

最终main重开后，helper仍捕获旧Page导致一次“Target closed”定位失败；重新绑定helper后恢复。恢复时总模拟调用由13升到14（随后15），检查system确认是既有“建议下一句用户请求”功能，不是任务执行。冻结契约的任务调用始终9次，重开前后不变。无付费调用。交互取消发生在任务宿主已启动、模型请求尚未开始阶段；真实模型在途取消由同一候选的桌面用例单独验证，不把此交互演示称为在途模型取消。正常app.close返回172ms，随后的已关闭process句柄读取不再可用；使用app诊断的process-exit=0核对。
