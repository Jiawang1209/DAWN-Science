# 子 Agent 按需读取技能与相关记忆

2026-10-18。用户已确认首版范围并授权独立分支实施；不合并、不推送、不替换安装版。

## 目标与边界

普通子 Agent（single / parallel / chain / 续问）与旧 Team 成员，通过父进程提供的只读工具发现技能和查询记忆。专业 Bot 沿用既有 NativeRuntime 装配，仅做兼容回归。主 Agent 仍必须在任务正文明确传递硬性约束；检索到的资源不能覆盖用户要求。

保留独立进程、关闭扩展、关闭提示模板和禁止新增递归委派的边界。不开启子进程默认技能目录扫描，不注入全量技能或记忆，不增加资源写入或记忆提议工具。首版不提供手动技能的自动调用能力；manual / off 不进入子任务资源目录，显式调用仍在主会话进行。

## 架构

父侧 `subagent/resources.ts` 使用 pi 的 `loadSkillsFromDir` 读取技能目录，按项目、全局、自带顺序先去重，再检查开关，防止停用的上层技能被下层同名版本替代。仅模型可调用的技能进入短索引。自带开关复用设置回调。读取技能关联的文本参考文件时限定在真实技能目录内，拒绝越界和越界符号链接。

记忆从现有 MemoryStore 的已确认活动条目读取，沿用 user / memory / key 三轨；key 限定当前 workspace，分支专属条目只在已知且匹配的分支可见。未知分支不返回分支专属条目。关闭记忆插件或读取族时不返回记忆。远端会话不能把本机同名目录当作远端项目资源：仅提供全局/自带技能及全局记忆，项目资源留待远端专门适配。

每轮子任务由父侧建立独立资源访问器，资源索引在首次调用时建立并保留在父进程；新轮次重新获取目录和开关。子进程只收到资源工具可用的标志。通过现有 NDJSON `call / reply` 传送 `resource_search` 和 `resource_read`，普通子进程启用资源时保持 stdin 可写，旧 Team 同一通道继续支持成员消息工具。资源请求只允许这两个名称。

`resource_search` 返回有界、可分页的名称/用途/来源索引，记忆只显示短预览。`resource_read` 接受父侧发出的资源 ID，可分页读取正文或技能目录内的相对文本参考路径；不接受任意绝对路径。返回实际来源、总量、截断及续读位置。权限拒绝、损坏资源、未知 ID、空库、超限分别明确说明。新增工具走现有子转录工具事件，不新增公开 UI 协议操作。

2026-10-18 实跑补充：记忆查询先归一化 NFKC/大小写/空白，精确短语优先；长查询按中文分词及非中文词边界，至少两个有效关键词命中才作为候选，按命中数/字数及原目录序稳定排序，再分页。技能维持名称/用途字面匹配。不是语义/同义词或跨语言搜索，候选必须再读正文确认；未命中可缩短查询或空查询分页列目录。检索只在已过滤的可见索引上执行。完整设计见 `2026-10-18-memory-query-recall-design.md`。

## 验收

1. 项目 > 全局 > 自带，同名上层停用不回落；manual / off 不可发现或通过 ID 读取。
2. 已确认/活动记忆可查询；归档、待确认、其他 workspace、其他分支不混入；读取开关生效。
3. 只读接口拒绝未知方法、未知 ID、路径穿越、越界符号链接、二进制和超大文本；分页不悄悄丢内容。
4. 真子进程 single / parallel / chain / 续问及旧 Team 的资源请求和回复可见，停止/超时与既有 EOF 模式兼容。
5. 真实构建 + 共享 mock 模型完成“查目录 → 读技能 → 查记忆 → 读记忆”，记录工具事件并证明全文未预先进入模型提示词。
6. NativeRuntime 装配实际提供资源；Bot 既有原生会话技能/记忆与协作回归通过。

## 不变式与限制

资源工具只读且不能给子 Agent 增加技能中提到的执行工具；没有对应工具时应报告限制。它不是 OS 文件系统沙箱，现有 read/bash 能力不由本改动重新定义。凭证不进入资源响应；使用确定性模型的验收证明机制，不证明真实模型必然选择正确技能或统计方法。
