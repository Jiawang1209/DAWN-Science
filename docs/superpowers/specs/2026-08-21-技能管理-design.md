# 技能管理：开关、导入、删除（skills-manage）

> 学自 `MichengAI/dsh-skills-manager` v0.1.23（Apache-2.0；本地副本 `ccb_hive_code_learn/dsh-skills-manager`，
> 解读全文 `dsh-skills-manager-解读.md`）。思路借、代码自己写。
> 作者 2026-08-21 定的：**开关写进文件**，不在 DAWN 配置里记名单。

## 问题

Agent Skills 那一屏（S20，2026-08-15）是只读清单。技能一多，不想让模型每次都看见某个技能，
唯一办法是删目录；从 GitHub 下下来的技能目录怎么进 DAWN，没有答案。

## 定案

### 三档开关，写进 SKILL.md 的 frontmatter

| 档 | frontmatter | 谁能用 |
|---|---|---|
| 开 `model` | 两行都没有（缺省） | 模型自己挑，`/skill:名` 也行 |
| 只手动 `manual` | `disable-model-invocation: true` | 只有 `/skill:名`（pi 原生认这一行） |
| 关 `off` | 再加 `user-invocable: false` | 谁都不给 |

- **为什么写文件**：这两行是 agentskills.io 的标准字段，Claude / Codex / pi 都认。记在 DAWN 配置里会让同一个技能在 DAWN 里关着、在别的工具里开着——两个真相。
- **为什么三档**（与它不同）：它一个开关管两件事；有人只想「模型别自己用、我手动还能调」。
- **怎么写**：文本级替换（`src/skills/invocation.ts`）——只删 / 加这两行，注释、键序、嵌套块、引号、`\r\n`、BOM 全不动；没有完整 frontmatter 就拒，不硬改。同目录临时文件 + `rename`，中断不留半截。
- **「关」怎么生效**：pi 不认 `user-invocable`；`native.ts` 的 `skillsOverride` 按文件上那两行把 `off` 的剔出清单——与技能屏同一份真相。
- **自带的只读**：在应用包里，没有开关、没有删除；后端守门（`技能文件必须可改`），不靠界面藏按钮。

### 导入：两阶段

1. `importSkill { dryRun: true }` 预检 → `{ pending, conflicts, failed }`；界面拿到 `conflicts` 才问「覆盖 / 只导没撞名的 / 取消」。**预检与实导同口径**（符号链接、层数、来源与目标重叠都在预检查）。
2. 正式导入：复制到目标同目录的临时路径 → 旧的改名备份 → 临时的改名到位；失败回滚，回滚也失败就把备份路径报出来。
3. 来源：含 `SKILL.md` 的目录 / `SKILL.md` 文件（用父目录）/ 一筐含 `SKILL.md` 子目录的目录。**只认目录形态**（标准只有这一种，pi 也只认这一种），`<name>.md` 不收。
4. 名字规整成 kebab；规整不出就失败并说原名，不猜。
5. 目标：`~/DAWN/skills`（你写的）或 `<工作区>/.dawn/skills`（这个项目）。
6. 「新建」仍然不做——让 agent 写（`writing-skills`）。

### 删除

整个技能目录进废纸篓（`shell.trashItem`），先确认。

### 出声

- 三件事各落一条 Run（`skill_invocation` / `skill_import` / `skill_import-overwrite` / `skill_delete`）。
- 界面每次都说「**新会话起生效**」——pi 在建会话时装技能，已经在跑的会话不变，不假装立刻生效。
- 导入结果说清导了几个、跳过几个、失败几个与原因、备份没清掉的警告。

## 协议 7.17

`listAgentSkills` 多 `invocation` / `mutable`；新增 `setSkillInvocation` / `importSkill` / `deleteSkill`。

## 不做 / 放弃

HTTP 那层的安全门（我们是 IPC）；flat `.md` 形态；它的上传弹窗（我们用系统选择器）；创建 / 在线编辑；
第二档（按来源筛、搜索；自带技能的「关」走配置覆盖）先放着。

## 顺手修的

e2e 的全局技能目录此前一直指着开发机真实的 `~/DAWN/skills`——加 `DAWN_SKILLS_DIR`，夹具隔离到临时目录。
