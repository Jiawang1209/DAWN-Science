# 本机配置、引导状态与密钥保护

正式版沿用固定应用标识与用户数据目录。API Key 继续由现有 CredentialStore 和系统安全存储管理，不写入前端 localStorage、源码或版本库。保留用户数据的正常升级/覆盖安装不会主动清除凭证。macOS 自身仍可能请求钥匙串授权；删除用户数据、换电脑、重置系统钥匙串不属于自动保留的范围。

引导只记录非敏感完成/跳过标记。配置过模型凭证，或完成/跳过引导后，新窗口启动进入首页；已有旧安装/版本标记会迁移。工作台和首页底部“导航栏”可随时手动打开四步引导，手动打开不撤销此前完成状态。

## 开发与提交

新克隆仓库后先运行：

```sh
npm run security:setup
```

它下载[官方固定版本 Gitleaks](https://github.com/gitleaks/gitleaks)，校验仓库固定的 SHA-256，将工具缓存放在用户目录下、仓库外的缓存中，并启用已有 `.githooks` 目录。已有自定义 hooksPath 不会被覆盖。仓库不包含扫描工具二进制、真实凭证或用户数据。CI 使用相同安装器，无需 npm 依赖。

- pre-commit 检查暂存文件的完整内容和文件名，不依赖工作区未暂存版本，并拒绝强制加入的运行时凭证文件。
- commit-msg 检查最终提交说明，防止只写在说明里的秘密绕过 pre-commit。
- pre-push 检查待推送提交历史、作者/提交者信息、提交说明、分支/标签名及标签说明（包含嵌套标签），包含写入后又被删除的内容；新分支只在确认目标 URL 与对应远端一致时排除该目标已知提交；不同远端、直接 URL 或不同 push URL 会检查完整可达历史。合并提交的差异也纳入检查。
- CI 检查 Git 当前跟踪快照、推送/PR 范围及标签说明；新建分支/标签和手动发布缺少历史起点时扫描完整可达历史；发布工作流必须通过密钥检查才打包和发布。
- 扫描缺失、失败或发现凭证时阻止对应操作。只输出不含原文的文件指纹、行号和规则，文件名本身可能含凭证，因此也不直接回显，禁止转发原始扫描日志或密钥值。临时扫描副本和脱敏报告使用系统临时目录，结束后删除。

手动检查：

```sh
npm run security:check
npm run security:test
```

`security:check` 检查 Git 索引快照；新文件和修改需要先暂存。不要将真实 Key 放入测试，测试仅使用生成的人工假值。不要通过排除整个测试、文档目录或新增大范围忽略来处理误报。现有例外仅限审计目录中的文件名与完整 SHA-256 摘要的组合，以及某个入站消息测试中固定的递增字节 AES 测试向量。

`.gitignore` 加上钩子的路径规则覆盖本地 `.env`、providers.yaml、credentials.json、handoff.json、.handoff-salt、models.generated.json、私钥文件等误复制情况。忽略规则本身不能保护已经跟踪或强制加入的文件，所以仍需内容和路径检查。

本地钩子可被人为绕过；CI 在代码上传后执行，不能撤回已发生的上传。模式检测也不能保证识别所有任意格式的秘密。真实秘密只留在本机凭证存储；如果实际 Key 意外进入 Git，应先撤销/轮换，再处理相关历史，不能仅删除最新文件。
