# 实时纠偏与科研并行：专项复审及本地集成

基线：本地 main `6f6c7251`；实现工作区 `codex/live-steering-parallel-science`。本轮用户明确授权修复、补测试、验证后本地提交并合并 main；不推送、不发布，不替换安装应用。

## 复审发现与修复

1. **并行异常未停止兄弟后端**：结算后的通知或写盘异常进入 `起一轮` catch，只中止当前控制器，再直接保存 paused 状态，绕过正常 mutation 中的全批中止。独立临时脚本复现 interrupted 批次仍有未取消的兄弟。异常入口现在先关闭派发并中止同团队全部活动控制器，真实排空前保留活动所有权，迟到成功不采用。
2. **写盘失败留下已排空的孤立尝试**：当前后端已结束但结算写盘失败，旧记录仍为 in_progress；有兄弟活动时无法全量恢复清理，最终会永远拒绝恢复。故障注入先复现，再只以本任务 ID／attemptId 关闭当前已经排空且仍非终态的尝试；不提前关闭兄弟。
3. **领取后通知／读取失败留下无后端 claimed**：领取已落盘，但后续通知或读取失败，原 catch 写通知后跳过启动，任务永久 claimed。现在将领取后读取和派单放入同一保护范围；只关闭令牌匹配且尚未准入的 claimed，暂停整批并排空真实兄弟。尚未落盘的 pending 或其他令牌拥有的任务不被误结算。
4. **旧代次草稿缺少显式恢复入口**：旧草稿在后台轮次变更后仍绑定旧 epoch，这个防误投行为正确，但用户即使替换整段文字也只能继续收到 stale 拒绝。界面现在明确提示过期、禁止提交，并提供“重写本轮纠偏”；只有清空后新写的指令绑定当前轮次，旧草稿绝不自动转投。

参数化回归覆盖 observer、persistence、claim notification、claim 后 read 四个故障点，验证全批取消、排空前不得恢复、迟到成功不采纳、排空后显式恢复成功。UI 回归覆盖轮询 epoch1→epoch2、替换旧文字仍不误投、显式重置后只提交 epoch2。

独立控制、并行检查点、锁／恢复三个方向分别只读审查；发现的问题修复后由原审阅者再次复核，无剩余 P1/P2。锁审查确认原 readonly 路径锁、workspace-exec 全工作区独占、正式提交验收期间持锁、隐藏 review 和完成项版本核验、宿主汇总及路线 CAS 仍保持。评测额外增加真实锁 grant／release 窗口互斥断言，不再仅凭“分析之间重叠为 0”推断全部锁互斥。
