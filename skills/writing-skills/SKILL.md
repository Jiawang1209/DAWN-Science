# 写一个技能

用户让你「把这个记下来」「做成技能」「以后都按这个来」时，在用户授权范围和当前工具权限内直接写文件。

## 什么时候用

- 用户说：把这套做法记下来 / 做成一个技能 / 以后都这么干 / 存成模板
- 你们刚一起摸索出一套可复用的做法（某类数据的清洗顺序、某种图的画法）
- 用户抱怨「每次都要跟你说一遍」——**那就是该写技能的信号**

## 什么时候不要用

- 一次性的做法（只对这一份数据成立）——写进技能只会污染以后每一段对话
- 用户只是想要一段代码 → 写成 `scripts/` 下的脚本，不是技能
- 内容是**这个项目的事实**（数据在哪、字段什么意思）→ 那属于 `AGENTS.md`，不是技能

## 格式

一个技能 = **一个文件夹 + 一个 `SKILL.md`**：

```
.dawn/skills/soil-eda/SKILL.md
```

```markdown
---
name: soil-eda
description: 一句话说清「什么时候该用它」以及适用边界
metadata:
  dawn:
    tags: [数据初探, 生态, EDA]
---

# 标题

## 什么时候用
- 具体的触发场景

## 什么时候不要用
- 边界。**这一节比上一节更重要**：没有边界的技能会在不该出现的地方冒出来

## 正文
真正的做法。给命令、给顺序、给理由。
```

**`description` 要写清触发场景。** 写成「数据分析相关」太宽；写成「拿到一份没见过的表格数据时先检查形状、缺失和分布」更容易判断。

当前检索使用 **name、description、标签**，并做中文分词、规范化和有限的中英文同义词匹配；不检索技能正文。包内标签可放在顶层 `tags` 或上例的 `metadata.dawn.tags`，顶层优先；技能页设置的个人标签会覆盖包内标签，空列表也会覆盖。标签要写真实任务词，不能靠堆词扩大触发范围。

检索只返回候选与命中依据，模型还要判断任务是否适用、再读取正文。自动调用的技能超过 20 项时，不再把所有说明注入系统提示，改用按需检索；小目录保留原有说明提示。读取指令不等于运行代码，也不授予新的工具或执行权限。

## 名字的规矩（硬的）

**只能用小写字母、数字、连字符**：`soil-eda`、`figure-for-paper`。
中文、空格、下划线都不行——**这个名字会被送进模型的工具/技能清单**，
不合规的名字会让整段对话失败（这个项目为此栽过一次）。

## 放哪儿

| 放哪儿 | 什么时候 | 你能不能直接写 |
|---|---|---|
| `<工作区>/.dawn/skills/<名>/SKILL.md` | 只跟这个课题有关 | 默认位置，按当前权限使用 `write` |
| `~/DAWN/skills/<名>/SKILL.md` | 用户明确要求跨项目复用 | 按当前运行时和权限档处理，不能承诺一定可写 |

默认写进项目里。原生会话把工作区外写入视为风险：根据权限档，可能允许、请求确认或拒绝；硬拒仍会拦截。外部 ACP agent 的文件工具可能有更严格的边界，以实际返回为准。

用户要求全局范围时，沿用已有授权并通过正常工具和权限流程写入。若权限拒绝，保留项目内文件，说明拒绝原因，以及可在技能页导入到全局或由用户移动目录的办法；不要声称已经全局生效。

**不要绕过权限拒绝**，例如改用 bash 的 `cp`、符号链接或另一工具写同一被拒路径；不要为了保存技能擅自修改权限设置。

## 写完之后

1. 告诉用户文件路径、项目或全局范围，以及尚未完成的权限或写入步骤。
2. 在技能页点击 **「刷新技能清单」**，重新读取文件列表和诊断；这只刷新页面，不代表当前模型会话已经更新。
3. 当前是已打开的原生会话时，等当前一轮结束、会话空闲后点击 **「刷新当前会话技能」**。成功后从下一轮生效，不需要重启应用或另开对话；忙碌或失败时按页面提示重试，不声称已刷新。检查同名覆盖顺序：项目 > 全局 > 自带；手动技能不进入自动检索，停用技能不能读取。
4. 外部 ACP agent 当前没有这条会话刷新实现，按钮会提示由外部 agent 自身管理。DAWN 网关的技能查询与外部 agent 自己加载的技能/提示不是同一份状态；不要声称 DAWN 按钮已经刷新了外部会话，按该 agent 自身提供的流程处理。
5. 用户要求修改时直接编辑文件，再按上述范围刷新。刷新只更新技能资源，不改变当前执行授权。
