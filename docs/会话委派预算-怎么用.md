# 运行总览与会话委派预算

本页对应专项分支 `codex/run-explanation-budget`；尚未发布或替换正式应用。实际演示和验证范围见 [审查报告](reviews/2026-11-06-run-explanation-budget.md)。

## 查看任务在等什么

打开当前 API 会话右侧的“团队”面板。即使没有创建团队，也可查看“运行总览”。

- 等统一调度：尚未取得执行槽。
- 等产物锁：显示预约范围，以及活动占用者或公平队列中排在前面的任务身份。
- 核验冻结输入：检查已有契约和输入版本。
- 后端执行：正在调用原执行器；不会据此猜测模型或工具内部的具体等待原因。
- 宿主验收：按原规则核查真实证据、文件和版本。
- 停止中：取消已发出，实际后端尚未完成排空。

阶段耗时只展示已结算部分。展开“关键执行历史”，查看本会话最近 256 条宿主事实；省略会明示。历史不是恢复指令，查看历史不会启动任务。

磁盘快照显示的是历史阶段和占用信息，不能证明进程现在仍在运行。执行完成和宿主验收通过是不同状态。

## 设置累计限制

在总览内展开“调整预算限制”，填写需要的限制，点击“委派限额生效”。留空表示不设置该项限制。

| 字段 | 含义 |
|---|---|
| 累计执行轮次上限 | 当前父会话经统一编排实际准入的普通子任务、Team 和 Bot 轮次；包括续问、返修，以及在锁等待/输入核验阶段停止的轮次 |
| 总历时上限 | 从首轮准入起的历时，包含暂停和离线；已存在较早执行的会话可能在设置后立即达到限制 |
| 可核验 token 上限 | 已结算 input、output、cacheRead 的可核验部分；不是金额额度，也不是请求发送前精确预留 |

根会话自身的模型调用、独立内核及其他会话不在这个委派预算内。它不能保证账户的总费用上限。

轮次额度用完后，已有合法准入的轮次可以完成，新轮次不启动。总历时到点或可核验用量触达限制时，沿用取消和排空；实际后端清理之前仍显示停止中。此前已验收成果保留。

字段缺失、partial、异常用量和重启前尚未结算的轮次会显示未知。设置 token 限额后，未知用量会阻止新轮次；用量不完整时可以显式调整限制，继续使用轮次/总历时约束。并发在途请求可能产生超额，不能把显示的已核验数字当成完整账单。

## 续问、重启和调整额度

- 续问和返修继续计入同一父会话，不重置账本。
- 重启保留已用轮次和可核验消耗；未结算轮次变为未知，不自动重放。
- 修改或关闭限额只改变限制，不清空消耗，也不自动重跑任务。
- 看到版本冲突时，用“重新读取预算”读取当前限额与消耗，再重新填写。
- 离线记录只读；当前 Native API 会话在线时才可修改，其他运行时明确报告不支持。
- 旧记录只统计能确认的代次；只有结果而没有代次的旧任务，至少计为一轮未知用量。不能从中复原完整旧账单或历史时间。

## 本地演示

在该专项工作区运行原 `npm run dev:mock`。打开“团队”，先设置两轮额度，再发送三次“演示委派预算”：前两次启动只读子任务，第三次被预算拦下。这个暗号只用于共享确定性演示，预算设置仍经过真实界面与协议。

科学对照沿用 `npm run evaluate:science -- <新的证据目录>`；它使用真实 Pi、进程、脚本、文件及宿主验收，推理回复为固定 fixture，不代表真实付费模型的质量或费用收益。
