# run_code 执行意图边界

用户确认的目标：减少普通咨询被误当作执行任务，保留明确科研计算任务的连续执行能力。

## 根因与范围

当前系统追加提示将“探索、看数据、画图、验证一段逻辑”直接映射到 run_code，工具描述再强调数据分析用这个。两者只定义执行载体，缺少执行意图判断。另有 science-layout 项目模板鼓励实际数据检查使用解释器；统一指引补充仅提及文件或挂载内核不代表需要执行，不改写用户已有项目文件。第一版同步修订内核指引与工具说明，不改权限、工具可见性、内核执行和方案期硬门，也不引入关键词分类器。

## 行为约定

1. 咨询、解释、比较方法、讨论方案、只要求代码示例：先用文字回答，代码示例放回复，不为演示或显得可靠而自动运行。
2. 用户明确要求计算、分析实际数据、作图或运行验证，或此前已经授权继续的任务确实需要计算：才执行，必要验证可连续进行，不对每一步重复询问。明确的“暂不运行、先讨论”优先；不能把旧任务授权带到新咨询。
3. 范围、分组、方法或执行意图不明确且会影响结果：先 ask_user_question 获取决定。已明确的信息不重复确认，跳过/取消不算授权。
4. 执行前说明目的和预期输出；优先复用已获得结果、读取现有文件等适用工具，减少无意义的小计算、重复探测/重跑。确实需要 Python/R 时使用 run_code，保持活内核与笔记本可见性；不能改用 bash 绕过不执行的要求。

## 验证及限制

单元测试保护系统指引、工具描述和 NativeRuntime 装配；真实 Electron 验证实际推理请求携带新指引、工具仍可用，复用笔记本真实内核及结构化问答回归。mock 不承担判断用户意图，不能用其固定回答声称真实模型调用频率下降。本轮不调用付费模型；真实行为仍需新建会话后观察。旧会话可能持有已定稿系统提示，需重建会话才能可靠获得新版指引。

## 新会话观察用例

| 输入 | 预期 |
| --- | --- |
| PCA 和 PCoA 有什么区别？ | 解释，不运行 |
| 给我一段缺失值检查代码，先别执行 | 展示代码，不运行 |
| 这里有一个 CSV，先讨论适合的分析方法 | 讨论，不因附件自动执行 |
| 计算这份数据各列缺失率并画图 | 执行，复用结果完成任务 |
| 继续按刚才批准的方案完成分析和验证 | 连续执行必要步骤 |
| 帮我做差异分析，但还没决定比较哪些组 | 关键选择影响结果时先澄清 |

以上是验收期望，不是本轮真实模型已通过的评估结果。
