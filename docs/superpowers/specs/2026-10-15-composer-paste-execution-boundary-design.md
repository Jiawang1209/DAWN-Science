# 光标粘贴与讨论 / 执行边界

用户已于 2026-10-15 批准本轮实现；仅在 `codex/composer-paste-execution-boundary` 修改，不合并、不推送、不替换安装版。

## 粘贴

保留附件、图片与粘贴 `@` 的既有行为。裸文件名检查共用一个处理器：记录粘贴发生时的 DOM 选区；系统剪贴板没有真实路径或读取失败时，在原选区插入文字并将光标放在新文字后。等待期间的输入不能被旧草稿覆盖；移动光标不能改变原粘贴位置；切换会话或卸载后，旧请求不能修改新输入框。多个待处理粘贴按输入变化移动锚点。真实 Chromium 中检查撤销与继续输入，保持 DOM 拥有文字和中文组词行为。

## 讨论与执行

采用统一提示词 + 明确指令的运行时门。单靠提示词不能兑现“先别运行”；给每一步增加确认会破坏已授权分析。统一提示词要求普通提问、概念解释、方法讨论以文字回答，不因环境可用而自检、计算或画示例图。明确的数据处理 / 分析 / 绘图请求可直接执行；同一已授权任务内的读取、计算、绘图、验证和交付不逐步询问。若用户只要代码，不能擅自运行。

明确“只讨论 / 先别运行 / 只给代码”等限制作为会话指令，拦截 `run_code`、shell、写入、`inspect_data`、未知工具和委派执行，允许类型明确的只读工具及声明只读的 MCP。后续明确“开始 / 继续执行”或内核快捷请求解除限制，已有方案审批与权限门仍独立生效。

门读取 pi 当前分支中实际送达的用户指令，不读待发队列、助手回复、工具输出、代码块或引用文字。pi 分支包含压缩前的原记录；续接、压缩和回退沿用同一权威，不新增持久状态副本。自然语言的普通讨论由提示词约束，明确限制由门兜底；不声称有限指令识别等于通用意图分类。ACP 的执行工具由外部运行时管理，本轮不承诺其硬门。

## 验收

先用欢迎页 / 会话组件和真实 Electron 复现中间插入与选区替换失败。覆盖查附件成功 / 失败、延迟输入 / 移动光标 / 换会话、普通文本 / `@` / 图片、撤销和中文组词。运行时测试强制模型调用工具，证明明确讨论约束能阻断副作用、解除后可连续执行；覆盖实际送达、会话隔离、压缩和续接。最终运行相关回归、类型检查、构建与真实 Electron 主路径，记录证据和边界。
