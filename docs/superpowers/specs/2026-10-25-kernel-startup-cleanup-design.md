# 内核启动期清理

用户授权逐项修复 F4，前一项 SSH 已独立合并并完成主目录复验。基线 main 2e4c26a0。

当前收() 只遍历表中内核，起中 Promise 未参与清理；runtime.start 晚到后无条件入表，旧 Notebook 执行继续写代码。采用对话清理代次和清理屏障：收开始即使旧启动/旧队列失效，阻止清理期间新懒起；等当时启动中的实例完成并回收，再报告清理结束。晚到实例不入表、不推“起来了”、不写代码；解释器读取期已失效则不发 start。失败按语言汇总，不因一台失败漏掉另一台。

保留明确的新请求：收完成后可重新拿同会话 ID 的新内核，旧 Promise 的 finally 不得删除新状态。执行入口与接回门/队列边界检查所属代次，已清理实例不得复活。收全部和有活内核计入启动/清理中资源，应用退出不能漏掉它们。

NativeRuntime.stop 同步开始本会话内核清理，并在关闭完成前等待回收；即便模型会话不在表里，也不能直接跳过名下内核。无协议和 UI 设计变更。

验收：解释器等待、runtime.start 等待、Python/R 并发、同对话重复清理、全局退出、回收失败、排队执行以及正常后续懒起的确定性回归先红后绿；Native stop 生命周期回归。真实 Electron/真实 Python 内核验证启动期间停止不会写入标记文件，原有 Notebook 同内核复用保持。
