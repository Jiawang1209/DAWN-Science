# 科研编排单／多 agent 评测基线

本基线通过真实 Pi 子进程、实际 Python 执行、文件、正式提交、内容核验与 Team 恢复运行；仅推理响应来自确定性 localhost 夹具，不读取真实提供商凭证。它证明软件路径及验收机制，不证明真实模型的科学质量、速度、费用或多 agent 收益。

在仓库根运行：

```sh
npm run evaluate:science
```

命令先重建 Electron/Pi 子进程，再运行脚本，默认写入 `docs/validation/incremental-science-20261105/evaluation/` 中的 `baseline.json`、`baseline.md`、`incremental.json` 和 `incremental.md`。指定另一目录可使用 `npm run evaluate:science -- /absolute/output/directory`。直接调用导出的测试函数时，由测试环境事先构建，和既有实际入口集成测试相同。

两种模式使用同一合成 CSV（x=1..5，单位 m）、方法、输入版本、声明输出、模型标识、工具、权限与相同最终宿主真值验收。single 使用一个分析执行者，multi 使用核查→分析→独立审阅流水线；不同阶段带来的请求与时间属于被测架构的开销。最终真值独立检查实际 result.json 的 n=5、mean=3、unit=m 和原输入保留，不采信模型自述。原始数据、配置、验收标准、故障注入及一次修正上限进入配对指纹；源码与 child 构建各有指纹。

五组场景：正常交付；缺单位须阻塞；共同初始单位缺陷后的返工；冻结后输入变化须阻塞；选定执行工具后中止并显式恢复。返工场景中，两条路径初次真实文件都缺单位：single 由共同宿主真值检查发现并要求修正，multi 由独立审阅提出同一修正；两条路径均最多一次修正。它检验返工机制，不构成独立审阅优于自查的证据。中断与恢复由测试脚本模拟操作者，干预次数不是实际用户行为统计。

JSON/Markdown 记录最终验收、独立真值、正确交付或阻塞、错误放行、输入保留、请求数、阶段尝试、返工、脚本干预、可见 token、未知/部分用量和本机耗时。`usage.partial` 即使有部分数值也标为不完整；模式汇总保留该标记。输入保留以故障注入后、执行器准入前的字节为基线：输入变化场景由测试脚本先改文件以验证拒绝旧检查点，不把这次外部注入算作 agent 写坏输入。未知 token 不估成费用，零个可见 token 也不等于证明零成本。没有进行真实模型实验或费用换算。

当前这组数据规模很小，只用来固定可复现回归条件。后续若评估真实收益，应另建有授权的真实模型数据集，统一交付质量与人工干预标准，重复运行并保留失败样本，不能用此处十条确定性记录外推。

## 代表性任务与真实模型小样本试验

2026-11-07 新增显式入口，默认 `evaluate:science` 仍只使用本地确定性推理，不读取真实凭证。任务是可分享的自制科研代表性数据，尚不是用户私有项目：48 个样地、多字段 CSV，目标列有 NA；一项按批准的缺失规则计算带单位均值，另一项要求单位未知时明确阻塞。独立答案留在宿主，不注入模型。

联网试验必须显式给出隔离输出目录、现有 DAWN 配置目录、provider 和精确 model：

```sh
npm run evaluate:science -- --research-current-api /absolute/new-trial-directory '/absolute/DAWN-profile' deepseek deepseek-flash
```

仅支持当前已验的 OpenAI completions API 路线，不自动替换模型；凭证通过现有 CredentialStore 只读获取，配置、凭证及正式 DB 不写入。每次完整试验最多 30 次转发，重试也计入；loopback 计数器达到上限拒绝后续转发。输出目录的 live-attempt.json 用排他创建防止误重跑同一次试验，不会删除旧试验后自动续费。取消继续沿 Pi/Team 和原编排收尾。输入、脚本、产物及隔离转录保留在指定输出目录，不使用正式项目目录。

报告保留 accepted / blocked / failed / cancelled / not-run；accepted 仍需实际 result.json 独立真值通过。未知单位任务必须实际读取输入、明确因单位缺失阻塞，任意失败不算正确阻塞。未运行行的输入核验为不适用，不虚构一个已执行但用量未知的任务。缺失用量不按零费用；不换算付费费用。

**共享上限的先后顺序会影响剩余额度。** 小样本若未形成完整配对，不能推断质量/费用优劣。首次真实试验单 agent 正确交付用 19 次，多 agent 用剩余 11 次后未完成，另外两行未启动；实际转发恰好 30 次，额度外 4 次拒绝。完整配对为零，因此尚无多 agent 收益结论。后续试验应独立安排相同的每组预算和重复次数，另行授权联网；不能拿本次不同可用额度作公平比较。

原始报告与失败样本保留于 `validation/evidence-evaluation-20261107/live/`。首次报告的未启动行有元数据展示问题，审阅后的 research-reviewed.json 只纠正“不适用”和未知任务计数，不修改执行结果，不重新联网；原始 research.json 没有覆盖。


## 增量对照

同一入口保留原五对测试，并追加两项批次：A 正常、B 实际生成并回报 999，而独立参考均值为 3。两种恢复方式都先支付同一个故障前置成本（commonSetup），随后比较完整重跑与显式派生的 recoveryIncrement。另验重复批次、单项输入变化、方法变化、外部篡改产物，以及实际临时 stdlib-only Python venv 环境变化（不联网、不安装包，运行后删除）。

记录新请求、新分析项、复用项、宿主验收回执、独立文件真值、源记录字节保留、当次可见/未知用量和耗时；不把复制的历史回执当新执行。重复批次即使没有模型请求，仍有宿主核验/汇总成本，不能解释为零费用。环境变化测试使用真实固定元数据探测，并要求两项失效；不是伪造环境指纹。

原五对测试继续固定上批契约与共同真值，新增行显式启用新版模板验收；两组结果分别报告，不把验收口径变化混成多 agent 收益。
