## 1. 查明的事实（2026-08-27，翻了作者 `tmp_20260819` 那段项目会话的 pi 转录）

- **`run_code` 工具在项目会话里是在的**：作者在笔记本里敲了 `tmp = "abc"`，下一轮 agent 用 `run_code` 读到了。所以不是功能缺失。
- 但同一段对话前面，agent 一直 `write` 脚本到 `analysis/scripts/` 再 `bash python3 …`；作者说「在笔记本里面显示一下」，它去 `pip install nbformat nbclient ipykernel`——**它不知道「笔记本」就是坞里那一格（= `run_code`）**。
- 普通（scratch）会话没有项目 `AGENTS.md` 里那段科研目录约定（`src/policy/science-layout.ts` 的 `约定正文`：「脚本与 notebook → `analysis/scripts/`、`analysis/notebooks/`」），agent 自然用 `run_code`。**根因是提示词把项目会话的 agent 引向了写脚本。**
- `约定正文` 逐字来自作者、写进每个项目的 `AGENTS.md`——改它管不到已经初始化过的项目。所以引导要放在**每段会话都带的**地方：`run_code` 的工具描述 + `appendSystemPromptOverride` 那一串（`src/runtime/native.ts:1209`）。
- **远端会话**：内核走 spawnteract + enchannel（ZMQ），**只会在本机起**（`src/kernel/channel.ts`）。远端会话现在也挂着 `run_code`，`workspaceOf` 给的是本机 scratch 目录——代码在笔记本上跑、文件在服务器上，**静默错位**，违反规格 7.5。
- 导出：`exportSession`（`src/workbench/backend.ts:3696`）只有 markdown，目录 = `download.dir` 设置或 `~/Downloads`；提示是一个 `<span className="conv-export-note">` 钉在按钮后面。笔记本格没有导出。

## 2. 项目会话真用笔记本（提示词）

两处都改，两处都要有测试锁住：

1. **`run_code` 描述**（`src/tools/run-code.ts`）追加：「用户说的『笔记本』『notebook』『在笔记本里跑/显示』指的就是这个工具——代码和输出会显示在界面右侧的笔记本面板里；**不要**去装 jupyter / nbformat，也不要生成 .ipynb 文件来代替。」
2. **系统提示追加一句**（`appendSystemPromptOverride`，只在装配给了 `kernels` 时）：「探索、看数据、画图、验证一段逻辑：用 `run_code`（内核活着，变量保留，用户在笔记本面板看得见）。只有用户要一个**可复用的文件**时才把脚本写到 `analysis/scripts/`——写完也可以在 `run_code` 里跑一遍给用户看。」

**不动 `约定正文`**：它是作者原话，且只管产物落位。

测试：`tests/tools/run-code.test.ts`（描述里含「笔记本」与「不要去装 jupyter」）；`tests/runtime/native*.test.ts` 里断言给了 `kernels` 时系统提示含「用 `run_code`」、不给时不含。

## 3. 远端会话说实话（本轮 A）

- `toolsFor`：`spec.remote` 时**不挂 `run_code`**（与 `look_at_image` 同一处判断）。理由写在代码里：内核只会在本机起，远端会话给它等于让代码在错误的机器上跑。
- 笔记本格（`NotebookPanel`）：`session.remote` 时整格一句 **「远端会话的内核还没做：代码只能在本机起内核，而这段对话的文件在 <服务器名> 上。先用对话里的 bash」**——不画输入框。传 `remote` 进面板（`sessionKind` 旁边加 `remoteLabel?: string`）。
- `runInKernel` / `interruptKernel` 对远端会话回 `invalid_request`「远端会话还没有内核」——界面拦了，协议也要拦（两处判据一致）。
- 变量面板、`listVariables` 不动（远端本来就没内核，列表为空）。

## 4. 导出落到工作目录 + 笔记本导出

### 4.1 一条规则，两处共用

后端新增 `导出目录(rec)`（`src/workbench/backend.ts`，纯函数，可测）：

```
项目会话（projectStore.get(rec.projectId).temporary !== true）→ join(rec.workspace, "docs")
普通会话（临时项目）                                        → settings.get("download.dir") || 默认下载目录()
远端会话                                                    → 同普通会话（远端 workspace 是本机 scratch，导出的是本机的转录；`docs/` 不往服务器写——作者硬约束）
显式给了 `dir`                                              → `dir`（不变）
```

`mkdirSync(..., { recursive: true })` 照旧。回的 `path` 是绝对路径。

### 4.2 `exportSession` 不改契约

只改目录规则。响应仍 `{ path, turns }`。

### 4.3 新协议操作 `exportNotebook`

```ts
exportNotebook: {
  request: { sessionId, format: "ipynb" | "md", dir?: string },
  response: { path: string, cells: number },
  mutating: true,
}
```

- cell 派生：把 `src/ui/notebook.tsx` 上半的纯函数 `cells()`（及 `Cell` 类型）**搬到 `src/session/notebook-cells.ts`**，UI 与后端共用一份（它只依赖 `TranscriptItem`，没有 React）。`notebook.tsx` 改为 re-export，调用点不动。
- 没有 cell → `invalid_request`「这段对话还没有 cell，没有东西可导」；转录不在本次运行里 → 与 `exportSession` 同一句话。
- **`.ipynb`**（`src/session/export-notebook.ts`，纯函数 `cells成ipynb(头, cells)`）：nbformat 4.5。`metadata.kernelspec` 按**多数 cell 的语言**（python3 / ir）；混排时另一门语言的 cell 用 `%%R` / 不做魔法——**如实**：语言不同于 kernelspec 的 cell 在源码第一行加注释 `# [R 内核]` 并在 notebook 顶部一格 markdown 说明「这段对话混用了 Python 与 R，各 cell 首行注明了语言」。每格 `metadata.dawn = { who, startedAt, runId }`。输出映射：`stream` → `stream`；`display_data`（图/表）→ `display_data`，`data[mediaType] = base64`；报错 → `error`（ename/evalue/traceback）；`tooLarge` 的输出 → 一条 `stream` 文字「已截断：原 N KB」。`execution_count` = cell 的 `n`。
- **`.md`**：每格 `### [n] python · agent · 时刻`，代码围栏，输出：文字原样围栏、报错围栏、PNG 写成 `![图 n](data:image/png;base64,…)`（内嵌，单文件带走），表格若有 `text/markdown`/`text/html` 就原样落。
- 文件名：`导出文件名()` 同一函数，后缀换成 `.ipynb` / `.md`；标题前缀加「笔记本-」以免与对话导出同名。
- **mock 分支**（硬规则 1）：`scripts/mock-inference-server.mjs` 所用的假后端补 `exportNotebook`，回 `{ path: <scratch>/docs/笔记本-….ipynb, cells: N }` 并**真的写文件**（与 `exportSession` 现有做法对齐——先看它怎么做）。

### 4.4 界面

- 笔记本格头部右侧，「变量 →」旁加两颗 ghost 按钮 **「导出 .ipynb」「导出 .md」**（文案互不为子串，也不是「导出对话」的子串——设计契约那条扫描）。没有 cell 时不画。
- 点击 → 调 `exportNotebook` → 成功/失败都用 §5 的浮出提示。

## 5. 导出提示浮出、淡去

- 新的小组件 `导出提示`（`src/ui/primitives.tsx` 或 views 里）：`position: absolute` 浮在触发按钮上方/旁边（形态沿用 `.copied-toast`，加宽以容纳路径），出现 → 停 4 s → 500 ms 淡出 → 卸载；再点一次重置计时。失败的红底（`.bad`）停 8 s。
- `aria-live="polite"` 一份文字给读屏（`.copied-toast` 现在是 `aria-hidden` + `sr-only`，照抄）。
- 对话头「导出对话」与笔记本格两处共用。删掉 `.conv-export-note` 那个钉在后面的 `<span>`。
- e2e：`toBeVisible` 后**量 opacity**（`getComputedStyle`）确认淡出（CLAUDE.md 那条：`toBeVisible` 对 opacity 0 仍算可见）。

## 6. 不做的、另起的

- **远端内核（B）**：SSH 在服务器上 `python -m ipykernel_launcher -f <连接文件>`，五个 ZMQ 端口走 `ssh -L`，连接文件得临时落到服务器 `/tmp`——与「服务器上不放任何文件」擦边，需作者定；服务器还得装 `ipykernel`。另写 `specs/远端内核-design.md`，不在本分支。
- 不做「导出所有会话」、不做导出格式设置项、不做导出到服务器。

## 7. 失败必须出声

| 情况 | 说什么 |
|---|---|
| 没 cell | 按钮不画；协议层回「没有东西可导」 |
| 目录建不了 / 写失败 | 浮出红提示「导不了：<原因>」，8 s |
| 远端会话点笔记本 | §3 那句，带服务器名 |
| 远端会话 agent 想用 `run_code` | 工具不存在——模型看不到它，就不会去猜 |
| 混排语言的 ipynb | 顶部 markdown 说明 + 每格首行注明（不静默塞进一个 kernelspec） |
| 输出截断 | 「已截断：原 N KB」原样进导出 |

## 8. 验证

- 单元：`导出目录` 三分支；`cells成ipynb` / `cells成markdown` 各一份含 stream/图/报错/截断/混排的快照测试；`nbformat` 结构用 `python3 -c "import json; …"` 做一次形状核对（不引 nbformat 依赖）；提示词两条。
- e2e：项目会话里笔记本导出两种格式 → 文件落在 `<workspace>/docs/`；普通会话 → 落在 mock 的下载目录；「导出对话」提示浮出后淡去。
- `npm run dev:mock` 人肉看一次浮出提示的形态。
