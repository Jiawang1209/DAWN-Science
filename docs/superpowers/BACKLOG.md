### worktree 隔离提前到 ①-B（已评估，决定不提前）
- **来源**：①-B 计划 §2.3 —— 「产出」栏需要一个干净基线才能把 agent 的改动与作者的手动改动分开
- **服务于**：不变式 5（声明层与事实层分离）的完整落地
- **评估结论**：**不提前**。worktree 隔离会改变作者的日常操作习惯（agent 的改动不在当前目录），而 G2 的判据恰恰是「愿不愿意用」——改习惯的东西不该在争取日常使用的阶段引入。①-B 改为「相对会话开始的 diff + 诚实标注可能混入手动修改」
- **预估归属**：③（实体 #50 原定位置）。若 ①-B 的两周观察期证明「分不清谁改的」是主要不满，再重新评估
- **记录日期**：2026-08-08

### 再探 claude 的 hook 体系，改善 PTY agent 可见性
- **来源**：①-B 计划 §2.2 的可见性分级表
- **服务于**：不变式 3（没有不可见的行动）—— PTY agent 的内置 Read/Edit/Bash 不经过我方注入的 MCP，当前只能标 `provenanceComplete: false`
- **评估结论**：Spike B 只验证了 Stop hook。claude 的 hook 体系还有 PreToolUse 等事件，若能拿到，PTY agent 的可见性可从「只有回合边界」提升到「知道调了什么工具」
- **预估归属**：①-B 观察期之后。**触发条件**：若两周观察期表明「不知道 agent 在干什么」仍是主要不满

### 凭证移出 process.env：OS keychain + 按 endpoint 定向注入
- **来源**：当前 `.env` 方案的已知缺口（见开发历史 2026-08-08「确立开发历史记录规范」条）
- **服务于**：不变式 3（没有不可见的行动）的安全侧推论——PTY Runtime 以 `env: { ...process.env, ... }` 派生第三方 agent CLI，等于把**全部**模型密钥交给每一个被托管的 agent 进程。一个被诱导的 agent 可以直接 `echo $ANTHROPIC_API_KEY`。规格 7.24 已为**验证命令**做了环境净化，但 agent 进程本身尚未净化
- **预估归属**：①-B（Electron 外壳到位后可用 `safeStorage` / macOS Keychain）。在此之前 `.env` 是可接受的过渡方案
- **记录日期**：2026-08-08
