# 共用科研审查规范与重点角色同步

2026-10-18。用户已批准“共用规范＋重点角色同步＋定向验收”，授权独立分支实施；不合并、不推送、不替换安装版。

## 目标

主会话、普通子 Agent 与专业角色采用一致的科研审查底线，同时保留专业分工。准确区分静态审查、运行范围、核对结果和科学判断，修正重启当前内核、逐字节判一致、无工具却要求重算等冲突。

## 内容与接入

新增自带技能 `scientific-review`：入口保留短的通用底线，按任务读取目录内 `references/checklist.md` 与 `references/reporting.md`。清单包含研究设计、数据/样本量对账、方法参数、数字图表、独立运行和结论边界；报告参考包含两维状态、问题分级及六个定向案例。只引用本技能目录内文件。

重点同步五个角色 stat-consultant、reproducibility-reviewer、reviewer-two、data-auditor、methods-writer；最小修正 data-cleaner 的重跑比较。同步 reproducible-analysis、analysis-delivery，并给 analyze-like-case 增加短的衔接段。角色/其他技能通过名称按需查找共用技能，不跨技能相对路径、不写开发机绝对路径。未启用或同名覆盖时沿用实际可见版本；不能绕过 manual/off，核心执行和证据底线在调用方仍明确。

只读审查不改分析文件。报告可直接在回复中交回；仅用户要求且具有写入能力时保存新报告，不能因角色模板指定路径就擅自落盘。允许执行且有实际工具时才重算；文件存在、read/bash 可用、当前内核状态、依赖安装均不是执行授权。已有授权不反复确认。保护当前内核和原数据/产物，独立重跑需核对解释器、输入/输出参数、超时及本次子进程清理；现有工具不满足就报告未执行。重建环境、网络、安装和昂贵重跑在实际授权范围内判断。

## 判断原则

- 先确认实验单位、分组、配对、重复测量或嵌套；表格行数与独立单位数分别记录，关键未知不猜。
- 对账输入/过滤/输出、单位、分组与各分析有效样本数；同一记录可有多个质量标记，移除计数需去重。无数据字典的范围判断是待确认假设。
- 数值容差事先按精度及任务声明，样本量、主键、分类和缺失结构单独精确核对；不为通过而事后放宽容差。图比较数据、轴/图例/误差定义与实际渲染，元数据哈希差异不等同科学差异。
- 同一原始输入重复运行是重复运行一致性；把第一次输出再次作为输入才是幂等性检验，不能混称。种子及版本记录不保证跨版本/并行逐字节一致，未记录不补造。
- 运行状态和发现分开：静态审查/部分运行/独立完整重跑/失败；问题分为影响结论/需确认/一般建议。明确输入、环境、比较对象及局限；成功运行不等于科学结论已独立核验，不给伪精确总分。

## 范围外

不新增运行时权限、工具、协议、数据库、前端页面、自动派审/重跑、评分平台或完整科研基准；不全面重写专业方法库，不改用户项目/全局角色或技能。仅应用自带 Markdown、契约与定向加载验收和文档。

## 验收

先跑内容/发现契约见红，再补内容见绿；真实 pi loader 与父侧资源服务验证新技能、参考分页、同名覆盖及禁用边界。构建后验证 dist 内容和 Electron 主会话显式展开、已有技能/子资源链路；确定性 mock 只证明加载与接线。

六个压力场景：只审不运行、保护活动内核、PDF 仅元数据差异、正文与表格 n 不一致、缺少数据/执行工具、相同案例的角色边界一致。写作技能要求的独立 Agent 文本演练与科学工具执行证据分开记录；本次不把文案测试视为真实科研质量保证。全量 Vitest、typecheck/build、相关 Electron 回归通过后独立只读复审，记录真实结果及限制。
