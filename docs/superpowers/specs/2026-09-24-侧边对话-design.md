# 侧边对话：坞里再开一段，同时跑，看得见主对话（学自 Codex）

2026-09-24 · 分支 `side-session` · 作者逐条定过（B 先、坞里一格、普通会话、只看不动）

## 1. 要解决什么

作者看 Codex 的侧边栏：*「侧边的对话其实是一个独立的对话，我可以在主对话的地方执行任务，
也可以开侧边的对话，询问当前工作执行到哪里了，甚至可以执行其他任务。」*

今天做不到的三件事：

1. **一次只看得见一段。** 后端早就能多段同时跑（`SessionManager.bound` 每段一个运行时），
   但界面的推送监听只把当前会话写进一套单例状态（`App.tsx` 那句 `!== $activeSessionId` 就 return），
   切走的那段在后台跑，人看不见它。
2. **两段互相看不见。** 在另一段里问「主对话做到哪了」，它答不上来。
3. **租约只续当前那一段。**

分两轮（作者定的顺序）：

- **本轮（B）**：坞里挂一段**独立**会话，与主对话同时跑；它能**只读**地看主对话此刻的进展。
- **下一轮（A）**：从主对话「岔出去问一句」——带着主对话的上下文开侧边。
- **也不做（下一轮再说）**：侧边往主对话里插话；坞里同时挂多段。

## 2. 交互

```
┌侧栏────────┐┌──── 主对话 ─────────┐┌ 坞 ──────────────────────┐
│▾ RNA-seq   ││ 你：清洗数据          ││ 文件 网页 … [对话]        │
│  清洗数据 ●││ agent：…跑着…        │├──────────────────────────┤
│  画图 ● 坞 ││                     ││ 画图 ●   [换到主区] [×]   │
│  上周分析   ││                     ││ 你：主对话跑到哪了？        │
│            ││                     ││ ▸ 看主对话                 │
│            ││                     ││ agent：在跑第 3 步归一化…   │
│            ││ [输入框]             ││ [输入框]                   │
└────────────┘└─────────────────────┘└──────────────────────────┘
```

### 2.1 怎么开

- 坞加第八格 **「对话」**。格子空着时：上面「＋ 另开一段」（描边按钮；在主对话同一个地方开，同会话页签的 ＋），
  下面列出同一个地方的其他会话，点一段就挂进来。
- **临时会话也有地方**（2026-09-25 作者在真机上跑过之后定的，推翻 Task 6 审查 I2「临时会话不算地方」）：
  作者的对话几乎全是临时会话，上一版坞里只剩一行灰字，这个功能在他的主路上用不上。本机的临时会话共用**一个**地方——
  侧栏「会话」那一组（记作 `t:`，不按临时宿主项目劈开）。在那儿「另开一段」建的是**又一段临时会话**（与侧栏新建、
  空态那张卡不挑去处时同一条路），主区不动，新那段挂进坞、落进「会话」那一组；同处清单列的就是那一组。远端的临时会话仍按连接算。
  散的临时会话今天没有会话页签，所以也没有右键「放进坞里」——挑一段已有的进坞走坞格清单（本轮不为它新造分栏）。
- **没有「地方」就不能另开**：什么都没选、也没选项目（新建任务那一屏）——坞格直说一句没处挂，命令面板
  「在坞里另开一段对话」同时置灰，不画一颗点了只报错的按钮。
- **终端（pty）不进坞**：坞格清单不列它、会话页签右键不给它开菜单；「换到主区」时若原主是终端，
  坞里那段照样换上主区、坞空出来并说一句。
- **看得见的入口不止一个**（悬停才出现的东西必须另有入口）：坞的「对话」页签本身常驻；会话页签右键「放进坞里」；
  命令面板「在坞里另开一段对话」「打开坞里的对话」。（侧栏会话行今天没有右键菜单，本轮不为它新造一个。）

### 2.2 同一段只在一处

- 挂进坞的那段在会话页签上带一个「坞」标记。
- 在侧栏点它 → 它回主区，原来主区那段不动，坞格变空。
- 坞里那段头上两个常驻按钮：
  - **换到主区**：两段对调。
  - **×**：只从坞里拿下来——**不归档、不停**。它在后台照样跑完，侧栏照常显示运行中 / 未读。
- 坞一次挂一段。

### 2.3 功能不打折

输入框、待发条（排队 / 插队 / 取回）、权限确认、`@` 引用、附件、斜杠命令全有——
它会自己跑工具，**权限请求弹不出来它就卡住**。坞窄，只省右侧的轮次刻度尺。

坞里其他格（文件、笔记本、产物…）仍跟着**主对话**。侧边那段有自己的内核（内核按会话分），本轮不在坞里看它的内核。

### 2.4 记住

- 坞里挂的是哪段**按地方记住**（项目 `p:` / 远端连接 `r:` / 本机临时会话那一组 `t:`；key 里写明 `project` 作用域），重开还在。
- 那段被归档或删除 → 坞格变空并**出声**提示一句，不静默消失。

### 2.5 侧边看得见主对话（只看不动）

- 侧边那段的 agent 有一个只读工具 **「看主对话」**（`read_main_session`）。人问进度时它自己去读主对话**此刻**：
  最近几轮的问与答、正在跑的工具与已跑时长、待发条上排着的话、这一段生成过的文件。
- **按需读**：人在侧边让它干别的活时，主对话的内容不进它的上下文。
- **主对话 = 此刻主区里那段。** 人在主区换了会话，侧边下次读到的就是新的那段。
- 侧边不能写主对话。要给主对话下指令，人自己去主区说（插话是下一轮）。
- **只有 native 会话有这个工具。** ACP / CLI agent 也能挂进坞，但坞格头上明写「这个 agent 看不见主对话」——不假装能看。

## 3. 分层

### 3.1 依赖决策（规格 §4）

坐在 pi-coding-agent 的 `AgentSession` 上：

1. 用 `customTools`（已在用，建会话时装）+ `setActiveToolsByName` / `getActiveToolNames`（新用）。
2. **放弃了**「只给侧边会话建会话时才装」：那样已有的会话挂进坞就没有这个工具，得重建会话。
   代价是每段 native 会话都多带一份（不启用的）工具定义。
3. 我们的不变式挂在**后端的对照表**上：工具每次调用都现查「我现在是谁的侧边、主对话是谁」，
   查不到就如实返回「你现在不在坞里」，而不是读错一段。启用 / 停用只是让模型平时看不见它。

### 3.2 协议 7.37

- 新增操作 `setSideSession({ sideSessionId: SessionId | null, mainSessionId: SessionId | null })`：
  界面在「挂上 / 拿下 / 主区换了会话」时发。后端据此更新对照表，并对进出坞的那段启用 / 停用工具。
- 快照不变（坞挂哪段是界面状态，后端只需知道配对）。
- **mock 同一次改动里补分支**（硬性准入规则 1）。

### 3.3 后端

- `src/workbench/side-session.ts`（新）：对照表 `侧边 → 主对话`，只存内存；界面启动时重发一次。
  会话归档 / 删除 / 关闭时把它从对照表里摘掉。
- 摘要函数 `主对话摘要(转录快照, 选项)`：纯函数，可单测。最近 N 轮（默认 6），每条截断到固定字数，
  **截断要说清省了多少**（规格 7.5）；正在跑的工具与已跑时长；待发单；生成过的文件（取产物清单）。
- 读主对话走 `SessionTranscripts` 已有的快照，不要求主对话被订阅。

### 3.4 运行时（`native.ts`）

- 装配时加 `read_main_session`：它通过注入的 `读主对话(侧边id)` 回调取摘要，自己不碰转录。
- 新方法 `setSideTool?(sessionId, on: boolean)`：`setActiveToolsByName` 加 / 减这个名字。
  只有 native 有，**有无即判据**（同 `editQueue`）。

### 3.5 界面

- **两个槽**：把「一段会话在界面上需要的那些状态」（转录条目、待发、待答权限、会话开关、斜杠、退回的图……）
  收成一个工厂 `创建会话槽()`，造一个主槽、一个侧槽。
  主槽沿用现有导出名（改动面小），侧槽是第二个实例。
- 推送监听按会话 id 分：侧边那段写进侧槽（先例：底部终端坞 `state/dock.ts` 就是这样的第二条订阅）。
- `ConversationView` 接一个槽，不再直接读全局单例。
- 租约续期覆盖主、侧两段。
- 右坞加房客 `"chat"`，`App.tsx` 那串三元加一支。
