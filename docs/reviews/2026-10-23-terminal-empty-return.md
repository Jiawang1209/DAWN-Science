# 空终端页面返回修正

用户反馈：未新建终端时，整页终端为空，返回箭头无法点击，必须先开终端才能离开。

根因：App 用 `returningTerminalId === dockSessionId` 判断是否正在返回。两个 ID 都未设置时仍相等，导致空终端的按钮被错误设置为 `disabled` 和 `aria-busy=true`。返回处理函数原有的“无终端则关闭面板”逻辑因此无法触发。

修正：只在有明确的返回中终端 ID、且它与当前终端一致时禁用按钮。不改变真实 Agent 会话的返回目标、并发导航保护或 PTY 生命周期。

## 验收清单

- 从未创建终端、无 Shell 配置：返回可点，恢复欢迎页。
- 关闭最后一个终端：空态返回可点，原页面和草稿恢复，不要求重建终端。
- 已有 Normal/DAWN、会话承接和图片：沿用原有回归，确保返回进行中保护仍保留。
- 实际开发预览：复现原始禁用状态，修正后点击空态返回，检查原页面恢复。

新增两条真实 Electron 用例在修正前都因按钮禁用而失败，未出现配置或启动错误。实际 main 也复现：终端数为0、按钮 disabled=true、aria-busy=true，截图 `artifacts/terminal-empty-return/01-main-empty-disabled.png`。
