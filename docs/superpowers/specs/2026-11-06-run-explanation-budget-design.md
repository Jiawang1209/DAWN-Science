# 运行解释与会话委派预算

用户授权：先实现运行过程解释、整项委派预算，沿用现有评测入口记录实测收益；测试、审查并逐阶段演示。不推送、不发布。本轮不自动提交或合并。

基线：main 9dd59f4f。采用 codex/run-explanation-budget 隔离工作区；一条实现主线。正式 App、凭证及其数据不变。

## 决策

比较三个方向：另建事件调度平台、只增加界面标签、在现有编排记录中补可核验事实。选第三个：继续由 OrchestrationService 调度、OrchestrationStore 原子落盘、BotOutputLocks 维护实际锁；新增历史仅供观察，不驱动恢复或重复执行。

## A：执行解释

- 在原 state.json 增加可选有界历史，按单调序号保留最近 256 条并明确显示较早记录已省略；旧记录没有的历史不倒推。
- 事件只包含宿主事实：childId、执行代次、时间、事件类别、阶段、验收状态、锁持有者的身份/标签。不给历史复制任务提示词、工具输出、密钥或其他会话正文。
- AsyncLocalStorage 只传递现有执行身份和观察回调；锁等待、锁获得、输入核验、后端执行、宿主验收都关联同一代次。观察回调失败不得跳过资源清理。
- 共享锁仍遵守现有 inode/路径归一化及公平队列。等待者说明直接冲突的活动占用者或排在前面的等待者；没有身份的旧调用显示未知，不推断为可中断的当前子任务。
- 总览显示当前阶段、已结算阶段耗时、历史和锁等待关系。冷读不构造 Store、不启动进程、不重写恢复；磁盘锁信息只能显示历史，不能声称现在仍占用。
- 验收/失败和恢复事件来自原结果及恢复门。现有批量/流水线中的复用原因继续由原科学界面展示，不另建第二套复用判断。

## B：预算边界

- 范围是当前父会话经统一编排准入的普通子任务、Team 和 Bot 轮次，包括续问及返修；不把根会话聊天、独立内核或其他父会话算入。界面明确称为“会话委派预算”。
- 可选限制：maxRuns（实际准入轮次）、maxElapsedMs（从首轮开始的总历时，包含暂停/离线）、maxTokens（已结算 input + output + cacheRead）。未配置限制维持现有行为。
- 使用原 state.json 原子保存累计轮次、各项用量、未知次数、在途身份、首轮时间及配置版本。准入计数与 epoch 增长同次写入；结算按在途身份至多记账一次。恢复时未结算轮次转为未知，不重复执行也不归零。
- 旧数据按已有 epoch 汇总已知轮次数，无代次但已有结果时至少计入一轮未知用量、标注旧历史时间/用量未知；不凭 updatedAt 编造开始时间。新增历时从启用后的首个真实准入开始。
- 轮次额度在下一次准入前生效；最后一个合法轮次可正常完成。历时到点走已有 AbortSignal，拒绝后续准入、取消排队，实际后端排空之前保持 stopping。
- token 限制按结算边界检查，不能精确封住已在途请求；任何缺失/partial 字段都不当作零。有未知已结算用量时禁止 token 限额下的新准入，界面说明原因；并发可能产生在途超额，必须明示。
- 修改限额只能由 UI 的版本化 IPC 操作触发，模型工具不能修改；有 expectedRevision 防止旧界面覆盖。修改限额不重置消耗、不恢复旧消息或自动重跑产物。
- 冷会话只读预算；修改前要求当前 Native 会话已装配。其他运行时明确报告不支持，不用一个离线 Store 与在线调度器竞争写入。

## C：展示与评测

沿用 evaluate:science 添加同输入的对照：无预算执行三轮与两轮预算的第三轮拒绝；输出保留，输入哈希相同。另展示实际共享锁等待、停止排空、重建 Store 后消耗不变。推理回复固定，真实 Pi/进程/文件的现有评测继续保留；不把本地确定性场景外推为真实模型质量/金额收益。
