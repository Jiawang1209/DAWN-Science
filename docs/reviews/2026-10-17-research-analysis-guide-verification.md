## 实现范围

- 保留技能 ID 与 `/skill:analyze-like-case` 调用方式、默认模型发现策略；中文标题与技能列表描述使用新名称。现有列表仍以技术 ID 为主标签，没有引入新的显示名称字段。
- 综合需求先理解目标和数据起点，必要时集中澄清最多三项关键未知，再形成带目的、输入、输出、依赖及适用条件的 S 编号路线。详细指导放入按需读取的 `references/comprehensive-analysis.md`。
- 按步骤从实际 MLAI 工具检索，保留语言等硬条件；初次综合回复最多八个不同案例，每步一至两个代表候选。区分未命中、调用失败、未展开，及元数据初筛、相关内容核对两种证据程度。
- 有必要时允许选择前只读核对最多两个案例；不再把 `verified` 或固定数量的案例承诺成当前环境运行通过。
- 使用 C 编号和完整 ID 将候选映射到步骤，复用回复底部的图片卡片与选择动作。后续展开需在当前轮重新检索或读取相关案例。
- 选择针对案例及相应步骤；“暂不运行”持续生效。输入和授权满足时连续完成已授权范围，保留原始数据和已有结果，不自动安装依赖或运行案例示例。

本次没有产品运行时、UI、协议、数据库、依赖或版本变更。技能指导依赖模型遵循，不能视为新增的执行硬门，也不能保证所有模型在自然语言请求中自动调用；显式调用方式保留。
