# 外部文件附件：粘贴 / 拖拽 → 发送才落盘 → `@` 引用（2026-08-25）

学自 `dsh-paste-input`（解读：`ccb_hive_code_learn/dsh-paste-input-解读.md`）。作者裁剪定案：抄三样，不抄 HTTP 批次协议 / Host 栅栏 / 气泡折叠。

## 世界观

与 `@` 引用一致：**文件进工作区、路径给模型**。外部文件（剪贴板、拖拽）不直接塞字节给模型——复制进 `<工作区>/.dawn/attachments/<会话目录>/<批次>/`，消息里带 `@相对路径`，与手敲 `@`、与「上传文件」按钮完全同一条识别语法（`mentions.ts` 的 `引用令牌`）。图片仍走「随轮送字节」的老路（native 会话）。

## 三条纪律（学来的）

1. **发送才落盘**：粘贴 / 拖拽只在内存排队（chip：图标 + 名 + 大小 + ×）；发送那一刻才写盘。×掉 chip = 磁盘无痕。写一半抛错 → 整个批次目录删掉，正式目录里永不出现半截批次。
2. **owner marker 才有资格谈清理**：每批次一份 `.dawn-attachments.json`（owner/version/sessionId/文件表/总字节）。用量与清理只认自家 marker；别人放进目录的东西不算数、必须活过清理。
3. **消毒进令牌**：文件名分隔符 / Windows 禁字 / 控制字符 / **空白**全换 `_`——存下来的名字必须能进 `@` 令牌（识别到空白就断）。撞名 `~N` 让位，不覆盖。

## 坐在哪一层

- `src/files/attachments.ts`：`存附件` / `附件用量of` / `清附件` / `安全文件名` / `会话目录名`，纯 node 可测（`tests/files/attachments.test.ts` 6 条）。
- 窄 IPC（与 `pickDirectory` 同一条理由，不进协议）：`dawn:shell:attach-save / -usage / -clean`；拖拽文件经 `pathForFile` 走主进程复制，字节不过 IPC；剪贴板文件走结构化克隆。
- UI（`views.tsx` 对话 composer）：`待发文件` 状态、整页 dragover/drop（`defaultPrevented` 的不再收——拖图那条老路优先）、粘贴非图片文件、发送时落盘拼 `@`、失败原样还回（话 + 图 + 文件）；附栏「上传文件」的黑色实心同样被它点亮。
- 概览一格 `AttachUsagePanel`（`attach-panel.tsx`）：批次 / 文件 / 占用 + 两步确认清理。
- 边界：**空态不收外部文件**（会话还没建，没有落盘的归属）；无工作目录时发送当场出声，不静默丢。
- 判据：`e2e/paste-input.spec.ts` 3 条（粘贴全链路 + 磁盘 marker；×掉无痕 + 按钮熄灭；拖拽 + 概览两步清理）。
