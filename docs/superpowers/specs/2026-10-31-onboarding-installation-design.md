# 安装与首次引导

用户确认：手动新装、同版本重装、覆盖安装，保留旧用户数据也必须从四步引导第 1 步开始；普通重启和应用内自动升级保留已完成或跳过状态。系统钥匙串授权独立于引导，不等待授权才能展示介绍，不清理凭证、模型、解释器、会话或数据库中的远端内核装机 ID。

采用独立安装世代：主进程在创建窗口前，根据安装文件实例识别当前安装，在 userData 的独立 JSON 里保存随机世代 ID。Mac 读取 .app、执行文件和应用清单的文件身份，不写入签名包；Windows NSIS 手动安装生成新标记，应用内更新明确使用 --updated 并沿用标记。便携包读取原始可执行文件，而不是临时解包目录。不能只按版本号区分，因为同版本重装同样需要重置。

预加载通过额外进程参数同步获得非敏感 ID，向导完成/跳过键按 ID 隔离，首帧即为 welcome。开发预览/浏览器没有安装 ID，沿用已有存储语义。应用内更新仅在成功换包后、重启前，把新文件身份接续到原世代；失败换包不接续，因此不会留下允许后续手动重装绕过引导的升级标志。

读取/写入安装元数据失败时记录错误并使用临时世代，允许进入引导和工作台，不阻断启动。首次引入安装世代时不继承未绑定安装的旧完成标记，以保证保留旧数据的重装会显示引导。文件实例识别针对实际替换/复制安装，不把原应用原地恢复同一文件实例视为新装；Windows 运行需实际设备验证。

验收：保留旧数据的首次安装、同版本覆盖、普通重启、引导中途重启、完成/跳过后重启、受控升级成功及失败、钥匙串等待、旧页面零闪现。实际 Mac 包使用独立测试目录和用户数据，检查数据文件内容保持；不替换已安装应用、不发送模型请求。
