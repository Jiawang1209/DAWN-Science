# 默认自动安排设计

用户已明确确认：任务粒度由具体任务决定，任务块数作为结果展示，允许调整，不预填数量。此设计替代上一轮手工结构表单，沿用成员入口成果。

## 核心行为

自动指拆分与分工方式由会话模型提出。用户在协作台描述目标或使用所属草稿，点击生成表示发起一次只读规划；普通聊天与正在运行的任务不会被后台自动切换。

模型读取任务/上下文及允许的文件信息，决定单任务、独立并行、依赖交接或科研审阅；没有固定三块模板。propose_plan 接收可选 arrangement（模式、理由、任务数组、疑问），宿主校验后转为规范可读 Markdown。明确的自动安排请求不能只交一份缺少结构的旧式方案。

任务数组包含 id、标题、目标、角色、输入、输出、依赖、验收、审阅标记。数量仅由有效数组长度得出，不作为输入配置，也不等于启动 Agent 数。角色是分工提议，尚非冻结执行者或科学验收证明。

## 存储与批准

复用原方案簿、planId/version/status、审批编辑及文件指纹：只存同一份 Markdown，不新增独立任务 JSON 或 DB 表。规范节为「任务安排（自动安排）」，字段是可读的目标/分工/输入/输出/依赖/验收；解析只负责读回宿主规范格式，不以关键词判断怎样拆任务。

UI 生成后先展示结果，调整表单折叠；可提出自然语言要求重提新版（旧版 superseded），也可在原方案卡编辑可读正文，数量随有效结构实时重算。Native 在写方案文件之前重验依赖和独立审阅，不允许删掉任务节静默绕过。待确认问题未清楚时不能批准。旧式无任务安排节的方案保留原行为。

## 发送、隔离和取消

复用 getSessionPlan 确认能力、取写权、dawn.plan 及原 writeToSession 链路；无新增推理通道、IPC 或权限捷径。每次等待之后验证 owner、窗口会话代次与取消信号；同 owner 同时只提交一次；父任务或子执行/排空活跃时不启动安排。

初始提交失败保留任务文本。若已开启只读模式但未能发送，不自动降级为执行模式。终止规划使用原 abortSession，只在当前 owner 仍可见且仍处于规划期时调用。模型回合结束但没有新有效方案时提示查看原因，不把旧方案当新结果。主/侧方案来自各自现有转录槽，恢复由原方案簿与快照完成。

## 复用与验收边界

本轮不创建第二套调度器，不自动将提议角色认定为已运行 Agent，不改已有冻结契约、产物版本、锁、预算、取消排空及恢复检查。采纳后仍走既有执行入口。

软件验证包含不同任务的 1/2/3 块和调整后的 2 块、正文编辑数量变化、宿主拒绝无效审批、取消、迟到回复、侧会话隔离和重启。确定性 mock 只证明软件链路；不代表真实模型拆解质量、费用或科研正确性。无需额外付费调用，不使用旧剩余额度。

不推送、不发布、不自动提交/合并，不操作正式安装 App 数据或凭证。历史偶发 7350/20690ms 退出与长期 Bot/MCP stopping 保持 OPEN，1500/4000ms 预算不变。
