# 会话状态与远端恢复

用户已批准补上排查确认的缺口。目标是在原 API 对话里恢复，保留历史、草稿和会话 id。

## 设计

- Electron 在创建窗口、迁移数据、装配后端之前按数据库真实路径获取单实例锁。第二个实例退出并唤起第一个窗口；不同测试数据库可并存。锁的 profile 与业务 userData 分开，不迁移用户配置或凭证。
- SessionManager 以本进程绑定的运行时校正被误写的 exited 状态；恢复重入合并。恢复后的退出事件仍写库并释放租约。
- subscribeSession 恢复失败必须返回真实错误，即使事件中枢里还有旧快照。恢复成功更新 UI 名单状态。
- 主区与侧边共用按 session id 存储的恢复状态；恢复中禁用重复请求，失败在输入区显示原因和“重新连接并继续”。服务器 ready 时仅重试正在看的失败/已结束 API 对话，不重新执行历史命令或主动重启内核。
- 记录会话结束事件以及恢复失败原因，不记录消息、凭证、工具参数。API 请求失败、SSH 断线、内核退出保持各自生命周期。

## 验证

先建立双管理器共库、恢复失败保留旧快照、恢复 UI 重试与跨会话隔离的红测试。再验证类型、相关回归、构建与隔离 Electron 主路径。测试不得打开真实数据库或连接真实服务器。
