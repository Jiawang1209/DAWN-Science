# 四步引导、首页、工作台与模块依赖检查

结论：工作台已有且能够使用顶部“首页”按钮返回 App 首页。此次检查发现并修复首页异步导航的时序问题，解除一处交付模块的静态运行时循环引用；已本地同步到 main，未推送。

## 页面入口与状态归属

- 首次新窗口：四步引导 → 首页 → 工作台。
- 已配置、已完成或跳过引导：新窗口直接进入首页；当前窗口刷新保留所处页面。
- 工作台顶部工具栏“首页”：返回 App 首页。位于左上方品牌、侧栏及快捷键控件附近。
- 首页与工作台底部“导航栏”：手动打开四步引导。关闭后回到发起页面，不清除长期完成记录。
- 首页/工作台由 `state/app-page.ts` 管理；工作台内部页面由 `state/view.ts` 管理。切回首页隐藏工作台，不销毁当前会话与编辑器状态。
- 会话列表、运行和凭证状态属于后端权威缓存；聊天草稿、编辑草稿与窗口导航状态分别维护。首页读取近期会话，不将各项目的结果混入当前项目会话槽。
- UI 经 WorkbenchClient → preload `window.dawn` → IPC/协议 → WorkbenchServer，再进入会话、运行时、内核、文件及存储模块。

设置和代码区沿用既有侧栏显示规则：主动打开设置后，设置仍可占用该列。重新打开关联脚本后恢复原编辑草稿；面板是否显示与草稿是否保留是两项独立状态，均已通过真实流程验证。

## 发现及修复

1. **首页异步导航回跳。** 打开近期会话或选择目录后，如果用户已转到其他页面、返回首页或打开引导，迟到回调仍可能切换选中项和页面。新增三个全 App 的延迟响应测试，原逻辑三条均失败；现通过窗口导航世代检查拒绝过期回调，引导打开也撤销旧导航意图。正常打开项目和近期会话仍通过真实 Electron 验证。
2. **交付服务与独立验证互相导入。** `delivery/service.ts` 调用验证器，验证器反向运行时导入服务里的文件辅助函数。将同样的路径校验/独占写入移至 `delivery/files.ts`；保留旧服务导出，验证器仅以类型引用 DeliveryOptions。工作区包含约束、符号链接拒绝、独占写入及权限均保留。
