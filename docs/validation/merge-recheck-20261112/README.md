## 发现并修复的遗漏

### 停止完成后立即重开仍拿到上一代启动错误

旧测试在 `await stop()` 后又等所有旧 `start()` 返回，随后才重开；这掩盖了停止已返回、完整启动收尾仍未完成的间隙。直接等待停止再重开，正常模型路径稳定复现“启动过程中被停止了”。初始新回归为 1 失败、1 通过，见 `runtime-red.txt`。

停止现在持有关闭状态，直到原始停止和旧启动清理都排空；启动取消路径由停止方回收，不再反过来等待公开停止 Promise，从而避免循环等待。新测试还要求重开的会话确实处于运行状态，重复启动必须被拒绝，防止把已停止的旧句柄当作成功。并发启动/取消和原有运行时用例一起通过。

### 日期校验漏了一次性和间隔任务

上次仅修复 `everyDays.start`，`once.at` 和 `interval.anchor` 仍直接使用 `Date.parse`，会把 `2026-02-30T08:00:00Z` 接受并归一化为 `2026-03-02T08:00:00.000Z`。初始纯函数回归 8 项失败，后端两种任务的创建回归也失败，见 `calendar-red.txt` 和 `backend-red.txt`。

现在按原始 ISO 日历日核验日期，再保留已有时刻解析兼容；有效闰日、毫秒、正负时区偏移和跨 UTC 日期的输入通过。创建及修改均经过同一校验，拒绝时不保存新任务、不改变原任务和版本。真实 Electron IPC 用例检查了两种任务的四个拒绝结果及原计划保留。
