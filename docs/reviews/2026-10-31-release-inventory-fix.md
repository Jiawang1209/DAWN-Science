# Linux x64 发布清单误报修复

v0.0.42 的 Linux x64 job 成功生成并上传 `DAWN-Science-0.0.42-linux-x86_64.AppImage` 和 `DAWN-Science-0.0.42-linux-amd64.deb`，但发布清单使用 `linux-x64.AppImage` / `linux-x64.deb` 查找，导致 10 个附件全部存在时仍输出缺包警告。原回归也使用了相同的错误文件名，未发现该问题。

修复工作流中的两个文件名匹配，并将缺包说明改为“未收到对应文件，请检查产物名称和打包上传步骤”，不再把未收到文件直接归因为打包 job 失败。保留既有的部分平台可发布、全部缺失时失败的策略。

回归直接解析工作流并在临时目录执行其中的 Bash，文件名样例来自 v0.0.42 真实附件，独立于检查脚本。覆盖：十份齐全、逐一缺少十个变体、完全没有产物、不能把错误命名或其他架构文件当作 x64、版本号跟随当前 tag。新回归在修复前为 13 项失败、1 项通过，修复后 14 项全部通过；连同打包配置检查共 18 项通过。

额外核验：从 GitHub 只读取得 v0.0.42 的实际 10 个附件名，以同名临时文件重放工作流检查，退出 0、输出“预期的10份安装包与便携归档均已收到”、没有缺包警告。`bash -n`、类型检查、`git diff --check` 通过。使用官方 SHA256 校验后的 actionlint v1.7.12 检查 `release.yml`，退出 0；本机没有 shellcheck，关闭其可选集成，Bash 语法及分支结果由前述检查覆盖。

验证范围是发布清单检查，不代表重新构建或运行安装包。本次未改动线上 Release 说明、标签或附件；现有 v0.0.42 的错误说明不会随推送 main 自动回写，需要另外更正。用户自行 push，本次仅本地提交与合并。
