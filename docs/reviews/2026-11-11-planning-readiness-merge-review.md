## 发现与修复

**P2：旧批量工具的缺单位拒绝过晚。** `start_science_batch` 原来先等待工作区输入锁、捕获输入版本和调用 `probeScienceEnvironment`，进入 `startPipeline` 后才拒绝显式缺单位。锁被占用时会无谓等待，锁空闲时会先启动解释器环境探测，尚未满足“已知缺信息立即停止”的要求。

两个回归用例先复现：锁空闲时进入意外环境探测；锁被持有时返回 waiting-for-lock 而不是单位缺失。修复复用 `scienceTemplate` 和 `scienceReadinessIssue`，在批量工具入口验证后、发现模型/成员/输入/解释器和获取锁之前拒绝。缺项不创建团队、不写当前指针；显式补齐单位后新请求仍可正常创建串行/并行批次。

| 检查项 | 核对路径与结论 |
|---|---|
| 方案执行绑定 | propose_plan 与批准共用纯依赖校验；执行读取原方案簿快照，核对 owner、planId、版本、正文指纹、存档和当前团队，重复启动不重放 |

| 取消排空 | 父 abort 与定向 stop 保留守卫；停止后的旧尝试仍需排空，任务和锁按原路径释放；缺单位入口不进入锁队列，不新增后台执行 |
| 恢复 | 批准任务重开保持暂停、显式继续核对文件版本；已有中断副作用不自动重放；缺单位补齐后新来源、新方案、新采纳 |
| 产物证明 | 显式缺单位早停不借用旧验收、版本或交付路径；输入原字节保留，文件别名/版本仍在批准与执行时复核 |
| 旧入口 | 普通安排、调整、取消、批准执行、科研批量、编排展开与返回沿用原入口；新拦截只针对明确的结构化缺项 |
