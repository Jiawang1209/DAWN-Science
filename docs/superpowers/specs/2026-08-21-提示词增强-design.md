# 提示词增强：输入框旁一颗 ✨，把草稿改写得更好再发

> 学自 `Fishsb/dsh-prompt-enhancer` v3.3.0（commit `3fd60f6`，本地副本在
> `ccb_hive_code_learn/dsh-prompt-enhancer`，解读全文 `dsh-prompt-enhancer-解读.md`）。
> **仓库没有 LICENSE——只借思路，提示词与代码全部自己写**，与本项目对参考项目的规矩一致
> （`docs/REFERENCES.md`：读设计、不复用代码）。

作者 2026-08-21 定的三件事：三档（基础 / 标准 / 专家）；用当前会话的模型；不做记忆链。

---

## 一、读出来的事实（决定设计的那几条）

1. **没有向量库、没有 embedding。** 全部是「提示词工程 + 几次小调用」：
   - 一个**输出纪律层**（最高优先级）：只输出改写后的提示词本体、不加导语、不回显指令、
     不解释；**语义保真**（对象 / 动作 / 约束 / 数量 / 语气一个不丢，模糊处可明确化但要有原文依据）；
     语言跟随输入；同一输入重复优化结果要稳定。
   - 一个**改写方法**（五步法）：原子拆解 → 要素盘点 → 逻辑重组 → 明确化 → 保真自检；简单任务 ≤ 800 字。
2. **五档只差在「带不带参考、带什么」**。标准：本会话前 2–10 轮切三个窗口 `[1,2] [3,5] [6,10]`，
   每个窗口一次 400 token 的小判定「相关吗」，**第一个相关的就停**，只注入那一个窗口。
   专家：再加工作区——先判「是不是开发意图」，是才扫 `.md`（关键词给文件名打分）→ 让模型
   从候选里挑相关的并摘要 → 摘要里说有项目地图才去扫代码。
3. **判定类小调用刻意关掉 thinking**（带 thinking 会把小预算吃空、出空流）。
4. **不信「请勿复述」**：输出后再用确定性规则剥掉导语 / 包裹 / 回显的指令。
5. **参考使用规则只在真带了参考时才追加**（省 token）。
6. 它的毛病，我们不带进来：专家模式追加的「调整方案」块与纪律层直接矛盾；检索四层兜底最后是
   「随便取前 N 个文件当项目事实」；中文分词写死、英文草稿检索基本失效；撤回只有一层且一敲键就没。

## 二、定案

### 坐哪一层（规格 §4）

- **新操作 `enhancePrompt`**（协议 7.15），住主进程 `src/workbench/backend.ts`，逻辑在新目录
  `src/enhance/`：
  - `prompts.ts`：纪律层、方法层、三档模板、两个判定模板。**纯字符串常量 + 单测锁文本**
    （借它「提示词与代码同仓、测试锁定」的做法）。
  - `retrieve.ts`：窗口切分、相关性判定、工作区候选（文件名打分 + 片段），**纯函数**，判定用注入的
    `问一句`。
  - `clean.ts`：输出清洗（剥导语、剥包裹、剥回显的指令块），纯函数。
  - `enhance.ts`：把三档串起来：`基础 → 调一次`；`标准 → 切窗 → 逐窗判定 → 调一次`；
    `专家 → 标准 + 开发意图判定 → .md 候选 → 文档摘要判定 → 调一次`。
- **模型**：`NativeRuntime` 加一个口子 `问一句(sessionId, { system, user, maxTokens, thinking: false, signal })`
  ——用**这段会话此刻的 provider + model + 凭证**（`pi-ai` 的 `complete(model, context, options)`）。
  **ACP / CLI 会话没有这个口子**：它们的模型不在我们手里，✨ 不画（**看不见的能力等于不存在**，
  反过来，按不动的按钮更糟）。没有会话（空态屏）时用配置里第一个 native agent 的模型。
- **上下文来源**：标准档的对话历史取 `SessionTranscripts` 里这段会话的 `turn` 条目（`who: user/agent`，
  `final` 的），**丢掉工具调用、思考、系统提示条**——与它「只看人话」同一口径。专家档的工作区就是
  这段会话的 workspace（远端会话用 `RemoteLike.exec("find …")` 列文件、`readFile` 读——**远端会话
  也能用专家档**，手伸到哪儿就在哪儿扫）。
- **取消**：`AbortSignal` 一路传到 `complete`；界面那颗按钮增强中变「取消」。
- **不做**：记忆链；一键发布；联网；模型链与连通性测试（用当前会话的模型，失败就说失败）；
  「调整方案」那个附加块。

### 三档到底差在哪（作者定的名字）

| 档 | 带什么 | 调用次数 |
|---|---|---|
| 基础 | 不带参考 | 1 |
| 标准 | 本会话前 10 轮切三个窗口，逐窗判定「相关吗」，命中即止，注入那一窗（≤ 2400 字） | 1–4 |
| 专家 | 标准 + 开发意图判定 → 工作区 `.md` 候选（≤ 5 个、深 3 层）→ 文档摘要判定 → 有项目地图再扫代码（≤ 3 个） | 2–6 |

**与它不同的三条**：① 关键词打不中就**不带**，不取「前 N 个」充数；② 关键词抽取按「中英混排」做
（中文按常用虚词切、英文按 CamelCase / snake_case / 路径切），不依赖中文；③ 文档注入**原片段**
（命中行 ±2 行，≤ 800 字），不用模型的二手摘要——项目事实要一手的。

### 提示词（自己写；意思借它的，措辞不是）

- **纪律层**（每次都带）：只输出本体；不加导语 / 结语 / 解释；不回显任何指令、参考、原文；
  不用代码块 / 引号包裹（除非内容本身需要）；**原意不丢**（对象、动作、约束、术语、数量、语气
  一致，疑问句可转为明确请求但焦点不变）；明确化必须有原文依据；语言跟随输入；重复优化要稳定。
- **方法层**：拆解 → 盘点 → 重组 → 明确化 → 自检；简单任务 ≤ 800 字；形式按内容定。
- **参考规则**（只在带了参考时追加）：参考只用来补背景与已确认的约束，吸收进结果、不复述；
  冲突以原文为准；参考推不出的不臆造；分级——对话历史 = 任务背景，文档 / 代码 = 项目事实。
- **判定模板**两个：「这段历史与当前输入相关吗」「这句话有没有开发意图」，都只回一个 JSON，
  宁可漏判不可错判，**不开 thinking**，`maxTokens ≤ 300`。
- 全部中文写，带一组中 → 中、一组英 → 英的小例子。

### 界面

`composer-controls` 左手那一排（上传文件 · 选择工作目录 · 终端）之后：**✨ 增强** + 一个小字标
（当前档名，点开三选一，选了就记在 `dawn.global.enhance-mode`）。

```
⊕ 上传文件   📁 选择工作目录 ▾   ▣ 终端   ✨ 增强 · 标准 ▾                    D deepseek ▾  ↑
```

状态：
- 草稿为空 → 按钮禁用（灰，有 title 说「先写点什么」）；
- 增强中 → 按钮变「取消」，字标旁转圈 + 一个字说到哪步了（「判定相关 1/3」「扫文档」「改写中」）；
- 改写完 → 草稿整段替换，按钮变「撤回」；**人一敲键盘撤回仍然在**（它那条「一敲键就没」我不抄）——
  撤回恢复到增强前那一版，可连点：每次增强压一层，最多 5 层；
- 失败 → 草稿不动，composer 下那条 `.composer-problem` 说原因（模型错、超时、输出为空）。
- 快捷键 `⌘⇧E`；命令面板「增强提示词」同一个动作。
- ACP / CLI 会话、或 provider 没配钥匙 → 按钮不画（同 ModelPill 的规矩）。

### 失败必须出声（规格 7.5）

- 模型失败 / 超时（基础 30 s，标准 60 s，专家 90 s）→ 说清是哪一步、哪个模型。
- 判定与检索**任何一步失败都降级为「不带参考」继续**，但结果旁写一句「这次没带上下文：<原因>」——
  不静默退化成基础档。
- 输出清洗后为空 → 报「模型什么都没给」，草稿不动。

## 三、协议与 mock（准入规则 ①）

`enhancePrompt`：`{ text, mode: "basic"|"standard"|"expert", sessionId?, signalId? }` →
`{ text, usedContext: { rounds?: [from,to], docs?: string[], code?: string[] } | null, note?: string, model }`。
取消走已有的 `abort*` 模式：`cancelEnhance { signalId }`。

`mock-inference-server`：加一个规则——system 里含纪律层标记句（`【只输出改写后的提示词】`）
时回 `改写：<原文>`；判定请求（system 含 `只回一个 JSON`）按正文里有没有「相关」/「开发」回
`{"related":true|false}` / `{"isDevIntent":…}`。e2e 据此能确定性地走三档。

e2e 至少四条：① 基础：写一句 → ✨ → 草稿变「改写：…」→ 撤回 → 原样；② 标准：先聊两轮再增强，
mock 收到的 system 里带那一窗参考；③ 专家：工作区放一个含关键词的 `.md` → 增强 → mock 收到
【项目文档参考】片段；关键词打不中 → 不带、结果旁有那句话；④ 增强中取消 → 草稿不动、按钮回来。

---

## 四、分期

- **E1**：`prompts.ts` + `clean.ts` + `retrieve.ts` 纯函数与单测；`NativeRuntime.问一句`。
- **E2**：`enhancePrompt` 操作 + 基础档 + 按钮 / 撤回 / 取消 + mock 规则 + e2e ①④。
- **E3**：标准档（窗口判定）+ e2e ②。
- **E4**：专家档（工作区，本地 + 远端）+ e2e ③。

## 五、放弃了什么

- 记忆链（作者定的：先不做）。
- 一键发布九章规格、联网检索、模型链与连通性测试。
- 「调整方案」附加块（与纪律层矛盾）。
- 检索兜底「取前 N 个」。
