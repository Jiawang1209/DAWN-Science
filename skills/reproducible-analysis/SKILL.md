# 让分析能被再跑一次

**可复现不是跑完之后补的，是写的时候顺手做的。** 这几条几乎不花时间，
而缺了任何一条，半年后重跑都可能得到不一样的数字。

## 什么时候用

- 写任何会产出图表、统计量、结论的分析脚本
- 用户提到「投稿」「审稿人」「交给合作者」「以后还要跑」
- 一段分析已经跑通了，要把它整理成脚本

## 什么时候不要用

- 一次性的探查（「这列有几个唯一值」）——那种代码不该被保存，更不用讲究
- 用户明确在赶时间做一次性的检查

## 共用审查规则

需要科研审查时按名称查找并读取 `scientific-review`，沿用当前可见版本；不可用时如实说明，不绕过停用或同名覆盖。**只审不运行**时仅静态核对；已有执行授权不重复询问，缺少执行工具则交回需验证项并标为未运行。保护当前内核、原数据和已有产物，运行成功不代表科学结论已核验。

## 五条

### ① 参数集中在最上面

```python
# ── 参数 ────────────────────────────────
输入 = "data/processed/soil_2019_2023.csv"
最小样本量 = 30
随机种子 = 42
输出目录 = "outputs/figures"
# ────────────────────────────────────────
```

**不要把数字散在代码中间。** 散着的话，改一个阈值要通读全文，
而「上次那张图用的是哪个阈值」就再也答不出来了。

### ② 随机的地方一律设种子

```python
import numpy as np, random
random.seed(随机种子); np.random.seed(随机种子)
# sklearn: random_state=随机种子      statsmodels/bootstrap 同理
```

```r
set.seed(随机种子)
```

涉及随机性的步骤记录实际种子和随机源，包括并行配置。未记录时说明局限，不能事后补一个种子声称与原运行相同；固定种子也不保证跨版本、硬件和并行调度逐字节一致。

### ③ 路径相对项目根，不用绝对路径

`/Users/某某/Desktop/…` 换台机器就断。用相对路径，
并按科研目录约定放：`data/raw/`（只读）、`data/processed/`、`outputs/`。

**`data/raw/` 里的东西不修改**——要改就读出来、处理完写到 `data/processed/`。
原始数据一旦被就地改过，之前所有的结果都失去了参照。

### ④ 把版本记下来

```python
import sys, pandas as pd, numpy as np
print(sys.version)
print({p.__name__: p.__version__ for p in (pd, np)})
```

pandas 从 1.x 到 2.x 改过 `groupby` 的默认行为，
**同一份代码在两个版本上会给出不同的结果**——不记版本，这种差异永远查不出来。

（在 DAWN 里，每段会话起内核时已经自动冻结了一份环境快照，
所以这一条主要是为了让脚本**离开 DAWN 也说得清**。）

### ⑤ 一个脚本从头跑到尾要能出全部结果

先遵守执行授权。**不重启、不清空用户正在使用的内核。** 已授权验证时，优先独立内核；或使用已核实的同环境解释器，在独立进程中从显式输入顺序执行，输出到新建验证目录。启动前检查脚本实际写入路径、超时及本次进程清理；无可靠能力就标为未运行，不假借共享内核中的 source/exec 宣称独立验证。具体做法按需读取 `analysis-delivery`。

核对退出码、实际产物、样本量和关键数值；数值比较说明预先采用的容差，图表检查数据与渲染。PDF 元数据等导致的字节差异不能单独判结果不一致。相同输入重跑是重复运行一致性，不能直接称为幂等。只有部分或缩小规模验证时注明范围；未运行和缺少参照分别说明。
