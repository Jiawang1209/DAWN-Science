# 数据集初探

**目标不是「画一堆图」，是回答三个问题**：这份数据能不能用、有哪些坑、下一步该做什么。

## 什么时候用

- 用户第一次给你一份数据文件，或说「帮我看看这份数据」
- 在做任何建模、统计检验之前
- 换了一份新的数据版本，要确认它和上一版是不是同一个形状

## 什么时候不要用

- 用户已经明确说了要做什么分析（那就直接做，别硬塞一轮初探）
- 数据是你自己刚生成的中间产物——你已经知道它长什么样
- 只是要读取一个已知格式的配置/参数文件

## 顺序（这个顺序是有理由的）

**先结构，再质量，最后分布。** 反过来做会浪费时间：在一列 90% 缺失的变量上画分布图是没有意义的。

### ① 结构：它是什么形状

```python
df.shape          # 多少行多少列——先知道量级，再决定要不要抽样
df.dtypes         # 类型是不是读对了
df.head(10)       # 真的长什么样
```

**类型读错是最常见的坑**：日期读成字符串、编号读成数字（前导零丢了）、
带单位的数值列读成 object。**看到 object 类型的数值列要立刻查**。

### ② 质量：有哪些坑

```python
df.isna().sum().sort_values(ascending=False)   # 缺失，按严重程度排
df.duplicated().sum()                          # 重复行
df.describe(include="all")                     # 极值一眼可见
```

要**说出数字**，不要只说「有一些缺失」。「`soil_ph` 有 312/1204 缺失（26%）」
才是能据以决策的话。

**缺失不等于零，也不等于「没测」。** 遇到缺失要问：是没测、测了没记、还是低于检出限？
这三种的处理方式完全不同——**不要自作主张填充**。

### ③ 分布：值合不合理

- 数值列：范围是否越界（pH 出现 14.7、经纬度出现 999）
- 分类列：`value_counts()` 看有没有拼写变体（`"内蒙古"` / `"内蒙古自治区"` / `"IM"`）
- 时间列：跨度、频率、有没有断档

**领域常识比统计更有用**：土壤 pH 不会是 14.7，日降水不会是负数，
物种数不会是小数。看到这类要直接指出来，而不是当作离群值处理掉。

## 交付什么

一段**结论**，不是一堆图。形如：

> 1204 行 × 18 列，2019–2023 年内蒙古 6 个样地的土壤观测。
> **能用**，但有三处要先处理：
> ① `soil_ph` 缺失 26%，且集中在 2021 年——那年的仪器可能换过，**建议先问清楚**
> ② `site` 列有 8 个取值但实际只有 6 个样地，`"乌兰敖都"` 和 `"乌兰敖都站"` 是同一个
> ③ 有 3 行 `annual_precip` 为负数，明显是缺失标记（-9999），**不能当数值用**

图只画真正说明问题的那一两张（比如缺失的时间分布），**不要画满一屏**。
