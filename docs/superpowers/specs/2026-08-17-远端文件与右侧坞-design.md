# 右侧坞与文件面板（本地 / 远端 · 预览 · 传输 · 删除）

> 2026-08-17 起 · 分支 `feat/远端文件` · 状态：**批 0–6 全部完成，真机验过**

## 为什么做这件事

作者 2026-08-17：*「我现在 ssh 到服务器上了，我想看看服务器上的图片能否搞一个
文件预览，上传和下载的功能。」* 以及：*「我觉得现在的文件窗口不好看，
应该学习一下 codex，放到右上角。」*

### 今天的实际状态（动手前量的，不是猜的）

| 事实 | 说明 |
|---|---|
| SFTP 的**壳**在，但**从没跑过** | `RemoteExecutor` 上有 `readFile` / `writeFile` / `readdir`，走真 SFTP 句柄——但**今天一个调用点都没有**（②-B 时写下，一直没人用） |
| 而且它与假 SSH **已经对不上** | 假 SSH 的 `readdir` 返回的 `attrs` 是个字面量对象，**没有 `isDirectory()`**；而 `RemoteExecutor.readdir` 正在调它。**这条路一跑就抛**——没人发现，因为没人跑过 |
| 文件面板完全不知道远端存在 | `listDirectory` / `readFile` 两个操作拿 `projectId` 查项目 `workspace`，用**本地 fs** 读 |
| 远端会话挂在隐藏的临时项目下 | 那个项目的 workspace 是**本机的 scratch 目录** |

**所以「传输这一层是现成的」这句话不成立**：现成的是形状，不是能跑的代码。
排期上要按「新写」算，不是按「接上去」算。

余下三条合起来是一个已经存在的 bug：**在一段远端会话里打开「文件」，
看到的是本机的一个临时目录**。它不报错，就是安静地给你看错东西——
而这正是这个项目最忌讳的那类失效。

预览那一半的功力都在：三态（图 / 文本 / 其它）、CSV 读成表、PDF 交给 Chromium、
路径守卫在 `files/access.ts`。**缺的是「这些字节从哪儿来」，不是「怎么显示」。**

而形态上的毛病同样具体：现在的「文件」是**占满整屏的一个视图**，
右上角一个「返回」。于是**看文件的时候对话没了**——
而看图的真实场景恰恰是「模型刚跑完，我想边看图边说下一步」。

## 一、右侧坞

学 Codex 桌面版：顶右角一个切换菜单，选中的那一块占住右边一栏，**与对话并排**。

坞里三个房客：**审阅 / 浏览器 / 文件**。

**本分支只做两个**：

| 房客 | 现在有什么 | 本轮 |
|---|---|---|
| **文件** | 预览三态、CSV、PDF、路径守卫 | ✅ 搬进坞 + 远端 + 传输 + 删除 |
| **审阅** | 「变更」pane（`panels.tsx`）——**只列改了哪些文件，不显示怎么改的** | ✅ 搬进坞（**就搬位置**） |
| **浏览器** | **一点都没有**（全项目 0 处 `webview` / `WebContentsView`） | ⬜ 单开一轮 |

### 「怎么改的」不在本轮（作者 2026-08-17 提出，另开一轮）

作者：*「可以看到代码，文件，是如何修改的。因为毕竟数据分析，
里面会经常有数据是如何修改的这种情况。」*

**这是新功能，不是搬家**——现在的「变更」pane 只列文件名。设计时先想清楚了三件事，
记在这里，下一轮开 spec 时直接用：

**① 逐行 diff 用在数据表上会骗人。**

| 你干了什么 | 逐行 diff 说什么 | 你其实想知道什么 |
|---|---|---|
| 改一个列名 | **每一行都变了** | 就一个表头变了 |
| 某列单位 g → mg | 每一行都变了 | **一列被整体乘了 1000** |
| 重新排序 | 全文件重写 | **一行都没少，只是顺序变了** |

后两种是数据分析里天天发生的事，而逐行 diff 在那两种情况下信息量接近零。
这个项目为同一条教训改过一次（CSV 原先落在「文本」那一支，屏幕上是一坨逗号原文）：
**CSV 的 diff 也该是表，不该是两栏红绿。**

**② 三种文件，三种「怎么改的」**：文本/代码走逐行；表格走**结构化 diff**
（行增删、列增删改名、单元格变化，并**认出「整列乘了同一个因子」这类事**）；
图片与二进制**并排摆两张**，其余只说「变了，从 A 大小到 B 大小」。

**③ 跟什么比——作者 2026-08-17 定的：跟 `git HEAD` 比**（*「和 Codex 一样」*）。

不是「跟这一轮开始时比」。于是这一屏答的是**累计**：从上次提交到现在改了什么。

两个后果必须一起做掉，否则这一屏会在最该说话的时候沉默：

- **`git diff HEAD` 不含未跟踪的文件**。刚跑出来的 `out/fig1.png` 正是未跟踪的。
  「新增」要单独列，不能指望 diff 给。
- **数据产物常常正好被 `.gitignore` 挡着**（`out/`、`data/raw/` 写进 ignore
  是科研仓库的常态）。于是一次分析生成 40 张图，`git diff HEAD` 会说**什么都没变**。
  **一个说「无变更」的审阅面板，而你刚跑完一整轮分析**——正是本项目最忌讳的失效形状。

**解法在我们自己手里**：不变式 5 已经让账本记着 agent 写了哪些文件。
**git 答不出的那一部分，账本答得出。** 所以这一屏是两个来源，
而且**必须看得出是两个来源**：上半是「仓库里的改动」（会被提交的），
下半是「这次跑出来的产物」（git 忽略的）。混成一张列表，
人就判断不了哪些会进版本库。

还有一条**因此更重要了**：`mayIncludeUserEdits`。跟 HEAD 比是累计口径，
里面本来就混着你自己手改的东西，而本阶段没有 worktree 隔离，分不清。
`panels.tsx` 那条「不能指望人记得加脚注」的纪律在这里必须继续守。

**基线从哪儿来——作者 2026-08-17 定的：**

| 情形 | 有没有基线 |
|---|---|
| 本地 + git 仓库 | ✅ 有，`git diff` 现成（与不变式 5 同一个来源） |
| 本地 + 非 git 仓库 | ❌ **没有。如实说「不知道」，不编** |
| **远端** | ❌ **不需要基线**——服务器上的目录多半不是 git 仓库，我们不替它造一份 |

由此推出一条**与 `dawn_run_in_kernel` 相反**的处置：那件工具在没配内核时
**根本不出现**（摆一个「点了说没配」的工具比不摆更坏，因为它的读者是模型，
模型会围着它规划然后撞墙）。**审阅房客不一样：读者是人。**
所以远端会话里它**照样在菜单里**（坞的菜单不该随会话变形），
但内容是一句明话：「gs191 上没有基线——这个目录不是 git 仓库，DAWN 不替它猜。」
**「不知道」与「确认没改」必须看得出区别**，这条纪律已经写在 `panels.tsx` 里了。

**浏览器为什么单开**：它要决定用 `WebContentsView` 还是 `webview`、要不要给 agent 用、
cookie 与凭据怎么隔离。那是一整套自己的安全面，混进这一分支会把它拖成一次大改。

**底部终端不动。** 作者明确：*「不，我就要文件预览和上传，下载，不要终端。」*
终端 dock 已经在底部工作得好好的，把它挪进右侧坞是纯粹的搬迁风险，换不来任何东西。

### 侧栏那个「文件」入口怎么办

**改成打开坞，不再是一个全屏视图。** 留着两个入口指向同一个东西，
就是「两处长得一样的东西，等于没有判据」的又一例。

## 二、看哪台机器：**跟着会话走，不给切换器**

作者：*「我在本地的话，我查看的肯定就是本地文件夹的文件，
我要是登陆的服务器的话，那么看的就是服务器的文件。」*

**没有「本机 ｜ gs191」这种切换器。** 你已经用「开哪段会话」表达过这个选择了，
再让你选一次是多余的。

### 树根跟着入口走

| 从哪儿进来 | 树根 |
|---|---|
| 项目收纳 | 项目文件夹（`project.workspace`） |
| 会话收纳 | 那段会话自己的目录 |
| 服务器收纳 | 那台机器的**家目录**（**先连上**，没连就先连） |

**规则的准确说法是「跟着你点进来的那个东西」，不是「跟着当前会话」**（Q2，2026-08-17）。
从服务器收纳进来时那台机器上可能一段会话都没有——作者：*「肯定是要先连接
服务器的，可以直接去预览文件的。」* 所以是：项目/会话进来 → 那段会话的机器；
服务器进来 → 那台服务器本身。

这条规则顺手否掉了「记住上次看哪儿」——**不需要记，入口本身就带着答案**。
少一份要存的状态，少一处会不一致的地方。

### 面板顶上必须写明是哪台机器

**这是硬要求，不是装饰。** 不写的话本地与远端在屏幕上长得一模一样,
而那正是今天那个 bug 的形状：它安静地给你看本机的目录，你根本没机会发现。

## 三、定位：**只做跳转，不做搜索**

一个路径输入框：输 `/data/liu/out` 回车就过去。远端认 `~` 与 `$HOME`。

**刻意不做文件名搜索**（作者选的甲）。理由是代价差一个数量级：

- **跳转**本质上是一次 `readdir`，本地远端都是**一次调用**。
- **搜索**在 SFTP 里**没有原语**。要么我们自己递归走目录（一个 `~` 底下几十万个文件的
  服务器会走到天荒地老），要么在服务器上跑 `find`——那是在别人的机器上起一个
  可能跑很久、很吃 IO 的进程。**能做，但要有上界，而且截断了必须说出来。**

等真的点累了再做，那时也会更清楚要搜的是「当前目录下的名字」还是「整台机器」——
这两个的做法完全不同。

## 四、传输

### 上传

系统「选文件」对话框 → 传到**树上当前这个目录**。

**不长第二棵树。** 上传天生是两头的事，而另一头永远交给系统对话框——
这与 composer 里那颗「上传文件」现在的做法是同一条路。两棵树的话，
「我现在看的是哪边」就得靠人一直盯着。

### 下载

树上选中 → 落到**设置里那个默认下载目录**。

设置里在「工作目录」那一块加一格「下载目录」，**默认值取 `app.getPath("downloads")`**。

> **不按平台写死路径。** `~/Downloads` 与 `%USERPROFILE%\Downloads` 是那类
> 会坏在别人机器上的东西（ACP 那条 `launch.ts` 刚栽过同一类）；
> 而且 `app.getPath` 跟得上用户改过的系统下载目录。

### 坞一直在右边（Q3）

作者选的乙：**坞不随左半的屏切换而收起**。你切到「设置」或「项目概览」，
右边那一栏还在。Codex 就是这样，而且「一边看设置一边看图」是成立的动线。

### 进度与取消

**两者都要，而且这里有个实现事实**：现在用的 SFTP `readFile` / `writeFile`
**没有进度回调**。

**用流，不用 `fastGet` / `fastPut`**（2026-08-17 开工时改的判断）。
`fastGet` 确实带 `step` 进度，但它是回调式的，**没有中止口——取消不掉**。
而一颗按不动的「取消」比没有这颗按钮更糟。
`createReadStream` / `createWriteStream` 两样都有：进度从 `data` 的字节数算，
取消靠 `destroy()`。

代价说清楚：**流是顺序传输**，`fastGet` 用并发块，在高延迟链路上更快。
我们拿速度换可取消——因为作者明确要取消。

所以 `RemoteExecutor` 上**新增 `download` / `upload`**，不是改现有的——
小文件预览继续走 `readFile`。

**「半截文件必须消失」这条保证放在 `download` / `upload` 自己身上**，
不放在调用方：它们是唯一知道「传完没有」的那一层。
落到 `<目标>.dawn-part`，传完才 `rename` 过去；出错或取消就把 part 删掉。
放在调用方的话，每多一个调用方就多一次忘记的机会。**两头对称**——
上传取消同样不该在服务器上留半个文件。

**进度条画在那个文件底下**（Q4，作者定）：*「当前文件下面有一个传输条，
包含传输进度和传输速度。」* 速度由 `step` 回调的字节增量算。

> **一处残留风险，记下来别忘**：进度条贴着文件，那么切到「审阅」房客之后
> 它就看不见了——而「看不见的能力等于不存在」这个项目栽过两次。
> 拟补一个**不占地方**的补丁：坞的「文件」标签上带一个小计数（正在传 2 个）。
> 它不是第二条进度条，只是一条「这边还有事在发生」的线索。**作者可否决。**

### 取消之后那半个文件必须消失

**下载先落到临时文件，传完才改名到最终位置**（同一目录内改名是原子的）。

不这么做的话，取消或断线会在下载目录里留下一个半截文件——
**而它跟完整的那个长得一模一样**。哪天拿它去跑分析都不会发现。

### 同名冲突：三选一，且**没有两个是同义词**

| 选项 | 行为 |
|---|---|
| **覆盖** | 写掉旧的 |
| **另存一份** | 自动改名成 `fig1 (1).png`，两个都留着 |
| **取消** | 什么都不做 |

> 作者原话是「覆盖 / 替换 / 取消」。**「覆盖」与「替换」是同一个意思**，
> 摆在一起人会愣住想「这俩有啥区别」。设计契约里那条
> 「没有一个按钮文案是另一个的子串」就是为这类事立的
> （2026-08-12 一天被同名文案咬了三次）。

## 五、预览：**远端预览就是一次下载**

SFTP 得把字节拉过来才画得出图。所以远端预览与正经下载**共用同一套进度与取消**。

由此多一条：**超过某个大小先问一句**——
「这个文件 820 MB，要传过来看吗？」，而不是默默拉半天。
（本地预览的上界照旧走 `files/access.ts` 那一份，不另开一套。）

## 六、删除：**文件和目录都能删**

### 先说清楚：这推翻了一条写下来的决定

`files/access.ts` 的文件头写着：

> **写、删、改名一概不做。** 这一阶段只读——写操作要走授权门（阶段 ④），
> 混进来会让一个「看看结果」的功能变成一把刀。

作者 2026-08-17 明确推翻：*「Q1 推翻那条「只读」的决定，可以删除文件。」*

**理由（也是它为什么不算破坏那条纪律）**：那条禁令针对的是
**agent 通过工具去写**——所以它说「要走授权门」，而授权门管的是 agent。
这次是**人自己点删除**。人对自己的数据负责，不需要一道给 agent 设的门。

**但 `files/access.ts` 那个文件头必须同步改掉**：留着一句已经不成立的禁令，
下一个读它的人（包括几个月后的我）会照着它做判断。

作者：*「本身删除动作也需要谨慎，这个是理所应当的。自己要为自己的数据负责。」*

### 本地删和远端删不是同一个操作

| | 按钮文案 | 确认框里说什么 |
|---|---|---|
| **本地** | **移到废纸篓** | 「可以从废纸篓找回来。」 |
| **远端** | **永久删除** | 「gs191 上没有废纸篓，删了找不回来。」 |

本地走 Electron 的 `shell.trashItem`（**可恢复**），远端只有 SFTP `unlink`（**没了就是没了**）。
同一颗按钮、同一个「删除」二字，一边可恢复一边不可恢复——
这次的代价是数据，所以**文案必须不同**。

`shell.trashItem` 跟现成的 `openPath` 走**同一条注入缝**（`main.ts` 传给 `wiring`），
不用新开一层。

### 本地锁在工作区内，远端不锁（Q5）

作者：*「本地依旧锁在工作区，这个是不能变的。」*

**这个不对称是有意的，而且要在界面上说得出口**——不然人会觉得
「凭什么服务器能跳，本地不能跳」：

- **本地**守的不是你，是**渲染进程**：一旦开了读文件的口子，
  渲染进程就能问后端要任意路径（`files/access.ts` 那个文件的全部重量在这儿）。
- **远端**你就是那个账号本人，SFTP 已经能碰它能碰的一切，
  再画一条我们自己的线是演戏。

路径框在本地跳出工作区时**响亮拒绝**，不静默地跳回去。

### 不设「树根以下」的限制

设计过程中我提过这条限制，**当场收回了**：它与本设计另一条
「远端不糊假边界」自相矛盾。你就是那个账号本人，SFTP 已经能碰它能碰的一切，
再画一条我们自己的线是演戏。

**改成给信息，而不是给禁止。** 确认框把你需要为之负责的事实摆全：

- 哪台机器
- **完整绝对路径**（不是相对的 `out/`——那句话在两台机器上可以指两个地方）
- 目录的话：**多少个文件、多大**

### 数不完就如实说

远端遍历可能很慢。**给遍历一个上界与超时**，没数完就说
「**至少** 5,000 个文件（还没数完）」——**编一个数字比不给数字更坏**。

### 正在预览的文件被删掉

预览要**清空并说一句**。留着一张已经不存在的图，是这个项目最不能忍的
那种「看起来一切正常」。

## 七、账本：**改变世界的操作要记一条 Run**

DAWN 的立身之本是不变式 5——这个结果是怎么来的，账本上要查得到。

| 操作 | 记不记 | 为什么 |
|---|---|---|
| **上传** | ✅ `file_upload` | 它是对那台机器的一次写入，与 agent 改一个文件没有性质区别。不记的话账本上有个洞：**数据是什么时候、从哪儿进去的，只有你自己记得** |
| **删除** | ✅ `file_delete` | 同上，而且不可逆 |
| **下载** | ❌ | 只读，不改变任何东西 |
| **预览** | ❌ | 同上 |

Run 上带：目标机器、绝对路径、字节数、成败。**失败也记**——
「它试过往一个只读目录传东西」本身就是事实。

## 八、失败必须出声（规格 7.5）

这一片上容易静默的地方，逐条点名：

| 情形 | 必须说什么 |
|---|---|
| 目标目录没有写权限 | 「**权限不够**」，不是笼统的「上传失败」 |
| 连接断了 | 说清是连接断了，并且**半截文件已经清掉** |
| 远端目录读不了 | 说清是哪个路径、什么错 |
| 遍历没数完 | 「至少 N 个（还没数完）」 |
| 文件太大 | 先问，不默默拉 |
| 预览的文件被删了 | 清空预览并说一句 |

## 九、协议与分层

| 层 | 改动 |
|---|---|
| `src/remote/ssh.ts` | 新增 `download` / `upload`（**流式**，带进度与取消、part 文件原子落位）、`unlink` / `rmdir`、`stat`、`rename`；**并修掉 `readdir` 那处 `isDirectory()`** |
| `src/remote/fake-ssh.ts` | **同一次改动里补齐**（准入规则 1）：`isDirectory()`、`createReadStream` / `createWriteStream`（要能分块报进度、要能被打断）、`rename`、`unlink` / `rmdir`、`stat`、只读目录（验「权限不够」那条）、以及**目录与文件的区分**——现在的假 SFTP 只有一张扁平的 `路径 → 内容` 表 |

## 十二·五、真机走了一遍（批 6，2026-08-18）

在 `ug2478@gs191.genek.cn` 上跑完整条路（应用由人正常启动并连接，
探针从 `--remote-debugging-port` 接管驱动界面）。

**结论：远端这一片在真机上是通的。** 逐项：

| 事 | 真机 |
|---|---|
| 连接 → 开一段远端会话 | 1.3 秒 |
| 家目录列目录 | **16 项，20 ms**（点文件、`.bashrc`、`workspace`…） |
| 面板顶上写的机器名 | ✅ 是那台 |
| 上传（55 字节） | 3.6 秒，落到 `/home/ug2478/…` |
| **撞名** | ✅ **真的问了三选一**；选「另存一份」得到 `… (1).txt` |
| 下载回本机 | 1.8 秒，**字节一字不差** |
| 删除 | ✅ 两个都删干净，服务器上不留残迹 |

### 真机露出来的那一处

**上传按下之后、服务器答复之前，传输条上挂着的是上一次的结果。**
假 SFTP 上这个窗口只有几毫秒，真机上是**一到三秒**——屏幕上就是
「我明明在传新的，它却说上一个传好了」。修法：按下就把条子清空；
撞名要问的时候把条子撤掉（还没开始传，留一根转着的条是假象）。

### 更值得记的是：**我自己的探针错了两次，而且都是「假的坏消息」**

第一版报了两条骇人的结论，**两条都是测量错**：

1. **「撞名没问——默默覆盖了」**。用的是 `isVisible()`，**它不等待**，
   立刻返回；对话框晚半秒出现就被判成「没问」。真跑起来它问得好好的。
2. **「家目录只列到 1 项」**。那 1 项是树根那一行本身，子项一个都没等；
   而那个「3 ms」量的是根行出现的时间，不是 `readdir`。等对之后是 16 项 / 20 ms。

**一个会误报的探针，和一个会漏报的判据一样坏**——前者让人去修没坏的东西。
这两条都当场重验过才写进这里。

- **行号只给一列**，不给「旧 ｜ 新」两列——两列 4ch 光行号就吃掉近 60px。

- **不做「左列文件 / 右侧 diff」的分栏**：380px 的默认宽度下分栏之后两边都不能看。

  Codex 那一屏的要害是**换文件不离开这一屏**，而那个性质这样也拿得到。

## 十三、风险

1. **远端目录很大时的第一次 `readdir`**。几万个条目的目录会让面板卡住。
   要有上界与「省略了多少」的说明（不静默截断）。
2. **传输中连接断了**。半截文件的清理必须在断线路径上也走到，
   不能只在「用户点取消」那条路上。
3. **搬家的回归面**。文件面板从全屏视图变成坞里的一格，
   视觉基线会动——**红了先看 diff 图**，别条件反射重存。
4. **假 SSH 服务器覆盖不到的东西**。`fake-ssh.ts` 是我们自己写的，
   它的 SFTP 行为与真 OpenSSH 不完全一样。**至少要拿一台真机走一遍**
   （ACP 那一轮的教训：从没跑过真适配器时，纸上的形状全是假设。
   而那一轮真适配器一接就露了三个纸上验不出来的问题）。
5. **这一层的代码量被低估的风险**。开工前我说过「传输基本是现成的」，
   量完发现那三个方法从没跑过、且与假 SSH 对不上。
   **写下来的代码不等于跑过的代码**——这条在本项目已经是第三次了
   （419 个测试全绿却点不动、1647 个测试全绿而菜单没有底板）。
