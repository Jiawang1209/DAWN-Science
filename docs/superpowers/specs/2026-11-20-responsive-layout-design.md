# 窗口响应式布局

用户于 2026-11-20 确认本轮只调整窗口变化时侧栏、正文和工作面板的比例。字体、按钮、间距和演示模式不在范围内。

## 行为

- 默认以 1440px 窗口为参照：侧栏 300px，工作面板 480px；随可用窗口宽度按比例变化。
- 侧栏保持 300–420px，保护完整品牌和导航；窄窗时进一步限制侧栏上限，给正文和面板留出空间。工作面板在宽窗口可超过原来的 720px：1440px 以上窗口的量程上限为半窗，最多 1440px；较窄窗口保留原 720px 量程，但始终受实际可用空间约束。常规正文保留至少 420px；窄窗口时正文与面板共同收窄，均保留至少 280px（900px 默认布局为侧栏 300、正文 296、面板 280，加 24px 网格间隔与内距）。
- 不采用整页缩放。正文使用余下空间，保留现有文本行长规则；文件预览随实际面板宽度切换单栏/两栏。
- 手动拖动后记住占窗口的比例；拉窄、再拉宽时恢复原比例，窗口变化本身不改写偏好。折叠侧栏时释放的空间归正文。
- 文件单双栏只按真实可用宽度决定；“加宽/收窄”独立于单双栏判断。恢复默认保存精确的 1/3 比例，避免像素取整后在另一窗口出现 1px 漂移。
- 旧像素偏好作为 1440px 参照宽度读取；首次手动调宽后保存独立的 global 比例偏好，不覆盖旧配置。设置栏与工作面板共用一套宽度规则。
- 按真实窗口 CSS 像素宽度计算，不按显示器物理分辨率放大控件。保留现有最小桌面窗口和移动断点，本轮验收桌面宽度 900–3840px。

## 实现与验收

在 `src/ui/workbench-layout.ts` 集中计算布局及保存比例，App 仅传入实际宽度；复用既有 SideSash，传入当前可用上下界。没有新运行依赖、主进程 API 或数据库迁移。

先用真实 Electron 复现默认侧栏/面板不随窗口增长，再验证多尺寸往返、边界无溢出、文字及按钮尺寸不变、手动拖动与重载保持比例、侧栏折叠及设置栏。单元测试覆盖非法存储、旧偏好、宽度预算和比例不被临时夹限破坏。
