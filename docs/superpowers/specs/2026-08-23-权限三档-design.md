# 权限三档（permission-ask）· 设计定案

> 2026-08-23。学自 `NanmiCoder/dsh-auto-mode`（MIT），解读在 `ccb_hive_code_learn/dsh-auto-mode-解读.md`。
> 分支 `permission-ask`。作者看完对照说「按照他的来」。

## 它补的是什么

2026-08-13 的门只有两档（全放行 / 拦下），而且：① 没有「问一句」——当年缺一条主进程到界面再回来的往返；② 没有硬拒清单——
`rm -rf ~`、`sudo` 在全放行档一个字不拦；③ 不分「删自己刚生成的」和「删之前就有的」——科研里最常见的清中间文件每次被拦。

## 形状（照 dsh-auto-mode 的 allow / ask / deny，坐在我们自己的门上）

| 层 | 东西 | 在哪 |
|---|---|---|
| 判据 | `看风险()` 仍是纯函数；多一类 `硬拒`、多一个 `不可问` 标志、语境多 `本会话创建()` | `src/policy/permissions.ts` |
| 决定 | `照这一档()` 回三态 `{allow} / {deny, reason} / {ask, reason, 类别}`；硬拒任何档都拒；全放行只拦硬拒；拦下直接拒；问一句交给人，但「目标看不清」的删除连问都不问 | 同上 |
| 硬拒 | sudo/su/doas；`git push --force`；curl/wget/scp 带私钥 / token 形状；mkfs / dd 到设备 / shutdown；rm / write 的目标是根、系统目录、主目录顶层、`~/.ssh` `~/.aws` `~/.gnupg` `~/.kube` | `硬拒理由()`、`受保护路径理由()` |
| 删除目标 | 一条命令里**一个可见的字面目标**才看得清；glob / 变量 / 命令替换 / 管道 / xargs / find -delete / 多目标 / 多条 → 「看不清」，拒并要求改写 | `删除目标()` |
| 本会话产物 | 包装器在 `write` / `edit` / bash 重定向成功后登记**此前不存在**的文件（设备号 + inode + 出生时间 + 类型）；删它们不算删除；改名 / 替换后身份不对就失效 | `src/policy/artifacts.ts` |
| 问一句 | 包装器拿到 `ask` → 发 `permission_request`（**与 ACP 权限卡同一形状**：`allow_once` / `reject`）→ 界面那张卡 → `answerPermission` → 运行时 `待答` 表；5 分钟没答 = 拒；会话中止 = 拒；答完发 `permission_settled` 让卡消失 | `runtime/native.ts` 的 `问权限()`、`workbench/events.ts` |
| MCP | 没过目的 MCP 工具在问一句档也问（同一张卡） | `tools/mcp-tool.ts` |
| 指引 | 系统提示里一段「动文件的规矩」：删除优先可逆、一次一个可见目标、被拒就换路 | `runtime/native.ts` `删除指引` |
| 界面 | **唯一入口是输入卡附栏右侧那颗「权限」**（`PermissionPill`，上拉菜单、与「优化输入」同一副样子）：会话里改的是这一段（会话开关 `dawn.permission`），空态屏改的是默认；三档**由低到高**排、各带图标、名字照作者的截图（「自动拦截 / 请求批准 / 完全访问权限」——截图中间那档叫「帮我批准」，我们那一档是拒不是批，故不叫它）；菜单底下一行「也作为以后新会话的默认」；最底下灰字说边界。设置里的「工具权限」一格删了（作者 2026-08-23 定的：*「放入到对话框里面…替换掉设置里面的工具权限」*） | `ui/permission-pill.tsx`、`native.ts` 的 config options |

## 定案

1. **授权只来自那张卡上的点头**。模型的理由、仓库文本、工具输出都不是授权（照它的「only direct-human messages are authority」）。
2. **拒绝与超时都把理由回给模型**并说清是人拒的还是没人答——模型据此换路，不原地重试。
3. **硬拒不可被任何后手覆盖**：它在 `看风险` 最前面，`照这一档` 第一句就处理。
4. 定时任务仍只在「全放行 / 拦下」里选——没人在旁边答卡。
5. **仍然不是沙箱**，菜单底下那行灰字继续如实写；沙箱要自己上 seatbelt / landlock，另开一项。
6. **不借**：分类器模型（第二档）、一次性精确越权、Windows 那套。

## 验证
- `tests/policy/permissions.test.ts` 62 条：三态、硬拒清单逐条、删除目标看得清 / 看不清、本会话产物。
- `tests/electron/wiring.test.ts`：走 `NativeRuntime` 真实的工具包装——问一句允许真写进去、拒绝不写且理由到模型、硬拒不弹卡、删自己写的不拦 / 删之前就有的拦。
- `e2e/permission.spec.ts`：输入卡那颗三档、默认全放行、空态改默认新会话跟着走、设置里没有那一格；假模型 `rm` 一个旧文件 → 卡 → 允许真删、拒绝没删；sudo 全放行也拒。
