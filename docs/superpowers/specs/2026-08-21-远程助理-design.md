# 远程助理：人不在电脑前，也能跟 DAWN 说话

> 侧栏一项「远程助理」，放在「远端服务器」正下面。微信通讯录里多一个联系人
> **DAWN-Science**——对它说话就是对工作台说话；任务跑完、出错、要你点头，它来报。
> 第一期只做微信；飞书留着同一个接口。

作者的原话（2026-08-21）：

> *「微信这边，其实不就是接入的微信龙虾吗？」*
> *「侧边栏叫远程助理，然后联系人叫做 DAWN-Science 吧。」*

---

## 一、量出来的事实（2026-08-21，读的是腾讯官方插件源码，不是猜的）

读的是 npm 上 `@tencent-weixin/openclaw-weixin@2.4.6`（MIT，作者 Tencent）。它是微信
「ClawBot」那一头的官方客户端，TypeScript 源码随包发布。完整报告在 scratchpad，
这里只留决定设计的那几条：

1. **纯 HTTPS JSON，没有 SDK 可依赖、也不需要。** 基址 `https://ilinkai.weixin.qq.com`，
   路径 `ilink/bot/*`。头：`Authorization: Bearer <token>`、`AuthorizationType: ilink_bot_token`、
   `iLink-App-Id`、`iLink-App-ClientVersion`、每次随机的 `X-WECHAT-UIN`。
2. **收消息是长轮询**：`POST ilink/bot/getupdates`，35 s（服务端可改），带一个不透明游标
   `get_updates_buf`，**要持久化**，重启接着上次的游标。连败 3 次退避 30 s。
3. **绑定是扫码**：`POST get_bot_qrcode?bot_type=3` → 回一个 URL（自己渲染成二维码）→
   每秒 `GET get_qrcode_status?qrcode=…` → 八态状态机（等待 / 已扫 / 要配对码 / 过期 /
   重定向 / 已绑定 / 确认）→ 确认时回 `bot_token` + `ilink_bot_id` + `ilink_user_id` + `baseurl`。
   **token 不过期、没有刷新**；服务端回 `errcode -14` 即失效（多半是在别处重新扫了码）。
4. **每条收到的消息带 `context_token`，回复时原样带回**——这是路由的全部。按
   「账号 : 用户」缓存并落盘。
5. **能发**：文字（一条 ≤ 4000 字；**没有 markdown**，图片链接会被剥掉）、图片 / 文件 /
   视频（客户端生成 AES-128 key，ECB/PKCS7 加密后 POST 到 CDN，取响应头 `x-encrypted-param`）、
   「正在输入」（要先 `getconfig` 拿 `typing_ticket`）、**工具调用进度条目**
   （`TOOL_CALL_START / TOOL_CALL_RESULT`，微信客户端会画成进度）。
6. **能收**：文字、图片、语音（**服务端已转好文字**，`voice_item.text`）、文件、视频、引用。
   **只能私聊，不能进群。**
7. **谁能跟它说话**：插件默认只认扫码那个人（`allowFrom`），空名单等于放行所有人——
   我们不继承这条缺省。
8. **依赖**：协议核心只用 Node 的 `crypto` 与 `fetch`。语音转码的 wasm 不要（语音自带转写）。
   二维码在桌面端用任意小库或直接给链接。
9. **许可**：插件 MIT，README 明确写着「二次开发者若需对接自有后端，需实现以下接口」。
   灰色地带：`ilinkai` **服务本身**的条款不在包里。

README 与代码有八处不一致（路径前缀、CDN 用 POST 不是 PUT、`aes_key` 两种编码…），
**以代码为准**，细节在报告里。

## 二、定案

### 坐哪一层（规格 §4：依赖决策必须写明）

- **自己实现协议，不经过 OpenClaw、不引插件包。** 插件里可复用的只有协议知识；
  它的其余部分是 OpenClaw 的插件骨架（`openclaw/plugin-sdk`），我们没有那个宿主。
  放弃「跑一个 OpenClaw 当中继」：多一个进程、多一份配置、多一层会话语义要对齐，
  而协议本身只有五个接口。
- **新目录 `src/channels/weixin/`**，住在主进程（workbench）那一侧——它本来就握着
  `SessionManager` 与 `EventHub`。三个文件：
  - `ilink.ts`：协议客户端（头、长轮询、扫码状态机、发消息、CDN 加解密）。**纯函数 + fetch 注入**，
    单测用假 fetch 走完整个状态机。
  - `channel.ts`：把微信消息接到会话、把会话事件接到微信（下面「语义」一节）。
  - `store.ts`：绑定账号、游标、`context_token`、允许名单的落盘。
- **凭证进钥匙串**：`bot_token` 经 `src/electron/credentials.ts`（`safeStorage`），与 SSH 口令
  同一条路。**不学插件写 json**。`ilink_bot_id` / `ilink_user_id` / `baseurl` / 游标这些不是秘密，
  进 SQLite 新表 `remote_channels`。
- **接缝是 `EventHub.onUpdate`**（`src/workbench/events.ts`）：它是全局推送出口，
  `electron/main.ts` 已经用它把事件送到渲染进程；微信通道是第二个订阅者。
  不改运行时、不改会话管理器。

### 语义：微信里说的话落到哪段会话

- **扫码那个人默认绑一段专属会话**「微信 · DAWN-Science」（普通任务，临时会话，
  agent 取配置里第一个 native），在侧栏「会话」里正常出现——**微信里聊的，电脑上全看得见**，
  反过来也是。
- 斜杠命令（客户端解析，不进模型）：
  - `/会话` 列出最近 10 段（序号 + 标题 + 多久之前）
  - `/用 3` 把这个微信用户接到第 3 段；之后的话都进那段
  - `/新建` 另起一段专属会话；`/新建 @实验室` 在那台服务器上开一段（作者问的：
    *「通过微信远程使用的时候，还可以访问到远程的服务器吗？」*——能，会话在哪儿干活是
    会话自己的属性，微信只是换了一张嘴）
  - `/停` 中止当前会话这一轮（`abortSession`）
  - `/在哪` 回当前绑着哪段、在哪台机器的哪个目录
  - 别的 `/…` 原样进模型（与插件同一口径）
- **回复怎么送**：会话的 `output` 流攒成段（沿用插件的口径：≥ 200 字或静默 3 s 就发一段；
  一条 ≤ 4000 字，超了切段）；markdown 用我们自己的过滤（代码块留着、图片链接剥掉、
  表格留着）；`tool_start` / `tool_end` 映成工具调用进度条目，微信客户端画进度；
  `idle` 时停掉「正在输入」。
- **图片**：模型那边产出的图（`tool_files` 里的 png/jpg，或回答里引用的本地图片路径）
  走 CDN 上传发过去；微信发来的图片下载解密后，**与上传文件同一条路**写进会话的
  `writeToSession({images})`（协议 4.13 已经支持带图）。

### 通知：三种时刻，主动推

订阅 `EventHub.onUpdate`，对**每一段**会话（不只微信绑的那段）：

| 事件 | 推什么 | 默认 |
|---|---|---|
| `idle` 且这一轮 > 60 s | 「『<标题>』跑完了（用时 3 分 12 秒）。回 `/用 N` 可接着聊。」 | 开 |
| `error` | 「『<标题>』出错了：<一句话>」 | 开 |
| `permission_request` | 「『<标题>』想 <title>。回 **同意** 或 **拒绝**。」 | 开 |

- 权限卡在微信里回「同意」/「拒绝」→ `answerPermission`。**只对 ACP 会话**：native 的权限门
  是按档放行 / 拒绝，没有「问一句」这一档（`policy/permissions.ts` 头上写着留待询问那条路通了再加）。
  文案里说清这一点。
- 60 s 门槛是为了不让一问一答的短回合也推一条；可在界面上调。
- **在电脑前时不推**：窗口聚焦且那段会话正开着 → 不推。判据取 `BrowserWindow.isFocused()`。

### 谁能说话（安全）

- **只认扫码那个人**（`ilink_user_id`）。别的微信用户发来的话**一律不回、记一条账**
  （不变式 5：事实要留痕）。不继承插件「空名单放行所有人」的缺省。
- 微信里过来的每一句都按 `as: "user"` 写进会话，账本里标来源 `via: "weixin"`——
  事后能分清哪句是手机上说的。
- token 失效（`-14`）：停轮询、界面上那张卡变红「绑定失效，重新扫码」、**推不出去的通知
  在界面上排队显示**，不静默丢（规格 7.5）。

### 那一屏

侧栏「远端服务器」正下方一项「远程助理」（图标：手机轮廓）。点开主区：

```
远程助理
人不在电脑前，也能跟 DAWN 说话。微信里那个联系人就是 DAWN 本人。

┌ 微信 ───────────────────────────────────────┐
│ [二维码]  用微信扫一扫 → 联系人「DAWN-Science」│
│ （绑定后这里换成：已绑定 · 刘越 · 2026-08-21  │
│   [解绑]   绑定的会话：「微信 · DAWN-Science」）│
└─────────────────────────────────────────────┘
┌ 飞书 ───────────────────────────────────────┐
│ 还没接。                                     │
└─────────────────────────────────────────────┘

通知
[✓] 任务跑完（超过 60 秒的）
[✓] 出错
[✓] 等我点头——回「同意」或「拒绝」即可放行（只对 ACP 会话）
[✓] 我正盯着这段会话时不推
```

- 扫码过程中的八态要**逐态出声**：「已扫，等手机确认」「手机上显示了配对码，填到这里：[____]」
  「二维码过期了，已换一张」。一个转圈什么都不说的二维码，和一个坏掉的二维码分不开。
- 联系人名字「DAWN-Science」是微信那头定的（扫码绑定时由服务端给），我们这边只展示。
  如果协议允许改名，放进这张卡；不允许就不画那个入口。

## 三、协议与 mock（准入规则 ①）

新操作（协议 7.14）：`weixinGetStatus` / `weixinStartLogin` / `weixinPollLogin`（带可选 `verifyCode`）/
`weixinUnbind` / `weixinSetNotify` / `weixinBindSession`。推送：`SessionUpdate` 新增
`{ kind: "weixin", state: … }` 让那张卡跟着变。

**假微信**：`scripts/fake-ilink-server.mjs`，与 `mock-inference-server` 同一个启动方式、
`dev:mock` 与 e2e 共用。它要会：出二维码 URL、按剧本走状态机（含「要配对码」那一支）、
长轮询吐消息、收 `sendmessage`、收 CDN 上传并校验能解密、回 `-14` 演失效。

e2e 至少四条：① 扫码绑定到卡变绿；② 假微信发一句话 → 会话里出现、回复回到假微信；
③ 假 ACP 问权限 → 假微信收到「同意/拒绝」提示 → 回「同意」→ 工具跑了；
④ token 失效 → 卡变红、通知排队在界面上可见。

## 四、分期

- **T1**：`ilink.ts` 协议客户端 + 单测（假 fetch 走完状态机、加解密往返）；假微信服务器。
- **T2**：绑定那一屏 + 钥匙串 + 专属会话 + 文字往返 + 斜杠命令。
- **T3**：通知三件 + 微信里回「同意」。
- **T4**：图片双向、工具进度条目、「正在输入」。
- 飞书：接口一样（`channels/feishu/`），等微信这条跑顺了再开。

## 五、不做的

- 不进群（协议不支持）。
- 不做「手机上新建任务并选目录」——微信里只有文字，选目录那一步在电脑上做；`/新建` 只开临时会话。
- 不自动重新扫码：token 失效是人在别处绑了，得让人知道。
- 不把 markdown 渲染成图片发过去（插件也不做；4000 字纯文本够用）。
