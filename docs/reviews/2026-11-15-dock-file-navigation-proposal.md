# 坞文件导航调研与方案建议

日期：2026-11-15
分支：`codex/dock-file-navigation`
状态：已按用户确认的交互原型实现；完成本地类型、构建、组件/后端与 Electron 验证。

## 用户范围

同时支持项目内逐级返回，以及从项目根目录继续向外浏览其他文件夹。

## 当前实现的限制

- `src/ui/files.tsx`：`根` 是当前树的起点，但位置说明取自 `初始根`；跳转后显示的位置不跟随变化。
- 路径输入框保留的是用户输入的跳转文本。目录搜索结果也能改变树根，但不会同步该文本。
- 跳转后只有“回到根目录”，缺少上一级、可点击路径层级和浏览历史。
- 点击树中目录只展开或收起，不改变浏览位置。展开状态与当前浏览目录需要分别建模。
- 当前目录保存在 `FilesView` 内。`App.tsx` 为宽窄布局使用不同 key，重新挂载时会回到初始位置。
- `files-memory.ts` 只保存展开目录与选中文件，没有保存当前浏览目录。
- 本地 `listDirectory`、`readFile`、`openExternally` 按项目或会话定位，并使用项目内相对路径。`resolveInWorkspace` 会拒绝绝对路径和越界路径。
- 搜索、删除、引用以及 Markdown 相对资源也依赖现有路径语义，不能把项目外绝对路径直接塞进原有回调。
- 远端列目录与读文件已支持服务器路径，向上浏览主要需要补齐导航交互和根路径处理。

以上为本地源码检查结果；未通过桌面交互复现所有状态组合。

## 方案比较

1. 只补“上一级”：实现量小，不能解决当前位置显示和项目外预览的完整链路。
2. 独立的文件浏览位置与完整导航：推荐。项目内外使用同一套交互，浏览位置独立于会话工作目录。
3. 浏览到哪个目录就切换项目或会话工作目录：不推荐。普通浏览会改变后续分析任务的执行位置，并可能产生额外项目记录。

## 推荐的用户交互

- 工具栏提供后退、前进、上一级、刷新和“回到项目”。上一级到文件系统根为止；远端在当前服务器内导航。
- 路径以可点击的层级显示，点击任意祖先目录即可跳转；点击地址栏空白或编辑入口后可以输入路径，Enter 跳转，Esc 恢复当前路径。
- 本机地址栏支持绝对路径，项目内相对路径以当前项目或会话工作目录为基准。当前位置以绝对路径展示，避免相对路径含义随导航变化。
- 地址栏右侧常驻“复制路径”按钮，一键复制当前目录的完整绝对路径。复制成功短暂显示“已复制”及勾选图标；失败时明确提示，并展开选中完整路径供手动复制。复制对象始终是当前已进入的目录，不是尚未提交的地址输入内容。
- 目录树保留单击展开或收起的行为，通过明确的“在此处浏览”操作改变浏览位置。这样现有树操作仍可使用。
- 文件预览提供“打开所在目录”，项目外图片、PDF、表格、脚本和 Markdown 尽量复用现有预览组件；Markdown 的相对图片和文件链接通过同一个浏览来源解析。
- 显示当前机器和当前位置；项目目录作为固定快捷入口。切换浏览目录不改变会话工作目录，也不自动建立项目。
- 窄坞优先保留导航按钮和路径入口，长路径折叠中间层级，完整地址仍可编辑和复制。
- 导航成功后再更新当前位置和历史；失败时保留原目录，显示目标路径与错误。快速连续跳转时，只接受最新导航请求的结果。
- 返回上级后高亮刚离开的子目录，并尽量恢复该位置的滚动状态。

## 建议的实现边界

### 导航状态

将当前位置、历史记录和地址栏编辑状态与目录展开状态分开。位置至少包含本机或远端身份、服务器连接标识以及绝对目录路径；不要仅用一个字符串表达不同机器上的文件。

持久保存当前位置和展开目录；历史记录可仅保留在本次应用运行期间。状态由文件面板拥有者持有，使宽窄布局重挂载后仍能恢复。切换项目、会话所属工作目录或服务器时，按完整来源身份隔离。旧记忆缺少当前位置时回到原始工作目录。

### 浏览数据来源

为文件面板增加专用的浏览适配层，提供列目录、读预览、搜索、系统打开和路径规范化。后端返回规范化后的当前路径、父目录和文件条目标识；界面不自行推测 Windows 盘符、UNC 根或远端根的父路径。

本地增加面向桌面文件浏览的接口，以绝对路径寻址；通过现有客户端/后端边界提供。原有工作区接口继续用于会话产物和工作区引用，保持原有语义。本机文件浏览能力的装配位置需在实现计划中明确，避免把浏览器中的“本机”误解释成其他服务主机。

远端适配现有 SFTP 列目录、读文件与搜索能力，明确连接身份。统一界面不意味着将远端路径交给本地系统打开接口。

预览组件继续复用文件内容类型和渲染能力。文件选择与预览读取携带浏览来源，不与会话产物的选中状态混用。

### 操作范围

第一版完成导航、搜索、预览、复制绝对路径及本机系统打开。项目外浏览不自动扩展删除、上传或工作区相对路径引用：现有这些操作只在其来源和目标仍符合原有接口语义时提供。

如果用户以后要把外部文件交给当前会话处理，沿用显式的附件或导入动作；普通预览不生成工作区引用。

## 实现验收建议

- 从项目内多层目录逐级返回，再从项目根返回父目录、进入兄弟目录并预览文件；随后一键回到项目。
- 后退/前进、地址输入、路径层级点击和“打开所在目录”使用一致的导航状态。
- 目录展开与当前位置互不替代；新浏览目录默认展开并确实加载。
- 项目外图片、PDF、表格、脚本和 Markdown 相对资源可预览；系统打开使用同一个文件来源。
- 加宽、收窄以及切换面板后当前位置保留；不同项目、会话工作目录和服务器之间不串位置。
- 跳转不存在目录、无权限目录、连续快速跳转、目录被移除时，原内容与错误提示保持一致。
- 覆盖 POSIX `/`、Windows 盘符根与 UNC 根、中文和空格路径、符号链接及远端 `/`。
- 浏览父目录或兄弟目录后，当前会话工作目录、产物读取和已有工作区路径守卫仍按原语义工作。

## 实现与验收记录

实现沿用本提案的第 2 种方案。协议版本升级至 8.54，新增 `browseDirectory`、`readBrowserFile`、`searchBrowserFiles`、`openBrowserFile`；旧的工作区相对路径接口与路径守卫保持原语义。

主要文件：

- `src/files/browser.ts`：本地浏览、普通文件检查、带字节限制的预览与有预算的搜索。
- `src/protocol/file-browser.ts`、`src/workbench/backend.ts`：明确本地/远端来源，规范化目录及父目录，沿用 SFTP 能力。
- `src/ui/state/file-navigation.ts`：验证成功后更新位置和历史，忽略旧请求，失效的已记忆目录回到项目起点。
- `src/ui/file-navigation.ts`：POSIX、Windows 盘符与 UNC 路径层级，以及 macOS 原始路径与 realpath 之间的工作区相对路径转换。
- `src/ui/file-navigation-bar.tsx`：上一级、前进/后退、可点击路径、Enter/Escape 地址输入、回到项目和一键复制完整路径。
- `src/ui/files.tsx`、`src/ui/App.tsx`：目录浏览入口、文件所在目录、项目外预览/搜索、宽窄与面板切换记忆、原项目操作接线。

旧版本地项目记忆只在原工作区身份匹配时兼容读取，不删除旧键；相对路径展开记录可正常展开和收起。切换来源时同时使旧预览请求失效，旧请求的成功或失败都不会写入新来源。

项目外浏览不提供当前项目的删除或 `@相对路径` 引用操作；远端保留已有服务器文件操作。初始化科研目录始终针对原项目；独立临时会话不显示与其工作目录无关的项目初始化入口。

验证包含：本地父目录/兄弟目录、Markdown 相对图片、真实桌面剪贴板、失败跳转保持位置、后退/前进、宽窄切换、跨面板恢复、旧记忆迁移、旧预览请求隔离、根目录文件预览、Windows/UNC 路径逻辑；已有图片/PDF/长脚本阅读、搜索预算、文件菜单和科研目录初始化回归。

远端验收使用本地 Fake SSH/SFTP 夹具，未连接实际服务器；Windows 盘符与 UNC 通过跨平台路径单元测试验证，未运行原生 Windows 桌面应用。未进行真实模型调用。
