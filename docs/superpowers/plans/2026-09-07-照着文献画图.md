# 照着文献画图 · 实施计划

**Goal:** 粘一张文献里的图，说「这种图我也想画」，agent 认出图型 → 从 MLAI-science 的 1538 个案例里
拿到「怎么画」→ 在你自己的数据上真画出来，落成产物。

**Architecture:** 这一轮**几乎不写生产代码**——四段链里三段已经通了（附件、识图、`run_code`），
缺的是**一条 MCP 接线**与**一份走法**。所以产出是：一份自带技能 + 一台 MCP 的配置与说明 + 判据。
规格：`specs/2026-09-07-照着文献画图-design.md`（定案 F1–F8）。

**Tech Stack:** 不新增任何运行时依赖。MLAI-science 那边只是被连接方（只读 MCP，stdio）。

**分支纪律：** 只在 `paper-figure` 上提交。**never checkout / switch / stash**。commit 英文，不加 Co-Authored-By，**不推**。

**验证纪律（准入规则 3）：** 技能本身测不出「好不好用」，所以判据分两层——
能被机器验的（技能被列得出来、MCP 那台连得上、工具名对得上）机器验；
**「真的能画出一张图」只有真跑一次算数**（T4，作者在旁边）。

### Task 1: 技能本身（F1–F6、F8）

- [ ] `skills/figure-like-this/SKILL.md`，按现有三份技能的骨架写
      （frontmatter：`name` / `description` / `metadata.dawn.tags`；正文：什么时候用 / 什么时候不要用 / 步骤 / 交付时说一句）。
- [ ] 里面必须有的六条（每条对应一个定案，且都写清**为什么**，不只是「要这么做」）：
  - 第一步确认 `mlai-science` 的工具在不在，**不在就停下说清楚**（F8）；
  - 描述按四行结构化写（F2），并给一个真例子；
  - 两个检索入口各自什么时候用（F1）；
  - `figure_types: []` 时**必须转述那句 notes** 并给兜底（F3）；
  - `how_to` 带 `<!-- mlai:notes=draft -->` 时**必须说明这是自动摘要**（F4）；
  - **不许 `get_asset` 拉图**（F5）；要 R 走 `search_cases(language=["r"])`（F6）。
- [ ] **判据**：`npx vitest run tests/skills/`（frontmatter 读得出、调用档默认是 model）。

### Task 2: 那台 MCP 的配置与说明（F7）

- [ ] `docs/照着文献画图-怎么装.md`：`uv sync` → `uv run mlai rebuild` → 设置 → MCP 加一台
      （给出那段 JSON/YAML 原文）→ **拨信任开关** → 点「测试」。
- [ ] 写明两个「看起来一样、其实不同」的失败：**没 rebuild**（工具回空）与
      **语料库里真没有**（回空但 `figure_types` 有值）。
- [ ] **判据**：照着这份文档在这台机器上真配一次，`testMcpServer` 通、列得出九个工具。

### Task 3: 自带技能的扫描（准入规则 2 的那一半）

- [ ] 现有 `tests/skills/` 只验解析器，没有一条盯着**随应用发布的那四份技能本身**。

      `name` 与目录名一致、正文有「什么时候不要用」这一节。
- [ ] **为什么值得**：技能是**给模型读的规格**，写坏了不会有任何报错——
