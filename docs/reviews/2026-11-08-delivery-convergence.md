## 重点核查

- 检查点只读取 TaskSubmission 的既有契约、证据及 observation；不调用 submit、不增加尝试次数、不接收路径/owner 参数。无契约旧子任务工具集保持原状。封存不重开，工具原结果与提示分离。
- 提示只标记“观察到”，不声称文件当前存在、内容正确或已验收；正证据引用沿用既有规则，重复 ID 不可引用；列表和字符串有界，压力用例低于 32KiB。
- 网关在第一个 await 前预占；并发预占、分区关闭、断连、取消排空沿用同一账本。单15、多15；规划计入共享11，审阅4不可借用；失败不自动重试。余额提示不含凭证或科学正文。
- 产物验收直接复用共享 outcome/settlement 纯选择器，绑定 owner/run epoch 或 team/task/attempt；不能从文件存在、模型文字、mtime 生成验收。阶段产物与最终成果、live 与 disk 历史明确区分。
- 主产物入口不创建伪 Run、文件观察或新产物版本。相同路径保留各版本来源；用户主动核对时复用有界 fileIdentity，核对前后再次验证来源身份；预览明确读取当前内容，不承诺原子一致快照。
- 原文件、路线、普通产物、保留/交付入口保留；任务历史读取失败不会阻断旧入口。迟到内容核对结果不会跨 owner/代次/版本复用。
- 紧凑卡片保留精确身份、状态、当前动作/阻塞、真实可见用量和详情入口。未知上下文不写0，执行完成与宿主验收分开。网络只展示真实直接委派，任务依赖另列。
- 无新调度器、恢复状态机或锁实现；原权限冻结、产物锁、取消排空和恢复由相关专项与桌面回归验证。
