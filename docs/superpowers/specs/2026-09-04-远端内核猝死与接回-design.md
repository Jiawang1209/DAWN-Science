# 远端内核：猝死察觉与断线接回

> 分支 `kernel-reattach`，从 main `ae4f8d2` 开出（远程内核 C 档已合入、作者 09-04 真机验过 Python）。
> 前一轮规格 `2026-09-03-远程内核-design.md` 的定案 3（断线 = 内核死）、定案 9（不借接回）、定案 10（猝死察觉不到）
> 由本规格改写；其余定案不动。

## 0. 作者定下的（2026-09-04）

| 问 | 定 |
|---|---|
| 这轮做什么 | 两件：①远端内核猝死（OOM、被集群杀）本地要能察觉，不是等 5 分钟；②意外掉线后重连，把还活着的远端内核接回来，变量不丢 |
| 哪种「断」接回 | **只有意外掉线**（网络断、合盖、VPN 掉）。作者自己按「断开」或关会话，照旧把服务器上的内核停干净 |
| 接回要不要问 | 不问。连上发现还活着就直接认领，转录里说一句 |
| `detached` 有没有上限 | 不设（我定的缺省，作者未反对）。DAWN 开着一直没连回去，那台内核就一直等 |
| 心跳间隔 | 10 秒（同上） |

为什么值得做：项目的意义在「活的内核」——数据读一次，之后所有追问都是增量的。集群上掉一次线就把三分钟的读取重来一遍，
「活」就打了折；被 OOM 杀了要等 5 分钟才知道，agent 那 5 分钟在等一个不存在的进程。

## 1. 今天的实际状态（动手前核的）

- 五条隧道里 `hb_port` **已经转发但本地从没打开过**（`enchannel-zmq-backend` 只开 shell / control / stdin / iopub）。
- 远端内核在本地只有内存里一条记录（`runtime/kernel.ts` 的 `Live.远端`：connectionId、label、executor、`起的{pid, 文件}`、关隧道）。
  **起完之后连接信息（端口、key）与 `setsid` 都丢了**，接回要用它。
- 远端 `KernelProcess` 只有 `pid` 与 `kill`，没有 `once("exit")`；`onExit` 远端永远不触发。本机猝死那条路（notice + `exited` exitCode 1）远端没有触发点。
- 挂载层的 5 分钟静默兜底（`挂载.ts` `武装超时`）只让在飞那段 reject，**内核状态停在 `busy`，永远不会变 `exited`**。
- 意外掉线与按「断开」本来就是两条路：前者 `ssh.ts` `c.on("close")` → `disconnected`；后者 `connections.disconnect` → `idle`，
  且 `backend.disconnectRemote` 先调 `服务器要断了`（TERM → 等 → KILL → rm）。`wiring.ts` 对两个状态都调 `连接断了` 把内核标死。
- 每次连上的 `扫残留` 杀掉**所有** `[d]awn-<装机id>-*.json`，不分「上次留下的」与「等着接回的」。远端文件名里没有对话 id。
- 假服务器（`fake-ssh-kernel.ts`）起的是真 python 子进程，`c.end()` 是唯一的断线模拟；e2e 只有按「断开」那条路。

## 2. 定案

### 猝死察觉

1. **心跳当报警，`kill -0` 当结论。** 本地在 hb 隧道上开一个 `zeromq` REQ socket（`zeromq` 6 已是依赖），
   每 10 秒发一个 ping，5 秒内没回音算一次「沉默」。沉默不是死：ipykernel 的心跳在独立线程里，忙时也答；
   **IRkernel 单线程，长计算期间不答心跳**（Jupyter 用户熟知）。所以沉默之后走 SSH `活着脚本(pid)`（已有）确认：
   `DAWNALIVE=0` 才判死；`=1` 记一句「心跳沉默但进程在」，继续等。
2. **忙时放宽。** 内核 `busy` 时心跳间隔放到 60 秒，确认最多每 60 秒一次；`idle` 时 10 秒。R 的长计算不会被 SSH 探针骚扰。
3. **链路不 ready 时不确认。** 掉线是另一条路（下面）；心跳在 `detached` 期间停。
4. **判死之后**：运行时收本地这半（关通道、关隧道），远端 `rm -f <文件> <文件>.log` 尽力而为；
   发 `exited`，`reason: "died"`。挂载层标 `exited`、在飞那段 reject；转录一句：
   「`<语言>` 内核在 `<服务器>` 上没了（可能是内存耗尽或被集群杀掉）；这一段没跑完，变量已经不在了；再跑会起新的一台」。
   账本：在飞的 `run_code` 照本机猝死的写法（工具报错、`failed`）。
5. **5 分钟静默兜底改为先确认。** 远端内核静默到点：进程死了 → 走定案 4；活着 → **不 reject**，重新武装，
   挂载层发一条 `reason: "silent"` 的状态变化（状态仍 `busy`），转录一句「`<语言>` 内核 5 分钟没有动静，进程还在，继续等；可以中断」，
   **每段执行只说一次**。本机内核这条路不动（本机有 exit 事件，静默就是卡住）。
   ——这顺手修掉「静默后永远 busy」：远端判死会变 `exited`；活着则本来就还在跑。

### 断线接回

6. **掉线 = 分离，不是死。** 连接进 `disconnected`（**不含 `idle`**）：运行时对这台服务器名下每台内核关通道、关隧道、停心跳，
   记录**留着**并从这一轮起多存 `连接信息`（远端五个端口 + key + 传输 + ip）、`setsid`、语言、cwd、解释器路径，
   再记 `分离 = { 掉线时刻, 掉线时在飞: boolean }`。发新事件 `detached`（带 reason）。
   挂载层新状态 **`detached`**，在飞那段 reject；转录一句：
   「与 `<服务器>` 断开；`<语言>` 内核可能还在服务器上活着，重新连上后会试着接回」。
   账本照旧 `远端断了`（`cancelled`），措辞改为「与服务器断开，这段的结果没收到」——它多半跑完了，只是我们不在。
7. **按「断开」照旧。** `服务器要断了` 先停远端内核再收本地，不进 `detached`。**停不掉的那台**（TERM/KILL 发出去链路已经死了）
   照旧标 `exited`（`disconnected`），留给下次扫残留——人已经说了不要，不替他留。移除服务器（`removeConnection`）同一条路。
8. **`start` 在飞时掉线**（隧道建好、握手没回）：照旧收掉，那个远端进程留给下次扫残留——半起的不接。
9. **重新连上后的顺序**：`ready` → 扫残留（**带一份「别动这几台」名单** = 这台服务器名下 `detached` 内核的文件名）→ 逐台接回 → 才放 `run_code`。
   `扫过` 门扩成「扫过且接回过」；`detached` 期间的 `run_code` 直接回错「与服务器断开，内核等着接回；连上后再试」，**不起新的**。
10. **接回 = 认领 + 重隧道 + 重握手。** 每台：`活着脚本(pid)` 且远端文件还在 → 用存下的连接信息重建五条隧道 →
    `attachKernelChannel` 走 `kernel_info` 握手（20 秒）→ 通过：同一个会话 id 恢复，状态回 `idle`，心跳重开，
    转录「重新连上 `<服务器>`，`<语言>` 内核还活着，变量都在」；`掉线时在飞` 为真再补一句
    「掉线时正在跑的那段可能已经跑完，输出没收到」。
    进程没了 / 文件没了 / 握手不通 → 尽力 `停远端内核`（TERM → KILL → rm），发 `exited`，`reason: "lost"`，
    转录「`<语言>` 内核没撑过这次断线，变量已经不在了；再跑会起新的一台」。
11. **扫残留只放过名单上的。** 脚本改成逐文件：不在名单里的，按 `basename` 拼 `pkill -9 -f "[d]awn-<装机id>-<语言>-<时间戳>.json"` 精确到那一台、再 `rm`；
    名单上的跳过、不计数。仍带方括号（前一轮定案 7 ③）。**两台电脑共用账号互不误杀**不变（装机 id 仍在文件名里）。
    没有 json 文件的孤儿进程从此不再被扫（旧脚本的全局 `pkill` 会）——ipykernel 不会自己删文件，这种孤儿只在人手删了 `$TMPDIR` 时出现，如实记。
12. **只在 DAWN 这一次运行内接回，不进库。** DAWN 关了或崩了，服务器上那台由下次连上的扫残留清掉（它不在任何名单上）。
    这与「只有意外掉线才接回」一致：关 DAWN 不是意外。规格里如实写：DAWN 开着一直没连回去，那台内核一直占着服务器内存。
13. **接回不生成新快照。** 同一个进程，S17 的快照在 `start` 那一刻冻的，照旧；接回后的 Run 仍挂原来的内核会话 id。
14. **人在 `detached` 期间按「断开」**：链路本来就没了，`服务器要断了` 停不了远端，只把本地记录清掉、状态 `exited`，
    转录「`<语言>` 内核退出了：已放弃接回；服务器上那台由下次连上时清掉」。

**账本只认「与服务器断开」这一种。** `died`（猝死）走的是本机猝死那条路：工具自己报错、那条 Run 记 `failed`，
不需要另一句话。`lost`（没撑过断线）与 `abandoned`（人放弃接回）发生时早已没有在飞的 `run_code`——
掉线那一刻 `detached` 就已经把它收口了，再记一次就是往账本里写一件没发生的事（不变式 5）。

## 3. 界面（看不见的状态等于不存在）

- 笔记本格头部胶囊多一态：胶囊本来就长成「`<语言>` · `<服务器>` · `<状态词>`」，所以 `detached` 只是多一个状态词——
  **「等接回」**（灰，不是红——它没错，只是不在），接回后自己变回「空闲」。判死 / 没撑过：照现有 `exited` 画法（「已退出」）。
  「为什么」由转录那几句说，胶囊只说「现在是什么状态」——两处各说一半，不重复。
- 变量面板：`detached` 时写「与服务器断开，等接回；变量在服务器上没动」，**不画空列表**（空会被读成「变量没了」）。
- 转录里的句子全部由 `内核变化出声` 说（前一轮教训：运行时 emit 的 `notice` 到不了普通对话的转录）。
- 心跳沉默但进程在：**不出声**（R 忙时每分钟一句会把转录刷满）；只在 5 分钟静默那条（定案 5）说一次。

## 4. 协议

`内核状态` 加 `"detached"`；`内核状态变化` 加 `reason` 的四个新值 `"silent" | "died" | "lost" | "abandoned"`，以及 `接回了?: { 服务器?: string; 掉线时在飞: boolean }`（转录要说清掉线时那段收没收到，光一个 `true` 说不出来）。
它们经事件流到界面 → 协议 minor 版本 7.31，兼容表照前一轮 7.30 的写法。**没有新的公开操作。**
多一个测试操作 `fakeSshControl{do: "dropLink" | "killKernels"}`：对这台装配上**所有**假连接掐线 / 杀掉假机器起的所有内核
（假客户端不知道自己的 connectionId，e2e 与 mock 也只有一台假机器）。**只在 `DAWN_FAKE_SSH=1` 时放行**，否则回 `invalid_request`；协议文档标「测试专用」。

| 运行时 | `src/runtime/kernel.ts` | `Live.远端` 补连接信息等；`连接断了` 改分离；新 `接回远端(connectionId)`（执行器用留下的句柄，它重连后仍指向这台机器）；心跳的确认回调（调 `活着脚本`）、判死收摊；`detached` / `reattached` 事件 |
| 脚本 | `src/remote/kernel-launch.ts` | `扫残留(exec, 装机id, 别动: string[])`；`删远端文件(exec, 文件)`；`活着脚本` 已有 |

| 装配 | `src/electron/wiring.ts` | `disconnected` 与 `idle` 分开：前者 `连接断了`（分离）、后者只清（定案 7/14）；`ready` → 扫（带名单）→ 接回 → 放行；`内核变化出声` 新句子；`内核变化记账` 认 `detached` |
| 账本 | `src/project/run-recorder.ts` | `disconnected` 措辞改 |

心跳坐在 zmq 上而不是 SSH 上：SSH 探一次要起登录 shell，集群上几百毫秒；zmq ping 是几毫秒。SSH 只用来下结论。

## 6. 失败必须出声（规格 7.5）

- 接回时隧道建不起来（`forwardOut` 被拒）：与前一轮定案 8 同一句话说清是哪一层，然后按定案 10 的失败路走（停、`lost`）。
- 判死后 `rm -f` 远端文件失败：console 一句，文件留给下次扫残留；转录那句不变。
- 心跳 socket 本身打不开（端口被占、zmq 报错）：**不算内核死**——运行时 `console.error` 一句「心跳通道没打开，猝死只能靠 5 分钟兜底」
  并发一条 `notice`（`kind: kernel` 会话看得见；普通对话那条路到不了转录，如实记），然后照前一轮定案 10 的行为运行。缺失 ≠ 死。
- 接回时握手没回音：20 秒封顶，按定案 10 的失败路走。**建隧道那一步没有单独的上限**（它落在 SSH 执行器自己的超时里）——
  如实记在这儿，真撞上「连上了但接回一直转」再补。

## 7. 怎么验（准入规则 3）

**单测**
- 心跳状态机（假时钟）：idle 10 s / busy 60 s；沉默 → 确认回调；确认活着不判死；确认死 → 判死一次且停心跳；socket 打不开 → 出声不判死。
- `扫残留` 脚本：改成逐文件杀（`basename` 精确到那一台）；名单为空时仍清所有自己装机 id 的文件与进程；名单上的文件不进 `pkill` 模式与 `rm`；假服务器真跑一遍，两个 python 子进程留一杀一。
- 运行时（假 executor + 假可转发）：分离保留记录且关隧道；接回三条路（活着且握手通 / 进程没了 / 握手超时）各自的事件与远端收摊；
  `start` 在飞时掉线仍收掉；`服务器要断了` 停不掉的照旧 `exited`（不进 `detached`）；`detached` 期间按「断开」→ `abandoned`。
- 挂载层：`detached` 期间 `执行` 回错且不起新台；静默兜底远端先确认、活着不 reject 且只出声一次；本机路径不变（拿现有用例断言）。
- 账本：`disconnected` 新措辞；`detached` 与 `exited{disconnected}` 都记一次、其余三种不记。
- 协议 7.31 兼容表。

**e2e（真内核 + 假 SSH）**
1. 掐线 → 转录「可能还活着…」、胶囊「等接回」；再连 → 「还活着，变量都在」；`run_code` 读掐线前定义的变量得 42。
2. 在 DAWN 背后杀内核 → **30 秒内**转录出「没了」那句（不是 5 分钟）；再 `run_code` 起新的一台且能算。
3. 掐线 → 杀内核 → 再连 → 「没撑过这次断线」→ 新的一台。
4. 前一轮那条「按断开 → 新的一台」保持绿（定案 7 没变）。

**人肉**：`dev:mock` 里把 Wi-Fi 关掉再开一次，看那三句话与变量面板。真集群上作者顺手验一次合盖。

## 8. 不做（YAGNI）

跨 DAWN 重启的接回（要进库、要在远端文件里记对话 id）；`detached` 上限与自动放弃；接回后补收掉线期间的输出（iopub 是 PUB/SUB，错过的没了）；
把心跳用于本机内核（有 exit 事件）；心跳沉默时出声；重连的自动重试（连接层的事，另说）。

## 9. 顺序

心跳 + 判死（不动断线那条路，可单独合）→ 脚本与运行时的分离 / 接回 → 挂载与装配 → 界面 → 假服务器开关 → e2e → 规格更正、历史。
每步可停，每步过一次 `dev:mock` 人肉看。
