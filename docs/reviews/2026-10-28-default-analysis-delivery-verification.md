# 默认分析交付规范验收

## 范围

用户批准“报告只记录脚本和调用方式，不嵌入全文”。在现有独立分支 `codex/markdown-project-delivery` 上实施，前置代码为 `096bb52d`，实现提交为 `905ed2c0`。本地 main 保持 `fa321f8c`，未合并、推送、发布或替换安装版。

## 实现

- 新交付默认生成 `分析报告.md` 和简短 README，沿用原 interpretation 角色，因此旧交付的 `结果解读.md` 仍可打开。
- 内置 `analysis-delivery` 增加完整分析报告触发及分步调用规范，保留普通探索不自动交付、用户格式优先、执行授权与独立验证边界。打包后的 `dist/skills/analysis-delivery/SKILL.md` 已核对包含新规范。
- 生成响应的可选 steps 描述脚本、argv、声明输入、选定输出与解读；旧响应仍可解析。模型不能提供“已执行”标志。模型叙述中的本地 Markdown 链接作为文字处理，程序依据真实复制清单生成链接和命令。
- `src/delivery/report.ts` 统一组装报告，不重新读取原工作区，也不插入脚本内容。采用的脚本副本位于交付 `files/` 下，建议命令明确在该目录调用，避免误指向后来变更的工作区脚本；输入、依赖、路径条件仍需准备，不承诺直接可跑。
- 只有后端冻结来源中的已完成简单直接 Python/Rscript 调用可显示为历史记录；复杂 Shell、状态不明、目标不匹配等不猜。历史命令完成不证明脚本版本，报告明确区分原工作区历史、当前副本建议与新生成的验证入口。
- 已有分步脚本不再被要求重新生成总脚本。副本在模型等待期间消失、引用未知文件、参数未记录、仅有图片等情况保留缺口。原始输入默认只引用，选择和复制文件不冒充执行或科学核验。
- 原整理/整理并验证入口保留；界面改为“阅读分析报告”，未增加选项或面板，项目文件选择和 Markdown 图片/脚本跳转沿用前一版。
