# 科研数据查询

在新建的 API 模型会话中，可直接使用「科研数据 · GEO」。设置 → 插件中可独立关闭整个插件，或分别关闭查询、保存功能。默认开启，明确关闭的旧设置保留；改动在新会话生效。ACP/外部 CLI 不因此新增工具。

## GEO

可以提问：

> 查询与 drought 相关的 Arabidopsis GEO 数据集，返回前 5 条实际记录。列出 GSE 编号、研究题名、实验类型、物种、样本量和来源，缺失信息标明未提供。

> 查看 GSE29235 的实验设计和平台，保留来源和查询时间，不要推断对照分组。

> 把刚查到的 GSE 详情保存到 outputs/datasets，生成 JSON 和 Markdown 清单。

`geo_search` 支持关键词或 Entrez 表达式，强制查询 Series（GSE），单页 1–20 条。`geo_get_series` 按 GSE 精确查询，从 GEO SOFT brief 补充实验设计；仅获取元数据，不下载 SOFT 数据表、补充文件或原始数据。样本编号和标题最多显示 40 条，来源缺失或截断会明确提示；不声称已获取全部逐样本特征。

`geo_save` 只接受同一会话实际查询返回的 recordId；最近 100 条在运行期缓存，重启后应重新查询。每次在 `outputs/datasets/records-*` 下新建 `records.json` 和 `数据清单.md`，不覆盖旧文件。产物可以在侧栏预览。记录保留数据库原始字段值、来源链接、API 请求、查询条件、时间和警告。

远端会话只查询，本地会话可保存。先出方案/讨论模式只查询；保存经过现有文件写权限门。不自动判断数据质量、实验设计合理性或分析可行性。零结果与错误分开报告。

NCBI 查询在当前应用进程共用串行队列，每 500 毫秒最多启动一次请求。单响应最多 2 MiB，每个网络请求最多 20 秒，可停止，不自动重试、翻页或跟随重定向。公共服务可限流或拒绝访问。

接口：[GEO 程序访问](https://www.ncbi.nlm.nih.gov/geo/info/geo_paccess.html)、[NCBI E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25497/)。

## NCBI SRA

「科研数据 · NCBI SRA」独立默认开启，可单独关闭。可以提问：

> 使用 SRA 检索 soil metagenome 的公开实验元数据，列出前 5 个实验的物种、平台、文库策略和测序 Run，并保留来源。

> 查询 SRR390728 所属实验，核对单/双端、文库策略和 Run 编号，不要把 Run 数量称为样本量。

> 将刚查到的 SRA 记录保存到 outputs/datasets，保留 JSON 和 Markdown 清单。

`sra_search` 支持关键词或 Entrez 查询表达式，返回 1–20 个 Experiment。`sra_get_accession` 支持 SRP/ERP/DRP 研究、SRS/ERS/DRS 样本、SRX/ERX/DRX 实验及 SRR/ERR/DRR 运行编号，并核对它们属于返回实验。研究/样本查询最多 20 个实验；每个实验最多显示 40 个 Run，截断会说明，精确查询指定的 Run 会保留。BioProject 可通过检索表达式查找，不作为本版精确编号接口。

清单区分 Experiment、数据库 Sample 和 Run。spots 保留为 spots，不擅自换算为 reads；bases 和归档体积保留数据库数值精度。缺失信息不推测，公开状态未知或受限 Run 明确标注；元数据可见不等于已有受控数据访问许可。

`sra_save` 只接受当前 SRA 会话实际返回的 recordId，不能使用 GEO 的标识。与 GEO 一样生成独立目录下的 records.json、数据清单.md，保存经过写门，远端只查、方案期不写。所有 NCBI 查询共用限流队列。首版不下载 FASTQ/SRA，不安装 Toolkit，不执行质控或分析。

官方：[SRA 检索单位、编号和检索语法](https://www.ncbi.nlm.nih.gov/sra/docs/srasearch/)。

## UniProt 蛋白信息

「蛋白信息 · UniProt」独立默认开启，可在设置中关闭。新 API 会话可以直接提问：

> 在 UniProt 查询人 TP53 蛋白，使用 gene_exact:TP53 AND organism_id:9606，列出主编号、蛋白名、审阅状态、功能注释及来源。

> 按主编号 P04637 精确核对规范序列和长度，保留功能注释的来源参考标识。

> 将刚查到的 UniProt 条目保存到 outputs/proteins，生成 JSON、Markdown 和实际完整序列的 FASTA。

`uniprot_search` 支持关键词及 UniProt 查询表达式，每次返回 1–20 项，保留服务报告的总量，不自动翻页。`uniprot_get_accession` 接受 6/10 位主编号，规范为大写，并核对返回的 primaryAccession；不将次级/旧编号映射当作主编号相同。首版读取规范序列，不扩展同工型或结构预测。

审阅状态（reviewed/unreviewed）来自 UniProt，功能注释和参考标识只转述数据库记录，不表示本应用验证了生物学功能。缺失信息保持未提供，功能注释最多 10000 字、基因名和参考标识最多 40 项；截断会明确提示。

`uniprot_save` 只保存当前会话实际查到的记录，在 `outputs/proteins/records-*` 下新建 `records.json`、`蛋白清单.md`；有可用完整序列时生成 `sequences.fasta`，每行 80 字符，可从产物列表直接打开 FASTA 文本预览。序列必须为实际来源字母且长度一致；缺失或超过 100000 残基时不伪造/输出截断 FASTA，保存结果明确列出有序列/无序列的条目数。FASTA 头部为实际编号与蛋白题名，换行不会注入额外序列记录。

UniProt 使用自己的串行请求队列，单请求 20秒/2MiB、可停止，公共限流明确反馈。远端仅查询；本地保存经过写门，方案/讨论阶段只查不写。GEO/SRA 清单仍在 outputs/datasets，文献仍在 outputs/literature，各来源缓存独立。

官方：[API 查询](https://www.uniprot.org/help/api_queries)、[主编号](https://www.uniprot.org/help/accession_numbers)。
