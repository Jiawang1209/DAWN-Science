## 0. 需要作者定的

每条后面是**推荐的缺省**，计划按它写；改了哪条，计划里对应的 Task 跟着改。

1. **入口放哪、带不带字。** 缺省：自己说的每一句下面那行（复制 / 修改 旁边）常驻一颗 **「↶ 回到这句之前」，带字**；
   命令面板再给一条「回到上一句之前」。不做悬停才出现（CLAUDE.md「看不见的能力等于不存在」）；不只画图标（「新建项目」那颗裸 `＋` 的教训）。
   代价：每句用户话下面多一行字，视觉上重一点。另一个选项是只在 agent 回复末尾的产物条上放「回退这一轮」——但那样「回到哪一句」不直观，对话也不知道从哪儿截。
2. **对话要不要一起退。** 缺省：**两种都给，「文件和对话一起回退」是主按钮**（推荐），「只回退文件」是次按钮。
   理由：只退文件、对话留着，模型读到的上下文里写着「我生成了 figures/fig1.png」，而那个文件已经没了——它会照着一段不存在的历史往下做。
   Claude Code 给三种（代码+对话 / 只对话 / 只代码）；我们**不单独给「只撤掉对话」**，只在文件退不了（远端、存档之前）时它作为唯一出路出现。
3. **大文件与存档上限。** 缺省：单个文件 **50 MB**、每段会话存档 **2 GB**（按文件逻辑大小算，APFS 克隆省下的空间不抵扣），**不做设置项**。
   超了的逐个列在确认框的「退不回」里、并在超的那一刻对话里说一句（每段会话每种原因只说一次）。`data/raw/` 一律不存不碰。
4. **远端会话。** 缺省：**文件不回退，对话可以撤**。作者硬约束「服务器上不放任何文件」——在服务器上建存档目录就违反了它；
   把每轮被改文件的旧版本经 SSH 拉回本机存，技术上可行（代价：每轮开头 stat 一遍远端目录 + 拉回变更文件），**本轮不做**，写在 §8。
5. **你后来自己改过的文件。** 缺省：**不动、列出来**。不给「也覆盖」勾选框——要覆盖的话自己改回去，或下一版再说。
6. **撤销回退。** 缺省：本轮**不做按钮**。被换下来、被挪走的文件都在工作区 `.dawn/trash/rewind-<时间>/` 里，对话里那句通知写着路径，人能自己拿回来。
7. **存档从什么时候开始。** 缺省：本版之后新开或续上的 native 会话，**从起来那一刻起**存；更早的那几句只能撤对话（确认框如实说「这句在开始存档之前」）。
8. **挪走而不是删。** 缺省：「这句之前还没有它」的文件挪进工作区 `.dawn/trash/rewind-<时间>/`（同盘 `rename`，几 GB 的也瞬间），不走系统废纸篓、不 `unlink`。

## 1. 要解决什么

agent 这一轮把你的脚本改坏了、把 `results/tables/` 里的表覆盖了、在 `figures/` 里生成了一堆不要的图——现在**没有一步能退回去**：

1. **审阅那一屏答不了「这一轮」。** `src/ui/review.tsx` 头注自己写着：*「它答的是**累计**——从上次提交到现在，而不是『这一轮干了什么』」*，
   并且 *「这里可能包含你自己的修改——本阶段还分不清是谁改的」*。它只会看，不会退。
2. **git 救不了一半。** 科研仓库常把 `out/`、`figures/`、`results/` 写进 `.gitignore`，`git checkout` 对它们无效；临时会话（`~/DAWN/scratch/<ts>/`）根本不是仓库。
3. **账本记得「改了哪些」，不记得「原来是什么」。** `src/runtime/provenance.ts` 在每次工具调用前后拍 git / 文件系统事实，得到的是路径清单（`filesWritten` / `filesCreated`），没有旧内容。

Claude Code 的 `/rewind`：只跟踪**它自己的编辑工具**，bash 改的文件它明说不管。Codex 的逐轮 undo 是在仓库里拍 ghost commit。
**我们两条都不能照抄**：科研工作的主路径恰恰是 bash 跑脚本、`run_code` 在内核里写文件——只跟踪编辑工具等于只退了最不要紧的那部分；
ghost commit 又依赖 git、会被用户的 `.gitignore` / `.gitattributes` / hook 左右。

## 2. 交互

### 2.1 入口

```
 ┌──────────────────────────────────────────────┐
 │                  把 out/ 里的图按期刊格式重画一遍 │  ← 你说的话（气泡）
 └──────────────────────────────────────────────┘
   ⧉  ✎  ↶ 回到这句之前                                ← 常驻，不悬停也在；忙着时灰着，读屏读得到理由

 agent：好的，我先改 analysis/scripts/plot.py ……
 › ✓ 运行了 3 条命令                         共 12 秒
 GENERATED · 4   fig1.png  fig2.png  …
```

- 只有 native 会话画这颗（本地、远端都画；远端的确认框只给「只撤掉对话」，见 §2.3）。acp / cli / pty / 内核会话不画——它们的工具不经过我们，无从存档。
- agent 在跑时灰着：「agent 还在跑，停下之后才能回退」。**不排队**：回退是改文件的动作，和正在跑的工具抢同一批文件没有好结果。
- 命令面板「回到上一句之前」= 对最后一句自己说的话点这颗；不可用时写清是哪一种原因（没说过话 / 不是内置对话 / 在跑）。

```
│   不动     notes.md                （你后来改过）                    │
│   退不回   data/processed/all.parquet（超过 50 MB，没存旧版本）      │
│ ⚠ 内核里的变量不会回退：python 内核还是现在的样子。                   │
│ 对话：选「文件和对话一起回退」，这句和它之后的对话撤掉，这句放回输入框。 │
│                                                                      │

│ 范围。挪走和换下来的文件放进工作区的 .dawn/trash/。                    │

```

- 三颗按钮：`取消`（默认焦点）/ `只回退文件`（次）/ `文件和对话一起回退`（主，danger 色）。文案互不为子串（设计契约扫描、英文由 `i18n.test.ts` 扫）。
- **内核那行只要这段对话挂着活内核就一定出现**（python / R，本地远端都算）——文件回得去，内核里的变量回不去（规格 7.5：失败必须出声）。
- 列表为空时写「这句之后 agent 没有动过文件。」——不画一张空表。
- 文件退不了（§2.3）时：列表位置写原因，按钮只剩 `取消` / `只撤掉对话`。

### 2.3 文件退不了的几种，逐条说原因

| 缘故 | 确认框里那句 | 还能做 |
|---|---|---|
| 远端会话 | 远端会话的文件在服务器上，DAWN 不在服务器上存任何东西 | 只撤掉对话 |
| 这句在开始存档之前 | 这句在开始存档之前（这段会话早于回退功能） | 只撤掉对话 |
| 之后有一轮没存上档 | 这句之后有一轮没存上档 | 只撤掉对话 |
| 工作区超过 2 万个文件 | 工作区超过 2 万个文件，没法存档 | 只撤掉对话 |

### 2.4 回退之后

```
 （这句和它之后的对话已撤掉）
 ⓘ 已回到「把 out/ 里的图按期刊格式重画一遍」之前：改回去 2 个文件、挪走 1 个（放在 .dawn/trash/rewind-2026-09-27T…/）。
   notes.md 你后来改过，没动。data/processed/all.parquet 退不回（旧版本没存）。
   文件已回退，内核里的变量没有回退：python 内核里还是回退前算出来的东西。
┌ 输入框 ─────────────────────────────────────────────┐
│ 把 out/ 里的图按期刊格式重画一遍                       │  ← 放回来，可以改了再发
└─────────────────────────────────────────────────────┘
```

- 通知进转录（`notice` 项），不是一闪而过的 toast——它说的是一件发生过的事。
- 「只回退文件」：对话不动，通知接在末尾；**同时给模型留一句**（不显示给人，§4.4）：哪些文件退回去了，前面对这些文件的描述已过时。
- 附过图的那句：图没法放回输入框（转录里只有缩略图），通知里说「附的 N 张图没放回来，要的话重新附」。
- 账本记一条 Run：`origin: "user"`、`requestType: "rewind:<做法>"`、`filesWritten` = 改回去 ∪ 挪走的（不变式 3：没有不可见的行动）。已经发生过的那几轮的 Run **不改不删**——那是事实。

## 3. 哪些会话有

**只有 native。** 存档挂在我们包的工具上（§4.2），acp / cli 的 agent 用它自己的读写工具，内核会话没有「一句话」这个单位。
远端 native 会话：只撤对话（§0.4）。**Windows**：存档本身只用 Node 的 `fs`，不依赖 git，照样可用；没有 APFS 克隆时是真拷贝，速度与空间见 §5。

## 4. 分层

依赖决策（规格 §4）：

- **坐在哪一层**：文件那一半是我们自己的「影子存档」（`src/project/checkpoints.ts`），**只用 Node `fs`**：
  复用 `fs-facts.ts` 的 `fsSnapshot()` / `FS_SKIP_DIRS` / `FS_SNAPSHOT_CAP` 扫描，`fs.promises.copyFile(…, constants.COPYFILE_FICLONE)` 存旧版本（APFS 上是克隆、几乎不占地方；别的盘自动退回真拷贝）。
  对话那一半坐在 pi-coding-agent 的 `AgentSession.navigateTree(entryId)`（`agent-session.d.ts`：目标是用户消息时 *「leaf = parent, text goes to editor」*，返回 `editorText`）、
  `SessionManager.getBranch()` 找这一句、`AgentSession.sendCustomMessage({…, display: false}, { deliverAs: "nextTurn" })` 给模型留话。
- **放弃了什么**：①**影子 git**（会话目录里另起一个 `GIT_DIR`）——要求用户机器有 git ≥ 2.25（Windows、没装 Xcode 命令行工具的 Mac 上没有；「首启路径要按产品原样测」）、
  会被工作区里的 `.gitattributes`（LFS 的 clean/smudge 过滤器）左右、每次要为变过的文件算哈希再压缩；我们只要「整文件退回某一版」，不要 diff 与合并。
  ②**只跟踪编辑工具**（Claude Code 的做法）——bash 与 `run_code` 才是主路径。③pi 的 `navigateTree({ summarize: true })`——不给被撤掉那段写摘要，撤掉就是撤掉。
  ④跨会话、跨 worktree 的隔离——同一目录里两段会话同时写，归属仍然分不清（§7）。
- **不变式挂在哪个钩子上**：①「这一句的第一件工具执行之前，先拍一张开头」挂在 native 运行时给**每一件**自定义工具套的一层包装上（与 `套上溯源` 同一种写法，
  包在 `toolsFor()` 的返回值外面——内置、内核、MCP、插件、`subagent`、团队工具一件不漏）；②「这一轮收尾拍一张结尾」挂在 `送一轮` 的 `.finally` 里发 `idle` 之前；
  ③「data/raw 不存不碰」挂在存档模块唯一的判据 `在原始数据里()` 上，判据只从 `science-layout.ts` 的 `原始数据目录` 取（设计契约扫描）。

### 4.1 存档怎么记（`src/project/checkpoints.ts`）

目录：`<会话目录>/checkpoints/`——会话删了它跟着删（会话归档 spec：删会话真删会话目录）。

- `snapshots.jsonl`：一行一张快照，**只记对上一张的增量**（`set` 变了的、`del` 没了的）。每条记 `ino / mtimeMs / size`，存了旧版本的多记 `obj`（对象名）与 `mode`，跳过的记 `skip`（`too_large` / `over_budget` / `raw_data`）。
  全量清单 2 万条 × 每轮两张会把磁盘吃掉，所以按增量存、用的时候从头重放。
- `ledger.jsonl`：一串「段」，按时间先后：
  - `turn`（这一句）：`entry` = pi 里这句用户话的 entry id，`start` / `end` = 两张快照；
  - `rewind`（一次回退本身）：它改的文件也算「我们改的」，下一次回退跨过它时不当成你改的；
  - `gap`（断档）：这一句该拍没拍上（超上限 / 出错）。
  外加一行 `origin`：存档开始时 pi 的 leaf——那之前的几句「在开始存档之前」。
- `objects/<size>-<ino>-<mtime>`：旧版本本体。**按 stat 身份起名，不算哈希**——不用把 50 MB 的文件读一遍；同一版只存一次。

什么时候拍：

| 时刻 | 拍法 | 为什么 |
|---|---|---|
| 这一句的**第一件工具**开始前（同一句后面的工具不再拍） | 扫一遍 + 把「上次存过之后变了的」存下来 | 模型只说话不动手的那几句不必拍；工具执行前工作区里只有你与上一轮留下的东西 |
| 这一轮收尾（`idle`） | 只扫 stat，不存 | 用来判断「之后你又改过没有」；存内容留给下一句开头 |
| pi 在同一轮里送进下一句（排队的话） | 同一张既是上一句的结尾、也是这一句的开头 | 中间没有人手插进来的空当 |

### 4.2 回退算什么（「回到第 N 句之前」）

1. 找 **S** = 第 N 句及之后（当前对话分支上）**最早有「开头」的那一句**的开头快照。一句都没有 → 「这句之后 agent 没有动过文件」。
2. 从 S 往后按快照重放，每两张相邻快照之间要么是**我们的**（一段 `turn` / `rewind` 的开头到结尾），要么是**你的**（上一段结尾到下一段开头，以及最后一张到此刻）。
3. **要退的** P = 在「我们的」区间里变过的路径。对 P 里每一个：
   - 在 `data/raw/` 下 → 「退不回：原始数据，回退不碰它」；
   - 在任何一段「你的」区间里也变过（**S 之后**）→ 「不动：你后来改过」；
   - S 时没有它 → 挪进 `.dawn/trash/rewind-<时间>/`；
   - S 时有、存了旧版本 → 改回去（先拷到旁边的临时名、设回权限、再把现在那份挪进废纸篓、最后 `rename` 就位——中途失败现在那份不丢）；
   - S 时有、没存（太大 / 存档满了）→ 「退不回」，带大小。
4. S 之前你在两轮之间改的，不在 P 里——**不会被退掉**。
5. **目录不删**：agent 建的空目录留着（`科研目录` 那几个空目录本来就是有意建的，删目录会把它们一起删掉）。

回退本身作为一段 `rewind` 记进账：先拍一张 stat、做、再拍一张 stat。

### 4.3 对话那一半

- 定位：界面给的是转录里那条用户发言的 id（`u<序号>`）。后端在转录里数出它是**倒数第几句**用户话，连同原文交给运行时；
  运行时在 pi 当前分支上取倒数第几条 `role: "user"` 的消息，**核对原文**（pi 那句用 `native.ts` 的 `取文本()` 取出来要**包含**转录那句——视觉转述会在后面追加描述、图片会变成「（图片）」；`/` 开头的技能调用不核对）。
  **从后往前数**：会话续接后转录由 `buildSessionContext()` 还原，压缩过的前半截不在里面，从前往后数会错位。对不上就说「对不上」，**不猜**。
- 撤对话：`navigateTree(那句的 entryId)`——leaf 退到它的父节点，原文回来当 `editorText`；之后按 `侧边工具开` 再设一次 `read_main_session`
  （`native.ts` 注释：`navigateTree` 会经 `_restoreToolsFromTranscript` 重建工具集）。
- 转录：从那条用户发言起（含）往后全部撤掉，**你在笔记本里自己敲的 `cell` 项留着**——内核没回退，它们仍是内核里的事实。整份换、推一帧快照（与 `restore()` 同一个理由）。
- pi 的会话文件是只追加的树：撤掉的那段还在文件里（另一条分支），只是不在当前分支上。续接时转录照当前分支还原。

### 4.4 给模型留的话（`display: false`，`deliverAs: "nextTurn"`）

| 做法 | 什么时候留 | 说什么 |
|---|---|---|
| 只回退文件 | 总是 | 哪些文件退回到了第 N 句之前的样子、哪些挪走了、哪些因为你改过没动；前面对这些文件的描述已过时，用之前先重读 |
| 文件和对话一起回退 | 挂着活内核时 | 内核里的变量没有回退，还是被撤掉那几轮算出来的 |
| 只撤掉对话 | 总是 | 文件**没有**回退，工作区里还留着被撤掉那几轮的改动 |

### 4.5 协议（**下一个 minor**，纯新增）

- `previewRewind`（只读）：`{ sessionId, turnId }` → `{ files: { ok: true, restore, remove, keep, cannot } | { ok: false, reason }, kernels, images? }`。
- `rewindTurn`（`mutating`）：`{ sessionId, turnId, mode: "both" | "files" | "conversation" }` → `{ restored, removed, keep, cannot, failed, trash?, editorText?, kernels, conversationError? }`。
  写权规则与 `writeToSession` 相同（持租约的才能回退）；在跑 → `conflict`；那句不在转录里 → `not_found`；远端带 `files` / `both` → `invalid_request`。
- 版本号：执行时 `src/protocol/version.ts` 的**下一个 minor**（别的分支也在并行加操作，别写死数字）。
- **mock 同一次改动补上**（准入规则 1）：假模型加「改两个文件」分支——这一句带「改两个文件」→ 先说「我改两个文件。」再调一条 bash：
  `mkdir -p out && printf 'x\n' >> out/图.txt && printf '改过\n' >> README.md`。`dev:mock` 里人点得到回退，e2e 与集成测试也用它（`out/` 可以在 `.gitignore` 里，中文文件名是刻意的）。

## 5. 上限与代价（说在前面，不静默跳过）

| 上限 | 值 | 超了怎么说 |
|---|---|---|
| 单个文件 | 50 MB | 该文件不存旧版本；它被改了，确认框「退不回」里列出、带大小 |
| 每段会话存档 | 2 GB（逻辑大小） | 超的那一刻对话里说一句（只一次）；之后改动的文件逐个列在「退不回」 |
| 工作区文件数 | 2 万（沿用 `FS_SNAPSHOT_CAP`） | 那一句记断档、对话里说一句（只一次）；跨过它的回退只能撤对话 |
| `data/raw/` | 不存、不碰 | 它被改了（本不该）→「退不回：原始数据，回退不碰它」 |
| `.git` / `.dawn` / `node_modules` / 虚拟环境 / 符号链接 | 不扫 | 确认框底部那句 safety 常驻 |

代价：一段会话**第一次**动手前要把工作区（除上面几类）存一遍——APFS 上是克隆，几乎瞬间、几乎不占地方；别的盘是真拷贝，几百 MB 要一两秒。之后每句只存变过的。

## 6. 测试

- 单元（`tests/project/checkpoints.test.ts`）：开头 / 结尾 / 同一句只拍一次 / 重开读回；三种跳过与只喊一次；断档；回退的五种去向；你两轮之间改的不退、之后改的不动；
  跨过一次「只回退文件」再退；权限位；恢复失败时现在那份不丢；`data/raw` 一个字节都不动。
- 真 pi 集成（`tests/integration/rewind.test.ts`）：两句「改两个文件」→ 预览 → 一起回退（文件、`history()`、`editorText`）→ 只回退文件（`.dawn/trash`、下一次请求里有那句话）；在跑时拒。
- 后端（`tests/workbench/rewind-backend.test.ts`）：倒数第几句的换算；远端；转录截断留 `cell`；通知里的内核那句；租约；`not_found`。
- 界面（`tests/ui/rewind.test.ts`）：确认框内容的纯函数——每种去向、退不了的每种缘故、内核那行、按钮组合。
- e2e（`e2e/rewind.spec.ts`）：两轮之后一起回退（`.gitignore` 里的 `out/` 也退了）；只回退文件；你改过的不动；按钮 `opacity === "1"`；在跑时灰着。
- 设计契约：`checkpoints.ts` 里不写 `data/raw` 字面量、只用 `原始数据目录`。

## 7. 已知边界（写进确认框或通知的，另标 ★）

- ★**内核里的变量回不去**（本地与远端内核都一样）。
- ★远端会话文件不回退。
- 同一目录里两段会话同时在写（主区 + 坞里同处那段）：这一段在跑时另一段写的文件会算进这一段的「我们的」——与 `review.tsx` 那句「分不清是谁改的」同一个边界。
  两轮之间另一段写的，算「你的」，不会被退。
- 团队成员、子 agent 在工具返回之后还在写的，算「你的」（保守：不动）。
- 应用在一轮中途崩了：那一段没有结尾，下次回退时它开头到「此刻」都算「我们的」。
- 同一路径被改后 `mtime` 与大小都恰好不变（`cp -p` 一类）：认成没变——与 git 的 stat 缓存同一个边界。

## 8. 不做

- 远端会话的文件回退（把旧版本拉回本机存）。
- 撤销回退的按钮；「你改过的也覆盖」的勾选框；「只撤掉对话」作为常驻第三颗按钮。
- 逐文件挑着退、逐个 hunk 退；在确认框里看 diff。
- acp / cli 会话（它们的工具不经过我们；账本那边的「拍基线」只有路径没有内容）。
- 重启内核按钮（通知里只说清楚内核没回退）。
- 可调的上限。
