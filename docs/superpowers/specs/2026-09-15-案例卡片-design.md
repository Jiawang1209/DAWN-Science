# 案例卡片 · 设计

> 2026-09-15。分支 `case-cards`。接着 `2026-09-14-照着案例分析-design.md`（那一份的定案 C4 把「对话里的案例卡片」列为「不做，等用出需要」——作者真用之后提出来了）。

作者的话：

> *「很好用了，基本上这个就完全符合我的预期了。不过……页面上其实显示的是每一个案例的链接。能否每一个案例，不要显示是链接形式的，而是……一个一个真实内容的效果呢？」*
> *「agent 其实就是从 MLAI-Science 里面取出案例，然后我们来进行选择就好了。后续让 agent 学习和模仿哪个具体案例，其实也应该是我们来进行选取的。」*

## 这属于哪一边（作者问过）

**DAWN。** MLAI 是不管界面的知识库（通过 MCP 交数据、图廊给图），它不知道对面是 DAWN 还是终端；
卡片、右侧打开、「照这篇做」、图片不进上下文，全是 DAWN 的东西。**MLAI 一行不改。**

## 定案

### K1 · 数据：从这一轮 MLAI 工具的返回里取（第二版）

**第一版**让 agent 附一段 ```mlai-cases 清单。作者真机试的第二次（「帮我看看绘制热图有什么案例？」），会话原始记录显示：
模型**根本没读 `analyze-like-case` 技能**，直接调了 8 次 MLAI 工具（`search_figures` ×4、`search_cases` ×2、`list_taxonomy`、`recommend_figures`），
写出一大段带 case_id 的文字——没有清单，卡片自然没出。**「模型记得按格式写」不可靠**；工具返回是结构化的、一定在转录里。作者选了改。

`src/ui/case-cards.ts`（纯函数）：
- **收**：这一轮（上一句用户发言之后）名字形如 `<服务器>__search_cases|semantic_search|search_figures|search_chunks|recommend_figures|recommend_pipeline|get_case`
  的工具返回，去掉 `[服务器] ` 前缀解析 JSON，**递归找带 `case_id` 的对象**，按 id 合并（`title`/`case_title`、`language`、`cover`/`preview`、
  `caption` 或 task·algorithms·figure_types 拼的一句话；先到的字段不被覆盖）。解析不了（结果超过 16KB 被截断）就跳过那一次。
- **出哪几张**：说完的 agent 发言**正文里提到的** case_id，按首次出现排。模型常把长 id 截短（真机见过 `20251019-xacaaee`）：
  8 位日期开头、≥12 字符的片段若**恰好是唯一一个**已知 id 的前缀也认；对不上唯一一篇的不猜。**一篇没提 → 不出卡**。
- **图廊根**：界面读 `listMcpServers`，有 `url` 的那台去掉 `/mcp`。stdio 起的那台没有图廊——卡片照出，封面位置写「这台 MCP 没有图廊」、不能点开详情。
- 对话层按条目 `useMemo` 算一次（流式时每个 token 都重渲染，不记住就每个字重解析一遍 JSON）。

### K2 · 封面：主进程取，协议 7.34 `fetchLocalImage`

界面 CSP 是 `img-src 'self' data:`，**不放宽**（放宽会让任何 markdown 都能从本机服务拉图）。
`src/workbench/本机图片.ts`：只认本机 http(s)、只收 `image/*`、上限 2MB、5 秒超时，任一条不过都抛出并说清；界面拿 base64 拼 data URL。
模型全程看不到图。

### K3 · 卡片与两个动作（作者定：选择权在人）

`src/ui/case-cards-view.tsx`：网格（`auto-fill, minmax(15rem, 1fr)`），每张：封面 · `n · 语言` · 标题（两行截断）· 一句话 · **「照这篇做」**。

- **点卡片主体** → 右侧「网页」格开 `<base>/gallery/case/<case_id>`。**不触发选择**。
- **「照这篇做」** → 替人发 `照这篇做：《标题》（case_id: …）`，走与手打同一条发送路（与 `onResend` 同形）。
  **常驻可见**；agent 在忙（`busy`）或会话只读时灰着。消息带 case_id，agent 不必从「第 2 个」去猜。
- 封面四态：取到 → 图；没有 `cover` → 「没有封面」；取不到 → 「封面没取到」；取着 → `Loader`「正在取封面」。

### K4 · 技能跟着改

`analyze-like-case` 第 ③ 步：每条写**完整 case_id**（反引号）+ 标题 + 语言 + 一句话；说明 DAWN 会据此出卡，所以别截短、只提推荐看的那几篇、不必贴链接。
**卡片不依赖技能被读到**——没读到时模型正文照样会提 case_id，卡照样出；技能只是让它提得更准。
第 ④ 步明写：**挑案例是他的事**，两种选择形态（按钮发来的 case_id / 手打序号）都认，对不上就问不猜。

## 验证

- 单元：`tests/ui/case-cards.test.ts`（只认 MLAI 案例工具、按 id 合并不覆盖、图级检索也拼得出卡、一句话的拼法、按正文先后、截短 id 唯一前缀、太短/歧义不猜、没提不出卡、图廊根与地址、那句话带 case_id）；
  `tests/workbench/local-image.test.ts`（起真 HTTP 服务：取到、非本机拒、404、非图片、超 2MB、超时）。
- e2e `e2e/case-cards.spec.ts`：`scripts/mcp-test-server.mjs` 以 HTTP 起一台 `mlai-science`（新增假 `search_cases`，同一台兼当图廊）；
  假模型只调一次工具、正文里平常地提到两篇（一篇截短 id）、**不给任何格式**。断言 2 张卡且顺序对、没被提到的那篇不出、
  封面是真加载的 data URL、点卡片右侧开详情、「照这篇做」opacity 1 且点了发出带完整 case_id 的话。
